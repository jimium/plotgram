# 21 · 专业术语表（Glossary）

> 用途：**快速建立领域词汇表**。图绘制（Graph Drawing）领域的论文与开源代码里，同一个概念常有 3 个名字，
> 而很多关键词（nudging、dogleg、cut value、kitty corner）在中文资料里几乎查不到解释。
>
> 每条格式：**英文（常见别名）** · 中文 · 一句话本质 · *为什么重要 / 踩坑*（→ 对应篇号）
>
> 检索建议：直接 Ctrl+F 搜英文词。术语按**主题**分区而非字母序，因为相邻术语往往互为前提。

## 1. 领域与总纲

- **Graph Drawing (GD)** · 图绘制 · 研究"如何把抽象图画成好看且可读的图形"的领域。
  *年度会议 GD（论文集在 Springer LNCS）是主要来源；Handbook of Graph Drawing and Visualization 是最全的手册。*（→ 12）
- **Node-link diagram** · 节点链接图 · 用点表示实体、线表示关系的表示法（相对于矩阵视图、树图 treemap 等）。
  *本项目讨论的全部内容都在这个表示法之内。*
- **Aesthetic criteria** · 美学准则 · 交叉少、弯折少、对称、边长均匀、面积小等一组可量化的"好看"标准。
  *不是玄学：Purchase 等人做过对照实验。实证有效性排序：交叉 > 弯折 > 交叉角度 > 对称 > 边长。*（→ 11）
- **Readability / Faithfulness** · 可读性 / 忠实性 · 前者=人看得懂，后者=画面不误导（不暗示不存在的关系）。
  *例：两个不相连的节点画得极近就是不忠实。*
- **Drawing convention** · 绘制约定 · 硬性几何规则（如"边必须正交""层必须水平")，与"美学准则"（软目标）区分。
  *约定是约束，准则是目标函数。混淆二者会让算法设计失焦。*
- **Layout algorithm vs Edge router** · 布局算法 vs 边路由器 · 前者定节点坐标，后者定边路径。
  *把两者拆成独立的一等公民，是 yFiles/现代引擎架构的关键决策 —— 于是"分层布局 × 正交路由"这类组合免费获得。*（→ 09）

## 2. 图论基础

- **Directed / Undirected** · 有向 / 无向 ·
- **DAG (Directed Acyclic Graph)** · 有向无环图 · 分层布局的理想输入。
- **Cycle / Feedback Arc Set (FAS)** · 环 / 反馈弧集 · 要删（实际是反向）多少条边才能无环。
  *Minimum FAS 是 NP 难；工业界用 Greedy-FAS（Eades–Lin–Smyth 1993）。*（→ 01）
- **SCC (Strongly Connected Component)** · 强连通分量 · 互相可达的极大节点集。
  *去环只需在每个 SCC 内部做 —— 跨 SCC 的边天然无环。这个观察能同时提速与提质。*（→ 14）
- **BCC (Biconnected Component) / Cut vertex / Block-cut tree** · 双连通分量 / 割点 / 块割树 ·
  删掉任一节点仍连通的极大子图；割点是删掉后分裂图的节点。
  *circular 布局按 BCC 分块、块割树上做树布局。*（→ 05, 14）
- **Bridge** · 桥 · 删掉后图不连通的边。
- **Planar graph / Planarity** · 平面图 / 平面性 · 能画成无交叉。
  *线性判定：Boyer–Myrvold（同时给嵌入）、Left-Right planarity（实现最短）。*（→ 02）
- **Embedding / Rotation system** · 嵌入 / 旋转系统 · 每个节点周围边的**环形顺序**；确定了嵌入就确定了所有的面。
  *"拓扑先定、几何后定"是 TSM 的思想根基。*（→ 02）
- **Face / Outer face** · 面 / 外面 · 平面嵌入把平面分成的区域。
  *Tamassia 的最小弯折流网络就建在"顶点 + 面"上。*
- **SPQR-tree** · SPQR 树 · 三连通分解，紧凑表示一个图的**所有**平面嵌入（S=串联/环，P=并联，R=刚性，Q=单边）。
  *用于"在所有嵌入中找最优边插入"。实现最难，收益最窄 —— 建议先用固定嵌入。*（→ 02, 14）
- **Kuratowski subgraph** · Kuratowski 子图 · 不平面的"证据"（$K_5$ 或 $K_{3,3}$ 的剖分）。
- **Bipartite graph** · 二分图 · 分层布局的相邻两层就是二分图（所以"两层交叉最小化"是核心子问题）。
- **Hypergraph / Hyperedge** · 超图 / 超边 · 一条"边"连接 ≥3 个端点（如一根信号连 5 个引脚）。
  *绘制时通常退化为"引入一个虚节点做 Star"，于是普通图算法全部可用。*（→ 18）
- **Compound graph / Clustered graph** · 复合图 / 聚类图 · 带分组（可嵌套）的图。
  *分组是产品级差异点，也是布局复杂度的主要来源之一。*（→ 08）
- **Multigraph / Parallel edges / Self-loop** · 多重图 / 平行边 / 自环 ·
  *这三者是"退化情形"的常客，必须有专门的 stage 处理，否则完全重合。*（→ 15）
- **Degree / Fanout** · 度 / 扇出 · 节点的边数 / 出边数。
  *高扇出（1 对 500）是压力测试的必备 case。*
- **Topological order / sort** · 拓扑序 · DAG 的线性化。
  *分层与序列图的"行号"分配都建在它之上。*
- **Spanning tree / Tight tree** · 生成树 / 紧树 · 后者是 network simplex 中"所有树边 slack=0"的生成树。（→ 01）
- **Treewidth** · 树宽 · 图"接近树"的程度。
  *理论上很多 NP 难布局问题在有界树宽上可解，但工程上基本用不到 —— 知道这个词即可。*

## 3. 分层布局（Sugiyama 框架）

- **Sugiyama framework / Hierarchical layout / Layered layout** · Sugiyama 框架 / 分层布局 ·
  四（五）相流水线：去环 → 分层 → 层内定序 → 坐标 → 画边。
  *流程图、架构图、状态图、ER、数据血缘的主力算法。*（→ 01）
- **P1–P5** · 本文库对五相的简称：P1 去环、P2 分层、P3 定序、P4 坐标、P5 边绘制。
  *每相有且只有一个自由度的写权 —— 这是本项目最重要的纪律。*（→ 01, 09）
- **Cycle removal / Edge reversal** · 去环 / 边反向 · 把回边临时反向使图变 DAG，最后画箭头时再翻回来。
  *"reversed" 位是 P1 的唯一输出自由度。*
- **Greedy-FAS** · 贪心反馈弧集 · 反复摘 sink/source，剩余取 $\text{outdeg}-\text{indeg}$ 最大者。
  *有质量下界保证，$O(V+E)$，工业标准。*（→ 01）
- **Layering / Ranking / Level assignment** · 分层 · 给每个节点定一个整数层号。
  三种做法：Longest-Path（快、图扁、dummy 多）、Coffman–Graham（限层宽）、**Network Simplex**（最小加权跨度，质量最好）。（→ 01）
- **Rank** · 层号（Graphviz 的叫法，等于 layer）。
- **Minlen / Min layer span** · 最小跨度 · 一条边至少跨几层（默认 1）。
  *设为 2 可以给边标签留出一整层空间 —— 这就是 label dummy 的原理。*
- **Network Simplex** · 网络单纯形 · 求"最小加权总跨度"的整数最优解。
  *dot 的 `rank.c`。实现难点是 cut value 的增量维护，建议先写全量重算版本。*（→ 01, 14）
- **Cut value** · 割值 · 去掉一条树边后，两侧之间的边权净差。
  *负值表示"可以改进" —— 这是换基的判据。*（→ 14）
- **Slack** · 松弛量 · $(\lambda_v - \lambda_u) - \text{minlen}$，即这条边"还能压缩多少"。
- **lim / low** · DFS 后序区间 · 用区间包含 $O(1)$ 判断"某节点在树边的哪一侧"。
  *network simplex 的关键加速结构。*
- **Node promotion** · 节点提升 · 把节点向上挪一层以减少 dummy 数。（→ 01）
- **Dummy node / Virtual node / Bend point node** · 虚节点 · 长边穿过中间层时插入的占位节点。
  *真实规模是 $V + D$，$D$ 常是 $V$ 的数倍。**dummy 是"上游给下游留的展开点"，是写权纪律的物理体现。***（→ 01）
- **Long edge chain** · 长边链 · 同一条边产生的 dummy 序列。
  *应作为整体处理（块级 sifting），否则宽层上 dummy 数量主导一切。*
- **Crossing minimization / Mincross** · 交叉最小化 · 定层内顺序使边交叉最少。
  *两层版本已 NP 难（Eades–Wormald 1994）；工业做法是层间来回 sweep。*（→ 01）
- **Layer-by-layer sweep** · 逐层扫描 · 固定一层、优化下一层，来回多轮。
- **Barycenter heuristic** · 重心法 · 节点新位置 = 邻居位置的平均。
- **Median heuristic** · 中位数法 · 取邻居位置中位数；有 3-近似保证，质量优于 barycenter。
  *为什么中位数更好：目标是 $L_1$ 型（位置差绝对值之和），而中位数是 $L_1$ 的最优点。*（→ 01, 18）
- **Transpose** · 相邻交换 · 试着交换相邻两点，若交叉减少就保留。
  *增量判定只需 $O(\deg_u+\deg_v)$，不要全层重算。*
- **Sifting** · 筛动 · 把一个节点在整层所有位置上滑一遍取最优；质量优于 transpose，更慢。（→ 01）
- **Best snapshot** · 最优快照 · 每轮记录最好结果，结束时恢复。
  *因为 barycenter/median 这类"全局一步"可能变差，最后一轮不一定最优。**这条被反复忘记。***
- **Edge weight (1/2/8)** · 边权 · dot 的经典配方：real–real 边权 1、real–dummy 2、dummy–dummy 8。
  *效果：让长边优先变直。几十行代码换来观感质变 —— 投入产出比最高的单项。*（→ 01, 13）
- **Bilayer cross counting** · 双层交叉计数 · Barth–Jünger–Mutzel 的 $O(E\log V)$ 算法（用 Fenwick 树）。
  *sweep 内循环反复调用，朴素 $O(E^2)$ 会成为热点。*（→ 14, 16）
- **Coordinate assignment / x-coordinate assignment** · 坐标分配 · 在层内顺序已定的前提下定次轴坐标。
- **Brandes–Köpf (BK)** · BK 算法 · 线性时间坐标分配：4 次对齐（上/下 × 左/右）+ 紧致化 + 取中位平均。
  *工业默认。**必读 2020 勘误** —— 原文 compaction 伪代码有错，多个开源库因此出过节点重叠。*（→ 01）
- **Type-1 conflict** · 一类冲突 · "真实边与长边交叉"的情形，BK 中必须标记以避免长边被拉弯。
- **Priority method** · 优先级法 · Sugiyama 原文的坐标法，按度数/类型给优先级迭代靠拢。*质量差于 BK，历史价值。*
- **Straightness of long edges** · 长边直线率 · 跨多层的边中"完全竖直"的比例，是 P4 质量的直接指标（BK 应 >90%）。（→ 11）

## 4. 正交布局

- **Orthogonal drawing** · 正交绘制 · 边只由水平/垂直段组成。
  *工程/电路/ER 图的默认风格；"专业感"的主要来源。*（→ 02）
- **TSM (Topology–Shape–Metrics)** · 拓扑–形状–度量 · 正交布局的三段式：
  平面化（定拓扑）→ 正交化（定弯折形状）→ 紧致化（定实际长度）。
  *"先定拓扑、再定形状、最后定尺寸"是极其干净的写权分层，值得借鉴到任何布局。*（→ 02）
- **Planarization** · 平面化 · 把交叉变成假节点（crossing dummy），使图变平面。
  *常用 remove-reinsert：先抽出一批边使其平面，再逐条以最少交叉插回。*
- **Crossing dummy** · 交叉假点 · 平面化引入的度 4 假节点，最后还原为一个交叉。
- **Orthogonal representation** · 正交表示 · 只记录"每条边的弯折序列 + 每个角是 90/180/270°"，不含长度。
- **Bend** · 弯折 · 路径的一个 90° 拐点。*正交图的第一质量指标。*
- **Tamassia's min-cost flow model** · Tamassia 流模型 · 把"最小弯折"转成最小费用流（顶点供流、面需求、面间弧费用 1）。
  *固定嵌入下**最优**且多项式；正交布局的理论基石。*（→ 02, 14）
- **Kandinsky model** · Kandinsky 模型 · 允许节点度 > 4 的正交模型（节点是有尺寸的盒子，多条边可从同一侧出）。
  *最小弯折在此模型下 NP 难（Bläsius et al.）—— 所以工业实现都是启发式。*
- **Compaction** · 紧致化 · 给定形状后确定实际坐标，最小化面积/总长。
- **Turn-regularity / Kitty corner** · 转向规则性 / 猫角 · 判断一个正交多边形能否被"无冲突地"紧致化的判据。
  *读它能理解"为什么紧致化会算错导致重叠"。Bridgeman et al. 1997。*（→ 02）
- **Saturating edge** · 饱和边 · 为破解 kitty corner 对而加入的额外约束边。
- **Grid drawing** · 网格绘制 · 所有坐标为整数。*对齐感强，也让相等判断变精确（避免浮点）。*
- **Vertex inflation** · 顶点膨胀 · 把一个高度节点展开成一个小环，从而套用度 ≤4 的理论。

## 5. 边路由

- **Edge routing** · 边路由 · 在节点位置已定的前提下算边的路径。
  *独立于布局的一等公民；产品观感的最后一公里。*（→ 03）
- **Polyline / Orthogonal / Curved / Straight-line** · 折线 / 正交 / 曲线 / 直线 · 四种路由风格。
- **OVG (Orthogonal Visibility Graph)** · 正交可见图 · 从每个关注点向四方向发射射线，交点构成的搜索图。
  *任意节点位置下都适用（拖动后重路由）；用扫描线构造 $O(n\log n + |E_{vis}|)$，别写双循环。*（→ 03）
- **Visibility graph** · 可见性图 · 互相"看得见"（连线不穿障碍）的点对构成的图。
- **Channel / Corridor** · 通道 / 走廊 · 节点之间的可通行空隙。
  *分层布局的层间空隙就是通道 —— **于是层间路由 = VLSI 通道布线**，四十年成熟算法可直接搬。*（→ 03, 18）
- **Track / Lane** · 车道 · 通道内的一条并行路径位置。
  *多条边并行时各占一个 track。分配 = 区间图着色（贪心按左端点即最优）。*（→ 14）
- **Interval graph coloring / Left-edge algorithm** · 区间图着色 / 左边界算法 · 按左端点排序 + 最小可用色。
  *区间图是完美图，所以贪心即最优（色数 = 最大重叠数）。出处：Yoshimura–Kuh 1982。*（→ 14, 18）
- **Nudging** · 微调 / 挪让 · 把同走廊内的多条平行段横向错开，使不重合且整齐。
  *英文原词无标准中译，直接用 nudging。做法：建偏序约束图 + VPSC 求解；偏序有环时需允许一次交叉。*（→ 03）
- **A\* search** · A\* 搜索 · 带启发式的最短路。
  *路由中**状态必须包含进入方向** `(vertex, dir)`，否则弯折惩罚失效 —— 这是最常见的路由 bug。*（→ 03, 16）
- **Admissible heuristic** · 可采纳启发式 · 不高估真实代价的 $h$，保证 A\* 最优。
  *正交路由可用 $h = |dx|+|dy| + \lambda_{bend}\cdot b_{min}$，其中 $b_{min}$ 是必需的最少转弯数（0/1/2 查表）。*
- **Bend penalty** · 弯折惩罚 · 搜索代价里对转向的加权。*调它就是调"宁绕远还是宁多拐"。*
- **Dogleg** · 折腿 · 允许一条边中途换 track（加一段垂直跳转）。
  *通道布线中用于打破"垂直约束图"的环。图路由里对应"允许一次交叉"。*（→ 18）
- **VCG (Vertical Constraint Graph)** · 垂直约束图 · 通道布线中"哪条 net 必须在哪条之上"的有向图。
  *有环 = 互相要求在对方之上 = nudging 的环冲突，同一个问题。*
- **Rip-up and reroute** · 拆线重布 · 拆掉拥塞区的部分边重新走。
  *解决局部拥塞的**正确**手段，取代"给某条边加特判"。*（→ 18）
- **History cost / Negotiated congestion (PathFinder)** · 历史代价 · 走廊代价随历史拥塞次数累加。
  *避免"两条边互相让路"的震荡。McMurchie–Ebeling 1995。极其实用。*（→ 18）
- **Global vs Detailed routing** · 全局 vs 详细布线 · 前者只决定"经过哪些走廊"，后者决定走廊内精确位置。
  *EDA 的这个两段式 = "拓扑自由度"与"几何自由度"的分离，与写权纪律完全一致。*（→ 18）
- **Congestion / Capacity / Demand** · 拥塞 / 容量 / 需求 · 走廊能容纳几条边 vs 实际要走几条。
  *demand 超容量时**回写层间距**（扩宽走廊），而不是在路由阶段挪节点。*（→ 20）
- **Bus routing** · 总线路由 · 一组边共享一条主干 + 各自短支线。
  *主干位置 = 端点坐标的**加权中位数**（$L_1$ 最优，可解析求出）。*（→ 18）
- **Steiner tree (rectilinear)** · （直角）斯坦纳树 · 连接多个点的最短树，允许加辅助点。
  *超边/总线的理论形态；工程上用 median trunk 近似即可。*
- **Edge bundling** · 边捆绑 · 让边互相吸引靠近以降低视觉杂乱。
  *Hierarchical Edge Bundles（Holten 2006）性价比极高；但曲线风格与正交冲突。*（→ 03）
- **Ordered bundles** · 有序捆绑 · 边共享走廊但保持有序的平行细线（可追踪 + 整齐）。
  *最适合工程图的捆绑方案（Pupyrev 2011 / MSAGL）。*（→ 18）
- **Jump / Hop** · 跳线 · 两边交叉处画小半圆或断口。
  *必须只让**一条**边让位，否则两边都断会看起来像断线。*（→ 15）
- **Incremental routing / Hysteresis** · 增量路由 / 滞回 · 只重算受影响的边；给旧路径打折扣使小扰动下路径不变。
  *折扣会破坏 $h$ 的可采纳性，实践中可接受。*（→ 17）
- **Waypoint** · 途经点 · 用户或上游指定边必须经过的点。
- **Self-loop placement** · 自环放置 · 自环画在节点哪一侧、多个自环如何错开。
  ***自环尺寸必须计入节点有效包围盒**，否则会压住邻居。*（→ 15）

## 6. 力导向与 stress 布局

- **Force-directed / Spring embedder** · 力导向 / 弹簧嵌入 · 边=弹簧、节点=同性电荷，迭代到平衡。（→ 04）
- **FR (Fruchterman–Reingold)** · 最广泛实现的力导向 + 退火降温。
- **Annealing / Cooling schedule** · 退火 / 降温 · 让每步最大位移随迭代递减，保证收敛。
- **KK (Kamada–Kawai)** · 基于图论距离的能量模型（stress 的前身）。
- **Stress (function)** · 应力函数 · $\sum_{ij} w_{ij}(\|p_i-p_j\| - d_{ij})^2$，让画面距离逼近图论距离。
  *比"力"更好的抽象：它是**明确的目标函数**，因此可度量、可比较、可证明单调下降。*（→ 04）
- **Stress majorization / SMACOF** · 应力优化 · 用二次上界迭代求解 stress，保证单调下降。
  *neato 的 `mode=major`。每步要解稀疏线性系统。*
- **SGD stress** · 随机梯度下降 stress · 每次随机取一对节点直接调整（Zheng 2018）。
  *20 行代码、比 SMACOF 快且好，**推荐作为主力实现** —— 而且不需要线性代数库。*（→ 04, 13）
- **MDS (Multidimensional Scaling)** · 多维缩放 · 由距离矩阵求低维坐标；stress 是其一种。
- **PivotMDS** · 枢轴 MDS · 只用 $k$ 个 pivot 的距离，$O(kE)$ 得到高质量初值（Brandes–Pich）。
  *大图必备：好初值让后续迭代次数骤降。*
- **Barnes–Hut / θ criterion** · 四叉树近似远场斥力，$O(n\log n)$；$\theta$ 控制精度/速度权衡。
- **Multilevel / Coarsening / Refinement** · 多级 / 粗化 / 精化 · 反复合并成小图 → 小图上求解 → 逐级插值+精化。
  *大图布局的唯一实用途径。粗化用 heavy-edge matching / MIS filtration / solar system。*（→ 04, 14）
- **Heavy-edge matching** · 重边匹配 · 粗化时优先合并权重大的边两端。
- **MIS filtration** · 最大独立集过滤 · sfdp 的粗化方式。
- **LinLog** · 对数吸引力模型 · 理论上其最优解 ≈ 社区结构（Noack 2007）。
- **ForceAtlas2** · 生产级力导向（度数缩放斥力 + local speed 自适应步长），Gephi 的默认。
- **PRISM (Proximity Stress Model)** · 消重叠的最佳质量方案：用 Delaunay 邻接构造"最小距离"stress 并迭代（Gansner–Hu）。
  *相比"硬推开"，它保留 mental map。*（→ 04）
- **Node overlap removal** · 消重叠 · 让有尺寸的节点互不重叠。*另一条路是 VPSC（更快、可与其它约束统一）。*
- **Polyomino packing** · 多联骨牌装箱 · 把多个连通分量紧凑排布（Freivalds et al.）。
- **Substructure detection** · 子结构识别 · 识别星/链/环/团并用专门样式画。
  *organic 图种"观感质变"的关键（yFiles Organic 的招牌能力之一）。*（→ 04）
- **Component layout / Packing** · 分量布局 / 装箱 · 各连通分量分别布局再排布。*天然可并行，最值钱的并行点。*（→ 16）

## 7. 树与径向布局

- **Reingold–Tilford (RT)** · 经典整齐树布局；5 条美学准则（同深同 y、父居中、镜像对称、同构子树同形状、紧凑）。（→ 05）
- **Contour / Thread** · 轮廓 / 线索 · 子树的左右边界；thread 是把轮廓串成链表的 $O(1)$ 技巧。
- **Walker's algorithm** · 推广到任意度树，但原实现最坏 $O(n^2)$。
- **Buchheim–Jünger–Leipert** · 修正为真正 $O(n)$（`ancestor` / `shift`/`change` 机制）。
  *树布局的**正确**实现依据（D3 `d3.tree` 即此）。*（→ 05）
- **Prelim / Mod** · 预备坐标 / 修正量 · 树布局中"先算相对位置、后一次性累加偏移"的经典手法。
- **NodePlacer** · 子节点摆放策略（居中 / 总线 / 双列 / 树状图 dendrogram 等）。*同一棵树换 placer 得到完全不同风格。*
- **Radial layout** · 径向布局 · 层 = 同心圆环。
  *关键：角需求自底向上传播，半径 $r_d = \max_i(w_i / \Delta\theta_i)$。*（→ 05）
- **Balloon layout** · 气球布局 · 每个子树画成一个圆盘围绕父节点。
  *半径二分求解：$\sum 2\arcsin(r_i/R) \le 2\pi - \text{reserved}$。*
- **Dendrogram** · 树状图 · 叶子对齐在同一层的树画法（聚类结果常用）。
- **Circular layout** · 圆形布局 · 节点排在圆周上；排序常用谱方法（Fiedler 向量）+ BCC 分块。（→ 05）
- **Treemap / Circle packing** · 矩形/圆形嵌套填充 · 非节点链接的层次表示法。
- **Tree reduction stage** · 树化 stage · 把图中的树状部分摘出来单独用树布局画，再挂回主图。
  *让"主体是 DAG、局部是树"的图（很常见）观感大幅提升。*（→ 09）

## 8. 标签

- **Label placement** · 标签放置 · 给节点/边/组的文字找位置。*NP 完全（Formann–Wagner 1991）。*（→ 06）
- **4-position model / Slider model** · 四位置模型 / 滑块模型 · 候选位置离散（角落四选一）或连续（沿边滑动）。
- **Candidate** · 候选位置 · 一个标签的所有可选放置。
- **Conflict graph** · 冲突图 · 候选之间"互相重叠"的图；求解 = 独立集/匹配问题（Kakoulis–Tollis）。
- **Label dummy** · 标签虚节点 · 在分层布局中把边标签变成一个占位节点（该边 minlen 设 2）。
  ***空间预留**优于事后避让 —— 事后避让必然重叠或飘远。这是标签问题的正解。*（→ 06）
- **Leader line** · 引出线 · 标签放远处时连回本体的细线。
- **Text measurement / Shaping** · 文本度量 / 排版整形 · 由字体度量算出文字盒子（kerning、连字、CJK）。
  *节点尺寸的输入，影响一切。工作量常被低估。Rust 侧用 ttf-parser + rustybuzz。*（→ 06, 15）
- **UAX #14 line breaking** · Unicode 断行算法 · CJK 与西文混排断行的规范依据。
- **Content-based sizing** · 按内容定尺寸 · 节点尺寸由其内容（文字/子元素）决定。
  *必须作为**独立的 measure 相**在布局之前完成（本项目 ADR-005）。*

## 9. 约束、增量与稳定性

- **VPSC (Variable Placement with Separation Constraints)** · 分隔约束下的变量放置 ·
  求解 $\min\sum w_i(x_i - x_i^{des})^2$ s.t. $x_j - x_i \ge g_{ij}$，$O(|C|\log|C|)$，**全局最优**。
  *布局界的万能扳手：消重叠、层内间距、正交紧致化、nudging、对齐、组框边距六处共用一份实现。
  投入产出比排名前三。*（→ 07, 14）
- **Separation constraint** · 分隔约束 · "b 至少在 a 右边 g 距离"。
- **Block (in VPSC)** · 块 · 约束已达紧绷而被绑在一起移动的变量集合。
  *算法核心是 block 的 merge 与 **split**（按负 Lagrange 乘子）；漏了 split 会在冗余约束下给出次优解。*
- **Projection (method)** · 投影法 · 交替"无约束优化一步"与"投影回可行域"。
  *投影必须是**欧氏最近点**投影，否则不保证收敛 —— 这是"用 VPSC 而非启发式挪位"的理由。*
- **IPSEP-CoLa** · stress + 分隔约束的统一框架（WebCola 的核心）。（→ 07）
- **PAV / Isotonic regression** · 池化相邻违反 / 保序回归 · $O(n)$ 求"最近的保序序列"。
  *用于受约束的层内排序（组内必须连续等）。*
- **Layer / Sequence constraint** · 层约束 / 序约束 · "A 必须在 B 上一层""A 必须在 B 左边"。
- **Alignment constraint** · 对齐约束 · 一组节点共享同一 x 或 y。*用户手工图里最常见的诉求。*
- **Mental map** · 心智地图 · 用户对图空间布局的记忆。三条可度量性质：
  **orthogonal ordering**（左右/上下相对序）、**proximity**（近的仍近）、**topology**（不产生新跨越）。（→ 07）
- **From-sketch / Incremental layout** · 由草图 / 增量布局 · 用当前坐标反推层与层内序作为初值。
  *效果最好的单一稳定性手段，约 100 行。*（→ 07, 17）
- **Partial layout / Fixed nodes / Pinning** · 部分布局 / 固定节点 / 钉住 · 只重排一部分，其余保持。
  *用户手工调过的元素应打 `pinned`，后续自动布局必须尊重。*
- **Stability metrics** · 稳定性指标 · 平均归一化位移、正交序违反率、k-NN 保持率（Jaccard）、重路由边数比。（→ 11, 17）
- **Layout morphing / Staged transition** · 布局形变 / 分阶段过渡 ·
  *实证结论：**分阶段**（先淡出→再移动→后淡入）优于同时进行（Heer–Robertson 2007）。*（→ 17）
- **Cluster motion** · 聚类移动 · 位移相近的节点同步移动，观感从"粒子云"变"板块移动"。
- **LOD (Level of Detail) / Semantic zoom** · 细节层级 / 语义缩放 · 缩小时隐藏文字与装饰。
  *阈值切换必须有 hysteresis（0.28 进 / 0.32 出），否则会闪烁。*（→ 17）
- **Focus + Context** · 焦点+上下文 · fisheye、双曲浏览、DOI 剪裁等。
  *正交/工程图风格应选 **DOI 剪裁**（只增删元素，不扭曲几何），而非 fisheye。*

## 10. 分组、泳道与端口

- **Group / Cluster / Compound node** · 组 / 聚类 / 复合节点 · 包含其它节点的容器。
  *三个词在不同库里指同一件事。yFiles 叫 group，cytoscape 叫 compound，OGDF 叫 cluster。*（→ 08）
- **Containment tree / Nesting** · 包含树 / 嵌套 · 组的层次结构。
- **Group boundary dummy** · 组边界虚节点 · 跨组边穿越组框处的占位点。
  *让"边从哪里穿出组框"成为一个有写者的自由度，而不是渲染时临时决定。*
- **Continuous block constraint** · 连续块约束 · 同组节点在层内必须相邻。
  *与"泳道内节点必须在同一列区间"是同一机制 —— 应共用实现，否则两套逻辑会冲突。*（→ 08）
- **Swimlane / Pool** · 泳道 / 池 · BPMN 中按角色划分的横/纵带。
- **PartitionGrid** · 分区网格 · 行 = 层区间、列 = 层内分段的二维约束网格。
  *泳道 + 阶段的统一实现方式（yFiles 的 `PartitionGridData`）。*（→ 08）
- **Recursive vs Global group layout** · 递归 vs 全局分组布局 ·
  前者组内单独布局再当黑盒（丢失跨组边信息），后者把组约束加进全局求解（质量好、实现难）。
  *推荐混合：全局定序 + 组框作为 VPSC 变量。*
- **Port** · 端口 · 边接到节点的具体位置。
- **Port constraint 五档** · `FREE`（自由）→ `FIXED_SIDE`（定边）→ `FIXED_ORDER`（定顺序）→ `FIXED_RATIO`（定比例）→ `FIXED_POS`（定坐标）。
  *这是一个**递增的约束强度**模型，能覆盖从流程图到 ER 字段级到 EDA 引脚的全部需求。*（→ 08）
- **Port candidate** · 端口候选 · 允许的端口位置集合（比 constraint 更灵活的表达）。
- **Port assignment** · 端口分配 · 决定每条边用哪个端口。
  *默认策略：**按对侧锚点坐标排序后均匀分布** —— 几十行代码消除大量"凭空交叉"。
  路由阶段临时发明端口是不可修复的反模式。*（→ 08, 13）
- **Edge grouping (source/target group)** · 边分组 · 声明一组边在源端/目标端合并成一股。
  *UML 泛化集、组织架构图的标准画法。*
- **Anchor** · 锚点 · 边端点或标签的附着位置（可以是端口、比例点、或形状边界交点）。

## 11. 质量度量与基准

- **Crossing number** · 交叉数 · 第一质量指标。
  *统计时要排除共享端点的边；建议**分类报告**（real-real / real-dummy / 跨组）以定位问题相。*（→ 11）
- **Crossing angle** · 交叉角度 · Huang 2008：接近 90° 的交叉几乎无害，小角度交叉很伤。
  ***便宜且被低估的优化点** —— 无法消除的交叉尽量正交化即可。*
- **Bend count** · 弯折数 · 统计前必须先做共线合并，否则数字虚高。
- **Angular resolution** · 角分辨率 · 节点处相邻边的最小夹角（理想 $360°/\deg$）。
- **Aspect ratio** · 长宽比 · 与"能否放进屏幕"强相关。
- **Ink** · 墨水量 · 边总长 / 包围盒对角线，归一化的"线有多密"。
- **Edge length uniformity** · 边长均匀性 · 用变异系数 CV 度量。
- **Symmetry metric** · 对称性得分 · 精确算法难，用候选轴投票近似（Purchase 2002）。*成本高，只离线跑。*
- **MinLA (Minimum Linear Arrangement)** · 最小线性排列 · 一维排列使 $\sum|\pi(u)-\pi(v)|$ 最小。NP 难。
  *生命线排序 / 泳道排序 / 组内排序都是它。*（→ 19）
- **Bandwidth / Cutwidth / Vertex separation** · 带宽 / 割宽 / 顶点分离 ·
  最长跨度 / 任一切面上的边数 / 顶点版割宽。
  ***cutwidth 直接决定"某时刻有多少箭头并行"**，是序列图可读性的关键次级目标。*
- **Determinism** · 确定性 · 同输入必须同输出。
  *本项目红线：不得依赖 `HashMap` key 序；需稳定序用显式排序或 `IndexMap`/`BTreeMap`。
  已知踩坑："HashMap 序平局取胜"导致渲染非确定。*（→ 11, 16）
- **Hard assertion vs Soft metric** · 硬断言 vs 软指标 · 前者应恒为 0（重叠、边穿节点、标签重叠），非零即 bug；
  后者只看趋势（交叉、弯折、面积）。*基准报告必须区分二者，硬断言失败即 FAIL。*
- **Rome graphs / AT&T (North) DAGs / SuiteSparse** · 经典公开基准集（正交对照 / 分层对照 / 大图性能）。（→ 11）
- **Holdout set** · 留出集 · 只在里程碑时看的 case，防止调参过拟合基准集。
- **Per-diagram-type report** · 分图种报告 · 按图种分组再汇总。
  ***防止"改好 A 图种、毁掉 B 图种"的唯一防线。***
- **Snapshot test (insta)** · 快照测试 · 断言坐标/路径的 JSON 与基线一致。
  *本项目约定：布局坐标优先 `insta::assert_json_snapshot!`。*
- **Bentley–Ottmann** · 扫描线求线段交点，$O((n+k)\log n)$。*度量与重叠断言的底层。*

## 12. VLSI / EDA（图路由的祖师爷）

- **VLSI (Very Large Scale Integration)** · 超大规模集成电路 · 单芯片上集成大量晶体管的技术。
  *之所以出现在图布局的词汇表里：**芯片布线与图布线是同一个数学问题**，而 EDA 界在这上面投入了几十年与数亿美元，
  很多"新"问题在那里早已解决（通道布线、拥塞消解、层次分割）。*（→ 18）
- **EDA (Electronic Design Automation)** · 电子设计自动化 · VLSI 设计的软件工具链总称。
- **Netlist / Net** · 网表 / 网络 · 电路的连接描述；一个 net = 一根信号连接的所有引脚（**天然是超边**）。
- **Pin** · 引脚 · 器件上的连接点（= 图里的固定端口 `FIXED_POS`）。
- **Placement** · 布置 · 决定器件位置（= 图里的 layout）。
- **Routing (global / detailed)** · 布线 · 决定连线路径（= 图里的 edge routing）。
- **Gcell (global routing cell)** · 全局布线格 · 全局布线用的粗网格单元。
- **Channel routing** · 通道布线 · 两排引脚之间的矩形通道内布线；left-edge algorithm 给出最少 track 数。
  ***分层图的层间路由与它完全同构。***（→ 18）
- **Switchbox routing** · 开关盒布线 · 四边都有引脚的区域布线；比通道难（track 数不能自由增加）。
  *对应泳道交叉处、组框之间的空隙。工程上用通道布线近似即可。*
- **Congestion map** · 拥塞图 · 各区域的"需求/容量"分布。*可视化它对调试路由极有帮助。*
- **Partitioning (KL / FM / METIS)** · 分割 · 把电路分成若干块使跨块连接最少。
  *图侧用途：自动分组推断、大图分块布局、多级粗化。FM 的 gain bucket 结构值得学（$O(1)$ 取最大增益）。*
- **Floorplanning** · 布图规划 · 决定各功能块的相对位置与形状。*对应"组框的位置与尺寸"问题。*
- **H-tree / Clock tree** · H 树 / 时钟树 · 多级分叉的对称分布网络。
  *对应"扇出极大时的多级总线主干"形态。*（→ 18）
- **Hierarchical / Flat design** · 层次式 / 平坦化设计 · 对应"递归分组布局"与"全局展开布局"。

## 13. 序列图与一维排列

- **Lifeline** · 生命线 · 序列图中代表一个参与者的竖线。（→ 19）
- **Major / Minor axis** · 主轴 / 次轴 · 前者由语义固定（时间/顺序），后者是需优化的一维排列。
  ***序列图、甘特图、泳道时序、火焰图是同一个布局器 + 不同参数** —— 这个抽象是 ADR-001 的具体体现。*
- **Activation bar / Execution specification** · 激活条 · 生命线上表示"正在执行"的竖条。
  *嵌套调用要右移，生命线宽度必须容纳最大嵌套深度。*
- **Combined fragment (alt / opt / loop / par / critical)** · 组合片段 · 包住一段消息的框（条件/循环/并行）。
  *范围 = 全部**后代**的行/列范围外扩 padding；只看直接子元素会错位。*
- **Self message** · 自消息 · 生命线给自己发消息（右侧回环，占 2 行）。
- **Reply / Return message** · 返回消息 · 虚线 + 开放箭头。
- **MSC (Message Sequence Chart)** · 消息序列图 · ITU-T Z.120 规范，比 UML 序列图语义更严谨。
- **Event partial order / Linear extension** · 事件偏序 / 线性扩展 · 并发生命线上的消息只有偏序，需拓扑排序得到行号。
  ***主轴行号分配就是分层问题** —— 复用分层零件，不要写第二套。*
- **Tick selection** · 刻度选择 · 时间轴上"好看的间隔"（1/2/5 × 秒/分/时/天…）。
  *选择依据是"标签宽度 vs 可用像素"，不是固定数量。*
- **Interval row assignment** · 区间行分配 · 甘特图中重叠任务分行 = 区间图着色（最优）。
- **Flame graph** · 火焰图 · 纯区间嵌套可视化（无边）。
  *用它验证"区间嵌套器"是否真的与序列图解耦。*

## 14. 几何与落笔（渲染层）

- **Ink phase / 落笔相** · 把布局结果展开成可绘制几何的阶段。
  ***零新决策**：只展开上游已定的自由度，不发明端口、不挪节点。*（→ 15）
- **Clipping** · 裁剪 · 求路径与节点形状边界的交点。
  *必须用**路径第一段的方向**，而不是"中心到中心"；已有显式端口时**不做裁剪**。*
- **Normalization (path)** · 路径规范化 · 去重点 → 合共线 → 去尖刺 → 轴吸附 → **再合共线** → 最小段长。
  *第二次共线合并常被漏，结果是"看起来直但有 3 个点"，圆角会画出微凸起。*
- **Collinear merge** · 共线合并 · 去掉三点共线中的中间点。
- **Snap to axis / grid** · 轴吸附 / 网格吸附 · 近似正交的段吸成严格正交；坐标吸到网格。
  *把"浮点近似判断"一次性变成"精确比较"，避免 A≈B、B≈C 但 A≉C 的不一致。*
- **Corner radius / Fillet** · 圆角 · 相邻段长不足时**降半径**（局部、无副作用），不要改路径形状。
- **Bézier / Catmull–Rom / Centripetal parameterization** · 贝塞尔 / 样条 / 向心参数化 ·
  *Catmull–Rom 会在急转处过冲、可能穿节点；用向心参数化（$\alpha=0.5$）显著缓解。*
- **Arrow inset** · 箭头缩进 · 实心箭头时路径应在箭头底部结束，否则线会从尖端透出。
- **Marker (SVG)** · SVG 标记 · `<marker>` + `orient="auto"` 画箭头；不继承 stroke 透明度，跨渲染器行为有差异。
- **Crow's foot** · 鸦爪 · ER 图表示基数（0..1 / 1 / 0..N / 1..N）的箭头族。
- **z-order** · 层叠顺序 · 建议 组框 < 边 < 节点 < 标签。
  ***把边放在节点下面**是廉价的"端点看起来完美"技巧。*
- **Quantization** · 量化 · 最终坐标取 2 位小数或 0.5px 网格。
  *SVG 体积减小 30%+，且让快照测试稳定。必须在所有几何计算**之后**只做一次。*
- **Hit testing / Picking** · 命中测试 / 拾取 · 判断鼠标点中了什么。
  *z 序**倒序**遍历；tolerance 要除以 scale；必须 $O(\log n)$（是 mousemove 热路径）。*
- **SDF (Signed Distance Field)** · 有向距离场 · WebGL 下渲染清晰文字的技术。
- **Effective bounding box** · 有效包围盒 · 节点 + 其标签 + 其自环的总占位。
  *布局必须用有效包围盒而非裸节点盒，否则标签/自环会压邻居。*

## 15. 引擎架构与工程

- **Layout pipeline / Phase** · 布局流水线 / 相 · 按顺序执行的算法阶段。
- **Stage (decorator)** · 阶段装饰器 · 包在核心算法外的"前处理 + 调用 core + 后还原"结构。
  *典型：RemoveSelfLoops、HandleParallelEdges、ComponentLayout、TreeReduction、**OrientationStage**、Labeling、
  FixNode、NormalizeCoordinates。**装饰器形式保证"还原"不会被忘记**（平铺管线容易漏）。*（→ 09）
- **Orientation stage** · 方向阶段 · 核心只实现 TB，其它三个方向靠输入/输出的坐标变换获得。
  *一百多行换四个方向；否则四套代码不可维护，且特性只在一个方向可用。*（→ 09, 13）
- **LayoutData / DataProvider** · 布局数据 · 逐元素传给算法的附加数据（约束、优先级、端口）。
  ***强类型映射优于字符串 KEY 的 DataProvider**（后者拼错 key 只会静默失效）。*
- **Degree of freedom (DoF) / Write authority** · 自由度 / 写权 ·
  ***每个几何自由度有且只有一个写者**；下游不得推翻上游，只得展开上游。
  判断句：修法若是"再加一个特判"，先问"这个自由度的写者应该是谁"。*（→ 09, 本项目 `design/layout/write-authority.md`）
- **Writer (typed)** · 类型化写者 · 用 `LayerWriter` / `OrderWriter` / `CoordWriter` / `RouteWriter` 在**类型层面**约束谁能写什么。
  *让写权纪律从"文档约定"变成"编译器强制"。*
- **DemandBoard / Parameter write-back** · 需求板 / 参数回写 ·
  下游把需求（走廊宽度、端口数、标签尺寸）登记，上游在**执行前**汇总为参数。
  *这是唯一被允许的"反向影响"形式；合并只允许 `max`（保证顺序无关 → 确定性）。*（→ 20）
- **Profile** · 图种预设 · 一组推荐参数的命名组合（flowchart / sequence / er / …）。
  ***引擎不接收 profile**，只在解析层展开为具体参数（本项目 ADR-001）。*（→ 20）
- **Parameter domain / Orthogonality** · 参数域 / 正交性 · 参数应是"机制维度"而非"图种名的别名"，且互不隐含。
  *检验：这个参数的每个取值是否至少有两个图种可能用到？*
- **IR (Intermediate Representation)** · 中间表示 · DSL 解析后、布局之前的图模型。
- **Contract (LayoutContract)** · 契约 · 引擎的输入边界结构（图 + 参数），不含图种信息。
- **Gate / Budget / Graceful degradation** · 门控 / 预算 / 优雅降级 ·
  规模超阈值时逐级放弃质量（L0 全质量 → … → L7 节点聚合），并**在诊断中如实报告**。
  *承诺不是"任意规模都最优"，而是"任意规模都在有限时间给出可用结果且说明降级"。*（→ 16）
- **Diagnostics output** · 诊断输出 · 分相耗时、指标、门控命中、约束报告、`params_hash`。
  *`params_hash` 让"结果变了"能归因到"参数变了"还是"代码变了" —— 极其实用。*（→ 09, 20）
- **SoA (Struct of Arrays)** · 数组结构体 · 把 `Vec<Node>` 拆成 `Vec<x>, Vec<y>` 提高 cache 命中。*只对最热循环做。*
- **Arena / Buffer reuse / Timestamp trick** · 竞技场分配 / 缓冲复用 / 时间戳标记 ·
  A\* 复用 `dist` 数组，用时间戳代替每次清零。（→ 16）
- **WASM (WebAssembly)** · 浏览器字节码 · 本项目主要交付环境。
  *约束：默认单线程（多线程需 SharedArrayBuffer + COOP/COEP 头）、`Instant` 不可用（必须走项目 perf 抽象）、
  体积敏感（`opt-level="z"` + `wasm-opt -Oz` + 避免正则/通用求解器等重依赖）、线性内存不可收缩（峰值决定一切）。*（→ 16）
- **ADR (Architecture Decision Record)** · 架构决策记录 · 一次决策 + 备选方案 + 放弃理由的短文档。
  *本项目关键条目：ADR-001 图种不进引擎、ADR-002 无自由形式选项、ADR-005 content-measure 参数。*
- **Table-driven test** · 表驱动测试 · 多 case 合并为一个 `#[test]` + 循环（本项目约定）。
- **Oracle (test)** · 测试神谕 · 用小规模精确算法（如 $n\le16$ 的 DP）验证启发式的质量差距。
  *一维排列器、VPSC 都可以这样测 —— 比手写期望值可靠得多。*

## 16. 容易混淆的词对（读论文时的坑）

| 易混对 | 区别 |
|---|---|
| **Layer vs Level vs Rank** | 同一个意思，不同流派用词（Sugiyama 派 / 理论派 / Graphviz） |
| **Position vs Coordinate** | 分层布局中 position = 层内第几个（整数序），coordinate = 实际像素坐标。**混用会写出错误代码** |
| **Order vs Ordering** | 前者常指结果（序列），后者指过程（定序） |
| **Bend vs Waypoint vs Control point** | 弯折（几何拐点） / 强制途经点（约束输入） / 贝塞尔控制点（可不在曲线上） |
| **Port vs Anchor vs Endpoint** | 端口（节点上的命名/受约束位置） / 锚点（附着规则） / 端点（最终坐标） |
| **Group vs Cluster vs Partition** | 前两者=容器（有边框、可嵌套）；partition 常指"划分算法的结果"（无视觉边框） |
| **Stress vs Energy vs Cost** | stress = 特定的距离拟合目标；energy = 力模型的势能；cost = 泛指目标函数 |
| **Force-directed vs Organic** | 同一类算法，后者是产品命名（yFiles/Gephi 用 organic） |
| **Crossing vs Overlap** | 交叉 = 线与线相交（软指标，可容忍）；重叠 = 面与面相交（**硬断言，必须为 0**） |
| **Channel vs Track** | 通道是空间（可容纳多条）；track 是通道内的一条车道 |
| **Nudging vs Compaction** | 都用 VPSC，但 nudging 目标是"分开且整齐"，compaction 目标是"压紧" |
| **Compaction vs Packing** | 前者压缩单个图的坐标；后者排布多个分量/子图 |
| **Incremental vs Dynamic** | incremental = 在已有布局上改（交互）；dynamic = 一个图序列（时间演化） |
| **Constraint vs Penalty** | 硬约束（必须满足，用 VPSC/投影）vs 软惩罚（进目标函数）。**混淆会导致"约束有时不生效"** |
| **Determinism vs Stability** | 确定性 = 同输入同输出；稳定性 = 相似输入相似输出。**两个完全不同的性质，都要测** |
| **Dummy node vs Crossing dummy vs Label dummy** | 长边占位 / 平面化的交叉假点 / 标签占位。三者生命周期与还原方式都不同 |

## 19. 怎么用这份表

1. **读论文卡住** → 搜英文词，看"一句话本质"够不够解锁，不够再跳对应篇号。
2. **写代码命名** → 用本表的英文原词（`layering` / `ordering` / `nudging` / `track`），
   不要自造中式命名（如 `sortNodes2`），这样日后能与论文/开源代码对上。
3. **评审设计** → 先问"这个改动写的是哪个自由度？写者是谁？"（§15 的 DoF / Writer 词条）。
4. **判断一个词是不是真问题** → 若某症状能在 §16「易混淆词对」里找到，通常是概念混淆而非算法缺陷
   （最常见：position vs coordinate、constraint vs penalty、crossing vs overlap）。
