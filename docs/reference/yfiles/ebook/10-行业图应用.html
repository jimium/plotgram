10 · 行业图应用（Domain-Specific Diagrams）

本篇回答"为什么 yFiles 值那么多钱"：不是算法更炫，而是把各行业的图形约定翻译成了布局约束。对 tautcore 的意义：每个行业的约定 = 一组 profile 参数 + 一小组必需的约束能力；本篇为每个行业列出必需能力清单。

应用 原始出处：tautcore 行业图能力清单（参考 yFiles / Graphviz / ELK / SBGN 等产品文档） ~230 行 · 6.5k 字

1软件工程

1.1 UML 类图 / 包图

  • 约定：继承向上（泛化箭头朝父类）、关联带多重度标签、包嵌套。
  • 布局诉求：分层（继承方向）+ 正交边 + 继承边汇聚成树干（多个子类的继承箭头合并到父类一个端口，形成"Λ"形）。
  • 必需能力：edge grouping（3.5/08）、分组（包）、端口约束、边标签（多重度在两端）。
  • 经典处理：把继承关系与关联关系分开处理——继承树用树/分层布局定骨架，关联边事后正交路由。这是 yFiles UML demo 的做法。

1.2 UML 序列图

  • 约定：参与者在顶部一行、生命线竖直向下、消息水平箭头、激活条、组合片段（alt/loop）嵌套框。
  • 布局诉求：完全不是通用图布局！是"一维序列 + 一维时间"的调度问题：
    • x：参与者顺序（可优化以减少消息跨度 = 一维排列问题，等价于最小线性排列 MinLA，NP 难，用 barycenter/谱序启发式）；
    • y：事件时间序（拓扑序 + 每个消息的高度需求 + 片段框的 padding）。
  • 必需能力：定序 + 一维坐标累加 + 嵌套框（组）。不需要通用路由。

1.3 状态机 / Statechart

  • 约定：初始态实心圆、复合状态嵌套、自转移、迁移标签（event[guard]/action）。
  • 布局诉求：分层（若有明显流向）或正交紧凑（状态机常有环）；自环必须优雅；嵌套复合状态 = 组。
  • 必需能力：自环路由、组、边标签（标签常很长 → 空间预留是刚需）。

1.4 数据流 / 编译器 IR / 计算图（TensorFlow 类）

  • 约定：节点有明确的输入/输出端口（有序！）、常量折叠、子图（scope）折叠。
  • 布局诉求：端口序是硬约束（矩阵乘的两个输入不能换）→ FIXED_ORDER 端口；分层 + 正交。
  • 必需能力：端口五档模型（08 篇）、组折叠/展开、边捆绑（大量 tensor 边）。
  • 参考：TensorBoard 的图可视化用的正是 dot 系分层 + 结构抽取（把重复的子结构折叠成一个）。

1.5 依赖图 / Monorepo 架构图

  • 规模大（数千节点）、环多（循环依赖是要发现的缺陷）。
  • 诉求：分层以暴露层级违规、环高亮、聚合到模块级（层次折叠）。
  • 必需能力：FAS（环检测的副产品要报告给用户，不只是内部反转）、多级折叠、规模门控。

2业务流程（BPM）

2.1 BPMN 2.0

  • 约定：泳道/池（Pool/Lane）、网关（菱形，含分支标签 yes/no）、事件（圆）、任务（圆角矩形）、边界事件、子流程。
  • 布局诉求（最苛刻的图种之一）：
    • 主流程水平笔直贯穿（happy path 一条直线）；
    • 网关分支上下分开、回边（loop）走在下方/上方绕行；
    • 严格遵守泳道分区（08 篇 §2）；
    • 边界事件的边从任务边框上的特定位置出发（固定端口）。
  • 必需能力：泳道（partition grid）、critical path 拉直（07 §3.2）、固定端口、正交路由 + 回边特殊处理、分支标签放置。
✓典型评价标准

主流程是否一条直线；这一项做好，整张图立刻"专业"。BPMN 是把"业务约定"翻译成 partition_grid + critical_path 拉直 + 固定端口 + 回边侧通道 的组合。

2.2 审批流 / 工作流引擎（国内产品的高频需求）

  • 简化版 BPMN：开始/结束、审批节点、条件分支、并行分支、回退。
  • 诉求：紧凑竖排、分支对称（左右对称的并行分支是强视觉期待）、回退边走侧边。
  • 必需能力：对称性（Brandes–Köpf 的 4-run 平均恰好给对称，01 篇 §4.4）、分支合并点对齐、侧边通道。

2.3 价值流图 / 泳道流程

  • 诉求：阶段（列）× 角色（行）的矩阵定位。
  • 必需能力：双向 partition grid。

3网络与 IT 运维

3.1 网络拓扑

  • 约定：设备图标、层级（core/aggregation/access 三层）、链路带宽用线宽、冗余链路成对。
  • 布局诉求：分层（按网络层级）或圆形/星形（环网、星型接入）；平行链路清晰分开；子网分组。
  • 必需能力：circular（05 篇 §4）、平行边散开、分组、bus routing（机架内多条上行链路）。

3.2 云架构图（AWS/Azure 风格）

  • 约定：VPC/子网/可用区的嵌套框、图标化节点、区域标签。
  • 布局诉求：嵌套组（3+ 层）+ 组内正交、跨区域连线走边框开口。
  • 必需能力：多层嵌套组、组框标题、组内 padding、跨组边的边界穿越点。

3.3 服务依赖 / 微服务调用链

  • 规模大、动态更新（实时）。
  • 诉求：稳定性（数据刷新不能整图跳，07 篇 §5）、异常路径高亮、按调用量粗细。
  • 必需能力：增量布局 + mental map 保持。

3.4 攻击图 / 事件关联（安全领域）

  • 诉求：从"入口"到"资产"的路径清晰（分层 + critical path）、时间轴维度。
  • 必需能力：分层 + 泳道（时间）+ 路径高亮。

4数据与知识

4.1 ER 图 / 数据库 schema

  • 约定：实体表格（字段列表）、关系带基数（1:N crow's foot）、外键连到具体字段行。
  • 布局诉求：边连到表内某一行（字段级端口！）→ 端口数多且固定序；节点很高（字段多）；正交边。
  • 必需能力：FIXED_POS 端口（字段行的 y 偏移）、大高宽比节点的分层布局、正交路由 + nudging。
  • 这是正交布局（02 篇）的经典应用，也是端口能力的试金石。

4.2 数据血缘（Data Lineage）

  • 诉求：严格左右流向、列级血缘（端口级）、可折叠（表级/列级切换）、大规模。
  • 必需能力：LR 方向（Orientation Stage）、端口级连接、折叠、bus routing（一张表数百列时必须捆绑）。

4.3 知识图谱 / 实体关系网络

  • 诉求：organic 布局 + 聚类可见、hub 节点突出、大规模（万级）。
  • 必需能力：多级 stress / ForceAtlas2、社区检测着色、消重叠、边捆绑。

4.4 ETL / 数据管道

  • 类似数据流图，见 1.4。

5生命科学

5.1 生物通路（SBGN — Systems Biology Graphical Notation）

  • 约定极其严格（SBGN 有正式规范）：三种子语言（Process Description / Entity Relationship / Activity Flow）、 节点形状有语义（macromolecule 圆角矩形、simple chemical 椭圆…）、过程节点是小方块，反应物/产物必须连到它两侧的特定端口、 复合物是嵌套、区室（compartment）是大框。
  • 布局诉求：区室边界不可穿越（除转运）、过程节点左右对称（底物在左、产物在右）、辅因子在上下、通路主链应可辨识（横向长链）。
  • 必需能力：固定端口（过程节点的 4 个端口有语义）、嵌套区室（组）、对称性、长链拉直。
  • 参考：SBGN-ED、Cytoscape 的相关布局；yFiles 有 SBGN demo。这是"图种约定驱动布局"最极端的例子，非常值得读其规范来理解产品化深度。

5.2 代谢网络 / 蛋白互作（PPI）

  • 规模大、无明显流向 → organic + 聚类。
  • 必需能力：多级力导向、消重叠、按属性着色/尺寸。

5.3 系统发生树（Phylogenetic Tree）

  • 约定：分支长度编码进化距离（边长有语义，不能为美观改！）、支持率标注、圆形/矩形/无根三种画法。
  • 必需能力：dendrogram（叶对齐）+ 固定边长布局 + radial/unrooted 变体。
⚠边长是硬约束，不是美学参数

这里"边长有语义"违背了通用布局的假设（通用布局把边长当成可优化的自由度），必须支持"边长作为硬约束"。否则画出的树在进化距离上误导读者，是科学性错误而非美观问题。

5.4 临床路径 / 诊疗流程

  • 就是流程图，但对"分支完整性"要求高（每个判断都要有全部分支）。

6电子设计（EDA）

6.1 原理图（Schematic）

  • 约定：引脚固定（元件符号的引脚位置是符号定义的一部分）、网络（net）而非边（一个 net 连多个引脚）、 总线用粗线、电源/地用符号而非连线、正交走线、导线交叉用跨越标记、T 型连接用实心点。
  • 布局诉求：这是 hypergraph 布局（net = 超边）+ 正交总线路由 + 元件方向（旋转/镜像也是自由度）。
  • 必需能力：固定端口、超边（Steiner tree 路由）、元件旋转、跨越标记。
ℹVLSI 文献与本文库的对接
  • 参考文献方向：VLSI placement & routing（Kernighan–Lin 划分、模拟退火放置、channel routing、Lee 迷宫算法 / A*）。
  • VLSI 的 channel routing 与 03 篇的 track 分配是同一个问题，其文献（Yoshimura–Kuh 1982 的 left-edge algorithm）就是区间图着色。

6.2 PCB / 布线

  • 与图绘制交集在"正交/45° 路由 + 通道容量"，但优化目标是电气性能，超出本文库范围。

6.3 FPGA / 数据通路框图

  • 约定：模块框 + 有序端口 + 总线宽度标注。
  • 必需能力：端口序固定、bus routing、端口标签。

7制造与工程

7.1 P&ID（管道仪表流程图）/ 工艺流程

  • 约定：设备符号、管线（带流向、规格标注）、仪表回路、正交走线、跨越优先规则。
  • 必需能力：固定端口（设备接口）、正交路由、管线标签沿线放置、跨越标记。

7.2 故障树 / FMEA

  • 树布局 + 逻辑门符号；要求"同层对齐、子树紧凑"。
  • 必需能力：树布局（05 篇）、多父节点（DAG 化的故障树）→ 退化为分层。

7.3 供应链 / 物流网络

  • 地理位置约束（节点位置由经纬度固定！）→ 完全固定节点 + 只路由边。
  • 必需能力：固定节点 + 边路由（03 篇）+ 边捆绑（减少视觉噪声）。这是"路由独立于布局"价值的最好证明。
✓路由独立于布局

供应链地图把节点位置完全交给地理坐标，布局器无事可做，只剩边路由 + 边捆绑。这是验证架构分层是否干净的最好场景：如果路由模块还偷偷依赖布局器，这里会立刻暴露。

8金融与商业

8.1 组织架构图

  • 树布局 + 助理岗（侧挂）+ 虚线汇报（非树边）+ 照片/多行信息节点。
  • 必需能力：树布局多种 NodePlacer（05 篇 §1.5）、非树边路由、节点内容自适应尺寸。

8.2 股权结构 / 关联方图谱

  • DAG（可能有环 = 交叉持股）、比例标注在边上、层级 = 控股层级。
  • 必需能力：分层 + 边标签 + 环检测报告。

8.3 反欺诈 / 资金流向

  • organic + 时间序（动态）+ 交易额编码；社区发现（团伙）。
  • 必需能力：organic 大图 + 增量 + 聚类。

8.4 决策树 / 归因分析

  • 树 + 节点内含图表（sparkline/饼图）→ 节点内容复杂，尺寸由内容定。

10对 tautcore profile 设计的启示

每个图种的 profile 应显式声明它需要的能力与参数，例如：

hcl 
profile "bpmn" {
  orientation      = LR
  partition_grid   = lanes          # 泳道
  critical_path    = auto_main_flow # 主流程拉直
  ports            = FIXED_SIDE     # 网关分支上下出
  routing          = orthogonal { back_edge_side = below }
  edge_labels      = reserve_space
  group            = subprocess_box
}
profile "er" {
  orientation      = LR
  ports            = FIXED_POS      # 字段行
  routing          = orthogonal { nudge = uniform }
  node_size        = content_driven { rows = fields }
}

这样"图种差异"完全落在参数上，引擎无需知道 bpmn 这个词——正是 ADR-001 的要求。同时这张表也是产品路线图：能力矩阵 P0/P1 做完，就能宣称支持上述大部分行业图。
