19 · 序列图与一维排列类布局（Sequence Diagram & 1D Arrangement）

对应 UML 2.5 Interactions / MSC ITU Z.120 / 甘特图 / 火焰图 / 事件溯源 的共同算法骨架：一维排列 + 主轴离散化 + 区间嵌套

应用 原始出处：Diaz–Petit–Serna 2002（MinLA 综述）、Juvan–Mohar 1992（谱方法）、Safro–Ron–Brandt 2006（多级 MinLA）、UML 2.5 §17、ITU Z.120、Gregg 2016（火焰图） ~240 行 · 8.5k 字

1共同抽象

text 
主轴（major axis）：由语义固定的离散序列（时间步 / 消息序号 / 任务顺序）
次轴（minor axis）：需要优化的一维排列（生命线顺序 / 泳道顺序 / 资源顺序）
元素：
  - 轴线（lifeline / lane / resource row）：占次轴一个位置，沿主轴延伸
  - 事件（message / activation / task）：连接一或两条轴线，占主轴一个区间
  - 区间容器（combined fragment / 阶段 / 里程碑）：占主轴一个区间 × 次轴一个连续区间

一旦这样抽象，序列图 / 甘特 / 泳道时序 / 火焰图就是同一个布局器 + 不同参数（对应 ADR-001：不按图种分支）。

图种主轴次轴事件
UML 序列图时间（向下）生命线顺序（左右）消息（箭头）
MSC同上同上消息 + 定时器
甘特图时间（向右）任务/资源行条形 + 依赖箭头
泳道流程时序阶段（向右）泳道活动 + 流转
火焰图栈深度（向上）时间/样本（向右）帧矩形（纯嵌套，无边）
事件溯源版本序聚合根事件
网络时序图（Wireshark 风格）时间主机数据包

工程结论：本项目已有 docs/design/layout/sequence/，其内核应设计成"一维排列 + 主轴离散化 + 区间嵌套"三件套，使甘特/时间轴图种后续零算法成本接入。

2次轴：一维排列问题（这是唯一的"难"部分）

2.1 问题定义（MinLA）

给定图 ，求排列 最小化

  • NP 难（Garey–Johnson–Stockmeyer 1976）；
  • 序列图语义： = 两条生命线之间的消息数 → 最小化"消息跨越的生命线距离"= 最小化长箭头与交叉。

相关变体（各有用途）：

问题目标布局含义
MinLA总箭头长度最短（主目标）
Bandwidth最长箭头最短（避免横跨全图的箭头）
Cutwidth任一竖直切面上的箭头数最少（决定通道宽度）
Vertex Separation同上的顶点版活动条并发数
Profile / SumCut综合
ℹ主目标 + 次级 tie-break 的选择

建议：主目标用 MinLA，用 cutwidth 作为次级 tie-break（同等 MinLA 下选 cutwidth 小的），因为 cutwidth 直接决定"某个时间点有多少箭头并行"，影响可读性最大。

2.2 求解阶梯（按实现成本）

L1 · 语义序（必做，零成本）
用户书写顺序 / 首次出现顺序 / 显式声明顺序。多数序列图这就是最优答案 —— 用户按叙事顺序写，天然合理。
纪律：显式声明必须绝对优先，永不被优化覆盖。 这是产品要求，不是算法问题。

L2 · 首次出现 + 贪心插入（推荐默认）

pseudo 
order = []
for msg in messages（按时间序）:
    for lifeline in [msg.from, msg.to] 中未放置者:
        pos = argmin_{插入位置 p} Δcost(order 插入 lifeline 于 p)
        order.insert(pos, lifeline)

， 通常 < 30 → 完全够用，且结果符合"按叙事展开"的直觉。

L3 · 局部搜索（相邻交换 / 插入移动）

pseudo 
loop:
    for each 相邻对 (i, i+1):
        if swap 降低 cost: swap
    for each 节点:
        尝试移动到所有其它位置，取最优
    until 无改进

cost 可 增量计算（只涉及该节点的边）。这是性价比最高的质量提升。

L4 · 谱方法初值（Juvan–Mohar 1992）
用 Fiedler 向量排序作为 MinLA 的初值（14 篇 §5.1），再跑 L3。理论依据：MinLA 的 松弛的最优解就是 Fiedler 向量。 大（>100 生命线）时明显优于贪心。

L5 · 多级（Safro–Ron–Brandt 2006）+ 模拟退火
只在 > 数百时需要。序列图基本用不到 —— 但甘特图的资源行可能有上千行，那时有用。

L6 · 精确（DP over subsets，）
时可给出最优解。可作为单测的 oracle：小实例上验证启发式的差距。这个用法很值钱。

2.3 约束下的排列

现实中次轴常有硬约束：

  • 生命线属于某个组/泳道 → 组内必须连续（08 篇的连续块约束）；
  • 显式 before 声明 → 偏序约束；
  • actor 必须在最左、数据库必须在最右 → 端点固定。
⚠层级分解，不要上通用求解器

处理：在组内做 MinLA + 在组之间做 MinLA（层级式），端点固定的元素先钉住再排其余。不要试图用一个通用带约束优化器 —— 层级分解足够且可预测。

3主轴：时间轴离散化与坐标

3.1 事件排序与并发

序列图的消息不总是全序：

  • 同步调用：send 与 recv 同一时刻（水平箭头）；
  • 异步：send < recv（可倾斜箭头，或仍水平但 recv 落在更下的行）；
  • 并发生命线上的独立消息：偏序 → 需要线性扩展（拓扑排序）。

做法：

pseudo 
1. 建事件偏序图：
     同一生命线上的事件按其顺序连边（本地全序）
     每条消息 send → recv 连边
     创建/销毁、片段边界加边
2. 检测环 → 语义错误，报诊断（不要静默修正）
3. 拓扑排序 → 得到"行号"（可用最长路分层，与 Sugiyama 的 P2 同构！）
ℹ关键认知：主轴行号 = 分层问题

主轴的行号分配就是分层问题（最长路 = ASAP，或 network simplex 最小化总跨度）。可以复用 14 篇的分层零件，而不是写第二套。

3.2 行高与 y 坐标

行号 → y 坐标要考虑：

  • 该行事件的标签高度（消息文本可能多行）；
  • 自消息（self message）需要额外高度（回环占 2 行或加高）；
  • 片段边界（alt / loop 的框线与标题）需要 padding；
  • 激活条（activation bar）的起止；
  • 最小行距（主题参数）。

写法：row_height[i] = max(各元素在该行的高度需求)，再前缀和。这是一维 VPSC 的退化情形（只有相邻约束），前缀和即最优，不需要求解器。

3.3 水平坐标与箭头

  • 生命线 x = 次轴排列 → 累积宽度（宽度 = max(生命线头部框宽, 其激活条宽)）；
  • 消息箭头就是水平段，起止 x = 两生命线 x（含激活条偏移）；
  • 激活条嵌套：同一生命线上嵌套调用 → 激活条向右偏移 depth * offset，生命线宽度需容纳最大嵌套深度；
  • 长标签超过箭头长度 → 三种策略：加宽生命线间距（推荐，回写次轴间距参数）、标签换行、标签外移。
⚠写权纪律：下游需求回写上游参数

长标签加宽间距是"下游需求回写上游参数"，必须在 x 坐标确定之前完成（写权纪律）。不能在路由阶段"为了不溢出"再挪生命线 —— 那是 P5 推翻 P4，违反每相只写一个自由度的硬约束。

3.4 自消息与找回消息

  • 自消息：右侧回环，宽度为参数，高度 = 标签高 + padding，占 2 个行号；
  • 找回消息（reply）：虚线 + 开放箭头；
  • 消息跨越其它生命线：不可避免（生命线是竖线，箭头必然穿过中间生命线）。惯例：箭头画在生命线之上（不断线），因为读者理解这是穿越而非连接。可选风格：在穿越处画小跳线（与 15 篇 §3.3 同一机制）。

4区间容器（combined fragment / 阶段）

alt / opt / loop / par / critical 框：

text 
框的主轴范围 = [其内最早事件行, 最晚事件行] 外扩 padding
框的次轴范围 = [其涉及的最左生命线, 最右生命线] 外扩 padding

要点：

  1. 嵌套的框必须严格包含 → 嵌套深度决定 padding 累加（外层 padding = 内层 + step）；
  2. alt 的分区线（虚线）位置 = 各分支的边界行；
  3. 框的标题（alt [cond]）占额外高度，需在行高需求中计入；
  4. 框涉及的生命线应该连续 → 这是次轴排列的一个约束（与组约束同构，§2.3）。若不连续 → 框会包住无关生命线。处理：作为软约束加入 MinLA 代价（惩罚项），或作为硬约束用连续块机制。
  5. 框相互交叠（部分重叠而非嵌套）在 UML 里是非法的 → 检测并报诊断。
ℹ火焰图：区间嵌套的纯粹形态

火焰图是这个机制的纯粹形态（只有嵌套矩形、无边）：主轴 = 时间/样本，次轴 = 栈深度，矩形 = 帧。布局退化为"前缀和 + 深度"，，不需要任何优化 —— 但它验证了抽象的正确性：同一套区间嵌套代码能画火焰图，说明抽象没有耦合序列图特有概念。

5甘特图 / 时间轴的差异点

主轴变成连续的真实时间而非离散序号，带来三个新问题：

5.1 时间→像素映射

  • 线性映射：x = (t - t0) * scale；
  • 非线性（对数、分段）：用于跨度极大的时间线（毫秒级与月级混排）；
  • 时间刻度分级（tick 选择）：给定像素跨度选"好看的时间间隔"（1/2/5/10 × {秒,分,时,天,周,月,季,年}）。算法：候选间隔表 + 选择"tick 数落在 [5,15] 且最接近目标密度"者。这是 D3 time.ticks 的做法。

5.2 重叠条的行分配

同一资源上时间重叠的任务 → 必须分行。这就是区间图着色（14 篇 §4.2）：按开始时间排序 + 最小可用行，最优。行数 = 最大并发数。

5.3 依赖箭头

甘特的依赖（FS/SS/FF/SF 四种）画成正交折线：

  • 起止点由依赖类型决定（条的头/尾）；
  • 路由用普通正交路由（03 篇），走廊 = 行间空隙；
  • 密集时用总线（18 篇）。

显式声明的顺序被"优化"掉优化器没有把声明当硬约束声明 = 固定，优化只作用于未声明者

7给本项目的实现建议

7.1 内核三件套（复用而非新写）

  1. 一维排列器：输入加权图 + 约束（固定位置、连续块、偏序），输出排列。实现 L1+L2+L3（约 200 行），保留 L6 精确解作为测试 oracle。同一个排列器服务：生命线排序、泳道排序、组内节点排序、circular 排序。
  2. 主轴分层器：复用 14 篇的分层零件（最长路 / network simplex），输入事件偏序图。
  3. 区间嵌套器：递归求后代范围 + padding 累加 + 行高/列宽需求汇总（前缀和）。

7.2 参数化（20 篇）

序列图 / 甘特 / 火焰图的差异应全部落在参数：主轴方向、主轴是否连续时间、是否有事件边、容器是否可嵌套、行高来源、次轴排列策略、箭头风格。

✓引擎里不出现 if diagram == sequence

引擎里不出现 if diagram == sequence。图种差异只经 profile 展开进算法参数（ADR-001）。这是 plotgram 区别于"按图种写特判"的工程分水岭，也是这一章抽象能成立的判据。

7.3 测试

  • 一维排列器：对 的随机图，比对 L2/L3 结果与 DP 精确解，断言相对差距 < 阈值（如 15%）；
  • 事件偏序：构造带环输入，断言报诊断而非 panic 或静默；
  • 区间嵌套：3 层嵌套的 case，断言严格包含 + 无相交；
  • 坐标快照：insta::assert_json_snapshot!（AGENTS.md 约定）；
  • 确定性：同输入两次一致。
✓一句话收敛

序列图、甘特、火焰图看似异质，内核却是"一维排列 + 主轴离散化 + 区间嵌套"三件套。把这三件套做成不按图种分支的通用零件，是这一章能落到 plotgram 的工程价值所在。
