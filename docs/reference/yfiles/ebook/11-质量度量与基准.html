11 · 布局质量度量、基准集与回归体系

主线：Purchase 1997/2002（美学准则的实证检验）、Ware–Purchase–Colpoys–McGill 2002（路径查找任务）、Huang–Hong–Eades 2008（交叉角度）、Bennett et al. 2007（美学综述）、Battista et al. 1997（An experimental comparison of four graph drawing algorithms，Rome 图集来源）、Dwyer et al. 2009（A comparison of user-generated and automatic graph layouts）、Klapaukh 2014（An empirical evaluation of force-directed graph layout）。

工程 原始出处：Purchase 等 · Graph Drawing 社区美学准则实证系列 ~186 行 · 6.5k 字

核心论点：如果不度量，就只能靠"看起来顺眼"来做算法决策，那么每次改动都是赌博。本篇给出可落地的度量清单与回归框架。

1美学准则及其实证地位

Graph Drawing 社区长期使用的"美学准则"，被 Purchase 等人做了对照实验。按实证效果排序（对人的任务表现的影响）：

准则实证结论可计算指标
减少边交叉影响最大、最一致（Purchase 1997、2002 多次验证）交叉数
减少弯折显著，次于交叉总弯折数、每边弯折数
增大交叉角度显著（Huang 2008）：接近 90° 的交叉几乎不影响可读性；小角度交叉很伤最小交叉角、平均交叉角
对称性显著（尤其对结构理解任务）对称性得分（需近似算法）
减少总边长 / 边长均匀弱到中等总长、边长方差
最大化角分辨率（节点处相邻边夹角）中等最小/平均角分辨率
减少面积 / 提高长宽比适配与任务无关，但与"能否放进屏幕"强相关面积、长宽比
正交性 / 网格对齐主观偏好强，客观任务提升有限段的正交比例
节点分布均匀弱最近邻距离分布

工程含义：优化投入的顺序应是 交叉 → 弯折 → 交叉角度 → 对称 → 边长。 特别注意 交叉角度：如果无法消除某个交叉，把它变成接近直角就几乎无害。这是一个便宜且被低估的优化（在 nudging 阶段可实现）。

另一个重要实证结论（Dwyer et al. 2009）：人手工排的图并不总是优于自动布局，但人排的图在"语义分组、对齐、留白"上明显更好。这提示产品重点：分组框、对齐、一致的间距，比算法最优性更影响观感。

2可计算指标的实现细节

2.1 交叉数

  • 直线段集合的交点计数：Bentley–Ottmann 扫描线 ，k 为交点数。
  • 要排除：同端点的边（共享节点不算交叉）、与自身相邻段。
  • 折线边：对每一段做，注意同一条边的相邻段共享端点。
  • 报告分类：real-real / real-dummy / 跨组 交叉分别统计，便于定位问题相。

2.2 交叉角度

在计算交点时顺便记录两段方向向量夹角，取 。 指标：最小值、平均值、< 30° 的交叉占比（这是最有信号的一项）。

2.3 弯折

  • 总弯折数、最大单边弯折数、弯折角度分布（正交图应全为 90°）。
  • 排除"共线冗余点"（先做共线合并再统计，否则数字虚高）。

2.4 重叠（应为 0 的硬指标）

  • 节点–节点重叠面积、节点–边交叉长度、标签–任意重叠面积、组框–组框重叠。
  • 用扫描线/R-tree，。
⚠重叠 = 断言而非指标

这些应作为断言（assert = 0）而非指标，任何非零都是 bug。把重叠放进"软指标"会让人产生"稍微退化可接受"的错觉——而重叠对可读性的伤害是阶跃式的，不是渐变的。

2.5 对称性得分

精确的图自同构 → 几何对称是难问题。实用近似（Purchase 的 symmetry metric）：

pseudo 
对若干候选对称轴（由节点对的中垂线生成，取投票最高的若干条）：
  统计"关于该轴镜像后能匹配上的子图规模"
得分 = 最佳轴的匹配规模 / 总规模

成本较高，建议只在基准集上离线跑，不进 CI 快路径。

2.6 边长与均匀性

  • 总长、平均、方差/CV（变异系数）。
  • 正交图用曼哈顿长度。
  • 对分层图另报 backward edge 数量与总跨度（反向边的视觉代价高）。

2.7 角分辨率

每个节点处相邻两条边（按角度排序）的最小夹角；报告全图最小值与平均值。理想是 。

2.8 面积与"墨水"

  • 包围盒面积、长宽比、节点覆盖率（节点面积/总面积，太低说明太散）。
  • 边总长/包围盒对角线（归一化的"墨水量"）。

2.9 稳定性（对增量场景）

见 07 篇 §5.2：平均归一化位移、正交序违反率、k-NN 保持率。

2.10 分层图专属

  • 层数、最大层宽、宽度方差；
  • dummy 节点数（直接反映 P2 质量）；
  • 长边直线率：跨多层的边中"完全竖直"的比例（Brandes–Köpf 应该给出高值）；
  • 同层边数量与其占用的通道数；
  • 主流程/critical path 的直线度。

3.2 自建集合的构成建议（本仓库 benchmarks/sets/ 的扩展方向）

  1. 微型手工集（每个 3–10 节点）：每个 case 精确针对一个特性（自环、平行边、同层边、单组、嵌套组、固定端口、泳道…）。这是回归的主力，快、可断言精确坐标。
  2. 产品回归集：真实用户/文档中的图，覆盖各图种。用 JSON 快照。
  3. 压力集：程序生成的规模阶梯（100/1k/10k 节点；树/DAG/网格/幂律/团簇），只测性能与门控。
  4. 病态集：极端长宽比节点、超长标签、极深嵌套、大量平行边、完全图 K10、超长链、宽扇出（1 对 500）。这些最能暴露 bug。
  5. 确定性集：任意子集跑两遍比较，作为独立测试。

生成器建议内置：tree(n, branching)、dag_layered(layers, width, density)、grid(w,h)、power_law(n, γ)、clustered(k, n_per, p_in, p_out)、complete(n)、long_chain(n)、wide_fanout(n)。

4回归框架设计

4.1 三层测试

pseudo 
L1 单元测试（cargo test）
    表驱动 + insta 快照；断言坐标/路径/SVG
    每个 case < 10ms
L2 特性断言（不变式检查，可在 L1 内实现）
    无重叠、无边穿节点、约束满足、确定性（跑两遍）
L3 基准（benchmarks/ 脚本，非 CI 阻塞）
    全指标表 + 与 baseline 对比 + 人工审阅渲染图

4.2 指标对比报告的格式

本仓库已有 benchmarks/snapshot.sh / compare.sh 的模式，建议报告长这样：

text 
                         baseline     current      delta
crossings                    1,284       1,197     -6.8%  ✓
bends                        3,410       3,502     +2.7%  ⚠
crossings_below_30deg          142          98    -31.0%  ✓
total_edge_len            1,204,300   1,188,900    -1.3%  ✓
node_overlaps                    0           0        —   ✓
label_overlaps                   0           3     +3     ✗ FAIL
area                     18.4M       17.9M        -2.7%  ✓
layout_ms (p50/p95)      12 / 88     13 / 91      +8%/+3% ⚠
determinism                   pass        pass       —    ✓

关键设计：

  • 硬指标（应为 0）失败即 FAIL，软指标只报趋势；
  • 按图种分组再汇总（避免一个图种的改善掩盖另一个的退化）——这是"改 A 图种毁 B 图种"的唯一防线；
  • 报告里带每个 case 的 top-N 退化榜，便于定位。

4.3 视觉审阅（不可替代）

指标好但图丑是常见的。建议：

  • 基准脚本同时输出对比画廊 HTML（baseline 与 current 并排 SVG）；
  • 只需扫一眼就能发现"指标变好但结构崩了"。

本仓库 showcase/ + benchmarks/viewer/ 已具备此基础设施。

4.4 性能测量的纪律

⚠性能测量纪律（违反任一条 → 数据不可信）
  • 只用 --release 测性能（AGENTS.md 已规定）；
  • 报告 p50/p95 而非均值；
  • 分相计时（09 篇 §6 的 phases 输出）；
  • 固定机器/固定线程数；把绝对值当趋势看，不做跨机器比较；
  • WASM 与原生分别测（WASM 通常慢 1.5–3×，且 SIMD/线程受限）。

5如何用指标做算法决策（实操）

流程：

  1. 先固定基准集与指标（本篇 §2、§3）；
  2. 记录 baseline；
  3. 改一件事（只改一相的一个机制）；
  4. 跑基准，看分图种的 delta；
  5. 若某图种退化，先判断是"该图种的参数需调"还是"机制本身有问题"——参数问题就调 profile，机制问题就回滚。
⚠常见陷阱
  • 指标打架：减少弯折常增加边长；减少交叉常增加面积。要预先约定权衡（例如"交叉优先，弯折其次，面积不作为门禁"）。
  • 过拟合基准集：调参调到基准最优但真实图变差。对策：留一部分 case 作为"holdout"，只在里程碑时看。
  • 平均值掩盖：一定要看最差 case（p95、top-N 退化）。
  • 只看指标不看图：必须配视觉画廊。

6给 tautcore 的具体建议

  1. 立刻补齐的硬断言（应为 0，进 CI）：节点重叠、边穿节点、标签重叠、组框重叠、确定性（双跑一致）。
  2. 补齐的软指标（进基准报告）：交叉数（分类）、<30° 交叉占比、弯折数、总边长、面积、长边直线率、dummy 数、分相耗时。
  3. 稳定性指标（07 篇）：位移、正交序违反率——在做 from-sketch / 增量前就应具备。
  4. 基准集扩充：按 §3.2 的五类补齐，特别是"病态集"（当前 stress-probe-set 可扩展）。
  5. 报告按图种分组，防止跨图种回归——这是历史上多次踩坑的直接对策。
  6. 每个 findings/修复都附指标 delta，让"这个改动是不是真的更好"不再靠感觉。
✓一句话收敛

度量先于优化：没有指标 delta 的算法改动是赌博，没有按图种分组的回归报告是盲区。把"硬指标 = 0 的断言"和"按图种分组的指标对比"写进 CI 与基准脚本，是 tautcore 工程化的分水岭。
