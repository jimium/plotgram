08 · 分组、泳道与端口约束（Groups, Swimlanes & Port Constraints）

对应 yFiles GroupNode / RecursiveGroupLayout / PartitionGrid（swimlane）/ PortConstraint / PortCandidateSet / EdgePortCandidates、BusRouter 的 edge grouping；ELK layered + portConstraints；Graphviz cluster；cytoscape.js compound nodes

核心算法 主线论文：Sugiyama–Misue 1991（compound graph 原文）、Sander 1996（clustered hierarchical）、Forster 2002（Applying Crossing Reduction Strategies to Layered Compound Graphs）、Dogrusoz et al. 2009（CoSE：compound spring embedder）、Schulze–Spönemann–von Hanxleden 2014（ELK 的 layered + ports） ~186 行 · 7.2k 字

这三件事（分组、泳道、端口）是产品级布局与玩具级布局的分界线。它们的共同特点：都是把额外的离散结构注入已有管线，且必须在正确的相注入。

1复合图（Compound / Clustered Graph）

1.1 模型

  • 节点集 上有一棵包含树（inclusion tree）：组节点有子节点，叶节点是普通节点。
  • 边可以连任意两个节点（含组节点本身，以及跨层级）。
  • 组框（group bounds）= 其内容包围盒 + padding + 标题栏高度。组框尺寸是被推导出的，不是输入（除非用户固定）。

1.2 三种实现策略

策略做法优点缺点
A. 递归（recursive）自底向上：先布局最内层组 → 该组收缩成一个"大节点" → 上层布局实现简单，组框天然紧凑跨组边被忽视，跨层级边质量差；组内看不到外部关系
B. 全局 + 组约束（flat with constraints）一次布局全部叶节点，组关系作为约束（同组节点相邻/在同层区间内）跨组边质量好需要在每相处理组约束，实现复杂
C. 混合递归得到组内布局作为"初值/形状"，再全局微调平衡最复杂

yFiles RecursiveGroupLayout 是 A（并允许每组用不同算法，这是很好的产品特性）；其 HierarchicLayout 内置的分组支持是 B。

ℹ策略选型建议

分层图种用 B（下面详述），organic 用 A/CoSE。递归策略 A 在 organic 上能借力 CoSE 的多级思想，而在分层图上会丢失跨组边质量。

1.3 分层布局中的分组（策略 B 详解）

这是 Sander 1996 / Forster 2002 的核心内容。

(a) 分层相（P2）：组内节点应占据连续的层区间。

  • 若允许组跨层（通常允许），只需保证"组的层区间不与其它同级组交错"吗？——不需要，交错在分层上是允许的；问题出在层内序。
  • 若要求组框是矩形且不与其它组重叠，则组内节点在每一层上必须连续（层内序上连续）。这是关键约束。

(b) 定序相（P3）：核心难点。要求：同一组的节点在每层内连续成块。

Forster 2002 的做法：

pseudo 
把每层的节点按"所属组的路径"分段（segment）：
  同组连续块 = 一个 segment
交叉最小化在两个粒度上交替进行：
  1. segment 之间的排序（把整个 segment 当一个超节点做 barycenter）
  2. segment 内部的排序（递归）
关键：barycenter 计算时，跨组的边贡献给"组超节点"，组内边贡献给内部

更简洁的等价实现（ELK 的做法）：

  • 引入 组边界 dummy 节点：每个组在其占据的每一层上插入"左边界 dummy"和"右边界 dummy"，并用序约束把组内节点夹在两者之间。
  • 之后 P3 照常跑（barycenter + transpose），只需在交换时检查"不越过边界 dummy"。
  • 这样不需要改交叉最小化算法本身，只需加序约束（回到 07 篇 §3.1 的受约束排序）。推荐这个做法：改动小、复用强。

(c) 坐标相（P4）：

  • 组框左右边界 = 组内节点 x 范围 ± padding；
  • 相邻组之间的间距 ≥ groupGap（两个组框不重叠）⇒ 在 VPSC 里加"边界变量之间的分隔约束"；
  • 组标题占用组框顶部高度 ⇒ 组的第一层需要额外的 y 偏移（或把标题当一个占位 dummy 放在组内第一层之上）。
⚠组框防重叠的正解形态

组框的包围盒不能事后"算出来发现重叠再挪" —— 边界应作为变量参与求解（这是 VPSC 的价值，也是仓库里"组框防重叠调整"的正解形态）。事后挪会把已确定的边弯折与坐标推翻，破坏 P3/P4 的写权分工。

(d) 路由相（P5）：

  • 跨组边穿越组框边界：应在边界上开口，且开口位置参与端口分配；
  • 组内边不得跑出组框；
  • 组框边界本身是路由障碍（对不涉及该组的边）。见 03 篇 §1.4。

1.4 Organic 的分组：CoSE（Dogrusoz et al. 2009）

Compound Spring Embedder：

  • 在力模型里增加：
    • 组内节点受"向组重心"的额外引力；
    • 组框之间的斥力（按框而非点）；
    • 跨组边的引力作用在组框上而非节点上（多级思想）。
  • 用"多级 + 组收缩"提速：先把每个组当一个点布局，再展开。
  • Cytoscape.js 的 cose-bilkent 即此，效果相当好，值得参考其参数体系。

1.5 组的折叠/展开（产品必备）

  • 折叠：组变成一个普通节点，跨组边聚合到该节点（多条边合并成一条带计数的边）。
  • 展开：需要"在原位展开"—— 用 07 篇的 PartialLayout / 增量布局，把新出现的内容塞进腾出的空间。
  • 稳定性：折叠再展开应回到（近似）原布局 ⇒ 缓存组内布局。

2泳道（Swimlane）与 Partition Grid

2.1 模型

泳道 = 与流向正交的分区。若图自上而下（层沿 y），泳道沿 x 划分列。

yFiles 的抽象是 PartitionGrid： 的网格，每个节点指定其 cell（行、列）。

  • 泳道 = 只用列（或只用行）；
  • 矩阵式布局（如"阶段 × 责任人"的 BPMN）= 同时用行和列。

2.2 算法落点

  1. 分层（P2）：行约束 = 层约束（若行对应阶段，节点必须在该行的层区间内）。实现：给每行分配连续的层区间，节点的层被限制在其行的区间内 ⇒ LP 加上下界。
    • 行区间长度未知（取决于内容）→ 两趟：先无约束分层看每行需要几层，再分配区间。
  2. 定序（P3）：列约束 = 层内序的分段约束。与分组的处理完全同构：同一列的节点在每层内连续。因此可复用组边界 dummy 机制。
  3. 坐标（P4）：
    • 每列有一个 x 区间 ，列宽 = 该列内容宽 + padding，列之间不重叠；
    • 列宽应满足"所有列内节点都在区间内" ⇒ 又是 VPSC 的分隔约束；
    • 空列也要有最小宽度（否则泳道标题放不下）。
  4. 路由（P5）：跨泳道边穿越泳道边界（允许），但通常要求"垂直穿越"（不要沿泳道边界走），可通过给"沿边界走"加惩罚实现。

2.3 常见陷阱

⚠泳道工程坑清单
  • 泳道高度/宽度必须容纳泳道标题（旋转 90° 的文字），标题尺寸要进 measure 相。
  • 泳道内为空时布局塌陷 → 设最小尺寸。
  • 泳道顺序由用户给定（不是算法优化的），必须严格保持 ⇒ 序约束优先级最高。
⚠最容易做错的点

层跨泳道对齐：BPMN 里"同一阶段的活动应水平对齐" ⇒ 行区间必须全局一致（所有泳道共享同一套层），不能每泳道各自分层。泳道是列，层是全局的——这条搞反就会得到"每条泳道独立分层、横向无法对齐"的错图。

3端口（Port）与端口约束

3.1 为什么端口必须是一等公民

边从节点的哪个位置出发，决定了：

  • 弯折数（从错误的侧出发必然绕行）；
  • 交叉数（端口序错了会凭空产生交叉）；
  • 语义正确性（BPMN gateway 的 yes/no 分支、UML 的组合端、电路的引脚）。
⚠端口必须上提到布局阶段

若端口在路由阶段"临时发明"，就会出现无法修复的绕行与交叉。 端口分配必须上提到布局阶段（这正是仓库纪律的原话：落笔相零新决策——下游不得发明端口，必须由上游写者确定）。

3.2 端口模型的层次

级别语义谁写
PortConstraint: side只约束"哪一侧"（north/south/east/west），位置自由用户/DSL 指定
PortCandidate 集合给出若干候选位置，算法挑一个用户给候选，算法挑
Fixed port位置完全固定（电路引脚）用户
Free port完全由算法决定布局算法
Port group一组边共享一个端口/相邻端口用户声明，算法落位

ELK 的对应概念是 portConstraints ∈ {FREE, FIXED_SIDE, FIXED_ORDER, FIXED_RATIO, FIXED_POS} —— 这个五档分级设计非常好，建议直接采用。

3.3 分层布局中的端口处理（ELK 的做法，值得照抄）

  1. P2 之后：若边因端口侧约束而"必须绕行"（例如从 north 侧出发但目标在下方），插入额外的 dummy 层/北向 dummy 节点，把绕行显式化 —— 这叫 north/south port dummy。ELK 会为节点北侧/南侧的端口创建"端口 dummy"参与定序。
  2. P3 定序：
    • 若 FIXED_ORDER 或更强，节点的邻边在层内序中的相对位置由端口序决定 ⇒ 交叉计数要按端口位次而非节点位次；
    • 实现：把节点"展开"成一串端口 dummy（类似 02 篇的顶点膨胀技巧），barycenter 作用在端口上。
    • FREE 时反之：先定序，再按邻居 x 序分配端口（这是最常见的默认行为，效果好且简单）。
  3. P4 坐标：端口偏移进入 x 的计算（节点锚点 vs 端口锚点）；对齐目标应是"端口对齐"而不是"节点中心对齐"，否则长边不直。
  4. P5 路由：端口位置作为输入，只求路径。

3.4 自由端口的分配算法（默认路径的核心）

给定节点 v 与其在某侧的边集，按"对侧端点的 x 坐标"排序，然后均匀分布在该侧：

rust 
fn assign_ports(v: &Node, side: Side, edges: &mut [Edge]) {
    edges.sort_by_key(|e| (opposite_anchor_x(e), e.id));   // 稳定
    let n = edges.len();
    let span = v.width - 2.0 * PORT_MARGIN;
    for (i, e) in edges.iter_mut().enumerate() {
        let t = if n == 1 { 0.5 } else { PORT_MARGIN + span * (i as f64) / (n - 1) as f64 };
        e.set_port(v, side, t);
    }
}
  • 按对侧 x 排序保证不交叉（这是一个简单但强力的不变式）；
  • 端口数多时节点需加宽（最小宽度 = n × portGap） ⇒ 端口需求回写节点尺寸 ⇒ 必须在 measure/尺寸相之前知道端口数。这是又一处"上游留位"。
  • 变体：集中式端口（所有边接同一点，如流程图的简单风格）与分散式端口是产品选项，不是算法差异。

3.5 Edge grouping（边聚合）

yFiles 的 source/target group id：同一 group 的边在其源/目标处共享端口并汇聚：

  • 实现：先各自路由，再在靠近共享端口的一段做"合并"（找公共前缀，取中线）；
  • 或直接用 bus routing（03 篇 §2.4）；
  • 视觉上非常干净，是"一对多"关系（继承、汇总）的标准画法。

4三者交互时的处理顺序（重要）

分组 + 泳道 + 端口同时存在时，约束可能冲突。推荐的注入顺序与优先级：

pseudo 
1. 泳道（行/列）约束      —— 最高优先级（用户显式指定的画布结构）
2. 组包含约束             —— 次高（语义结构）
3. 层/序约束（用户指定）  —— 再次
4. 端口约束               —— 在上述框架内落位
5. 算法自身的优化目标     —— 最低（交叉、边长）

冲突检测与降级策略必须显式（07 篇 §7.5）：例如"节点 A 在泳道 1 但被要求与泳道 2 的 B 同层"是可行的（层是全局的）；而"A 在组 G 内但被要求在 G 外某节点的左边且该节点在 G 的右边"是不可行的 → 报告并丢弃低优先约束。

5plotgram 落地清单

  1. 组与泳道复用同一套"层内连续块"机制（边界 dummy + 受约束排序）。不要写两份。
  2. 组框边界作为 VPSC 变量，不要事后调整包围盒。这解决"组框重叠"和"组框把边挤出去"两类顽疾。
  3. 端口五档模型（FREE / FIXED_SIDE / FIXED_ORDER / FIXED_RATIO / FIXED_POS）先落 DSL 与 IR，算法逐步支持；默认 FREE + "按对侧 x 排序分配"就能覆盖大多数图。
  4. 端口数回写节点最小尺寸，在 measure 相处理。
  5. 约束优先级表写进设计文档，冲突时的降级路径可观测（诊断输出）。
  6. 测试：对每个特性做"约束满足性断言"（组内节点确在组框内、泳道内节点确在列区间内、端口序与邻居序一致），而不是只看图好不好看。
✓一句话收敛

分组、泳道、端口的共同点是把离散结构在正确相注入既有管线：组与泳道复用"层内连续块 + 边界 dummy"机制，端口用五档模型上提到布局阶段。三者都不在路由相"临时发明"，否则必然产生无法修复的绕行与交叉。
