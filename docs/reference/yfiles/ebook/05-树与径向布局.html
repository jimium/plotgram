05 · 树与径向布局（Tree & Radial Layout）

对应 yFiles TreeLayout（多种 NodePlacer）/ RadialLayout / BalloonLayout / CircularLayout，Graphviz twopi / circo，D3 tree / cluster / pack / partition

核心算法 主线论文：Reingold–Tilford 1981 · Walker 1990 · Buchheim–Jünger–Leipert 2002（线性时间修正）· Eades 1992（radial/balloon）· Six–Tollis 1999（circular）· Wetherell–Shannon 1979 ~200 行 · 6.5k 字

树布局看似简单，实则是最容易写出 或产生不对称丑图的地方。本篇给出正确实现的全部细节。

1分层树布局（Layered / Reingold–Tilford）

1.1 美学要求（RT 论文原文的 aesthetic rules）

  1. 同深度节点在同一层（y 相同）。
  2. 父节点在子节点的水平中心。
  3. 树的镜像 = 布局的镜像（对称性）。
  4. 同构子树布局形状相同，与在树中的位置无关（子树一致性）。
  5. 尽量窄。

规则 3、4 是 RT 优于 Wetherell–Shannon（1979）的关键；WS 会因扫描顺序产生不对称结果。

1.2 核心机制：轮廓（contour）+ 相对偏移

pseudo 
后序遍历（bottom-up）:
  1. 递归布局每个子树，得到各自的"左右轮廓"（每层的最左/最右 x）
  2. 从左到右合并子树：把新子树紧贴已合并部分的右轮廓
     （逐层比较，取最大所需推移量 shift）
  3. 父节点 x = 首末子节点 x 的中点
  4. 记录本节点的 mod（子树整体偏移），最终 preorder 累加得绝对 x
  • 轮廓串成"线程（thread）"：叶子的轮廓不连续时，用 thread 指针把下一层的轮廓节点串起来，使"沿轮廓走"是 而不是重新遍历子树。
⚠必须用 thread

朴素实现（每次合并重新算轮廓）→ 。必须用 thread 把不连续的轮廓串起来，否则深树会明显卡。

1.3 Walker 1990 与 Buchheim et al. 2002（正确的线性时间版）

Walker 把 RT 扩展到任意度树（不只二叉），但其论文的原始算法实际是 （Buchheim 指出并修正）。

Buchheim–Jünger–Leipert 的 算法要点（现代实现的依据，D3 d3.tree 即此）：

rust 
fn first_walk(v: &mut Node) {          // 后序
    if v.is_leaf() {
        v.prelim = v.left_sibling().map_or(0.0, |w| w.prelim + distance(w, v));
    } else {
        let mut default_ancestor = v.first_child();
        for c in v.children_mut() {
            first_walk(c);
            apportion(c, &mut default_ancestor);   // ← 关键
        }
        execute_shifts(v);          // 把累积 shift/change 分摊给各子节点
        let mid = (v.first_child().prelim + v.last_child().prelim) / 2.0;
        v.prelim = match v.left_sibling() {
            Some(w) => { v.mod_ = (w.prelim + distance(w, v)) - mid;
                         w.prelim + distance(w, v) }
            None => mid,
        };
    }
}
fn second_walk(v: &Node, m: f64) {      // 先序，累加 mod
    v.x = v.prelim + m;
    for c in v.children() { second_walk(c, m + v.mod_); }
}

apportion 的三个技巧（易错点，逐条说明）：

  1. thread：v.thread 指向"下一层轮廓上的节点"，使沿左右轮廓下行不需要遍历整棵子树。
  2. ancestor / default_ancestor：发现冲突需推移时，要知道"推的是哪个上层子树"，用 ancestor 指针在 摊还内找到（不是向上遍历，那会退化）。
  3. shift / change 的分摊：多个子树间的推移量不能只加到最后一个，要在所有中间子树间线性分摊（否则间距不均匀，图会歪）。execute_shifts 用两个累加器 shift / change 一遍逆序扫描完成。
✓实现建议

复杂度 ，输出满足 RT 全部 5 条美学。建议直接实现这一版，不要自己"简化"——简化成"每次算轮廓"在深树上会明显卡。

1.4 变宽节点与非均匀间距

distance(w, v) = w.width/2 + v.width/2 + siblingGap。RT/Buchheim 天然支持（distance 是函数参数）。

层高：y(depth+1) = y(depth) + maxHeight(depth) + layerGap；也可逐子树紧凑（每个子树自己的层高，产生"参差"效果，yFiles 有此选项）。

1.5 NodePlacer 风格谱（yFiles TreeLayout 的产品面）

风格描述适用
Default / centered子节点水平排开，父居中组织架构图
Left-aligned / bus子节点竖排，父连一条"总线"下挂文件树、思维导图侧枝
Double-line子节点分两行交错排宽扇出的树，省宽度
AR (aspect ratio)按目标长宽比递归分配子树方向需要填满画布
Dendrogram所有叶子在同一层（末层对齐）聚类树、系统树
Compact允许子树"插进"兄弟的空隙空间优先，牺牲子树一致性
Assistant某些子节点标记为"助理"，放在父节点侧面组织架构图的助理岗

Compact tree 值得单独说：RT 的轮廓合并本身已是"轮廓级紧凑"（不是包围盒级）。真正"更紧"的是允许子树上下交错插入，面积可再降 20–40%；yFiles CompactNodePlacer 的做法是对每个子树尝试若干种 aspect 配置 + 记忆化的有界搜索。

1.6 非树图怎么办

  • 求生成树（BFS/DFS/最大权），非树边事后路由（可能产生交叉）。
  • 或用分层布局（01 篇）——树是 DAG 的特例，Sugiyama 在树上也能给好结果，但通常更宽。
  • yFiles TreeReductionStage：图→树归约 → 树布局 → 非树边用独立 router 补上。这是很好的架构模式：把"图→树"的归约做成 stage，树算法保持纯粹。

2径向布局（Radial）

节点按深度放在同心圆上，角度按子树大小分配。

2.1 基础算法（Eades 1992 的 radial drawing）

pseudo 
1. BFS 分层，depth(v) → 半径 r_d（等差或按需增长）
2. 角度分配（先序）：
   根分配 [0, 2π)；父 v 有区间 [a,b)，按子树"叶子数"或"角宽需求"比例切分给子节点
   子节点 c 的角度 = 其区间中点
3. x = r*cos(θ), y = r*sin(θ)

2.2 必须处理的三个问题

  1. 半径必须够大：第 d 层节点在其角扇区内的弧长须 ≥ 节点宽度 ⇒ 逐层求 ，再与 取最大。漏了这条必重叠。
  2. 子树角区间不能溢出：自底向上先算每个子树的"最小角宽需求" ，再自顶向下按 demand 比例分配。这就是"上游给下游留位"的树版本。
  3. 0/2π 边界：角度统一到 ，比较时取模；输出保持连续以免边绕远。
⚠径向布局的三条硬约束

上面三条缺一不可：漏第 1 条必重叠；漏第 2 条子树溢出兄弟扇区；漏第 3 条边绕远。这是"上游给下游留位"在极坐标下的实例——角宽 demand 自底向上传播，分配自顶向下执行。

2.3 扇形 / 局部径向

只用部分角度（如 ）→ "扇形树"，适合 focus+context 的从焦点展开。

2.4 边的画法

  • 直线：简单但穿越内圈。
  • 圆弧 + 径向段：先沿同心圆弧走到目标角度，再径向走——正交在极坐标下的类比，非常整洁，推荐。
  • 层次边捆绑（见 §4.3）。

3Balloon / 泡泡布局

每个子树占据一个圆盘，父节点在中心，子树圆盘绕父排布。

rust 
fn balloon(v: &Node) -> f64 {                 // 返回本子树外接圆半径
    let child_radii: Vec<f64> = v.children().map(balloon).collect();
    // 把 k 个半径 r_i 的圆排在半径 R 的圆周上不重叠：
    // 每个圆占圆心角 ≈ 2*asin(r_i / R)，要求 Σ角 ≤ 2π - reserved
    let R = binary_search_min(|R| {
        child_radii.iter().map(|r| 2.0 * (r / R).asin()).sum::<f64>() <= TAU - reserved
    });
    assign_angles_proportional(&child_radii, R);
    R + child_radii.iter().cloned().fold(0.0, f64::max)
}
  • 二分求 R 是关键：asin 之和无解析解。二分 30 次足够。
  • 根子树可用整圆；非根子树要为"连向父的边"预留角度缺口 reserved，否则子树挡住父边。
  • 变体：按子树大小排序放置影响观感；固定"从父边方向开始逆时针"保证确定性。
  • 适合：文件系统、分类体系、网络自治域。

4圆形布局（Circular）

4.1 单圈的圈序

圆上交叉最小化 NP 难（与 book embedding 相关）。启发式：

  • Six–Tollis 1999：基于双连通分量与边长最小化的启发式圈序。
  • DFS/BFS 序：简单可用，相连节点排近。
  • 谱序：拉普拉斯 Fiedler 向量排序（最小化 的连续松弛）——便宜且质量好，推荐首选。
  • 边画成朝内圆弧（弦或往圆心弯的贝塞尔），弯曲度按弦长自适应。

4.2 分层圆形（yFiles CircularLayout 的实际形态）

  1. 求双连通分量（BCC）；
  2. 每个 BCC 内部排成一个圆（用上面的圈序）；
  3. BCC 之间构成 block-cut tree → 用树/balloon 布局排列这些圆。

既体现环状结构，又不把所有点挤到一个巨圆上。

4.3 Edge bundling（层次边捆绑）

Holten 2006 Hierarchical Edge Bundles：

  • 边 的控制点 = 层次树上 u→LCA→v 路径上的节点位置；
  • B-spline 平滑 + bundling strength （0 = 直线，1 = 完全贴树）在控制点与直线间插值。
  • 上千条边的圆形/径向图唯一可读方案；实现约 50 行，性价比之王。
  • 无层次结构时用 Force-Directed Edge Bundling（Holten–van Wijk 2009）：边离散成控制点，相似边（方向 + 邻近 + 可见性兼容）间施加吸引力迭代。，需空间索引加速。

7tautcore 落地建议

  1. 树布局照抄 Buchheim–Jünger–Leipert，包括 thread / ancestor / shift-change 三件套。别简化成"每次算轮廓"，深树会明显卡。
  2. TreeReductionStage 模式：把"图→生成树 + 非树边"做成独立 stage，非树边交给 03 篇的 router。
  3. Radial 的角度需求自底向上传播必须实现，否则深层必重叠——"上游留位"纪律在极坐标下的实例。
  4. NodePlacer 抽象（centered / bus / double-line / dendrogram）是低成本高收益的产品扩展点。
  5. 层次边捆绑作为渲染层可选装饰（不改路由结果），先做 β 插值版本。
✓一句话收敛

树/径向布局的核心纪律：角度与半径的需求自底向上传播，分配自顶向下执行——这是写权纪律在极坐标与递归圆盘下的具体化。实现上照抄 Buchheim 三件套（thread / ancestor / shift-change），别简化。
