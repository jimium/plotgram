15 · 几何与落笔层（Ink / Geometry Layer）

布局算出坐标之后，决定「图看起来是不是专业」的整层工作：端点裁剪、路径规范化、圆角、箭头、自环、平行边、标签锚点、数值稳定 —— 公开文献极少，但产品观感的一半在这里，也是 bug 最密集的地方

工程 纪律（AGENTS.md）：落笔相零新决策 —— 只展开上游已决定的自由度，不发明端口、不挪节点、不改路由拓扑 ~235 行 · 6.5k 字

1自由度分层（谁写什么）

路径拓扑经过哪些走廊、拐点序路由相❌ 只读

⚠判断句（写权纪律）

如果要在落笔层「移动一点让它不重叠」，说明上游少写了一个自由度 —— 应上提，不要在这里补。落笔相只允许「展开上游已决定的自由度」，不允许发明端口、不允许挪节点、不允许改路由拓扑。下面每一节都标注了它读什么、写什么。

2端点裁剪（clipping）

路径的第一段/最后一段要在节点边界处终止，而不是从节点中心出发。

2.1 各形状的解析裁剪

给定节点中心 、外部点 ，求射线 与形状边界交点：

形状解法
矩形，交点 （注意 dx 或 dy 为 0）
圆角矩形先按矩形求；若交点落在圆角区域内，再解圆弧交点（二次方程）
椭圆
菱形（decision）与两条边界线段求交，取 最小的正解
平行四边形 / 梯形4 段线段求交
多边形 / 任意路径逐段线段求交，取最近；或用 SDF 二分
⚠裁剪要点
  1. 裁剪必须用路径的第一段方向，而不是「中心到对端中心」方向 —— 正交路由下这两个方向不同，用错会让边「斜着扎进」节点。
  2. 端口已固定时不做裁剪：端口点本身就在边界上，裁剪反而会把它挪走。
    → 正确逻辑：if has_explicit_port { use port_point } else { clip_to_shape }。
  3. 有 stroke 宽度时，裁剪点应在描边外沿（+ strokeWidth/2），否则箭头会盖住边框。
  4. 起点在节点内部（自环、极短边）时解析式会退化 → 需要 fallback（见 §6）。

2.2 端点留白（gap）

专业观感常需要边与节点之间留 0–2px 空隙（或紧贴，取决于风格）。把它做成主题参数 edge.endGap，而不是硬编码。注意 gap 会与箭头缩进叠加，需统一在一处计算：

text 
effective_end = clip_point + dir * (endGap + arrow_inset)

3正交路径规范化

路由输出的点序列往往有冗余，必须规范化，否则弯折统计虚高、圆角会画错、SVG 变大。

3.1 规范化流水线（顺序不能乱）

pseudo 
1. dedup_points(eps)          // 去掉重复点
2. merge_collinear(eps)       // 三点共线 → 去中间点
3. remove_degenerate_spikes() // A→B→A 的往返（长度 < eps）
4. snap_to_axis(eps)          // 近似水平/垂直的段吸附为严格正交
5. merge_collinear(eps)       // snap 之后可能又产生共线 → 再来一遍
6. enforce_min_segment(min)   // 太短的段：合并或让位（见下）

第 5 步的二次共线合并经常被漏，结果是「看起来是一条直线但有 3 个点」，圆角算法会在这里画出微小凸起。

3.2 最短段问题

圆角半径 要求相邻两段长度都 ≥ （各占 ）。段太短时的三种处理：

  • 降半径：该拐角用 —— 推荐，局部、无副作用；
  • 吸收该段：把两个拐角合并成一个（改变路径形状，仅在段长 < eps 时可用）；
  • 上游解决：nudging 阶段就加「最小段长」约束（VPSC 的分隔约束）—— 正解，但落笔层仍需降半径兜底。

3.3 交叉标记（可选风格）

两条正交边交叉处画「跳线」（半圆或断口）在电路/流程图风格中常见。实现：

  • 用扫描线求所有交点；
  • 每个交点归属给一条边（约定：水平段让位垂直段，或 id 较小者让位），否则两边都断开会看起来像断线；
  • 跳线宽度需 < 最短相邻段，否则退化 → 跳过该点。

4圆角与曲线

4.1 正交圆角（arc / quadratic）

对拐点 ，前后邻点 、：

pseudo 
r_eff = min(r, |PA|/2, |PB|/2)
p_in  = P + normalize(A - P) * r_eff
p_out = P + normalize(B - P) * r_eff
SVG: L p_in  Q P p_out      // 二次贝塞尔，控制点就是原拐点

用 A（圆弧）更「正圆」，用 Q 更省字符且视觉几乎一致。推荐 Q：无需算 sweep Flag，不会因浮点导致大弧/小弧翻转。

4.2 折线转平滑曲线（organic / 树图种）

  • Catmull–Rom → 三次贝塞尔转换（张力参数 0.5）：过所有点，实现 10 行；
  • 注意过冲：Catmull–Rom 会在急转处冲出折线包围盒，可能穿节点 → 用 centripetal 参数化（）可显著缓解；
  • 分层图的长边（dot 风格）：在 dummy 链构成的多边形通道内做分段贝塞尔拟合（Gansner 1993 附录），保证曲线不出通道。简化做法：用 dummy 点作为控制点、真实端点作为锚点的三次样条，再做一次「是否出通道」的校验，出界就退回折线。

4.3 曲线与箭头的切线

箭头方向必须用曲线在端点的切线（贝塞尔末端切线 = 最后控制点→端点），不能用「倒数第二个折点→端点」。用错在急转弯处很明显。

5箭头与装饰

5.1 缩进（inset）

箭头是实心多边形时，路径应在箭头底部结束，否则线条会从箭头尖部透出（半透明或浅色时可见）：

text 
path_end = clip_point - dir * arrow_length

每种箭头有自己的 length 与 inset（空心三角要全长，斜线箭头 inset = 0）。做成箭头描述表：

rust 
struct ArrowSpec { path: &'static str, length: f64, inset: f64, filled: bool }

5.2 常见箭头族（各行业需要，见 10 篇）

名称用途形状要点
triangle-filled普通有向边等腰，长:宽 ≈ 1:0.8
triangle-hollowUML 继承白色填充 + 描边，必须遮住线
diamond-hollow/filledUML 聚合/组合菱形，长度约 1.6× 三角
open（V 形）UML 依赖 / 序列图异步两条线段，不填充，inset=0
crow-footER 基数三线扇形 + 竖线/圆圈组合（0..1、1..N 等 4 种组合）
circle / dot状态机初始、SBGN需处理与端点 gap 的叠加
bar（T 形）UML 导航禁止、SBGN 抑制垂直于切线

5.3 边标签与装饰的锚点

落笔层只负责把上游给定的锚点参数变成坐标：

  • t ∈ [0,1] 沿路径弧长参数 → 需要累积弧长表（正交路径就是曼哈顿长度前缀和）；
  • side + offset：法向偏移（正交段的法向是明确的；曲线用切线旋转 90°）；
  • 不允许在落笔层「发现标签重叠就挪」 —— 那是 06 篇标签相的职责。

6退化情形清单（bug 的主要来源）

情形症状处理

⚠共同原则

落笔层遇到退化 → 兜底出图 + 诊断 warning，绝不 panic、绝不静默改变上游决策。退化是上游 bug 的信号，吞掉等于把 bug 藏进图里。

7数值稳定与确定性

7.1 浮点纪律

⚠数值稳定要点
  • 比较一律用带 eps 的比较器，eps 与坐标量级挂钩（相对 eps）：eps = 1e-6 * max(1, |a|, |b|)；
  • 不要用 f64 做等值判断驱动分支（如「是否共线」）而后续依赖该判断的传递性 —— 会出现 A≈B、B≈C 但 A≉C 的不一致；正解：在规范化阶段一次性 snap 到网格（如 0.01），之后用精确比较；
  • 累加长度用 Kahan 或直接用 f64（图坐标量级下够）。

7.2 量化与输出

  • 最终坐标量化到 2 位小数（或 0.5px 网格）后输出：SVG 体积减小 30%+，且让快照测试稳定；
  • 量化必须在所有几何计算完成后做一次，不要中途反复量化（会累积漂移）；
  • 量化后再跑一次重叠断言（罕见但确实可能因量化产生 1e-2 级重叠 → 上游间距应留 ≥ 量化步长的余量）。

7.3 确定性（AGENTS.md 红线）

  • 落笔层遍历顺序：按 edge.id / node.id 排序，不用 HashMap 迭代；
  • 不使用未 seed 的随机（自环方向、平行边偏移都要确定性规则）；
  • 同输入两次输出的 SVG 字符串应逐字节相同 —— 这可以作为一个测试。

8输出层（SVG / Canvas / 其它）

8.1 SVG 结构建议

xml 
<svg>
  <defs> markers, gradients, clipPaths, fonts </defs>
  <g class="groups">   <!-- 组框最底 -->
  <g class="edges">    <!-- 边在节点下：节点可遮住端点毛刺 -->
  <g class="nodes">
  <g class="labels">   <!-- 标签最上 -->
</svg>

z 序原则：组 < 边 < 节点 < 标签。把边放在节点下面是廉价的「端点看起来完美」技巧。

8.2 marker vs 内联多边形

  • <marker> + orient="auto"：省字符，但各渲染器对 markerUnits、refX 的处理有差异，且不继承 stroke 的 opacity；
  • 内联多边形：完全可控、可单独着色，代价是字符数。

建议：内联（图数量有限、可控性优先），或 marker + 每种颜色一个实例。

8.3 文本

  • 文本尺寸由 measure 相给出（06 篇），SVG 里用 x/y + dominant-baseline 定位；
  • 不要依赖渲染器的 text-anchor 做布局 —— 布局必须知道盒子，否则对齐与避让都不可靠；
  • 多行文本：每行一个 <tspan x=... dy=...>，行高由 measure 相给定；
  • 字体缺失导致的度量偏差：嵌入字体子集，或在输出中声明 fallback 链并接受轻微偏差（需在基准中固定字体）。

8.4 Canvas / WebGL 的差异

  • Canvas：无 marker，需自己画箭头；圆角用 arcTo；文本度量走 measureText（与布局期的度量必须同一实现，否则错位）；
  • WebGL/大图：边转三角带、文本转图集（SDF），此时圆角与虚线要在着色器里做 —— 建议大图模式降级为直线 + 无圆角（16 篇门控）。

9落笔层的测试策略

测什么怎么测
裁剪正确构造各形状 × 8 个方向，断言交点在边界上（）且在射线上
规范化幂等normalize(normalize(p)) == normalize(p)（表驱动，含所有退化情形）

无重叠输出后跑扫描线断言（节点-节点、标签-标签、边-节点）

建议加一个「几何不变量测试」套件：随机生成 500 个小图，对每个输出跑全部硬断言。这类测试的 bug 捕获率远高于手写 case。

10与本项目的对接

  • 落笔层属于 tautcore-render（几何展开 + SVG 序列化）；文本度量属于 tautcore-content（见 ADR-005）。
  • tautcore-engine 输出的应是规范化前的语义路径（拐点序列 + 端口引用 + 标签锚点参数），render 只做展开：这条边界让「引擎的快照测试」与「渲染的视觉测试」能分离，也让 §1 的写权表可执行。
  • 需要在 render 层落地的清单：形状裁剪表、箭头规格表、规范化流水线（§3.1 六步）、圆角降半径、自环/平行边展开、量化、z 序、诊断 warning 通道。
✓一句话收敛

落笔层的价值不在某一节算法多巧，而在严格遵守「零新决策」的写权纪律：只展开上游、只兜底退化、只量化输出。把这层做厚的引擎，产品观感会有质变。
