2分阶段路线图

每个阶段给出：交付物、验收标准（可自动检查）、预期难点。

M0 · 地基（无算法）

交付

  • LayoutGraph 纯几何模型（IndexMap 存储，稳定 ID）；
  • Writer 类型（LayerWriter / OrderWriter / CoordWriter / RouteWriter），每个自由度一个；
  • Stage 装饰器 trait + 流水线构建器；
  • 诊断输出结构（分相耗时、指标、门控命中、约束报告）；
  • VPSC 求解器（约 300–500 行，含 block merge/split、不可行检测）；
  • 度量模块：交叉数（Bentley–Ottmann）、重叠检测（扫描线）、弯折统计。

验收

  • VPSC 单元测试：随机约束集，断言 (a) 所有约束满足，(b) 目标值 ≤ 任意可行解（对小实例枚举验证）；
  • 度量模块对手工构造图给出已知正确值；
  • 同一输入连跑两次，LayoutGraph JSON 完全一致。

难点：Writer 改造要一次做对，后期补很痛。VPSC 的 split（负乘子）容易漏，漏了会在"约束冗余"场景给出次优解。

M1 · 分层主路径（能出图）

交付：P1 Greedy-FAS → P2 Network Simplex → 长边 dummy 化 → P3 median+transpose(+边权 1/2/8, best snapshot) → P4 Brandes–Köpf → P5 dummy 链还原为折线。Orientation Stage、自环 stage、平行边 stage、分量 stage + 行装箱、NormalizeCoordinates。

验收

  • 硬断言：节点无重叠、边不穿节点、确定性双跑一致；
  • 软指标基线：在 AT&T DAG 集（或自建 DAG 集）上记录 crossings / bends / edge_len / area / dummy 数；
  • 长边直线率 > 90%（BK 应该做到）；
  • 微型手工集的坐标 insta 快照。

难点

  1. Network Simplex 的 cut value 增量维护（lim/low 区间）容易写错 → 用"全量重算 cut value"版本先跑通，再优化；
  2. Brandes–Köpf 的 type-1 conflict 标记与 compaction，务必对照 2020 勘误；
  3. dummy 数爆炸：先加"长边链"抽象，别让 P3 每层独立处理。

M2 · 正交路由（决定观感）

交付：通道图构造（层间/层内空隙）→ A*(状态含方向) → 区间着色 track 分配 → VPSC nudging（端口对齐 + 最小段长 + 标签避让）→ 圆角/箭头装饰。走廊 demand 回写层间距。

验收

  • 硬断言：无边穿节点、无两条边完全重合、圆角段长足够；
  • 指标：总弯折数、<30° 交叉占比（正交图应≈0）、总曼哈顿长度；
  • 门控：边数超阈值时降级并在诊断中报告。
⚠M2 实现难点
  1. A* 状态忘记含方向 → 弯折惩罚失效（最常见 bug）；
  2. 走廊 demand 回写必须是"参数回写"而非"路由阶段挪节点"，否则打破写权；
  3. 反向对边重合：根因在端口分配而非路由（见 03 篇 §7 表）。

M3 · 端口与标签（专业度分水岭）

交付：端口五档模型落 IR + DSL；FREE 端口的"按对侧 x 排序 + 均匀分布"；端口数回写节点最小尺寸；FIXED_ORDER 的端口 dummy 参与定序；label dummy（边标签）+ 节点标签计入有效包围盒 + 末尾 greedy labeling。文本测量（真实字体度量 + CJK 断行）。

验收

  • 端口序与邻居序一致性断言（不产生"凭空交叉"）；
  • 标签重叠面积 = 0；标签压边长度指标；
  • 中英混排标签的尺寸跨平台一致（WASM 与原生一致）。
⚠M3 难点：文本测量常被低估

文本测量的工作量常被低估（字体加载、kerning、CJK 断行、WASM 字体分发）。建议尽早做，因为它是节点尺寸的输入，影响一切。

M4 · 分组与泳道（结构表达力）

交付：包含树模型；组边界 dummy + 受约束排序（PAV 投影）；组框作为 VPSC 变量（含 padding、标题高度、组间距）；跨组边的边界穿越点；PartitionGrid（行=层区间、列=层内分段）；组折叠/展开 + 布局缓存。

验收

  • 约束满足断言：组内节点确在组框内、组框互不重叠、泳道内节点确在列区间内、层跨泳道全局一致；
  • 嵌套 3 层以上的 case 无重叠；
  • 折叠→展开→折叠的布局稳定（位移 ≈ 0）。

难点：组与泳道要复用同一套"层内连续块"机制，否则两套逻辑会互相冲突。约束冲突的优先级与降级必须显式（08 篇 §4）。

M5 · 树 / organic / 其它图种

交付：Buchheim 树 + NodePlacer 策略集（centered/bus/double-line/dendrogram）；TreeReductionStage；Radial（角需求自底向上传播）；Balloon；PivotMDS + SGD stress + PRISM + 装箱；circular（谱序 + BCC 树）。

验收：各图种硬断言 + 各自的专属指标（树：宽度/对称；organic：stress 值单调下降、消重叠后重叠=0）。

M6 · 交互与稳定性

交付：from-sketch（由当前坐标反推层与序）；PartialLayout（fixed/partial）；增量路由（依赖索引 + hysteresis）；FixNode 锚定；稳定性指标（位移、正交序违反率、k-NN 保持）。

验收：拖一个节点后，未受影响区域位移 = 0；正交序违反率低于阈值；重路由只涉及受影响边（可断言重路由边数）。

3贯穿全程的三条纪律（对应 AGENTS.md）

⚠三条硬纪律（与 AGENTS.md 一致）
  1. 每个自由度一个写者：用 Writer 类型强制。新增机制前先回答"这个自由度的写者是谁"。
  2. 下游只展开、不推翻：唯一允许的反向影响是参数回写（走廊 demand → 层间距；端口数 → 节点尺寸；标签尺寸 → 间距），且必须发生在上游相执行之前。
  3. 不按图种分支：图种差异全部走 profile → 参数。看到 if diagram_type == 就是设计出问题了。

自检清单（每次修 bug 前问自己）：

  • 这个症状是"上游决策错"还是"下游落笔错"？
  • 我的修法是"加特判"还是"把自由度上提"？
  • 这个修法在别的图种上会不会反噬（基准分图种报告能否证明）？

5投入产出比排序（如果资源有限）

按"每单位工作量的观感/能力提升"排序：

  1. P3 的边权 1/2/8 + best snapshot（几十行）——立刻让长边变直、图变整齐。
  2. Orientation Stage（一百多行）——一次拿到四个方向。
  3. VPSC（几百行）——服务五处需求（间距、消重叠、nudging、紧致化、组框）。
  4. 端口按对侧序排序分配（几十行）——消除大量"凭空交叉"。
  5. label dummy 预留标签空间（几十行）——彻底解决标签重叠。
  6. 走廊 demand 回写层间距（上百行）——解决"边挤在一起/穿节点"。
  7. 层次边捆绑（约五十行）——大边数图的可读性质变。
  8. substructure detection（星/链/环）（数百行）——organic 图种观感质变。
  9. from-sketch（上百行）——交互场景的用户价值极高。
  10. 分图种基准报告（脚本层）——让上述每一项的收益可证明。
✓建议顺序

先做第 10 项（度量），再按 1–6 依次做，每做一项跑一次基准并记录。这样每一步都有证据，也不会互相掩盖。
