06 · 标签放置（Label Placement）

对应 yFiles GenericLabeling / LabelingBase / 各布局内置的 LabelLayoutData（PreferredPlacement）

核心算法 主线论文：Formann–Wagner 1991（点标注 NP 难 + 2-近似）、Wagner–Wolff 1997（实用启发式）、Kakoulis–Tollis 1997/2001/2003（图标注通用框架，本篇主干）、Klau–Mutzel 2003（ILP 精确解）、Christensen–Marks–Shieber 1995（模拟退火，实证对比） ~176 行 · 5.8k 字

标签是“图看不看得懂”的核心，却常被当成渲染层的事后补丁。正确做法：标签需求参与布局，标签位置由独立求解相决定。

1问题模型

1.1 三类标签

类型自由度候选空间
节点标签内部（居中/上/下…）或外部（8 方位 + 自由）离散 8–9 位；或连续（节点周边）
边标签沿边的位置 + 侧偏（左/右/居中）+ 距离连续 slider 或离散候选点
端口/端点标签靠近某端点的小范围离散小集合

1.2 硬/软约束

  • 硬：标签矩形之间不重叠；标签不压节点；标签不压边（可放宽为“惩罚”）。
  • 软：标签靠近其宿主（距离最小）；符合偏好方位（PreferredPlacement）；同类标签风格一致（都在边上方）。

1.3 复杂度

  • 点特征标注（4-position model）判定可行性即 NP 完全（Formann–Wagner 1991）；
  • 最大化“能放下的标签数”是 NP 难，最大化“统一缩放因子”有 2-近似且 不可近似；
  • 边标注同样 NP 难（Kakoulis–Tollis）。
▸结论

⇒ 一律启发式 + 可选 ILP 精确小实例。

2候选位置生成（Candidate Generation）

好的候选集比好的求解器更重要。

2.1 节点标签

  • 离散 8/9 位：N, NE, E, SE, S, SW, W, NW, Center（各带 offset）。工业默认。
  • 加密候选：每边中点 + 两端 → 12–16 位，质量提升明显，成本线性。
  • 连续：沿节点边界滑动（slider model），求解转为区间问题。

2.2 边标签（关键）

  • 沿边采样：把边的折线按弧长离散成 个位置（=10–30），每个位置 × {左, 右, 中} × {距离档} → 候选。
  • 优先选“长直段的中点”：短段/弯折附近的标签极难读。给候选打分：score = segLen 奖励 - 距端点惩罚 - 距理想位置(中点)惩罚。
  • 正交路由的特例：标签占位作为 nudging 的约束（03 篇 §4.2），使段之间自然留出标签宽度。
ℹ分层布局的特例：label dummy 节点（重要技巧）

把边标签实现为尺寸 = 标签尺寸的 dummy 节点，插入长边的中间层。这样：

  • 标签空间由 P4 坐标相自动预留（不会重叠）；
  • 标签自动落在边上、水平居中；
  • 层间距自动加大以容纳标签高度。

这是 ELK / yFiles 分层布局的实际做法，远优于事后避让。代价：需要边跨度 ≥2（不够时强制拉开一层）。

2.3 候选的合法性预筛

每个候选先做碰撞检查（与节点、与其它已知固定物）→ 打上 hard_invalid 标记，减小搜索空间。用 R-tree / 网格索引做 查询。

3求解算法

3.1 Kakoulis–Tollis 的通用框架（推荐主线）

把标签放置归约为二分图匹配 / 冲突图上的独立集：

pseudo 
1. 生成候选：每个标签 l 有候选集 C(l)
2. 建冲突图 H：顶点 = (l, c) 候选对；
   边 = 两候选几何冲突（重叠）或属于同一标签（互斥）
3. 求最大权独立集 / 或者：
   3'. 若冲突图退化为二分图（候选按"槽位"划分），用最大二分匹配 O(E√V) 精确求解
4. 剩余未放置标签：放到"最少冲突"位置并标记 overlap（不丢失信息）

Kakoulis–Tollis 的贡献在于证明了：对相当一类候选构造（每个标签的候选位于互不相交的“区域”），问题可以退化成匹配问题从而精确求解。工程上直接用“贪心 + 局部搜索”逼近即可。

3.2 贪心 + 局部搜索（工业默认，先实现这个）

rust 
fn place_labels(labels: &[Label]) -> Placement {
    // 1. 按"难度"降序处理：候选数少的、标签大的、宿主拥挤的先放
    let mut order = labels.to_vec();
    order.sort_by_key(|l| (l.candidates.len(), Reverse(l.area), l.id)); // 稳定
    let mut idx = SpatialIndex::new();
    let mut result = Placement::new();
    for l in &order {
        let best = l.candidates.iter()
            .map(|c| (cost(c, &idx), c))
            .min_by(|a,b| a.0.partial_cmp(&b.0).unwrap().then(a.1.id.cmp(&b.1.id)))
            .unwrap().1;
        idx.insert(best.rect); result.set(l, best);
    }
    // 2. 局部改进：对有冲突的标签尝试换位（含"交换两个标签的位置"）
    for _ in 0..MAX_ROUNDS { if !improve_conflicted(&mut result, &mut idx) { break } }
    result
}

fn cost(c: &Candidate, idx: &SpatialIndex) -> f64 {
      W_OVERLAP_LABEL * idx.overlap_area_with_labels(c.rect)
    + W_OVERLAP_NODE  * overlap_area_with_nodes(c.rect)
    + W_OVERLAP_EDGE  * crossed_edge_length(c.rect)
    + W_PREF          * preference_penalty(c)      // 偏离 PreferredPlacement
    + W_DIST          * dist_to_host(c)
}

关键点：

  • 处理序决定质量：候选少者先放（最受限优先），这是约束满足的标准启发式（most-constrained-variable）。
  • 代价用“重叠面积”而非布尔，梯度更平滑，局部搜索有方向可走。
⚠产品硬要求：不能丢标签

必须允许“放不下就重叠但标记 overlap”，不能丢标签。少一个标签比标签重叠严重得多——这是标签放置与“求最优解”的工程分界线。

3.3 模拟退火（Christensen–Marks–Shieber 1995）

实证研究表明，对点标注 SA 明显优于各种贪心（论文对比了 5 种方法）。

  • 状态 = 每个标签的候选选择；邻域 = 随机换一个标签的位置；能量 = 冲突数（含加权）。
  • 降温：，每温度 次尝试。
  • 成本可控（每次移动只需局部重算冲突），质量最好的启发式之一。若贪心不够用，直接上 SA 而不是继续调贪心。

3.4 ILP 精确（Klau–Mutzel 2003）

变量 ，约束 （或 ≤1 允许丢），冲突对 。

  • 加“最大化统一缩放因子 ”的目标可做“字号自适应”。
  • 分支切割在几百标签内可解。适合离线高质量导出。

3.5 Slider model（连续位置）

Van Kreveld–Strijk–Wolff 1999：标签可沿特征边界连续滑动。

  • 1D slider（只沿一个方向滑）有 的可行性判定与 2-近似；
  • 实际对边标签特别合适（沿边滑动）。实现：把每条边的可用区间做区间调度（与 03 篇的 track 分配同构）。

4与布局的耦合（架构决策）

三种耦合程度，从弱到强：

模式做法优缺点
A. 事后标注布局完成 → 独立 labeling 相实现简单；空间可能根本不够 → 必有重叠
B. 空间预留布局阶段把标签尺寸计入节点/边的间距需求推荐。标签当 dummy 节点或计入 ；之后再精细放置
C. 联合优化标签位置作为变量进入布局的约束系统（VPSC/QP）质量最好，复杂度与耦合度高

yFiles 的实际做法接近 B + A：布局算法接受 LabelLayoutData（含 preferred placement），内部为标签预留空间，最后可再跑 GenericLabeling 精修未固定的标签。

✓tautcore 建议：直接做 B
  1. 测量相（measure）计算所有标签尺寸（含字体度量、换行）；
  2. 分层布局：边标签 → label dummy 节点；节点外部标签 → 计入节点的“有效包围盒”；
  3. 正交路由：标签矩形作为 nudging 的避让约束；
  4. 末尾跑一次 greedy labeling 处理剩余自由标签（如组标题、端口标签）。

5文本测量与排版（容易低估的工程量）

标签放置的前置条件是准确的文本尺寸：

  • 字体度量：需要真实字体的 advance width；用 ttf-parser/rustybuzz/fontdue 读 hmtx + kerning。WASM 环境下不能依赖系统字体 → 必须内嵌或按需加载字体。
  • CJK 与混排：CJK 全宽、无空格断行；换行需按 UAX#14 line breaking（至少实现“CJK 任意处可断 + 拉丁按空格/连字符断”）。
  • 换行与自动尺寸：给定最大宽度做贪心换行（或 Knuth–Plass 最优换行，视觉更佳但需要更多工作）；节点尺寸由文本尺寸反推 ⇒ 这就是“content-based sizing 作为独立 measure 相”的必要性（仓库已有相关记录）。
  • 缩放：标签字号随缩放变化时，若“标签尺寸影响布局”，缩放会导致重排 → 约定布局用固定基准字号，视觉缩放不重排。
⚠测量必须确定性

同一文本 + 字体 + 字号 → 完全相同的尺寸，且跨平台一致（不要走系统渲染栈）。否则同一布局在不同环境输出不同结果，回归测试无法断言。

6质量检查与回归

自动可断言的指标：

  1. 标签–标签重叠面积总和（目标 0）；
  2. 标签–节点重叠面积（目标 0）；
  3. 标签压边的总长度（目标小）；
  4. 标签到宿主的平均距离（越小越好）；
  5. 偏好方位满足率；
  6. 未放置/强制重叠标签数（目标 0）。

把这 6 项做成基准脚本输出，即可在算法改动时定量比较（见 11 篇）。

7常见失败模式

症状根因修法
边标签叠在节点上事后标注 + 空间未预留改用 label dummy（模式 B）
长边标签飘到很远候选只在边中点，中点恰在弯折处候选打分加“长直段优先”
同类边标签一会儿上一会儿下无一致性项加“与同批标签同侧”的软约束/后处理统一
标签在缩放时抖动布局依赖当前视觉字号布局固定基准字号
中文标签测不准导致节点忽大忽小用了近似字宽表上真实字体度量
两次运行标签位置不同候选遍历序/平局无 tie-break全链稳定排序
