# 05 · 树布局与径向 / 圆形 / 泡泡布局

> 对应 yFiles `TreeLayout`（多种 NodePlacer）/ `RadialLayout` / `BalloonLayout` / `CircularLayout`，
> Graphviz `twopi` / `circo`，D3 `tree`/`cluster`/`pack`/`partition`。
> 主线论文：Reingold–Tilford 1981、Walker 1990、Buchheim–Jünger–Leipert 2002（线性时间修正）、
> Eades 1992（radial/balloon）、Six–Tollis 1999（circular）、Wetherell–Shannon 1979。

树布局看似简单，实则是**最容易写出 $O(n^2)$ 或产生不对称丑图**的地方。本篇给出正确实现的全部细节。

---

## 1. 分层树布局（Layered / Reingold–Tilford）

### 1.1 美学要求（RT 论文原文的 aesthetic rules）
1. 同深度节点在同一层（y 相同）。
2. 父节点在子节点的**水平中心**。
3. 树的镜像 = 布局的镜像（**对称性**）。
4. 同构子树布局形状相同，与在树中的位置无关（**子树一致性**）。
5. 尽量窄。

规则 3、4 是 RT 优于 Wetherell–Shannon（1979）的关键；WS 会因扫描顺序产生不对称结果。

### 1.2 核心机制：轮廓（contour）+ 相对偏移
```
后序遍历（bottom-up）:
  1. 递归布局每个子树，得到各自的"左右轮廓"（每层的最左/最右 x）
  2. 从左到右合并子树：把新子树紧贴已合并部分的右轮廓
     （逐层比较，取最大所需推移量 shift）
  3. 父节点 x = 首末子节点 x 的中点
  4. 记录本节点的 mod（子树整体偏移），最终 preorder 累加得绝对 x
```
- **轮廓串成"线程（thread）"**：叶子的轮廓不连续时，用 `thread` 指针把下一层的轮廓节点串起来，使"沿轮廓走"是 $O(\text{contour length})$ 而不是重新遍历子树。
- 朴素实现（每次合并重新算轮廓）→ $O(n^2)$。**必须用 thread。**

### 1.3 Walker 1990 与 Buchheim et al. 2002（**正确的线性时间版**）
Walker 把 RT 扩展到**任意度树**（不只二叉），但其论文的原始算法实际是 $O(n^2)$（Buchheim 指出并修正）。

Buchheim–Jünger–Leipert 的 $O(n)$ 算法要点（现代实现的依据，D3 `d3.tree` 即此）：
```rust
fn first_walk(v: &mut Node) {          // 后序
    if v.is_leaf() {
        v.prelim = v.left_sibling().map_or(0.0, |w| w.prelim + distance(w, v));
    } else {
        let mut default_ancestor = v.first_child();
        for c in v.children_mut() {
            first_walk(c);
            apportion(c, &mut default_ancestor);   // ← 关键
        }
        execute_shifts(v);          // 把累积 shift/change 分摊给各子节点
        let mid = (v.first_child().prelim + v.last_child().prelim) / 2.0;
        v.prelim = match v.left_sibling() {
            Some(w) => { v.mod_ = (w.prelim + distance(w, v)) - mid;
                         w.prelim + distance(w, v) }
            None => mid,
        };
    }
}
fn second_walk(v: &Node, m: f64) {      // 先序，累加 mod
    v.x = v.prelim + m;
    for c in v.children() { second_walk(c, m + v.mod_); }
}
```
**`apportion` 的三个技巧（易错点，逐条说明）：**
1. **thread**：`v.thread` 指向"下一层轮廓上的节点"，使沿左右轮廓下行不需要遍历整棵子树。
2. **ancestor / default_ancestor**：发现冲突需推移时，要知道"推的是哪个上层子树"，用 `ancestor` 指针在 $O(1)$ 摊还内找到（不是向上遍历，那会退化）。
3. **shift / change 的分摊**：多个子树间的推移量不能只加到最后一个，要**在所有中间子树间线性分摊**（否则间距不均匀，图会歪）。`execute_shifts` 用两个累加器 `shift` / `change` 一遍逆序扫描完成。

复杂度 $O(n)$，输出满足 RT 全部 5 条美学。**建议直接实现这一版，不要自己"简化"。**

### 1.4 变宽节点与非均匀间距
`distance(w, v) = w.width/2 + v.width/2 + siblingGap`。RT/Buchheim 天然支持（distance 是函数参数）。
层高：`y(depth+1) = y(depth) + maxHeight(depth) + layerGap`；也可**逐子树紧凑**（每个子树自己的层高，产生"参差"效果，yFiles 有此选项）。

### 1.5 NodePlacer 风格谱（yFiles TreeLayout 的产品面）
| 风格 | 描述 | 适用 |
|---|---|---|
| **Default / centered** | 子节点水平排开，父居中 | 组织架构图 |
| **Left-aligned / bus** | 子节点竖排，父连一条"总线"下挂 | 文件树、思维导图侧枝 |
| **Double-line** | 子节点分两行交错排 | 宽扇出的树，省宽度 |
| **AR (aspect ratio)** | 按目标长宽比递归分配子树方向 | 需要填满画布 |
| **Dendrogram** | 所有叶子在同一层（末层对齐） | 聚类树、系统树 |
| **Compact** | 允许子树"插进"兄弟的空隙 | 空间优先，牺牲子树一致性 |
| **Assistant** | 某些子节点标记为"助理"，放在父节点侧面 | 组织架构图的助理岗 |

**Compact tree** 值得单独说：RT 的轮廓合并本身已是"轮廓级紧凑"（不是包围盒级）。真正"更紧"的是允许子树**上下交错插入**，面积可再降 20–40%；yFiles `CompactNodePlacer` 的做法是对每个子树尝试若干种 aspect 配置 + 记忆化的有界搜索。

### 1.6 非树图怎么办
- 求生成树（BFS/DFS/最大权），非树边事后路由（可能产生交叉）。
- 或用分层布局（01 篇）——树是 DAG 的特例，Sugiyama 在树上也能给好结果，但通常更宽。
- yFiles `TreeReductionStage`：图→树归约 → 树布局 → 非树边用独立 router 补上。**这是很好的架构模式：把"图→树"的归约做成 stage，树算法保持纯粹。**

## 2. 径向布局（Radial）

节点按深度放在同心圆上，角度按子树大小分配。

### 2.1 基础算法（Eades 1992 的 radial drawing）
```
1. BFS 分层，depth(v) → 半径 r_d（等差或按需增长）
2. 角度分配（先序）：
   根分配 [0, 2π)；父 v 有区间 [a,b)，按子树"叶子数"或"角宽需求"比例切分给子节点
   子节点 c 的角度 = 其区间中点
3. x = r*cos(θ), y = r*sin(θ)
```
### 2.2 必须处理的三个问题
1. **半径必须够大**：第 d 层节点在其角扇区内的弧长须 ≥ 节点宽度 ⇒ 逐层求 $r_d = \max_i \frac{w_i}{\Delta\theta_i}$，再与 $r_{d-1} + layerGap$ 取最大。**漏了这条必重叠。**
2. **子树角区间不能溢出**：自底向上先算每个子树的"最小角宽需求" $\text{demand}(v)=\max(\text{own}(v), \sum_c \text{demand}(c))$，再自顶向下按 demand 比例分配。这就是"上游给下游留位"的树版本。
3. **0/2π 边界**：角度统一到 $[0,2\pi)$，比较时取模；输出保持连续以免边绕远。

### 2.3 扇形/局部径向
只用部分角度（如 $[-60°,+60°]$）→ "扇形树"，适合 focus+context 的从焦点展开。

### 2.4 边的画法
- 直线：简单但穿越内圈。
- **圆弧 + 径向段**：先沿同心圆弧走到目标角度，再径向走——正交在极坐标下的类比，非常整洁，推荐。
- 层次边捆绑（见 §4.3）。

## 3. Balloon / 泡泡布局

每个子树占据一个**圆盘**，父节点在中心，子树圆盘绕父排布。

```rust
fn balloon(v: &Node) -> f64 {                 // 返回本子树外接圆半径
    let child_radii: Vec<f64> = v.children().map(balloon).collect();
    // 把 k 个半径 r_i 的圆排在半径 R 的圆周上不重叠：
    // 每个圆占圆心角 ≈ 2*asin(r_i / R)，要求 Σ角 ≤ 2π - reserved
    let R = binary_search_min(|R| {
        child_radii.iter().map(|r| 2.0 * (r / R).asin()).sum::<f64>() <= TAU - reserved
    });
    assign_angles_proportional(&child_radii, R);
    R + child_radii.iter().cloned().fold(0.0, f64::max)
}
```
- **二分求 R** 是关键：asin 之和无解析解。二分 30 次足够。
- 根子树可用整圆；非根子树要为"连向父的边"预留角度缺口 `reserved`，否则子树挡住父边。
- 变体：按子树大小排序放置影响观感；固定"从父边方向开始逆时针"保证确定性。
- 适合：文件系统、分类体系、网络自治域。

## 4. 圆形布局（Circular）

### 4.1 单圈的圈序
圆上交叉最小化 NP 难（与 book embedding 相关）。启发式：
- **Six–Tollis 1999**：基于双连通分量与边长最小化的启发式圈序。
- **DFS/BFS 序**：简单可用，相连节点排近。
- **谱序**：拉普拉斯 Fiedler 向量排序（最小化 $\sum(\text{pos}_i-\text{pos}_j)^2$ 的连续松弛）——**便宜且质量好，推荐首选**。
- 边画成朝内圆弧（弦或往圆心弯的贝塞尔），弯曲度按弦长自适应。

### 4.2 分层圆形（yFiles CircularLayout 的实际形态）
1. 求**双连通分量（BCC）**；
2. 每个 BCC 内部排成一个圆（用上面的圈序）；
3. BCC 之间构成 block-cut tree → 用**树/balloon 布局**排列这些圆。
既体现环状结构，又不把所有点挤到一个巨圆上。

### 4.3 Edge bundling（层次边捆绑）
Holten 2006 *Hierarchical Edge Bundles*：
- 边 $(u,v)$ 的控制点 = 层次树上 u→LCA→v 路径上的节点位置；
- B-spline 平滑 + **bundling strength $\beta$**（0 = 直线，1 = 完全贴树）在控制点与直线间插值。
- 上千条边的圆形/径向图唯一可读方案；实现约 50 行，**性价比之王**。
- 无层次结构时用 **Force-Directed Edge Bundling**（Holten–van Wijk 2009）：边离散成控制点，相似边（方向 + 邻近 + 可见性兼容）间施加吸引力迭代。$O(E^2)$，需空间索引加速。

## 5. 其它层次可视化（非节点链接）

| 方法 | 出处 | 算法要点 | 适用 |
|---|---|---|---|
| **Treemap** | Shneiderman 1992 / Bruls **Squarified** 2000 | 递归切矩形；squarified 贪心维持长宽比≈1 | 面积编码大小 |
| **Sunburst / 极坐标 icicle** | Stasko 2000 | partition 布局的极坐标版 | 层次占比 |
| **Circle packing** | Wang et al. 2006 / D3 `pack` | 递归 front-chain 装圆 + 最小外接圆（Welzl） | 层次 + 大小 |
| **Icicle / Partition** | Kruskal–Landwehr 1983 | 矩形按子树大小切分 | 紧凑层次 |

Squarified treemap 核心约 20 行，值得内置作为"另一种视图"。

## 6. 复杂度总表与实现优先级

| 布局 | 复杂度 | 实现难度 | 建议优先级 |
|---|---|---|---|
| RT / Buchheim tree | $O(n)$ | 中（apportion 易错） | **高**（组织图/思维导图必备） |
| Radial | $O(n)$ | 低-中（角需求传播） | 高 |
| Balloon | $O(n\log)$（二分） | 中 | 中 |
| Circular（谱序 + BCC 树） | $O(V+E)$ + 特征向量 | 中 | 中 |
| Squarified treemap | $O(n\log n)$ | 低 | 低（视图型） |
| Edge bundling（层次） | $O(E\cdot k)$ | 低 | 中（大边数时高） |

## 7. tautcore 落地建议

1. **树布局照抄 Buchheim–Jünger–Leipert**，包括 thread / ancestor / shift-change 三件套。别简化成"每次算轮廓"，深树会明显卡。
2. **`TreeReductionStage` 模式**：把"图→生成树 + 非树边"做成独立 stage，非树边交给 03 篇的 router。
3. **Radial 的角度需求自底向上传播**必须实现，否则深层必重叠——"上游留位"纪律在极坐标下的实例。
4. **NodePlacer 抽象**（centered / bus / double-line / dendrogram）是低成本高收益的产品扩展点。
5. 层次边捆绑作为**渲染层可选装饰**（不改路由结果），先做 β 插值版本。
