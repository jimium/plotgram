# 17 · 动画、过渡与视图交互

> 布局算完不是终点。**"图怎么变过去"和"图长什么样"同等重要** —— 用户在动画中理解结构变化，
> 在视口交互中导航大图。本篇覆盖：layout morphing、边形变、视口与焦点技术、命中测试、
> 以及"增量布局 + 动画"的稳定性要求。
>
> 主线文献：Friedrich–Eades 2002（*Graph Drawing in Motion*）、Friedrich–Houle 2002（*Graph Drawing in Motion II*）、
> Misue et al. 1995（mental map）、Bederson–Boltman 1999（动画对空间记忆的作用）、
> Heer–Robertson 2007（*Animated Transitions in Statistical Data Graphics*）、
> Archambault–Purchase 2013（*Mental map preservation helps user orientation in dynamic graphs*）、
> Lamping–Rao–Pirolli 1995（双曲浏览器）、Furnas 1986（fisheye）、Sarkar–Brown 1992（graphical fisheye）。

---

## 1. 为什么要动画（有实证依据的部分）

- **Bederson–Boltman 1999**：动画过渡显著提升用户对空间布局的记忆，即使动画只有 ~1s。
- **Heer–Robertson 2007**：分阶段（staged）过渡优于同时（simultaneous）过渡 —— 把"移动"和"出现/消失"分开做，用户跟得上。
- **Archambault–Purchase 2013**：动态图中保持 mental map 有助于定位任务；但如果保持 mental map 导致布局质量明显下降，收益会被抵消。
  **结论：先保证新布局质量可接受，再在此约束下最大化稳定性**（而不是反过来）。
- **Friedrich–Eades 2002**：给出了 layout morphing 的工程框架 —— 分阶段、聚类移动、避免路径交叉。

**工程含义**：动画不是"锦上添花"，是"让增量布局可用"的必要条件。没有动画，节点跳变会让用户彻底失去上下文。

## 2. 节点的过渡

### 2.1 最简：线性插值 + 缓动
```
p(t) = p_old + (p_new - p_old) * ease(t),  t ∈ [0,1]
```
缓动建议 `cubic-in-out`（对称、无过冲）。**不要用带弹性/回弹的缓动**：图元素众多时回弹会造成视觉噪音。
时长：300–600ms；节点数多时略长（但不超过 1s，超过用户会失去耐心）。

### 2.2 分阶段过渡（推荐）
```
Stage 1 (0–30%):   删除的节点/边淡出 + 收缩
Stage 2 (25–75%):  保留的节点移动（可重叠 Stage 1/3 少量）
Stage 3 (70–100%): 新增的节点/边淡入 + 展开
```
理由：同时做三件事，用户无法追踪任何一件。分阶段后"什么消失了、什么移动了、什么出现了"清晰可读。
额外好处：Stage 2 中间不会出现"新节点从 (0,0) 飞入"这种伪运动。

### 2.3 聚类移动（Friedrich–Eades）
当一大片节点整体平移时，逐个插值会让中间帧显得混乱。改进：
- 检测"位移向量近似相同"的节点组（k-means on displacement 或简单的网格量化）；
- 组内同步移动（同一时间曲线），组间可错开出发时间（stagger 30–80ms）。
效果：观感从"粒子云"变成"板块移动"，可理解性明显提升。

### 2.4 避免中间帧穿越
线性插值可能让节点在中途穿过其它节点甚至穿出画布。三种缓解：
- **两阶段路径**（先散开再聚合）：对交换位置的节点对，让一个走弧线；
- **按需绕行**：只对"中间帧重叠面积超阈值"的节点做弧线插值（检测成本 = 采样 3–5 个中间帧 + 扫描线）；
- **接受它**：多数场景下短时重叠不影响理解 —— 建议先接受，只在 demo 级场景做优化。

## 3. 边的过渡（比节点难）

难点：边的**拐点数在过渡前后不同**（3 拐点 → 5 拐点）。

### 3.1 拐点对齐（path resampling）
```
1. 把 old_path 与 new_path 都按弧长重采样为 N 个点（N = max(len_old, len_new) 或固定 16）
2. 逐点线性插值
3. 中间帧不做正交约束（允许斜线），末帧回到严格正交
```
优点：实现简单、无退化。缺点：中间帧不正交（视觉上"边在扭动"）—— 多数用户接受，因为很快。

### 3.2 保持正交的形变（更贵）
- 找 old/new 路径的**最长公共正交结构**（共有的走廊序列），只对差异段做插值；
- 拐点数变化用"零长段插入"表示：在 old_path 中插入长度 0 的段，使拐点数与 new 相同，再逐点插值。
  这样中间帧始终正交。**推荐做法**，实现约 100 行。

### 3.3 简化策略（性价比最高）
边数多时：
- 过渡期间**边淡出，只动画节点，末帧边淡入**；
- 或过渡期间边退化为直线（起终点插值），末帧切回正交路径。
用户注意力在节点上，这个偷懒几乎不被察觉，且省掉全部边形变逻辑。**建议作为默认，正交形变作为高质量模式。**

### 3.4 标签
标签跟随其宿主（节点/边锚点），不单独做动画。文字内容变化时用交叉淡入淡出，不要做字符级形变。

## 4. 稳定性要求（动画的前提）

动画只能"演示"变化，不能"掩盖"抖动。如果新布局与旧布局无关，动画反而放大混乱。所以：

### 4.1 必须成立的性质（见 07 篇）
1. **正交序保持**：旧布局中 $a$ 在 $b$ 左边，新布局尽量仍在左边；
2. **邻近保持**：相邻节点仍相邻；
3. **拓扑保持**：不引入新的"跨越"关系。

### 4.2 实现路径（按代价排序）
| 手段 | 代价 | 效果 |
|---|---|---|
| **from-sketch**：由旧坐标反推层与层内序作为 P2/P3 初值 | 低（约 100 行） | 效果最好的单一手段 |
| **固定未受影响区域**：只对受影响子图重算，其余 pin 住 | 中 | 位移=0 的保证 |
| **旧坐标作为 P4 的期望位置**（VPSC 的 $x^{des}$） | 低 | 坐标层面平滑 |
| **约束式稳定**：把"正交序"加成 VPSC 分隔约束 | 中 | 硬保证，但可能牺牲质量 |
| **增量路由 + hysteresis**：只重路由受影响边，且旧路径有"粘性"加成 | 中 | 避免边全体跳变 |

### 4.3 hysteresis 的具体做法
在 A\* 的代价里给"旧路径经过的边"一个折扣：
```
cost(e) = base_cost(e) * (if old_path.contains(e) { 1.0 - HYST } else { 1.0 })
```
`HYST ≈ 0.15–0.3`。效果：小扰动时路径完全不变，大扰动时仍会重选。
**注意**：折扣会破坏 A\* 启发式的可采纳性（$h$ 不再是下界）→ 要么同步缩放 $h$，要么接受次优（实践中可接受）。

### 4.4 度量（进基准）
- 平均归一化位移 $\frac{1}{n}\sum \|p_i^{new}-p_i^{old}\| / \text{diag}$；
- 正交序违反率（旧 x 序对 vs 新 x 序对的逆序对比例）；
- k-NN 保持率（Jaccard）；
- **重路由边数 / 总边数**（增量路由的直接指标）。

## 5. 视口与导航

### 5.1 基础
- **fit-to-view**：包围盒 + padding → scale = min(vw/bw, vh/bh)，clamp 到 [minZoom, maxZoom]；
- **zoom-to-cursor**：缩放时保持鼠标下的图坐标不变：
  ```
  world = screen_to_world(cursor)
  scale *= factor
  translate = cursor - world * scale
  ```
  这条公式写错是最常见的交互 bug（表现为"缩放时图会漂"）。
- **平滑 zoom/pan**：对 `log(scale)` 做插值（不是 scale 本身），否则感觉不匀速。

### 5.2 语义缩放（LOD）
大图必须做，否则缩小后是一团糊：
| 缩放级别 | 显示 |
|---|---|
| < 0.3 | 只画节点色块，无文字、无箭头、边为细直线（或聚合边） |
| 0.3–0.7 | 节点 + 简化标签（截断）+ 边无圆角 |
| > 0.7 | 全细节 |
实现要点：**LOD 阈值切换要有 hysteresis**（0.28 进 / 0.32 出），否则在阈值附近抖动会闪烁。

### 5.3 焦点 + 上下文技术
| 技术 | 出处 | 适用 |
|---|---|---|
| **Fisheye**（图形鱼眼） | Sarkar–Brown 1992 | 局部放大 + 保持全局；对节点链接图效果好，但正交边会被扭曲成曲线 → **与正交风格冲突，慎用** |
| **双曲浏览器** | Lamping et al. 1995 | 大树导航；数学优雅但用户容易迷失 |
| **Degree-of-Interest 图** | van Ham–Perer 2009 | 按兴趣度剪裁子图 —— **更适合正交/分层风格**（不扭曲几何，只增删元素） |
| **概览 + 细节**（minimap） | 通用 | 实现最简、效果稳定。**首选** |
| **邻居高亮 / 路径高亮** | 通用 | 成本极低、用户价值极高。**必做** |
| **折叠 / 展开组** | — | 大图的主力手段（见 08 篇），配合动画 |

**建议优先级**：邻居高亮 > minimap > 折叠展开 > LOD > DOI 剪裁 > fisheye/双曲（后两者基本不做）。

## 6. 命中测试与拾取

| 元素 | 方法 |
|---|---|
| 节点 | 空间索引（网格哈希/R-tree）查询点所在矩形 → 再做形状精确测试（菱形/椭圆需要） |
| 边 | 点到折线段距离 < tolerance（≈ 5px / scale）；先用段的包围盒过滤 |
| 标签 | 矩形测试；标签在最上层，优先命中 |
| 组框 | 只命中**标题栏与边框带**，不命中组内空白（否则无法框选组内） |
| 端口 | 小半径圆，命中优先级高于节点（用于连线交互） |

要点：
- **z 序倒序遍历**（最上层优先命中），与渲染顺序相反；
- tolerance 必须除以 scale（缩小后仍好点中）；
- 边命中要用**渲染后的路径**（含圆角），或用折线近似 + 稍大 tolerance；
- 命中测试是交互热路径（mousemove），必须 $O(\log n)$，不能全量扫。

## 7. 交互式编辑与布局的关系

用户拖动节点后，三种产品策略：

| 策略 | 行为 | 适用 |
|---|---|---|
| **自由放置** | 完全接受用户坐标，只重路由受影响边 | 图编辑器（Dunnart 风格） |
| **约束吸附** | 接受用户意图但投影到约束可行域（VPSC 投影：不重叠、对齐、组内） | **推荐默认** |
| **重新布局** | 用新位置作为 sketch 重跑布局 | "整理"按钮的显式动作 |

关键设计：
- 拖动过程中**只做轻量更新**（受影响边直线化 + 60fps），松手后再做完整重路由 + 动画；
- 用户手工调整过的元素应打 `pinned` 标记，后续自动布局尊重它（PartialLayout 的 fixed 集合）；
- **"整理"必须是显式动作**，不能因为用户加了一个节点就重排全图 —— 这是最招骂的行为。

## 8. 实现架构建议

```
Layout Result (t=0) ──┐
                      ├─→ Transition Planner ─→ Frame Interpolator ─→ Renderer
Layout Result (t=1) ──┘        │
                               ├ 节点配对（by stable id）
                               ├ 分类：kept / added / removed
                               ├ 聚类移动检测
                               ├ 边路径重采样或零长段插入
                               └ 阶段时间轴
```

要点：
- **稳定 ID 是一切的前提**：过渡靠 id 配对。id 由 DSL/模型层保证（不能用数组下标）；
- Transition Planner 是**纯函数**（两个布局结果 → 一个动画计划），可单测；
- 动画计划应可序列化（便于录制回放、便于测试断言）；
- 渲染层只按 `t` 求值，不含逻辑；
- **可关闭动画**（`prefers-reduced-motion` + 用户设置 + 测试环境）—— 测试必须能跑 `t=1` 的终态。

## 9. 测试策略

| 测什么 | 怎么测 |
|---|---|
| 过渡计划正确 | 表驱动：给定两个布局，断言 kept/added/removed 分类与阶段时间 |
| 插值端点 | $t=0$ 等于旧布局、$t=1$ 等于新布局（逐字段） |
| 中间帧有限 | 采样 $t \in \{0.1..0.9\}$，断言所有坐标为有限数、在合理范围内 |
| 边形变不退化 | 断言中间帧拐点数一致、无 NaN、（正交模式下）所有段轴对齐 |
| 稳定性指标 | 对"加一个节点""删一条边""改标签"三类微扰动，断言位移与重路由边数低于阈值 |
| 视口数学 | zoom-to-cursor：随机 cursor/scale，断言光标下的世界坐标不变（eps 内） |
| 命中测试 | 随机点 + 暴力全量比对，断言结果一致 |

## 10. 给本项目的建议

1. **先做稳定性，后做动画**：from-sketch + 增量路由 hysteresis + 稳定性指标（13 篇 M6）。动画建立在稳定之上，顺序反了会做无用功。
2. **动画从"节点动、边淡"起步**（§3.3），把正交边形变（§3.2）列为后续增强。
3. **Transition Planner 做成纯函数并单测**，不要把插值逻辑散在渲染层。
4. **必做的交互三件套**：邻居高亮、minimap、折叠展开 —— 每件成本都远低于一个布局算法，用户价值更高。
5. **命中测试用网格哈希**（16 篇 §复用），z 序倒序，tolerance/scale。
6. **稳定 ID 贯穿 DSL → 模型 → 布局 → 渲染**，任何一层用下标代替 id 都会让动画与增量失效。
