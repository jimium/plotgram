> **不含任何 yFiles 私有源码信息**——涉及 yFiles 的部分均为对其公开 API 语义与可观测行为的逆向归纳。

## 推荐阅读路径

- **第一次进这个领域**：21（术语表 §0「先看这 20 个词」）→ 01 → 03。
  先建词汇表再读算法，能省掉大量"这词是啥"的往返。
- **直接开工**：13（选型表 + M0–M6 路线图）→ 09（架构）→ 14（零件库）。
- **做 Hier（架构图/流程图主路径）**：01 → 03 → 08 → 09 → 11。
  Sugiyama 是骨架；正交路由决定成品观感；分组/泳道/端口是产品级差异点。
- **做正交紧凑布局（ER 图、电路类）**：02 → 03 → 06 → 18。
- **做 organic / 知识图谱**：04 → 07 → 11。
- **做序列图 / 时间轴**：19 → 06 → 08。
- **定引擎架构**：09 + 20 必读，配合仓库内 [`写权纪律`](../../design/layout/write-authority.md)。
- **优化性能**：16 → 11（先度量再优化）。

## 写作约定

- 伪代码用 Rust 风格命名，但不承诺可编译；目的是表达数据流与写权。
- 每个算法标注：**出处（作者+年份）、复杂度、决定性（是否依赖迭代随机性）、写的自由度**。
- 「工程坑」小节记录开源实现（Graphviz/OGDF/ELK/libavoid）踩过的公开已知问题。
- 汉语行文，算法术语保留英文原词（layering、crossing minimization、nudging…）以便检索论文。
