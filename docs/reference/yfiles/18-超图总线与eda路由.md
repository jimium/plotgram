# 18 · 超图、总线路由与 EDA 布线

> 一大类真实图不是"二元边"：一个信号连接 5 个引脚、一条总线承载 32 位、一个反应有 3 个底物 2 个产物。
> 用普通边建模会得到 $\binom{k}{2}$ 条重复边或一团意大利面。本篇讲**超边（hyperedge）的建模与绘制**，
> 以及它在 EDA（电路）、数据血缘、SBGN 通路中的具体形态。
>
> 主线：Eschbach–Günther–Becker 2006（*Orthogonal Hypergraph Drawing for Improved Visibility*）、
> Sander 2004（*Layout of Directed Hypergraphs with Orthogonal Hyperedges*）、
> Newton–Sýkora–Vrťo 2002（超图绘制模型）、Mäkinen 1990（subset vs edge standard）、
> Pupyrev et al. 2011（ordered bundles）、Wybrow et al. 2009（libavoid）、
> Lengauer 1990（*Combinatorial Algorithms for Integrated Circuit Layout*，VLSI 经典）、
> Kernighan–Lin 1970 / Fiduccia–Mattheyses 1982（分割）、Yoshimura–Kuh 1982（通道布线）。

---

## 1. 超图的两种绘制标准（Mäkinen 1990）

| 标准 | 画法 | 优点 | 缺点 |
|---|---|---|---|
| **Subset standard** | 超边画成包住成员的闭合区域（Venn 风格） | 成员关系直观 | 区域重叠难避免，规模一大即不可读 |
| **Edge standard** | 超边画成树/星形连接线 | 与常规图视觉一致、可正交化 | 需要选一个"内部结构" |

**结论：图工具应用 edge standard**（subset standard 只适合 <10 个小超边的示意图）。
于是问题变成：**给定要连接的 $k$ 个端点，画一棵什么形状的连接树？**

---

## 2. 超边的四种内部结构

设超边连接端点集 $P = \{p_1..p_k\}$。

| 结构 | 形状 | 顶点数 | 适用 |
|---|---|---|---|
| **Clique 展开** | 所有对之间连线 | 0 | ❌ 不要用：$O(k^2)$ 条线，视觉灾难 |
| **Star（引入超边节点）** | 中心一个虚节点，$k$ 条边辐射 | 1 | 通用、最简单；中心点位置是新自由度 |
| **Steiner 树 / 总线** | 一条主干 + 若干支线 | 若干 | **正交场景最佳观感**（"总线"形态） |
| **链（daisy chain）** | 依次串起来 | 0 | 只在有天然顺序时（如时序链） |

### 2.1 Star 建模（推荐起步）
把超边变成一个**度为 $k$ 的虚节点**（hyperedge node）：
- 分层布局中，这个虚节点参与分层与定序，**它的层就是超边的"高度"**；
- 有向超边（$m$ 输入 → $n$ 输出）：虚节点的入边来自输入、出边去往输出，方向语义自然保留；
- 虚节点尺寸可以是 0（纯连接点）或有形状（SBGN 的反应节点、EDA 的 net 标记就是有形状的）。

**这是最重要的一步认知**：超边一旦变成节点，**整套普通图布局机器立即可用**（分层、交叉最小化、路由都不需改）。
不要试图让布局算法"原生理解超边"。

### 2.2 Steiner 树 / 总线建模（观感升级）
Star 的缺点是所有线汇于一点，$k$ 大时该点周围拥挤。改为**正交 Steiner 树**：
```
主干（trunk）：一条长直线（水平或垂直）
支线（stub）：每个端点用 1–2 段接到主干
```
自由度分解（写权很清晰）：
| 自由度 | 决定者 |
|---|---|
| 主干方向（H/V） | 由端点分布决定：跨度大的方向做主干 |
| 主干位置（另一坐标） | 一维优化：见 §3 |
| 主干范围 | 端点在主干方向上的 min/max |
| 每个 stub 的接入点 | 端点在主干方向的投影（可能需 nudging 去重） |
| 拐角圆角 / T 形接点标记 | 落笔层（15 篇） |

---

## 3. 主干位置的最优解（可解析求出）

**问题**：主干是水平线 $y = c$，端点 $y_i$，最小化总线长 $\sum_i |y_i - c|$（曼哈顿）。
**解**：$c = \text{median}(y_i)$。中位数，$O(k)$（nth_element）。

若加权（不同支线重要度不同）：加权中位数。
若限制在可行区间 $[lo, hi]$（不能穿节点）：**clamp 到区间**即为最优（目标函数在区间上单峰）。
若同时有多条总线争抢同一走廊：变成 §5 的 track 分配 + nudging。

这个"median 就是最优"的结论也解释了 P3 用 median 而非 barycenter 的部分直觉（$L_1$ vs $L_2$）。

**多主干（H 树 / T 树）**：$k$ 很大且端点分两簇时，单主干会很长。做法：
- 对端点做一维聚类（gap 大于阈值处切分）；
- 每簇一条子主干，子主干再接到一条上级主干（递归，深度 ≤2 足够）。
这就是 EDA 里的 H-tree / 时钟树形态。

## 4. 总线路由（bus routing）在普通图上的应用

即使没有真超边，**把"同源多宿"或"多源同宿"的边捆成总线**也能极大降低视觉复杂度。

### 4.1 何时捆
- 一个节点扇出 > 阈值（如 6）且目标节点在同一层区域；
- 一组边有相同标签/类型（如 "extends"、"depends"）；
- 用户显式声明 `edge group`（DSL 层能力，见 08 篇 edge grouping）。

### 4.2 与 edge bundling 的区别
| | bus routing | edge bundling |
|---|---|---|
| 几何 | 正交主干 + 支线，边**共享**几何 | 边被吸引靠近，仍各自独立 |
| 语义 | 明确表示"这是一组" | 只是视觉聚合 |
| 可追踪性 | 单条边在主干上不可区分（除非分色/分 track） | 平行细线仍可追 |
| 适用风格 | 正交 / 工程图 | organic / 大规模概览 |

**正交风格的图应选 bus routing**，不要用力导向 bundling（曲线与正交风格冲突）。
折中：**ordered bundles**（Pupyrev 2011）—— 边共享走廊但在走廊内保持有序的平行细线，可追踪且整齐。这是最适合工程图的方案。

### 4.3 ordered bundles 的关键约束
走廊内边的顺序必须**全局一致**，否则会在走廊内部产生交叉：
- 为每个走廊建立边的偏序（由两端的端口序推导）；
- 多走廊串联时，顺序在走廊间传递 → 可能出现冲突（环）→ 环检测后在某处允许一次交叉（选代价最小的位置）。
这与 03 篇 nudging 的偏序约束图是**同一套机制**，应共用实现。

## 5. VLSI 布线：可借鉴的三个经典模型

EDA 是"图布线"研究最深的领域（几十年、数亿美元的优化），有三个模型直接可用。

### 5.1 通道布线（Channel Routing）
**模型**：两排引脚（上/下），中间是通道，用水平段（trunk）+ 垂直段（branch）连接。
- **left-edge algorithm**（Yoshimura–Kuh 1982）：把每个 net 的水平跨度当区间，区间图着色分配 track → **最少 track 数 = 最大重叠数（下界可达）**；
- **垂直约束图（VCG）**：若 net A 在某列的上引脚、net B 在同列下引脚，则 A 的 track 必须在 B 之上 → 有向图；VCG 有环时必须"分裂 net"（dogleg）；
- **dogleg 路由**：允许一个 net 用多个 track（中间加垂直跳转）→ 破环、减少 track 数。

**移植到图布局**：
- 分层图的层间空隙**就是一个通道**；
- 上层节点的出端口 = 上排引脚，下层的入端口 = 下排引脚；
- track 分配用 left-edge；
- **VCG 环 = "两条边互相要求在对方之上"** → 这正是 03 篇 nudging 环检测的本质，解法也一样（允许一次交叉 = dogleg）。

这个对应关系非常值钱：**分层图的层间路由 = 通道布线**，四十年的成熟算法可以直接搬。

### 5.2 开关盒布线（Switchbox）
四边都有引脚的矩形区域。比通道难（不能自由选 track 数）。
移植场景：泳道交叉处、组框之间的空隙。
实用做法：不追求最优，用"通道布线 + 允许绕行"即可。

### 5.3 全局布线 + 详细布线两段式
**这是 EDA 最有价值的架构思想**：
```
全局布线（Global Routing）：把芯片划成粗网格（gcell），只决定"每条 net 经过哪些 gcell"
                            目标：容量不超限、总长最短 → 多商品流 / 迭代拆线重布
详细布线（Detailed Routing）：在每个 gcell 内决定精确轨道
```
**移植到图布局**：
- 全局布线 = 决定边经过哪些走廊（拓扑决策）；
- 详细布线 = track 分配 + nudging（几何决策）；
- **拆线重布（rip-up and reroute）**：拥塞的走廊上，把代价最高的边拆掉重走 —— 这是解决"局部拥塞"的正确手段，比"给某条边加特判"好得多。

拆线重布的骨架：
```
route_all_greedy()
for iter in 0..MAX:
    congested = corridors with demand > capacity
    if empty: break
    victims = 选择经过拥塞走廊、代价最高的 k 条边（稳定排序）
    unroute(victims)
    提高拥塞走廊的通行代价（history cost，PathFinder 风格）
    route(victims)   // 现在会自然绕开
```
**history cost** 是 EDA 的关键技巧（PathFinder，McMurchie–Ebeling 1995）：代价随"历史拥塞次数"累加，
使得反复拥塞的走廊逐渐被避开，避免"两条边互相让路"的震荡。

### 5.4 分割（Partitioning）
Kernighan–Lin 1970 / Fiduccia–Mattheyses 1982（FM，$O(E)$ 每 pass）：
- 移植场景：自动分组推断、大图的分块布局、泳道自动归属；
- FM 的 gain bucket 数据结构值得学（$O(1)$ 取最大增益移动）。

## 6. 各领域的超边形态

| 领域 | 超边是什么 | 惯用画法 | 布局要求 |
|---|---|---|---|
| **EDA 原理图** | net（一根信号连多个引脚） | 正交总线 + T 形接点（实心圆点）+ 网络标签 | 引脚位置固定（FIXED_POS）、总线不可交叉时用跳线、器件方向可翻转 |
| **数字总线** | 32 位并行线 | 一条粗线 + 斜线 + 位宽标注 | 只需一条边 + 装饰，最简单 |
| **SBGN 通路** | 反应（多底物多产物） | 反应节点（小方块）+ 有向线 + 化学计量数标签 | Star 建模天然吻合；节点类型的形状语义严格 |
| **数据血缘** | 一个作业读多表写多表 | 作业节点（Star）+ 列级细线 | LR 方向、列级端口（FIXED_ORDER）、可折叠到表级 |
| **知识图谱 n 元关系** | 一个事件多个角色 | 事件节点 + 带角色标签的边 | Star 建模；边标签必须有位置（06 篇） |
| **BPMN 网关** | 分支/汇聚 | 菱形节点 | 已是节点，不需超边 |
| **Petri 网** | 变迁 | 变迁节点（长条） | Star 已内建于模型 |
| **UML 泛化集** | 多子类共享继承箭头 | **总线形态**：多条线汇成一条到父类的箭头 | 这是 §3 主干的经典用例（UML 工具都这么画） |

**观察**：绝大多数领域的"超边"在数据模型里**本来就是一个节点**（反应、作业、变迁、网关）。
真正需要"隐式超边节点"的只有两类：EDA net 与 UML 泛化集。
→ **工程结论**：优先支持 `edge group` / 总线渲染（把多条普通边画成总线），而不是引入完整的超图数据模型。这是投入产出比最高的路径。

## 7. 落到本项目的设计建议

### 7.1 数据模型
不引入 hyperedge 类型。改为两个更小的能力：
1. **`edge group`（08 篇已有）**：声明一组边共享一段几何。渲染为总线。
2. **`connector node`（虚拟节点）**：DSL 层可显式声明一个"汇聚点"节点（尺寸为 0 或小圆点），用户手动建 Star。
   这样超边由用户在语义层表达，引擎无需特殊处理 —— 符合 ADR-001 的"引擎不按语义分支"。

### 7.2 总线渲染相（新增，属路由后置）
```
输入：edge group 内各边的端点/端口坐标（已由上游确定）
1. 判定主干方向（跨度大者）
2. 主干位置 = 加权中位数，clamp 到可行区间（避开节点，用走廊信息）
3. stub 接入点 = 端点投影；重复点用最小间距分散（VPSC 一维）
4. 输出：主干段 + 各 stub 段 + T 形接点标记
```
**写权**：本相只写"该 group 内边的路径几何"，不动节点、不动端口。若主干无可行区间 → 诊断 warning 并退回逐边路由（降级，见 16 篇）。

### 7.3 从 EDA 借的两件事（优先级最高）
1. **全局/详细两段式路由** —— 让"走哪条走廊"与"走廊内什么位置"成为两个自由度、两个写者。这与写权纪律完全一致。
2. **history cost + 拆线重布** —— 解决拥塞的正确机制。**它替代的正是"给某条边加特判"这种反模式。**

### 7.4 不做
- 完整超图布局算法（Sander 2004 那套）：收益窄；
- subset standard（Venn 风格）：不可扩展；
- 开关盒布线的最优算法：用通道布线近似即可；
- 力导向 edge bundling：与正交风格冲突（用 ordered bundles 代替）。
