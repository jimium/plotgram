# 03 · 正交边路由（Orthogonal Edge Routing）与 Nudging

> 对应 yFiles `EdgeRouter`（正交）/ `PolylineEdgeRouter` / `ChannelEdgeRouter` / `BusRouter`，
> 开源对标：adaptagrams **libavoid**（Wybrow, Marriott, Stuckey）、ELK `libavoid`/`OrthogonalEdgeRouter`。
> 主线论文：Wybrow et al. 2010 *Orthogonal Connector Routing*（SoCG/GD）、
> Miriyala–Hornick–Tamassia 1993 *An incremental approach to aesthetic graph layout*（channel routing），
> Wybrow et al. 2009 *Orthogonal connector routing* + 2014 *Incremental connector routing*。

**边路由是与布局解耦的独立问题**：节点位置已固定（用户拖的、或布局给的），只求边的折线。
这是产品观感的最后一公里，也是最容易被"打特判"污染的地方。本篇给出干净的分解。

---

## 0. 问题定义与自由度分解

输入：节点矩形集 $R$（障碍）、边的端点/端口约束、间距参数。
输出：每条边的正交折线。

自由度（按写权顺序）：

| 层 | 自由度 | 写者 | 目标 |
|---|---|---|---|
| L1 | 端口位置（边接在节点哪条边、哪个位置） | Port assignment | 减少绕行、分散端口 |
| L2 | 路径的**拓扑走向**（经过哪些走廊/格点） | Path search（A*/Dijkstra） | 最短 + 最少弯折 |
| L3 | 同走廊内多条边的**次序**（谁在里谁在外） | Ordering / channel assignment | 无交叉、无重合 |
| L4 | 每条边在走廊内的**精确偏移** | Nudging | 均匀间隔、对齐 |
| L5 | 圆角、箭头缩进、标签让位 | Decoration | 视觉 |

**纪律**：L4 不得改变 L3 的次序，L3 不得改变 L2 的走向。如果 nudging 阶段"想穿到另一边"，说明 L2/L3 的目标函数缺项，应上提。

## 1. L2 · 搜索图的构造（最关键的建模选择）

### 1.1 Orthogonal Visibility Graph（OVG）—— libavoid / yFiles 路线
从每个障碍角点与每个端点，向四个方向发射射线，直到撞上障碍。所有射线的交点成为图的顶点，射线段成为边。

```
fn build_ovg(obstacles: &[Rect], terminals: &[Point]) -> Graph {
    let xs: Vec<f64> = 障碍左右边界 ∪ 端点 x，按需加 margin，排序去重
    let ys: Vec<f64> = 同理
    // 每条竖线 x=xi 被障碍切成若干可见段；每条横线同理
    // 顶点 = (xi, yj) 且该点不在任何障碍内部
    // 边 = 相邻可见顶点之间（同一条线上无障碍阻隔）
}
```
- 规模：$O(n^2)$ 顶点最坏（n 个障碍 → 2n 条竖线 × 2n 条横线）。实践中稀疏。
- **构造要用扫描线**：$O((n+k)\log n)$，k 为输出边数。朴素双循环在 1000 障碍上就会卡。
- **margin/inflate**：障碍先向外膨胀 `spacing`，使路径天然离开节点边界；避免"贴着节点走"。

**变体：Reduced / interesting lines only**。只对"可能被用到"的坐标生成线（障碍边界 ± margin、端点坐标、组框边界），可把顶点数降一个量级。这是性能的主要杠杆。

### 1.2 均匀网格（grid graph）—— 简单但危险
把画布切成固定网格找路。优点：实现 10 行；缺点：
- 网格粒度与节点尺寸不匹配时找不到通道（假阻塞）；
- 顶点数 $O(W\cdot H / g^2)$，大画布爆内存；
- 路径贴格，nudging 空间被网格量化限制。
**只建议作为原型验证，不要进产品。**

### 1.3 通道图（Channel Graph）—— 分层布局的最佳搭档
若节点已按层排布，空白区域天然是**规则的走廊网格**：
- 水平走廊 = 层间空隙；竖直走廊 = 同层相邻节点之间的空隙（含左右边界外）。
- 图的顶点 = 走廊交叉点，边 = 走廊段。规模 $O(\text{layers}\times \text{width})$，极小。
- 这就是 yFiles `ChannelEdgeRouter` 的思路，也是**分层图路由的正解**：不必建 OVG，直接用布局的结构信息。
- 走廊有**容量**（能塞几条 track），路由时容量参与代价 → 自然做负载均衡。

> **tautcore 建议**：Hier 主路径用通道图；自由布局/用户拖动后的重路由用 OVG。两者共用同一个"搜索 + track 分配 + nudging"下游。

### 1.4 边界情况
- **端口在节点内部**：从端口点先"出针"（沿端口方向走 `portStub` 长度）再进搜索图，保证边垂直出入节点。
- **端点在障碍内**（节点重叠）：需要允许穿越自身障碍的特例——用"起终点所属障碍免检"实现，而不是全局关闭碰撞。
- **组框（cluster）**：既是障碍（外部边不得穿越）又是容器（内部边可以）。libavoid 用 cluster boundary 的"穿越惩罚"实现；干净做法是给每条边一个"允许穿越的组集合"（其两端所在组链的并集）。

## 2. L2 · 路径搜索

### 2.1 目标函数
$$\text{cost} = \sum \text{segLen} + \lambda_{bend}\cdot \#\text{bends} + \lambda_{cross}\cdot\#\text{crossings} + \lambda_{shared}\cdot\text{sharedLen} + \lambda_{cluster}\cdot\#\text{clusterCrossings}$$

典型权重（libavoid 默认量级，需按你的间距体系标定）：
- `bendPenalty` ≈ 节点间距的 1–4 倍（太小 → 楼梯状；太大 → 长距离绕行）
- `crossingPenalty` 通常 0（默认关！因为它使搜索非马尔可夫），需要时用后处理消交叉
- `segmentPenalty`、`fixedSharedPathPenalty`、`reverseDirectionPenalty`（惩罚"往回走"）

### 2.2 A* 的关键细节：状态必须含方向
弯折惩罚使代价依赖"从哪个方向进入该点"，因此搜索状态是 **(vertex, incoming_direction)**，不是 vertex。忘记这点会导致：
- 弯折数算错；
- `visited` 集过早剪掉更优的（换向）路径。

```rust
struct State { v: NodeId, dir: Dir4 }  // 4 倍状态空间

fn route(g:&Graph, s:Point, t:Point) -> Path {
    // h() = 曼哈顿距离 + 必要弯折数下界（若 s,t 不同轴则 +1 个 bend 的惩罚）
    // 这个 h 是 admissible 的，且比纯曼哈顿紧很多 → 明显加速
    astar(g, State{s, dir_of_port(s)}, |st| st.v == t, h)
}
```
- **可采纳启发式**：$h = |dx|+|dy| + \lambda_{bend}\cdot b_{min}$，其中 $b_{min}$ 按 dx/dy 与当前方向的关系取 0/1/2。
- **多端点/多边**：对每个源做一次 Dijkstra 得到到全体的距离场，可批量路由（libavoid 对每个节点缓存 visibility）。

### 2.3 惩罚共享路径（关键的观感项）
`fixedSharedPathPenalty` 使多条边不喜欢重合 —— 但**注意**它使代价函数依赖其它边的结果 ⇒ 顺序敏感、非确定。libavoid 的做法：
- 分两轮：第一轮无共享惩罚全部路由；第二轮带惩罚重路由（用第一轮结果作为"已有占用"）。
- **确定性要求**：边的处理顺序必须是稳定序（ID 序），并记录轮数上限。

### 2.4 Bus routing（总线/树形聚合）
多条同源/同汇的边合并成"干线 + 支线"（像电路总线）。yFiles `BusRouter`。
- 建模：Steiner tree 近似（最小化总线长），或"先路由主干后挂支线"。
- 正交 Steiner tree 是 NP 难；用 Hanan grid 上的启发式（1-Steiner / Batched Greedy）。
- 视觉收益极大（大量边汇聚的架构图/网络图必备）。

## 3. L3 · 通道内定序（Ordering within channels）

多条边共用一条走廊时必须决定谁在内谁在外。**这一步决定交叉数**，做错了 nudging 只能"把交叉挪个位置"。

### 3.1 区间图着色（同向段的无交叉分配）
走廊内的每个水平段是一个区间 $[x_1, x_2]$。若两段区间重叠，必须分到不同 track。
- 这是**区间图着色**，区间图是 perfect graph ⇒ 贪心（按左端点排序、复用最早空出的 track）给出**最优**着色数 = 最大重叠数。
- $O(m\log m)$，用最小堆维护"各 track 当前右端点"。
```rust
fn assign_tracks(mut segs: Vec<Seg>) -> Vec<usize> {
    segs.sort_by_key(|s| (s.x1, s.id));          // 稳定
    let mut heap: BinaryHeap<Reverse<(f64, usize)>> = ..; // (右端点, track)
    for s in &mut segs {
        if let Some(&Reverse((r, tr))) = heap.peek() && r + gap <= s.x1 {
            heap.pop(); s.track = tr;
        } else { s.track = next_new_track(); }
        heap.push(Reverse((s.x2, s.track)));
    }
}
```
- **但**：仅"不重叠"不等于"不交叉"。track 的**上下顺序**还要与边两端的相对位置一致，否则产生本可避免的交叉。

### 3.2 减少交叉的定序：转成两层交叉最小化
走廊内的段序问题可以规约为 **one-sided crossing minimization**（见 01 篇 P3）：
- 每个段有"进入端 x"和"离开端 x"；
- 两段交叉 ⟺ 进入序与离开序相反且 track 序选错。
- 用 barycenter/median 排序 + greedy switch，与 P3 完全同构 ⇒ **代码复用**。

### 3.3 Nudging 的经典分解（Wybrow et al. 2010 §5）
1. 按"段所在直线"分组（同一 x 的所有竖直段 / 同一 y 的所有水平段）；
2. 组内建**偏序约束图**：若两段必须保持某侧关系（由其邻接段的位置决定），加一条约束弧；
3. 检测约束图中的**环**（互相矛盾）⇒ 说明存在不可避免的交叉，任选一处打破；
4. 无环后拓扑排序 ⇒ 得到 track 序。

这一步与 02 篇的紧致化约束图**结构相同**（差分约束 + 环检测），可共用求解器。

## 4. L4 · Nudging（精确偏移）

给定 track 序，求每条段的精确坐标。

### 4.1 三种目标
- **均匀分布**：走廊内 k 条 track 等距铺开：$offset_i = c + (i - (k-1)/2)\cdot gap$。最简单，够用。
- **最小总位移 / 最直**：LP/QP：$\min \sum w_e (\text{段偏移与理想值之差})^2$，s.t. 相邻 track 间距 ≥ gap、次序不变。用 VPSC（07 篇）秒解。
- **对齐机会**：如果两条边可以共线一段而不重合（例如它们本就同源），允许 gap = 0 的"合并"以减少视觉噪声（bus 效果）。

### 4.2 关键补充项（漏了就丑）
- **端口对齐**：段的一端接在端口上时，理想偏移 = 端口坐标 ⇒ 目标里给这项高权重，使边"直着进节点"。
- **箭头/标签让位**：标签占位应作为 nudging 的约束（标签矩形与其它段不重叠），而不是事后挪标签（见 06 篇）。
- **圆角半径**：相邻段长度必须 ≥ 2×半径，否则圆角画不出来 ⇒ 作为最小段长约束进 nudging，不要在渲染层裁。

### 4.3 后处理（合法的"展开"）
- **冗余弯消除**：`A-B-C` 三点共线则删 B；`U 形` 若中段可移到边界外则拉直（需重查碰撞）。
- **段合并**：同一边连续同向段合并。
- **不要**在这里做"发现重叠就挪一点点"的贪心修补 —— 这是特判的温床，症状会在别处冒出来。重叠说明 L3 的约束漏项。

## 5. 增量路由（交互式必备）

Wybrow et al. 2014 *Incremental Connector Routing*：用户拖一个节点，只重路由受影响的边。
- 维护 OVG 的**增量更新**：移动一个障碍只影响其射线邻域 ⇒ 局部重建。
- 维护每条边的"依赖障碍集"（路径经过的走廊涉及哪些障碍）⇒ 反向索引，$O(\text{affected})$ 重路由。
- **稳定性优先于最优性**：重路由时给"与上一次路径相同的走廊"打折扣（negative penalty / hysteresis），否则拖动时边会乱跳（mental map 破坏，见 07 篇）。
- 实测：libavoid 在数百节点上可做到交互帧率。

## 6. 性能预算与规模门控

| 阶段 | 复杂度 | 1k 节点 / 2k 边预期 |
|---|---|---|
| OVG 构造（扫描线） | $O((n+k)\log n)$ | 数十 ms |
| A* per edge | $O(k\log k)$，k=OVG 边数 | 每条 0.1–1 ms |
| Track 分配 | $O(m\log m)$ | 可忽略 |
| Nudging（VPSC） | $O(m\log m)$ 近似 | 可忽略 |

**门控策略**（工业通用）：
- 边数 > 阈值：关闭"共享路径惩罚的第二轮"、关闭交叉惩罚，只走单轮最短路。
- OVG 顶点数 > 阈值：退化为通道图或粗网格。
- 记录门控命中，作为可观测指标（本仓库已有"两轮路由规模门控"的实践）。

## 7. 常见 bug 的根因清单（血泪）

| 症状 | 常见根因 | 正确修法 |
|---|---|---|
| 两条反向对边完全重合 | 反向标记丢失 / 两条边端口相同且共享惩罚未生效 | 端口分配阶段就把两条边分到不同端口位（L1 上游修） |
| 边贴着节点边缘走 | 障碍未 inflate | 建图时膨胀 margin |
| 边穿过节点 | 端点所属障碍免检范围过大；或 OVG 顶点判"在障碍内"用了闭区间 | 精确定义 margin 与开闭区间；只免检自身 |
| 楼梯状多余弯 | bendPenalty 太小 / 搜索状态未含方向 | 调权重 + 修状态定义 |
| 同输入两次结果不同 | 边处理序来自 HashMap；track 分配平局无 tie-break | 全链稳定排序 |
| 拖动时边乱跳 | 无 hysteresis | 增量路由给旧路径折扣 |
| 圆角画不出/穿模 | 最小段长未约束 | 进 nudging 约束 |
| 组内边跑到组外 | 组框未参与惩罚 | 每边携带"可穿越组集合" |

## 8. tautcore 落地建议

1. **两条路由后端，一套下游**：`ChannelRouter`（分层，走廊图）+ `FreeRouter`（OVG）；共享 `TrackAssign → Nudge → Decorate`。
2. **端口分配上提为独立相**（L1），由布局阶段写，路由不得改端口 —— 直接对应仓库纪律"若需发明端口，先上提写者"。
3. **走廊容量回写层间距**：路由前先做一次"需求估计"（每层间的最大重叠段数），把 `demand × trackGap` 作为层间距的下界回写给坐标相。这是唯一允许的反向影响。
4. **nudging 用 VPSC**，与坐标相共用求解器；把端口对齐、标签避让、最小段长都写成约束，杜绝事后特判。
5. **可观测断言**：SVG 路径快照 + 「无边穿节点」「无边重合」「弯折数」三项自动检查，作为回归门禁。
