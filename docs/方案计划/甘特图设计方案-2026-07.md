# 甘特图（Gantt）设计方案

> 状态：待审核
> 日期：2026-07-16
> 作者：trae agent
> 参考：[`sequence.rs`](../../crates/plotgram-core/src/layout/node/sequence.rs) 是最佳模板（位置由声明顺序确定性决定，布局阶段直接产出边几何，跳过通用 edge_routing）

## 1. 设计决策摘要

### 1.1 算法策略：新增专属布局器，不复用任何现有图布局

甘特图不是图论意义上的"图"，而是时间坐标系下的确定性条形排列：
- 任务条 x 位置由 `start/end` 时间**直接映射**到时间轴，y 位置由任务序号堆叠
- 没有"节点位置优化"问题，Sugiyama / 力导向 / 圆形 / 分层等算法全部不适用
- 依赖箭头几何简单（A 右端 → B 左端），不需要通用边路由的避障 / bundling / lane 体系

**与 sequence 同一范式**：位置由数据确定性决定 → 实现 `produces_edge_geometry = true` → 在 `compute()` 阶段直接产出任务条矩形 + 依赖箭头路径，跳过通用 edge_routing。

### 1.2 DSL 策略：语法层零改动，扩展 standard 属性白名单

Parser / Lexer / AST 零改动。**唯一缺口**：[`validation/attrs.rs:31`](../../crates/plotgram-core/src/validation/attrs.rs#L31) 对 `attributes.standard` 做白名单校验，甘特图的时间属性（`start`/`end`/`duration`/`progress`/`at`）不在 [`STANDARD_ENTITY_ATTRS`](../../crates/plotgram-core/src/profile/standard_attrs.rs#L11) 里。

**分层原则**：
- diagram config：只放时间轴视口级配置（`time_axis` / `start` / `end`），与 `title`/`layout` 同级
- entity 属性：放每个任务的时间数据（`start`/`end`/`duration`/`at`/`progress`），与 `owner`/`description` 同级，自包含

### 1.3 复用清单（零改动）

| 子系统 | 复用情况 |
|---|---|
| Parser / Lexer / AST | 完全复用 |
| prepare / pipeline 调度 | 完全复用 |
| SVG / PNG / WebP / Drawio / ASCII / JSON 导出 | 完全复用 |
| 主题系统（`CompiledRenderContext`） | 完全复用 |
| [`layout/catalog.rs`](../../crates/plotgram-core/src/layout/catalog.rs) | 自动从 profile + registry 生成，零改动 |
| Diff / Patch | 完全复用 |

## 2. DSL 语法设计

### 2.1 完整示例

```
diagram: gantt

config {
  title: "项目排期 Q3"
  time_axis: week          // day | week | month | quarter
  start: "2026-07-01"      // 视口左边界
  end: "2026-09-30"        // 视口右边界
}

group design "设计阶段" {
  entity[task] ui "UI 设计" {
    start: "2026-07-01"
    duration: 10            // 单位由 time_axis 决定（day→天，week→周）
    progress: 0.8
    owner: "Alice"
  }
  entity[task] review "设计评审" {
    start: "2026-07-10"
    duration: 2
    progress: 0.3
  }
  ui -> review
}

group dev "开发阶段" {
  entity[task] backend "后端开发" {
    start: "2026-07-13"
    duration: 20
    progress: 0.1
    owner: "Bob"
  }
  entity[milestone] mvp "MVP 发布" {
    at: "2026-08-02"
  }
  entity[task] frontend "前端开发" {
    start: "2026-07-15"
    end: "2026-08-20"       // end 与 duration 二选一
    progress: 0.0
  }
  review -> backend
  backend -> mvp
  review -> frontend
}
```

### 2.2 元素映射（全部复用现有 AST）

| 甘特图概念 | AST 承载 | 备注 |
|---|---|---|
| 任务条 | `Entity` + `type: task` + 时间属性 | 矩形条 |
| 里程碑 | `Entity` + `type: milestone` + `at` 属性 | 菱形 |
| 阶段/泳道 | `Group`（已支持嵌套） | 水平分组带 |
| 依赖关系 | `Relation`（`A -> B`） | FS 默认；label 可标 `SS`/`FF`/`SF` |
| 时间轴配置 | diagram 级 `attributes` | `time_axis`/`start`/`end` |
| 负责人 | `owner`（已在白名单） | 任务标签内显示 |
| 配置块 | `config { ... }` 语法已支持 | 视口级 |

### 2.3 时间属性规则（布局器内部推导，不增加 DSL 语法）

- 任务条：`start` + (`duration` | `end`) 二选一，另一个自动算
- 里程碑：用 `at` 单点（语义等价于 start==end）
- 依赖箭头 `A -> B` 默认 FS（A 完成后 B 开始）
- 缺失 `start` 的任务：可从依赖链推导（`start = max(前置.end)`）
- `progress` ∈ [0, 1]：任务条内绘制进度填充

## 4. 布局算法设计（`layout/node/gantt.rs`）

### 4.1 输入解析

```rust
pub struct GanttConfig {
    row_height: f64,        // 任务行高，默认 32
    row_gap: f64,           // 行间距，默认 8
    group_gap: f64,         // 阶段间距，默认 24
    bar_height: f64,        // 任务条高度，默认 20（< row_height）
    time_axis_padding: f64, // 时间轴左右留白，默认 60
    label_width: f64,       // 左侧任务名标签列宽，默认 140
}
```

通过 [`define_layout_config!`](../../crates/plotgram-core/src/layout/algorithm_config.rs#L47) 宏生成，与 sequence 一致。

### 4.2 时间→x 坐标映射

```
1. 解析 diagram 级 start/end/time_axis → 视口 [t_min, t_max]
2. 若未声明视口，扫描所有 entity 的 start/end/at 自动推导
3. day 粒度：1 day = px_per_day（默认 24px）
   week 粒度：1 week = px_per_week（默认 120px）
   month/quarter 类推
4. x(t) = label_width + time_axis_padding + (t - t_min) * scale
```

### 4.3 y 坐标堆叠

```
row 0: design.ui
row 1: design.review
group_gap
row 2: dev.backend
row 3: dev.frontend
row 4: dev.mvp

y(row) = top_padding + row * (row_height + row_gap) + group_index * group_gap
任务条 y = y(row) + (row_height - bar_height) / 2
```

### 4.4 依赖箭头几何

```
A -> B（FS 默认）:
  起点：A 任务条右端中点 (x(A.end), y(A) + bar_height/2)
  终点：B 任务条左端中点 (x(B.start), y(B) + bar_height/2)
  路径：折线
    若 y(A) == y(B)：直线
    否则：[起点, (mid_x, y_a), (mid_x, y_b), 终点]
      mid_x = max(x(A.end), x(B.start)) + 12  // 右探再下折
```

用 `PathGeometry::Polyline`，`from_port = Right`，`to_port = Left`。

## 5. 渲染设计（`render/paint/gantt.rs`）

### 5.1 `paint_export_node`

根据 `entity.type` 分派：

- `task`：圆角矩形 + 进度填充（`progress` 比例的深色覆盖）+ 右上角 owner 标签
- `milestone`：菱形（旋转 45° 的正方形），尺寸 ~16px

### 5.2 `paint_export_edge`

依赖箭头：折线 + 箭头标记，虚线表示被动依赖（`-->`）。

### 5.3 时间轴绘制

在 `paint_export_node` 之外，由 `paint_svg_defs` 或额外的 scene 钩子绘制：
- 顶部水平时间轴线
- 刻度（按 `time_axis` 粒度：day→每日短刻度，week→每周长刻度 + 日期标签）
- 竖向网格线（淡灰，与刻度对齐）

> **注**：时间轴是画布级装饰，不属于单个 entity。实现上可在 `paint_svg_defs` 返回，或在 `ExportScene` 构造时注入一个虚拟"轴"节点。参考 sequence 的生命线绘制方式（在 `paint_export_node` 内借用 `scene.layout.total_height` 画整列）。

## 7. 校验规则（`kinds/gantt/validate.rs`）

```rust
pub fn validate(diagram: &Diagram, result: &mut ValidationResult) {
    // 1. 每个 task 必须有 start + (duration | end)
    // 2. 每个 milestone 必须有 at，不得有 duration/end
    // 3. progress ∈ [0, 1]
    // 4. 依赖箭头端点必须是 task 或 milestone（不能指向 group）
    // 5. 依赖图无环（拓扑排序检测）
    // 6. diagram 级 start <= end（若都声明）
    // 7. 所有 task 的 [start, end] 落在视口 [view_start, view_end] 内（若声明视口）
}
```

## 10. 风险与决策点

### 10.1 时间轴绘制位置

时间轴是画布级装饰，但现有 `paint_export_node` / `paint_export_edge` 都是 per-entity 的。两个方案：
- **A**：在 `paint_svg_defs` 里画（它接收 `CompiledRenderContext`，但拿不到 LayoutResult 的 total_width）
- **B**：在 `ExportScene` 构造时注入一个虚拟"轴"节点（侵入性较大）
- **C（倾向）**：参考 sequence 生命线，在第一个 `paint_export_node` 调用时画整条时间轴（用 `scene.layout.total_width` + `hints.gantt`），用 `OnceLock` 保证只画一次

**待审核决策**：选 C，与 sequence 生命线绘制模式一致。

### 10.2 日期解析复杂度

若支持 ISO `YYYY-MM-DD` 字符串，需引入日期解析。两个方案：
- **A**：引入 `chrono` 依赖（项目当前未用）
- **B（倾向）**：自实现轻量日期解析（仅 `YYYY-MM-DD` → day offset from epoch），避免新依赖

**待审核决策**：选 B，保持依赖精简。

### 10.3 time_axis 粒度

`day | week | month | quarter` 四种粒度。month/quarter 的刻度对齐（月初/季初）需要日期运算。
**待审核决策**：M1 先实现 day + week，month/quarter 留 M2。

### 10.4 是否支持 swimlane（泳道分组带）

group 在甘特图里天然作为"阶段"出现。是否额外渲染水平泳道分隔带（背景色交替）？
**待审核决策**：M3 实现，用 group 的 `color` 属性驱动。
