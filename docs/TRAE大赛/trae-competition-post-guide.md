# TRAE 比赛：评分标准 & 初赛发帖指南

> 本文档整合比赛评分维度与初赛 Demo 作品帖推荐模板，供撰写初赛帖子时参考。

---

## 一、评分标准（总分 100%）

评审将从以下四个维度打分，撰写帖子时可对照各维度，突出对应亮点。

### 1. 创新性（30%）

评估作品在创意构思上的突破程度。

| 子项 | 说明 |
|------|------|
| **需求创新** | 是否准确识别生活娱乐、学习工作、社会服务等真实场景中，长期存在但未被很好解决的用户需求 |
| **解决思路** | 解决方案是否具有突破性，能以不同于现有产品的方式回应上述需求 |
| **技术创新** | 是否在运用 **TRAE** 能力方面展现出独特思路 |

**写帖建议：** 在「创作思路」部分重点交代痛点的新颖性、方案差异化，以及在 TRAE 实践过程中有哪些非常规或创新的用法。

---

### 2. 实用性（30%）

评估 Demo 的实际使用价值。

| 子项 | 说明 |
|------|------|
| **场景洞察** | 是否准确识别真实场景中的用户需求，目标用户是否清晰；**硬件交互赛道**还需体现对开发、调试、测试或交付场景的真实理解 |
| **解决效果** | 是否有效提升效率、降低成本或改善体验，用户是否有明确使用意愿 |
| **落地可行性** | 当前 Demo 能否验证核心价值，而非纯概念展示 |

**写帖建议：** 在「Demo 简介」中写清目标用户与核心功能价值；用截图或演示证明「真的能解决问题」，而非停留在想法层面。

---

### 3. 完成度（20%）

评估 Demo 的功能实现程度。

| 子项 | 说明 |
|------|------|
| **核心链路** | 核心功能路径是否完整可用，用户能否完成主要操作；**硬件交互赛道**需体现 TRAE 是否真正参与关键设备开发、调试链路 |
| **用户体验** | 体验是否流畅，无明显 Bug 或卡顿 |
| **价值传递** | 产品核心价值是否能让用户清晰感知 |

**写帖建议：** 展示可跑通的主流程截图/录屏；体验链接或视频需能完整走通核心路径；避免只展示局部功能。

---

### 4. 美观度 / 设计体验（20%）

根据赛道不同，评估侧重点有所区别。

#### 非硬件交互赛道（生活娱乐 / 学习工作 / 社会服务）

评估作品的**视觉与交互体验**。

| 子项 | 说明 |
|------|------|
| **视觉设计** | 界面设计专业，布局清晰合理，配色协调，视觉体验舒适 |
| **交互友好度** | 交互符合用户习惯，学习成本低 |

#### 硬件交互赛道

评估**硬件与软件系统的协同能力**。

| 子项 | 说明 |
|------|------|
| **交互流畅** | 软硬件数据传输稳定，响应及时，TRAE 参与后的调试/反馈链路顺畅 |
| **体验融合** | 硬件功能与软件能力深度融合，提供完整服务体验 |

**写帖建议：** 非硬件赛道多放界面截图，体现设计与交互；硬件赛道侧重联调过程、数据流、端到端演示视频。

## 二、初赛 Demo 作品帖怎么写（推荐模板）

在**初赛专区**发帖，按以下格式填写。重点是把「**用 TRAE 做出来**」的过程讲清楚。

### 【标签】

- 按所选赛道选择话题标签，**四选一**：
  - `生活娱乐`
  - `学习工作`
  - `社会服务`
  - `硬件交互`
- 参加附加赛题的可**加选** `社会公益` 标签
- ⚠️ 标签须与**报名通过的赛道保持一致**

### 【标题】

```
报名赛道 + Demo 名称
```

示例：`学习工作 · FlowML 智能图表布局助手`

### 【正文】

至少包含以下 **4 个部分**，可增加额外部分（如经验总结、开发心得等）。

---

#### 1. Demo 简介

| 要素 | 写什么 |
|------|--------|
| **是什么** | 一句话说清产品形态（App / 小程序 / 网站 / 系统 / 硬件等） |
| **面向谁** | 核心用户是哪些人 |
| **主要功能** | 列出 2–3 个核心功能；**建议配产品截图或界面展示**，让评审一眼看懂 |

> 对应评分：实用性（场景洞察、解决效果）、完成度（价值传递）、美观度（视觉设计）

---

#### 2. Demo 创作思路

| 要素 | 写什么 |
|------|--------|
| **灵感来源** | 你为什么想到做这个 |
| **想解决的问题** | 用户真实存在的痛点 |
| **为什么做这个方向** | 你的判断和取舍 |

> 对应评分：创新性（需求创新、解决思路）、实用性（场景洞察、落地可行性）

---

#### 3. Demo 体验地址（三选一）

| 方式 | 要求 |
|------|------|
| **在线部署** | 随时可公开访问的体验链接 |
| **离线 HTML** | 交互式可体验的 HTML 文件，**Zip 打包**上传到社区 |
| **演示视频** | **硬件交互赛道**可用演示视频替代在线体验；视频上传第三方平台后附公开链接 |

> 对应评分：完成度（核心链路、用户体验）、实用性（解决效果）

---

#### 4. TRAE 实践过程

| 要素 | 要求 |
|------|--------|
| **完整流程** | 清晰展示用 TRAE 完成 Demo 开发的完整流程 |
| **关键步骤截图** | 不少于 **3 张** |
| **Session ID** | 附关键任务对话的 Session ID，不少于 **3 个**，用于证明作品由 TRAE 开发完成 |

> 对应评分：创新性（技术创新）、完成度（核心链路）；硬件赛道还需体现 TRAE 在开发调试链路中的参与

---

## 三、发帖检查清单

发帖前可逐项核对：

- [ ] 话题标签与报名赛道一致（四选一，可选加 `社会公益`）
- [ ] 标题格式：赛道 + Demo 名称
- [ ] Demo 简介：形态、用户、2–3 个核心功能 + 截图
- [ ] 创作思路：灵感、痛点、方向取舍
- [ ] 体验方式：链接 / Zip / 视频（硬件赛道）三选一且可访问
- [ ] TRAE 实践：流程说明 + ≥3 张截图 + ≥3 个 Session ID
- [ ] 整体是否覆盖评分四维：创新、实用、完成度、美观/协同
