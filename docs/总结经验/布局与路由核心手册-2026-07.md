## 0. 一句话

改布局/路由时：**先弄清「最终输出是谁写的」再调启发；几何未冻结前不做激进折点清理；用 `cargo run -p plotgram-cli` 验真；用节点坐标 + **product-gate 严重度**谈退化；禁止图名特判。**

法则分两档：

| 标记 | 含义 |
|------|------|
| ★ | **硬红线**：违反会系统性假修好 / 不可复现 / 特判污染 |
| ○ | **强建议**：当前最佳实践；可用更好方案替换，但须说明写权与回归证据 |

## 1. 工作法则与失败模式

### 1.0 第一性原理六条公理（doc 23；Phase 6 固化）

后续改布局/路由前先对照下表。细则与 CI 判据见 [`docs/优化重构/23-布局与路由第一性原理重构方案-2026-07.md`](../优化重构/23-布局与路由第一性原理重构方案-2026-07.md) §2。

| 公理 | 规则（摘要） | 机械门禁 |
|------|--------------|----------|
| **A1** | 可行域由**构造/硬过滤**保证；罚项只排合法候选优先级，禁止大数伪装硬约束 | `benchmarks/scripts/check-penalty-ratio.sh`（max/min ≤ 100）；罚项集中 `layout/routing/objectives.rs` |
| **A2** | 一个量只有一个决策点；冻结后类型上不可写 | typestate（`FrozenNodeProduct` / materialize→audit→freeze）；`pub fn &mut [EdgeLayout]` ≤3（语义隔离脚本） |
| **A3** | 几何是求解变量，不是「算完再狂改」的派生值；**group 是变量（与节点同级），无几何 hint** | group 写权 debug 阈值 ≤1（`materialize`）；`write_counter` / `check-group-writes.sh`；目录结构见 [34-layout模块结构重构](../优化重构/34-layout模块结构重构-2026-07.md) |
| **A4** | 目标词典序分层，禁止跨层加权求和冒充优先级 | `LexCost`（DefaultScorer / LexA*）；日常勿再堆跨层大数罚项 |
| **A5** | 语义只能从 contract 进入内核；内核禁止读 `DiagramType` / 图名 / `algo ==` | `benchmarks/scripts/check-semantic-isolation.sh` |
| **A6** | 无解时显式降级，禁止静默兜底 | `orthogonal_debug.degraded_count` / route audit `degraded` 进 bench；`[solver-status]` 日志 |

### 1.1 法则

| # | 档 | 法则 |
|---|----|------|
| 1 | ★ | **先追写权与时序**：改字段前回答「谁最后写入」。Atlas 主路径：`Plan → metric → Ink → label`；旧正交链（若仍触达）是 `route → snap/repulse → sanitize → label`。sanitize/Ink 会重建 label 时，避让必须在几何冻结之后。见 §3.1。 |
| 2 | ★ | **激进清理勿过早**：router 内 sanitize 宜保守；会改变折点拓扑的逻辑（如 `merge_overshoot`）不得在节点仍可能重定位时启用（会反馈 space-budget → 假回归）。 |
| 3 | ★ | **勿信陈旧 binary**：优先 `cargo run -p plotgram-cli`；日志与源码不一致时先查 mtime / fingerprint（含沙箱注入的 `CARGO_TARGET_DIR`）。 |
| 4 | ★ | **退化要可量化**：节点坐标 diff + **product-gate** 严重度/质量轨（[`benchmarks/sets/product-regression-set.txt`](../../benchmarks/sets/product-regression-set.txt)；非单图观感、非只数 violation、**非**全量 showcase / stress）。仓库既有失败先钉死，勿与本次改动混谈。 |
| 5 | ★ | **禁止图名特判**；可接受合法单调台阶暂留；**不可为消 lint/warning 引入穿模**；**不可为压 stress 质量数字加图名分支**。 |
| 6 | ★ | **确定性迭代**：禁止靠 HashMap key 序驱动布局/路由（`AGENTS.md` §2）。 |
| 7 | ★ | **渲染不得反推路由语义**：FanIn/共享 trunk/sharp corner 应消费 annotation（或同等单一语义源）；禁止按 `points.len()` / 固定 index 猜。 |
| 8 | ○ | **refine 候选破约即拒绝本轮**：若候选**新制造**节点碰撞、层缝破坏等，回滚该候选并走既有降级；不是禁止一切推点，而是禁止「破约后再在反馈环里硬补」。 |
| 9 | ○ | **基线可抬、债须显式**：门禁数字不是永恒真理。有意抬基线时须说明原因、**角色**与残余样例（`raise product:` / `raise stress (expected):`）；不得把「单图好看」或「只修了 stress」说成「无退化」。 |
| 10 | ○ | **角色分层门禁**：`{role}.{slug}.pgm`；[`compare.sh`](../../benchmarks/scripts/compare.sh) 对 product/smoke 质量硬 FAIL，stress/demo 质量默认 WARN，mech 不挡质量；**正确性（穿组 / det）全角色硬**。详见 [`benchmarks/README.md`](../../benchmarks/README.md)。 |
### 1.2 常见失败模式

| 模式 | 识别 | 防御 |
|------|------|------|
| 陈旧产物 | 加了日志却看不到 | 先核 binary，再疑控制流 |
| 过早局部猜因 | 调偏移/分数，结果仍被后步覆盖 | 先找最终写者 |
| 节点动了当修好 | 视觉好但坐标整体漂 | 激进逻辑挪到几何冻结后 |
| 未读调用上下文 | 犹豫改签名，其实已有 map | 先读参数与阶段 |
| 阈值治死锁 | `cand==curr` 时调阈值无效 | 改打分，禁恒等胜出 |
| 多写者无最终所有者 | 改了 X 结果没变 | 明确字段最终写者 |
| 假设独占共享资源 | 赋锚未查占用 | 查 map → 切线错开 |
| 孤立决策 | 只看本边 | 视觉歧义按群体问题处理 |
| 路径点数猜语义 | 4/5 点样例好看，6 点误判 | annotation / `MergeInterval` 标记合流边界 |
| 全图投影当“同列” | 修一对却拉散跨组/宏 rank | 作用域至少 `(leaf-group, rank)` |
| 反馈后再推点补缝 | 局部好、全量穿模升 | 候选前后比违规集；新违规则回滚 |
| 合流重造整条路径 | 共享干有了，源 stub/走廊被盖 | 保留绕障前缀，只改必要 suffix |
| 设计取舍随上下文失效 | 按文档实现了审美结论，成品出来后发现前提已变（如 end 同层旁置 vs 沉底，在主干拉直后结论反转） | 文档自己标注的冲突点（「与旧审美冲突」）先问「最终形态下还成立吗」，把权衡摆上台面再动手，勿机械执行 |
| 新机制接入既有管线 | 加的偏置不生效 / 排好的顺序被后步换回 | 动手前摸清索引体系（DAG vs proper graph 两套 NodeIndex）与所有会写同对象的 pass（median / transpose / normalize） |

### 1.3 改动后 DoD

1. `cargo run -p plotgram-cli` 验目标图  
2. 节点坐标相对基线可解释（仅预期节点动，或已说明为何整体漂）  
3. 相关单测 + **product-gate** 严重度/门禁有结论（持平、可解释上升、或显式抬基线）；若跑了 stress，正确性不升、质量变化标为探针观测  
4. 无图名分支  
5. 目标图视觉通过但 **product-gate** 红：只能声明「目标修复」，不得声明「无退化」  
6. 仅 stress/demo 质量变差、product 持平或变好：日常可绿（stress 最多 WARN），不得写成「全量无退化」

## 2. 母题与判定规则

### 2.1 两类系统问题

1. **语义错位（假邻居）**：邻居/边集宽于或方向异于 FAS **effective** DAG + **邻层**约束。  
2. **契约破坏**：陈旧下标、尺寸双轨、几何已换标签未换、端点离框、**检测成功却不修复**。

### 2.2 通用判定（审计复用）

1. DAG 语义单一来源（effective 邻接）  
2. 邻域默认 rank±1；长边经 dummy，禁止远端 real 直接进 median  
3. 后处理不得宽于主算法（coordinate / stub_fix / straighten）  
4. 硬过滤与软惩罚一致；检测为真须改善或显式 degraded  
5. 确定性枚举（显式排序 / `IndexMap` / `BTreeMap`）  
6. 端点在边界；换几何后重建标签；容器变异后重算下标；单尺寸源  

### 2.3 有意启发式（勿当 bug）

长边 barycenter/dummy 加权、`stub_fix` 长度容忍、straighten 直连偏好、长跨度侧通道车道、degraded fallback、合法单调台阶暂留、overlap 迭代上限等。

## 3. Atlas 三相管线（现状地图）

> 本节描述 **Stage 7 收口后** 的主路径（组合相 → 度量相 → 落笔相）。  
> 旧两段式「节点求解 → `FrozenNodeProduct` → 正交 20+ 阶段」已退出生产；`pipeline: legacy` 已删除。  
> 改架构时同步更新本图，并证明写权仍清晰（★1–2）。

### 3.1 当前阶段序（对照用）

```text
compile_atlas(Diagram)
  → Dialect / Scheme / Contract          ← 唯一读 DiagramType 的入口
  → 组合相（相 I）
       ChannelGraph 选路 → Plan
         · channels / gates / ports / bundles
         · provenance 每条成功边必有（Stage 7 硬门禁）
         · L6 verify_no_group_penetration + verify_route_scope
  → 度量相（相 II）
       Occupant Demand + track LP / Cross 投影
         · solve_from_contract / CoordinateProblem::from_contract
         · 只读 Plan；不做离散决策
  → 落笔相（相 III）
       ink::materialize_edges(&Plan, …)
         · 无 DiagramType / 无 mut Plan
         · LabelSolver（几何冻结后）
  → canvas_finalize
```

Tree / Sequence / Circular Dialect 委托既有 recipe 布局/路由，但仍挂在 `AtlasPipeline` 下（不再因图种回落 Legacy）。

### 3.2 写权与不变量（Stage 7）

| 不变量 | 落点 |
|--------|------|
| 相 II/III 无离散决策 | `check-atlas-phase-api.sh`；Ink 仅 `&Plan` |
| Provenance 100% | `provenance_check` + `check-provenance-coverage.sh` |
| 内核无 DiagramType | `check-semantic-isolation.sh` |
| LexCost 无跨层求和 | `kernel/cost.rs` + `check-penalty-ratio.sh` |
| 穿组由构造保证 | L6 + `verify_route_scope`（product flowchart 表驱动） |
| 组框 materialize-only | `check-group-writes.sh`（main≤1） |

### 3.3 与旧正交消毒的关系

旧 `edge_routing_orthogonal` 目录仍在仓库（MCF / 物理清空记债），**不是** Hierarchical 生产落笔路径。  
Ink 产出后仅保留 LabelSolver 与画布收尾；禁止把密采样曲线写回正交 `Polyline` 再交给无障碍的 `force_orthogonal`。

### 3.4 增量

跨渲染增量走 `compute_layout_incremental(&Plan)`（Plan diff）；旧 `FrozenRoutingSolution` 指纹增量已废除。

### 3.5 Shadow 对拍

`pipeline: shadow` / `PLOTGRAM_PIPELINE=shadow`：双跑 LayoutPipeline vs Atlas，返回 Atlas 结果，差异摘要打 stderr。用于诊断，不是生产默认。

## 5. V3b 悬挂对齐（摘要）

- flowchart：`sugiyama_v2` 内 `align_pendants_under_anchors`（宜在 `normalize_layout_to_padding` 之后、route 之前）。

- 路由后不要再挪节点做 pendant「补救」。

## 7. 重构 ROI 原则（非清单）

1. 死代码直接删（AGENTS §1）；删功能时连带删掉只为它存在的抽象（单变体枚举、恒为常量的字段、空操作 filter）  
2. 障碍检测 / 采样常量一处定义  
3. `reroute_and_repulse` 与 pipeline 传同一 snap 配置  
4. 巨型阶段函数可按 phase 拆，便于时序审计——**拆分不等于冻结阶段名**  
5. sugiyama 与 architecture coordinate **不是**字节拷贝，勿误合并  
6. annotation 一旦存在，渲染 / 校验 / 标签归属复用同一语义源  
7. 多写者字段宜收敛为「检测 + 一个最终重申」，其余阶段拒绝破约候选  
8. **算法级重写走「帕累托 + 退火」，非贪心棘轮**：日常改动不劣化 **product-gate**；但推翻管线时序 / 换生成器这类大重构，允许过程中接受有界临时退化（stress 可更大），以最终「目标维度帕累托更优 + 显式抬基线（note 带角色）+ 列残余样例」为准（`AGENTS.md` §7）。★ 卫生红线（确定性、禁特判、验真、勿信陈旧 binary）不豁免。

lint 与性能冲突时：优先算法效果与简洁性（`AGENTS.md` §4）。

## 8. 给 Agent 的最短清单

1. ★ 先找最终写者；动坐标优先在路由前。  
2. ★ 验证用 `cargo run -p plotgram-cli`，核 binary / `CARGO_TARGET_DIR`。  
3. ★ 无图名特判；不为消 lint 引入穿模。  
4. ★ 回归：坐标 diff + **product-gate** 严重度；既有失败先钉死。  
5. ★ sharp/round、FanIn 看 annotation，不看路径点数。  
6. ○ §3 是 Atlas 三相现状地图，可演进；改架构时更新对照并留回归证据。
7. ○ refine 本轮破约就回滚候选，不是禁止一切推点。  
8. ○ 单图修好但 **product-gate** 红：声明「目标修复」或显式抬基线 + 列残余样例（note 带角色）。  
9. WASM 禁用裸 `std::time::Instant`（`AGENTS.md` §6）。  
10. ○ 门禁：`./benchmarks/snapshot.sh` + `./benchmarks/compare.sh`（或 `scripts/` 下同名脚本）；无退化 ≠ 全量 showcase。
