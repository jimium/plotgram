## 1. 工作法则与失败模式

### 1.1 必守法则

| # | 法则 |
|---|------|
| 1 | **先追管线时序**：`router → snap/repulse → sanitize → resolve/assign`；sanitize 会重建 label 时，避让必须在几何冻结之后 |
| 2 | **激进清理放管线末尾**：router 内 sanitize 保守；`merge_overshoot` 不得在节点仍可能重定位时启用（会反馈 space-budget → 假回归） |
| 3 | **勿信陈旧 binary**：优先 `cargo run -p plotgram-cli`；日志与源码不一致时先查 mtime / fingerprint |
| 4 | **无退化可量化**：节点坐标 diff + 全量 showcase **严重度**（非计数、非单图观感）；仓库既有失败先钉死 |
| 5 | **禁止图名特判**；可接受合法单调台阶暂留；不可为消 lint/warning 引入穿模 |
| 6 | **确定性迭代**：禁止靠 HashMap key 序驱动布局/路由（`AGENTS.md` §2） |

### 1.2 常见失败模式

| 模式 | 识别 | 防御 |
|------|------|------|
| 陈旧产物 | 加了日志却看不到 | 先核 binary，再疑控制流 |
| 过早局部猜因 | 调偏移/分数，结果仍被后步覆盖 | 先找最终写者 |
| 节点动了当修好 | 视觉好但坐标整体漂 | 激进逻辑挪到几何冻结后 |
| 未读调用上下文 | 犹豫改签名，其实已有 map | 先读参数与阶段 |
| 阈值治死锁 | `cand==curr` 时调阈值无效 | 改打分，禁恒等胜出 |
| 多写者无最终所有者 | 改了 X 结果没变 | 明确字段最终写者 |
| 假设独占共享资源 | 赋锚未查占用 | 查 map → 切线错开 |
| 孤立决策 | 只看本边 | 视觉歧义按群体问题处理 |

### 1.3 改动后 DoD

1. `cargo run -p plotgram-cli` 验目标图  
2. 节点坐标相对基线可解释（仅预期节点动）  
3. 相关单测 + 全量严重度不升  
4. 无图名分支

## 2. 母题与判定规则

### 2.1 两类系统问题

1. **语义错位（假邻居）**：邻居/边集宽于或方向异于 FAS **effective** DAG + **邻层**约束。  
2. **契约破坏**：陈旧下标、尺寸双轨、几何已换标签未换、端点离框、**检测成功却不修复**。

### 2.2 通用判定（审计复用）

1. DAG 语义单一来源（effective 邻接）  
2. 邻域默认 rank±1；长边经 dummy，禁止远端 real 直接进 median  
3. 后处理不得宽于主算法（coordinate / stub_fix / straighten）  
4. 硬过滤与软惩罚一致；检测为真须改善或显式 degraded  
5. 确定性枚举（显式排序 / `IndexMap` / `BTreeMap`）  
6. 端点在边界；换几何后重建标签；容器变异后重算下标；单尺寸源  

### 2.3 有意启发式（勿当 bug）

长边 barycenter/dummy 加权、`stub_fix` 长度容忍、straighten 直连偏好、长跨度侧通道阈值、degraded fallback、合法单调台阶暂留、overlap 迭代上限等。

## 3. 正交管线与 sanitize

### 3.1 统一阶段序（追 gap / 共锚时对照）

```text
4b replan_slots
 → 4c straighten_align
 → 4d reroute
 → 4e stub_fix              ← 在 lane 之前
 → 4f lane_assignment
 → 4g sanitize               ← collapse_micro_jogs + simplify_path×2（可压 parallel gap）
 → 5 labels
 → [pipeline] snap_and_repulse
 → sanitize_ext(merge_overshoot=true)
 → label_resolve             ← 最终避让，不可再被 sanitize 丢掉
```

追 **parallel gap**：只盯 lane **之后**（4g / snap / merge_overshoot）。stub_fix 不是「lane 后压 gap」元凶。

### 3.2 Sanitize 职责（E0）

| 步骤 | 意图 | 注意 |
|------|------|------|
| `fix_endpoint_reverse_stub` | 切背向折点 | 禁止 stub-only 截断 |
| `ensure_outward_stub` / `repair_post_stub_inward` | 外向 stub | 已修内向肘 |
| `force_orthogonal` / `collapse_micro_jogs` | 整形 | 共线合并分数选角；非救穿模 |
| `simplify_path`×2 | 合并近共线 | 可压 parallel gap |
| `merge_overshoot`（**仅末尾**） | 消 Z 折 | 无障时可能拉直侧通道台阶（R12 边界） |
| 安全网回退 | 保连通 | 可能保留脏几何 → 依赖 degraded |

## 5. V3b：邻层悬挂对齐（已落地）

### 5.1 语义

| 情形 | 对齐 |
|------|------|
| 单 pendant | movable 与 anchor **主轴中心重合**（门禁 ≤ 2px） |
| 同锚同层多 pendant | **组质心**对齐 anchor；组内按 **`node_gap`**（非 `layer_gap`）对称排开 |

flowchart 走 `sugiyama_v2`；architecture 的 L2 **不**自动覆盖 flowchart。路由后禁止挪节点。

### 5.2 P-Pendant

- rank 相邻；**无向邻层 Real 邻居集合** = `{anchor}`（按邻居节点数，**非边条数**）  
- Dummy 不计入；**禁止**全图 `all_pred`  
- 锚点邻层邻居集大小 > 1（枢纽）；两端皆叶 → skip（P-Mutual 未做）

### 5.3 R1–R4

- **R1** 锚点不动，只动 movable / 组  
- **R2** 冲突：先 pack；仍与非 pendant 冲突 → 整组放弃  
- **R3** 每节点本轮至多写一次；pack = 组内原子赋值，禁止二次微调；失败整组回滚  
- **R4** 两对抢同一 movable → 锚点邻居更多或上层优先  

### 5.4 S-PackUnderAnchor

- **E1** 组内皆同锚 P-Pendant；**E2** 推荐整层 Real 皆该组，否则降级 SkipIfConflict  
- 排序 `(center, id)`；scoped `node_gap` 校验失败 → 回滚  

### 5.5 调用序

```text
BK + compaction + overlap
 → align_singleton_layers
 → normalize_layout_to_padding
 → ★ align_pendants_under_anchors   // 必须在 normalize 之后
 → route …
```

`finalize_canvas_bounds` 可能因 bbox 左扩做**整体**平移；非 pendant 的相对关系应保持。  
单测：`sugiyama_v2::tests::v3b_user_auth_pendants_pack_under_auth`。  
与 V3a 正交：先布局对齐 → 路由 → gap。

### 6.1 R12 产品边界（O5.1）

`sanitize` / `collapse_micro_jogs` **没有障碍物信息**。对「无障可共线合并」的侧通道多段台阶，若强行拉成直段，可能穿模或破坏已分配的侧通道。

**产品边界**：合法单调多段台阶**可以暂留**；默认不为实现「更直」而在无障感知下拉直。若将来要消台阶，须带障碍感知或保守谓词（O5.2），否则拒绝改码。
