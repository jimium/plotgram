## 1. 工作法则与失败模式

### 1.1 必守法则

| # | 法则 |
|---|------|
| 1 | **先追管线时序**：`router → snap/repulse → sanitize → resolve/assign`；sanitize 会重建 label 时，避让必须在几何冻结之后 |
| 2 | **激进清理放管线末尾**：router 内 sanitize 保守；`merge_overshoot` 不得在节点仍可能重定位时启用（会反馈 space-budget → 假回归） |
| 3 | **勿信陈旧 binary**：优先 `cargo run -p plotgram-cli`；日志与源码不一致时先查 mtime / fingerprint |
| 4 | **无退化可量化**：节点坐标 diff + 全量 showcase **严重度**（非计数、非单图观感）；仓库既有失败先钉死 |
| 5 | **禁止图名特判**；可接受合法单调台阶暂留；不可为消 lint/warning 引入穿模 |
| 6 | **确定性迭代**：禁止靠 HashMap key 序驱动布局/路由（`AGENTS.md` §2） |
| 7 | **渲染不得反推路由语义**：FanIn/FanOut、共享 trunk、sharp corner 必须消费 annotation；禁止按 `points.len()` / 固定 index 猜 |
| 8 | **反馈候选破约即拒绝**：refine 若新制造节点碰撞、层缝破坏，不得在反馈环内二次推点补救；回滚候选并走既有降级 |

### 1.2 常见失败模式

| 模式 | 识别 | 防御 |
|------|------|------|
| 陈旧产物 | 加了日志却看不到 | 先核 binary，再疑控制流 |
| 过早局部猜因 | 调偏移/分数，结果仍被后步覆盖 | 先找最终写者 |
| 节点动了当修好 | 视觉好但坐标整体漂 | 激进逻辑挪到几何冻结后 |
| 未读调用上下文 | 犹豫改签名，其实已有 map | 先读参数与阶段 |
| 阈值治死锁 | `cand==curr` 时调阈值无效 | 改打分，禁恒等胜出 |
| 多写者无最终所有者 | 改了 X 结果没变 | 明确字段最终写者 |
| 假设独占共享资源 | 赋锚未查占用 | 查 map → 切线错开 |
| 孤立决策 | 只看本边 | 视觉歧义按群体问题处理 |
| 路径点数猜语义 | 4/5 点样例好看，6 点或普通绕障误判 | 由 `MergeInterval` / route annotation 标记合流边界 |
| 全图投影当“同列” | 修一对节点却拉散跨组/宏 rank | 作用域至少限定 `(leaf-group, rank)`，只修真实碰撞或明确关系 |
| 反馈后再推点补缝 | 局部图变好，全量穿模/严重度上升 | refine 前后比较契约；新违规则整轮拒绝 |
| 合流重造整条路径 | 共享干出现了，但源 stub/跨组走廊被覆盖 | 保留原绕障前缀，只重写局部 suffix；同 rank pendant 可在源 stub 后合流 |

### 1.3 改动后 DoD

1. `cargo run -p plotgram-cli` 验目标图  
2. 节点坐标相对基线可解释（仅预期节点动）  
3. 相关单测 + 全量严重度不升  
4. 无图名分支  
5. 目标图视觉通过但全量门禁失败时，只能声明「目标修复」，不得声明「无退化」

## 2. 母题与判定规则

### 2.1 两类系统问题

1. **语义错位（假邻居）**：邻居/边集宽于或方向异于 FAS **effective** DAG + **邻层**约束。  
2. **契约破坏**：陈旧下标、尺寸双轨、几何已换标签未换、端点离框、**检测成功却不修复**。

### 2.2 通用判定（审计复用）

1. DAG 语义单一来源（effective 邻接）  
2. 邻域默认 rank±1；长边经 dummy，禁止远端 real 直接进 median  
3. 后处理不得宽于主算法（coordinate / stub_fix / straighten）  
4. 硬过滤与软惩罚一致；检测为真须改善或显式 degraded  
5. 确定性枚举（显式排序 / `IndexMap` / `BTreeMap`）  
6. 端点在边界；换几何后重建标签；容器变异后重算下标；单尺寸源  

### 2.3 有意启发式（勿当 bug）

长边 barycenter/dummy 加权、`stub_fix` 长度容忍、straighten 直连偏好、长跨度侧通道阈值、degraded fallback、合法单调台阶暂留、overlap 迭代上限等。

## 3. 正交管线与 sanitize

### 3.1 统一阶段序（追 gap / 共锚时对照）

```text
4b replan_slots
 → 4c straighten_align
 → 4d reroute
 → 4e stub_fix              ← 在 lane 之前
 → 4f lane_assignment
      └─ enforce_reverse_pair_min_gap  ← C 预修（正反向窄域）
 → S3 semantic_trunk_merge             ← 先业务 FanIn，写 MergeInterval
 → S4 monitor outer reroute
 → 4g sanitize               ← 保守；collapse + simplify（可压 parallel gap）
 → S4.x monitor escape repair
 → B.2 monitor local trunk             ← 必须在 S4/S4.x 后，否则会被覆盖
 → [pipeline] snap_and_repulse
 → sanitize_ext(merge_overshoot=true)
 → enforce_reverse_pair_min_gap  ← D 一次审计
 → enforce_reverse_pair_dock_separation
 → label_resolve             ← 最终避让，不可再被 sanitize 丢掉
 → dedupe labels on declared merges
```

正反向 gap 写权（P3.1）：**仅** C 预修（4f 末）+ D 审计；4g 后不再连环 enforce。

### 3.2 Sanitize 职责（E0）

| 步骤 | 意图 | 注意 |
|------|------|------|
| `fix_endpoint_reverse_stub` | 切背向折点 | 禁止 stub-only 截断 |
| `ensure_outward_stub` / `repair_post_stub_inward` | 外向 stub | 已修内向肘 |
| `force_orthogonal` / `collapse_micro_jogs` | 整形 | 共线合并分数选角；非救穿模 |
| `simplify_path`×2 | 合并近共线 | 可压 parallel gap |
| `merge_overshoot`（**仅末尾**） | 消 Z 折 | 无障时可能拉直侧通道台阶（R12 边界） |
| 安全网回退 | 保连通 | 可能保留脏几何 → 依赖 degraded |

### 3.3 走廊、stub 与合流的边界

1. **节点 stub 与组边框腿不是同一种资源**：节点端必须满足 port outward/clearance；走廊已在目标组外侧时，入组腿应直接接边框，不能再按 `entry_side` 向外走一步后折返。
2. **禁止用 sanitize 掩盖构造器错误**：走廊产生 Z 折时先修 exit/entry/final leg 的方向；`collapse_micro_jogs` 没有障碍与完整语义，不应在 4g 强制换另一候选角。
3. **合流只改必要范围**：普通 FanIn 保留源端 stub 和既有绕障前缀，目标附近接共享 trunk；同 rank、同出侧 pendant 为保持对称，可在源 stub 后立即合流。
4. **监控合流后置**：S4 外环负责与业务干线分流；监控局部 trunk 必须在 S4/S4.x 后写，且只合目标同侧，不得取消外环。
5. **共享干标签去重**：同一显式 `MergeInterval.group_key` 上文案相同的标签只保留确定性代表；不同文案不得吞并。

### 3.4 层缝与 refine 的作用域

- 禁止全图按 X 投影重叠枚举“同列”并逐节点下推：它会跨 group、跨宏 rank 级联扩壳。
- 层缝检查至少以 `(leaf-group scope, sugiyama rank)` 为域；普通节点只处理真实投影碰撞，正反向对可声明更强的 clearance 需求。
- 跨 rank 修复应移动下游 rank **整带**，保持同层关系；但在 refine 反馈环中不直接执行该修复，而是比较候选前后违规集合：候选新制造违规则回滚。
- 最终 guard 可修初始布局残余，但任何节点移动都必须触发 group frame 刷新与相关边重路由。

### 3.5 全局变换与正交降级

- `RouteAnnotationSet` 使用绝对坐标；canvas padding、标题带裁剪等 `translate_all` 必须同步平移 start/end、stub、protected run、merge interval 与 occupancy 轴。只平移路径会让渲染误把合流角画成圆角。
- 正交图的 refine 不得把密采样 spline 写回 `Polyline` 再交给 `force_orthogonal`；斜线采样会被栅格化为人类不会绘制的连续阶梯。
- **architecture / 正交原边**：refine 降级一律走障碍感知 dogleg / 多层外廊；问题边再多也禁止退回 spline。候选须通过与 lint 对齐的穿节点/穿组硬过滤；找不到干净通道则保留原边。
- 正交降级必须仍由障碍上下文生成：优先单次 dogleg，其次左右/上下外廊；按折点数、长度、确定性坐标选优。无合法候选时显式 degraded，禁止无障碍后处理“猜直”。
- 同宿 FanIn 若所有源节点明确位于目标同一侧，应先统一目标正对端口，再做 semantic merge；后续 stub 修正不得按单边最短路把成员旋到其它侧。
- 仅穿组不穿节点的边也必须进入 refine fallback 候选，否则永远得不到纠正。

## 5. V3b：邻层悬挂对齐（已落地）

### 5.1 语义

| 情形 | 对齐 |
|------|------|
| 单 pendant | movable 与 anchor **主轴中心重合**（门禁 ≤ 2px） |
| 同锚同层多 pendant | **组质心**对齐 anchor；组内按 **`node_gap`**（非 `layer_gap`）对称排开 |

flowchart 走 `sugiyama_v2`；architecture 的 L2 **不**自动覆盖 flowchart。路由后禁止挪节点。

### 5.2 P-Pendant

- rank 相邻；**无向邻层 Real 邻居集合** = `{anchor}`（按邻居节点数，**非边条数**）  
- Dummy 不计入；**禁止**全图 `all_pred`  
- 锚点邻层邻居集大小 > 1（枢纽）；两端皆叶 → skip（P-Mutual 未做）

### 5.3 R1–R4

- **R1** 锚点不动，只动 movable / 组  
- **R2** 冲突：先 pack；仍与非 pendant 冲突 → 整组放弃  
- **R3** 每节点本轮至多写一次；pack = 组内原子赋值，禁止二次微调；失败整组回滚  
- **R4** 两对抢同一 movable → 锚点邻居更多或上层优先  

### 5.4 S-PackUnderAnchor

- **E1** 组内皆同锚 P-Pendant；**E2** 推荐整层 Real 皆该组，否则降级 SkipIfConflict  
- 排序 `(center, id)`；scoped `node_gap` 校验失败 → 回滚  

### 5.5 调用序

```text
BK + compaction + overlap
 → align_singleton_layers
 → normalize_layout_to_padding
 → ★ align_pendants_under_anchors   // 必须在 normalize 之后
 → route …
```

`finalize_canvas_bounds` 可能因 bbox 左扩做**整体**平移；非 pendant 的相对关系应保持。  
单测：`sugiyama_v2::tests::v3b_user_auth_pendants_pack_under_auth`。  
与 V3a 正交：先布局对齐 → 路由 → gap。

## 7. 重构 ROI 原则（非清单）

1. 死代码零成本删（无生产引用、过时 backup 注释等）— 符合 AGENTS §1；O6.1 已清一批，见开放项计划  
2. 曲线路由：障碍检测 / 前置设置 / 采样常量一处定义  
3. space_budget：`reroute_and_repulse` 统一含 `repulse_edges_only`；pipeline 与 `complete_routing` 须传同一 `edge_snap_config`（O6.2 已对齐）  
4. 巨型阶段函数按 phase 拆（正交主流程见 `edge_routing_orthogonal/run.rs`，O6.3）— 便于时序审计  
5. scoring 平行段 conflict/spacing 统一分类  
6. LayoutHints / 阶段写权文档化（对接「多写者」母题）  
7. sugiyama 与 architecture coordinate **不是**字节拷贝；勿误合并  
8. semantic annotation 一旦存在，渲染、sanitize 校验、标签归属应复用同一来源，禁止各自再推导一套 FanIn/共享干语义
9. 布局缝、hub 对齐、group frame 若有多个写者，应合并为一个最终重申阶段；其余阶段只检测或拒绝候选

lint 与性能冲突时：优先算法效果与简洁性（`AGENTS.md` §4）。

## 8. 给 Agent 的最短清单

1. 改前读本文 §1–§3；动坐标只在路由前。  
2. 验证用 `cargo run -p plotgram-cli`，不信陈旧 release binary。  
3. Label/折点：先画「谁最后写结果」。  
4. 回归：坐标 diff + 严重度 + 单测；既有失败先钉死。  
5. 无图名特判；检测为真须修复或显式 degraded。  
6. WASM 路径禁用裸 `std::time::Instant`（见 `AGENTS.md` §6）。
7. sharp/round corner 看 annotation，不看路径点数。
8. refine 新造空间违规就回滚，不在反馈环里二次推点。
9. 单图修好但全量严重度失败时，明确保留门禁红灯与样例清单。
