## 3. Phase C1′ — 穿节点硬约束（审计方案，非「禁止无契约线」）

### 3.1 采用的策略（接受评审 §问题 5）

| 语境 | 策略 |
|------|------|
| **非 degraded** | 禁止 `node_dirty=1` 胜出（主路径已基本如此） |
| **degraded** | **仍允许** dirty，避免边消失；同时强制升档（channel / z-fold / 外框）再搜，尽量找 clean |
| **禁止** | 「预算 1–2 档扩走廊失败 ⇒ 无输出」——劣于穿模 |

### 3.2 执行步骤

1. **对照 §11.3 R2**：确认 `orthogonal_degraded_fallback` 是否在选 dirty 前已用尽升档；不足则补升档循环（有上限，但上限内优先 clean）。  
2. **R11 分析交付物**（短文即可）：from/to 全程豁免导致哪些自穿漏网；方案选项：  
   - (a) 仅豁免端点 stub 长度内；  
   - (b) 豁免源/宿但中间段仍检测穿过源/宿盒；  
   - 选定后再改，避免误伤合法 stub。  
3. **R3**：确认 corridor / 穿组约束是否仍漏；与 R2 升档一并验。  
4. Gate：无 clean 时图上边仍在；degraded 可打点/统计；非 degraded 无 `edge_through_node`。  
5. **R1**：已落地（§2.1），本批**不重做**；回归时勿回滚 `opposite_channel_path_is_clean`。

### 3.3 明确不做

- 新建空壳 `geometry_contract.rs`「重申」C-Attach/C-Outward/C-Connected（已有保证处）。  
- 若未来抽契约模块：只封装**仍会被违反**的检查（自穿漏网、gap、同侧互斥），作为测试/CI 助手，而非大重构前提。

## 5. Phase E — V2 / V3（在 C1′ + E0 之后）

### 5.1 V2 — 同侧入出错开（先分析现有 slot）

**禁止**：未分析就新建 `allocate_port_slots` 与 `DockingStrategy` 平行的第二套 API。

#### E-V2.1 分析任务（先读代码，再针对性 dump）

**问题 1（代码已确认，不必再猜）**：`endpoint_bundling_key`（`mod.rs`）含 `is_from` → 同侧 **in / out 必然分桶**；两侧若各只有 1 条边 → 各自 `DockingStrategy::Single` → 均得中心 `frac=0.5` → **共锚是分桶设计结果**，不是 Compact 间距偶然撞车。  
分析时把它当作前提；dump 仅用于**确认现场锚点坐标**与回归对照，不把精力花在「是否同桶」上。

剩余问题（分析主战场）：

2. 同侧 **多条同向**（皆 in 或皆 out）时：是 **Compact 16px 不够**，还是 **Concentrate 共享中心** 故意汇流？**入出混合**场景是否应禁用 Concentrate、改为跨 `is_from` 联合 Compact？  
3. 共竖干是否来自 **lane_assignment** 合并 trunk（锚点已错开但干线 x/y 被并）？  
4. `replan_slots` / `deconflict_flip_anchor` 是否覆盖该路径，或仅 flip 后触发？对「分桶共锚」是否完全无触及？

#### E-V2.2 方案原则（分析后选一）

| 方向 | 适用 |
|------|------|
| **增强现有（优先）** | 同 `(node, side)` **跨 `is_from` 联合**走 Compact 分布，打破「分桶各 Single → 共心」；入出混合禁止 Concentrate 共心 |
| **扩展 deconflict** | 把 `deconflict_flip_anchor` 提升为「凡写入锚点后」的通用去冲突，复用 SLOT 间距（可与上条叠加） |
| **lane 保槽位** | 锚点已分离时，禁止无关 trunk 合并抹平切向差 |

对齐 ELK「每边独立 port」= **互斥切向坐标**，不是新名词 API。

#### E-V2.3 Gate

- 同节点同侧 ≥2 条边（含一入一出）：切向间距 ≥ 现有 Compact 间距（或明确参数）。  
- 无图名特判；`stress_nested` 核心业务服务无「单竖线穿心」观感。

### 5.2 V3a — Parallel gap（先追管线）

#### E-V3a.1 分析任务（必须先交付）

按**真实管线顺序**（`mod.rs` 约 372–484 + `pipeline.rs` 末级）记录平行段间距，**不要**把 stub_fix 当成 lane 之后的嫌疑步骤：

```text
4b replan_slots
 → 4c straighten_align
 → 4d reroute
 → 4e stub_fix          ← 在 lane 之前；不可能是「lane 之后压破 gap」的元凶
 → 4f lane_assignment    ← 此处应按 min_gap=parallel_gap 分离
 → 4g sanitize           ← collapse_micro_jogs + simplify_path×2 等，可能微移坐标
 → 5 labels
 → [pipeline] snap_and_repulse          ← 像素量化可能碰 gap
 → sanitize_ext(merge_overshoot=true)   ← 激进 overshoot 合并
 → label_resolve
```

**lane 之后**重点追：`4g sanitize`（含 `simplify_path`）、`snap_and_repulse`、`sanitize_ext(merge_overshoot=true)`。  
另记：`lane_assignment` 若用 `abs(layer差) >= min_gap` 跳过同组，可能留下「恰好贴下限」的段，下一碰即破。

交付：在哪一步 gap 从 ≥ `profile.parallel_gap` 掉到 &lt; gap。

#### E-V3a.2 方案（仅分析完成后填写）

候选（分析前不预选）：

- 对会移动共线平行段的步骤加 **gap 守卫**（违则跳过该变换）  
- 或 pipeline 末级 **再跑一次** 最小 lane 分离  
- 或收紧 sanitize/merge 对「已分离平行段」的触碰条件  

Gate：`n.user-auth` 平行段 min gap ≥ profile；节点坐标不因本步改变。

#### E-V3b.1 若仍需拉齐——定义（消除模糊）

| 术语 | 定义 |
|------|------|
| **单跨边邻层对** | 两 real 节点分属相邻 rank，且其间**恰好一条**有效前向边（无多边扇出干扰）；或「该层对该节点唯一主跨邻」——实现前在测试里写死判定函数 |
| **无冲突** | 将 A 中心移向 B（或互相加权）后：同层最小间距仍满足；不产生节点重叠；不破坏已有 BK 块顺序 |
| **时机** | **仅布局阶段、路由之前**；禁止路由后挪节点 |

优先复用/扩展现有 `align_singleton_layers_to_predecessors` 类逻辑，避免第三套对齐。
