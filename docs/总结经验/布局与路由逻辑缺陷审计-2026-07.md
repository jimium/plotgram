# 布局与路由逻辑缺陷审计

> 日期：2026-07-13（扩写同日：不限「假邻居」类，补充其它正确性缺陷）  
> 位置：`docs/总结经验/`  
> 触发：状态图修复会话中发现「FAS 假前驱污染 singleton 对齐 median」类缺陷后，对布局/路由做逻辑错误复盘  
> 对照：[布局与路由改造踩坑复盘-2026-07.md](./布局与路由改造踩坑复盘-2026-07.md)、仓库 [`AGENTS.md`](../../AGENTS.md) §2 / §5  
> 范围：`sugiyama_v2` / `architecture_v2` / `state` / `sequence` / `edge_routing_*` / `edge/common` / `refine` / `pipeline`

## 0. 一句话结论

本轮暴露两类会**直接损害绘图正确性**的系统问题：

1. **语义错位（假邻居母题）**：后处理 / 对齐 / 侧通道用的邻居或边集合，宽于或方向异于 FAS effective DAG + 邻层约束。  
2. **契约破坏（本节扩写）**：索引在变异容器上失效、放置宽度与游标宽度不一致、几何已换路径但标签仍按旧曲线采样、端点离开节点边界、检测成功却不修复等。

下列条目区分 **真逻辑错误**、**部分修复残余**、**有意启发式**；禁止用图名特判「修观感」。

## 1. 母题：已知已修案例（定标尺）

这些是「什么叫逻辑错误」的标尺，后续发现都按同一标准归类。

| ID | 表象 | 真正根因 | 修复要点 | 状态 |
|----|------|----------|----------|------|
| K1 | TCP：`SYN_RCVD→…→LAST_ACK` 阶梯右偏 | `align_singleton_layers_to_predecessors` 用**全部** DAG 前驱 median；FAS 反转长回边变成假前驱 | 主路径只认**邻层**前驱/后继 | **已修（主路径）**；fallback 仍开放 → L1 |
| K2 | warning→healthy 穿节点列 | 仅 FAS 回环边拿侧通道；长前向边走 Bottom↔Top；`stub_fix` 又把侧端口翻成 Top | 长跨度边进侧通道；侧通道边禁止 stub 翻 LR↔TB | **已修** |
| K3 | 引线指到箭头 / 一律中点破坏架构图 | 最近点落终点；错误改为强制 t=0.5 | 在**端点保护区外的弧长窗口内**找最近点 | **已修（引线）**；标签候选仍开放 → R4 |
| K4 | 双向弧贴在一起 | circular 正反边都走短弧同侧 | `arc_side` ±1 弦两侧分离 | **已修（同圆）**；跨圆仍开放 → R8 |
| K5 | label 避让被丢 / overshoot 死锁 | 管线时序 + sanitize 启发死锁 | 末尾 sanitize + 再 resolve；共线分数选角 | **已修**（见踩坑复盘） |

**通用判定规则**（后续审计复用）：

1. **DAG 语义单一来源**：median / barycenter / alignment / spine / side-channel 必须在 FAS **effective** 邻接上操作。  
2. **邻域默认 rank±1**：长边只经 dummy 进入邻域，禁止远端 real 节点直接进 median。  
3. **后处理不得宽于主算法**：coordinate / stub_fix / straighten 不得使用比 order/BK 更宽的邻居或更自由的端口。  
4. **硬约束与软惩罚一致**：`path_is_clean` 拒绝的路径不应仅因短而从 dirty 通道胜出；检测为真必须有修复或显式 degraded。  
5. **确定性**：驱动布局的节点/边枚举显式排序（AGENTS.md §2）。  
6. **几何契约**：路径端点在节点边界；替换几何后标签/引线同步重建；容器变异后不得用陈旧下标；同一布局只用一套尺寸源。

## 2. 布局算法发现

### 2.1 P1 — 真逻辑错误 / 高风险

#### L1 — singleton 对齐 fallback 仍用全图邻居（K1 残余）

| 项 | 内容 |
|----|------|
| 位置 | `sugiyama_v2/coordinate.rs` → `align_singleton_layers_to_predecessors` |
| 症状 | 无邻层前驱/后继时回退 `all_pred_centers` / `all_succ_centers`，再次纳入 FAS 假邻居 |
| 为何是逻辑错误 | 主路径注释已写明「只认邻层」，fallback 复现同一 bug class |
| 状态 | **部分修复** |
| 修复方向 | fallback 也只允许 rank±1；再无则 **跳过**，不要用全图邻居 |

#### L2 — Architecture 无 group 路径 BK：缺 effective 边 + 长边无 dummy

| 项 | 内容 |
|----|------|
| 位置 | `sugiyama_v2/coordinate.rs` → `assign_layer_centers_for_string_graph`；调用方 `architecture_v2/layout/coordinate.rs` |
| 症状 | （1）rank/order 用 `is_effective_edge`，BK 建边却扫原始 `out_edges`；（2）只连 `to_layer == from_layer + 1`，**不插 dummy**，rank 差 ≥2 的边对 BK 完全不可见 |
| 为何是逻辑错误 | 与 `build_proper_layer_graph`（会插 dummy）行为不一致；长边端点无法竖直对齐，正交路由易多余折弯 |
| 状态 | **开放** |
| 修复方向 | BK 建边走 effective DAG；跨层边插 dummy 或复用 proper layer graph 入口 |

#### L3 — `align_nodes_to_neighbors` 后处理可覆盖 BK

| 项 | 内容 |
|----|------|
| 位置 | `architecture_v2/layout/coordinate.rs` → `align_nodes_to_neighbors`；`NeighborAlignmentPhase` |
| 症状 | 对全部 in/out 边取 median，无 `is_effective_edge`、无邻层过滤；单节点层直接平移 |
| 为何是逻辑错误 | 与 K1 同类，且在 BK **之后**运行，可撤销正确对齐 |
| 状态 | **开放** |
| 修复方向 | 仅 rank±1 + effective 边；或与 singleton 对齐共用一套邻居过滤 |

#### L4 — `pull_toward_neighbors` 缺 effective 边过滤

| 项 | 内容 |
|----|------|
| 位置 | `architecture_v2/layout/coordinate.rs` → `pull_toward_neighbors`（组内/ intra 坐标仍调用） |
| 症状 | 有邻层 `neighbor_x` 过滤，但仍遍历原始 in/out；邻层上的反转边仍可拉动 |
| 为何是逻辑错误 | 「邻层」必要但不充分；方向必须是 effective DAG |
| 状态 | **开放** |
| 修复方向 | 增加 `reversed` / `is_effective_edge`，与 order 一致 |

#### L5 — 状态图 semantic rank 硬覆盖可破坏 DAG 单调性

| 项 | 内容 |
|----|------|
| 位置 | `sugiyama_v2/engine.rs` → `apply_state_semantic_rank_constraints`（`initial→0`，`final→max`） |
| 症状 | 若 DAG 中存在指向 initial 的边或从 final 出发的边，硬改 rank 产生 `rank(u) ≥ rank(v)` 的回退边；`build_proper_layer_graph` 可能画非 proper 层间边 |
| 为何是逻辑错误 | 语义约束未与拓扑求交，结构性违反分层前提 |
| 状态 | **开放** |
| 修复方向 | 冲突时传播调整或降级为软约束；禁止单点硬覆盖破坏 `∀(u→v): rank(u)<rank(v)` |

### 2.2 P2 — 中低风险 / 设计边界

| ID | 位置 | 问题 | 状态 |
|----|------|------|------|
| L6 | `engine.rs` → `apply_group_rank_constraints` | group 窗口重排后 ungrouped 节点原 rank 不变，可能跨界倒挂 | 开放（设计取舍） |
| L7 | `architecture_v2/.../infrastructure_anchor_x` | 锚点用任意层已放置邻居，无 FAS/邻层过滤 | 开放 |
| L8 | `center_group_hub_nodes` / `align_client_nodes_to_hubs` | 有下层集合过滤，缺 `is_effective_edge` | 开放 |
| L9 | `compute_spine_nodes` | FAS-DAG 上按出度贪心；长前向捷径可能抢走 spine | 启发式（影响 BK tie-break / compaction 权重） |
| L10 | `sugiyama_v2/graph.rs` → `greedy_cycle_reversal` | `node_indices().collect()` 未按 id 排序；与 `state/mod.rs` 显式 `sort` 不一致 | 开放（确定性） |

### 2.3 布局侧已正确（对照基线）

- `sugiyama_v2/order.rs` 的 `weighted_median_stats`：经 `neighbor_pos` 隐式限邻层。  
- BK `vertical_alignment_blocks` / conflict 检测：显式邻层。  
- `architecture_v2` rank/order：普遍 `is_effective_edge`。  
- `common/acyclic.rs` → `greedy_fas`：sink/source 剥离前排序。  
- `compact_layer_centers`：在 layered_graph 上操作，real 邻居必邻层。

## 3. 路由算法发现

### 3.1 P1 — 真逻辑错误 / 高风险

#### R1 — `rank_span==1` 仍偏好正对端口，可穿中间列

| 项 | 内容 |
|----|------|
| 位置 | `feedback_side.rs` → `prefers_opposite_ports_over_side_channel` |
| 症状 | 相邻层且投影重叠时跳过侧通道；几何上中间仍可能有节点列 |
| 为何是逻辑错误 | 用图 rank 差代替「正对通道是否干净」；与 K2 同类边界漏网 |
| 状态 | **开放** |
| 修复方向 | `rank_span==1` 时对正对候选跑 `path_is_clean`；不干净则强制侧通道 |

#### R2 — 无 clean 候选时可选穿节点 dirty 路径

| 项 | 内容 |
|----|------|
| 位置 | `path.rs` → `select_best_path_with_scorer_stats` / `orthogonal_degraded_fallback` |
| 症状 | `best_strict` / `best_nodes_only` 皆空时走 `best_dirty`；兜底允许 `node_dirty` |
| 为何是逻辑错误 | 硬过滤与软惩罚不一致；干净通道未生成时短脏路径胜出 → lint `edge_through_node` |
| 状态 | **开放**（部分为故意降级，但与产品「不穿节点」冲突） |
| 修复方向 | dirty 前强制升档 channel/z-fold；非 degraded 标记禁止 node_dirty |

#### R3 — 非 corridor 边不强制 `path_avoids_group_interiors`

| 项 | 内容 |
|----|------|
| 位置 | `mod.rs` → `should_strict_group_transit`；`path.rs` 选择分支 |
| 症状 | 非 corridor 架构边可走 `best_nodes_only`（穿无关 group） |
| 为何是逻辑错误 | 分组硬约束与 `GROUP_TRANSIT_PENALTY` 软惩罚混用 |
| 状态 | **开放**（注释称防 k8s 回归） |
| 修复方向 | 长跨度/feedback 边强制避组内部；或 profile 级 strict 开关 |

#### R4 — 标签候选仍用无保护区最近点（K3 残余）

| 项 | 内容 |
|----|------|
| 位置 | `label_candidate.rs` → `preferred_t_for_label` / `path_t_for_center` / `score_candidate` |
| 症状 | 引线已用 `leader_anchor_on_path`；标签本体偏好 t 仍可被箭头端 stub 吸引 |
| 为何是逻辑错误 | 同类缺陷不同代码路径；引线修好后标签仍可贴箭头 |
| 状态 | **开放** |
| 修复方向 | 共享「弧长窗口内最近点」工具函数 |

#### R5 — circular 穿障检测成功但 detour 为空时保留穿障曲线

| 项 | 内容 |
|----|------|
| 位置 | `edge_routing_circular.rs` → `route_edges_circular` |
| 症状 | `curve_intersects_obstacles` 为真且 `shortest_path` 为空 → 仍输出穿障 Bezier |
| 为何是逻辑错误 | 检测与修复不对称 |
| 状态 | **开放** |
| 修复方向 | 空 detour 时 outer 折线 / spline 全路由 / 显式 degraded 标记 |

### 3.2 P2 — 中低风险

| ID | 位置 | 问题 | 状态 |
|----|------|------|------|
| R6 | circular `compute_lane_offsets` | `from_groups.values()` 未按 key 排序 → 扇出 lane 可能抖动 | 开放（确定性） |
| R7 | circular 障碍索引构建 | `HashMap` 迭代建 `node_list` / idx → skip 索引不稳定 | 开放（确定性） |
| R8 | `route_inter_circle_edge` | 跨圆双向边无 `arc_side`（仅同圆修了） | 开放 |
| R9 | `coordinate_port_sides` vs feedback 覆盖 | 协调按 pair 整组改端口，覆盖只按 hint 边恢复 | 部分 |
| R10 | `rank_span_for_edge` 无 ranks | 像素/48 估算可能达不到长跨度阈值 | 开放 |
| R11 | `path_is_clean` 端点豁免 | from/to 全程豁免，中间段仍可穿源/宿节点膨胀盒 | 开放（或为 stub 故意放宽） |
| R12 | 管线末尾 `merge_overshoot` | 无障碍上下文，可能拉直侧通道台阶 | 已知边界（踩坑复盘 §7） |
| R13 | `label_avoidance` 节点障碍 | Phase-2 未排序；与 `label_candidate` 不一致 | 开放（确定性） |

## 4. 其它正确性缺陷（不限假邻居类）

本节为第二轮扩写：凡**破坏几何契约 / 索引契约 / 检测-修复对称性**、导致漏画、穿模、重叠、端点离框、标签挂错路径的，均收录。已用源码核对。

### 4.1 布局：索引 / 尺寸 / 成员集合契约

#### C1 — `group_aware_reorder`：在已变异的 `result` 上用原始下标（P1）

| 项 | 内容 |
|----|------|
| 位置 | `architecture_v2/layout/order.rs` → `group_aware_reorder`（约 177–224） |
| 症状 | 同层多个「多成员 group」时，先处理的组会 `remove`/`insert` 改写 `result`；后续组仍用**第一次** `ordered` 的下标去索引**当前** `result`，取错/删错节点 |
| 为何是逻辑错误 | 「从后往前」只保证**单组内** remove 安全；跨组后下标契约已失效，排序结果确定性错误 |
| 复现 | Architecture 全局 Sugiyama：同 rank 两个 top group 各 ≥2 节点 |
| 状态 | **开放** |
| 修复方向 | 每轮按**当前** `result` 重算组成员位置；或一次性用稳定置换生成新序，禁止边变异边索引 |

#### C2 — 无 group 节点被当成同一组 `""` 吸附（P1）

| 项 | 内容 |
|----|------|
| 位置 | 同上，`unwrap_or_default()` → gid `""` |
| 症状 | 层内 ≥2 个基础设施/无组节点被当成「同一多成员组」强行聚块 |
| 为何是逻辑错误 | 注释意图是「同 top group 相邻」，实现把互不隶属节点并组 |
| 复现 | 基础设施行或多 ungrouped 同层 |
| 状态 | **开放** |
| 修复方向 | 无 group 时**不**进入 multi_groups；仅对真实 gid 吸附 |

#### C3 — Sequence 放置用 `w`、游标步进用 `DEFAULT_NODE_WIDTH`（P1）

| 项 | 内容 |
|----|------|
| 位置 | `layout/node/sequence.rs` → `compute`（约 118–130） |
| 症状 | `NodeLayout.width = styled_node_size(...).w`，但 `current_x += DEFAULT_NODE_WIDTH + spacing`；长标签参与者与右侧重叠，`total_width` 偏小 |
| 为何是逻辑错误 | 同一布局用两套宽度，违反矩形不重叠不变量 |
| 复现 | Sequence：多个长 label / 加宽样式参与者 |
| 状态 | **开放** |
| 修复方向 | 游标与 `total_width` 一律用实际 `w` |

#### C4 — 组内同 rank Y 对齐漏 `group_id` 成员（P2）

| 项 | 内容 |
|----|------|
| 位置 | `architecture_v2/two_phase.rs` → `align_intra_group_same_rank_y`（约 1860+） |
| 症状 | 只扫 `g.entity_ids`；仅挂在 `entity.group_id` 上的成员不参与 Y 微对齐；与 `effective_entity_ids` 成员集不一致 |
| 为何是逻辑错误 | 同组节点集合定义不唯一 → 视觉不齐 |
| 状态 | **开放** |
| 修复方向 | 与 `group_bounds::effective_entity_ids` 共用成员解析 |

#### C5 — BK `horizontal_compaction` 在 `lower>upper` 时仍写入违反下界的坐标（P2）

| 项 | 内容 |
|----|------|
| 位置 | `sugiyama_v2/coordinate.rs` → `horizontal_compaction`（约 693–712） |
| 症状 | 约束冲突时 `candidate.min(upper)` 可得到 `< lower_bound`，层内间距约束被打破 → 同层重叠风险 |
| 为何是逻辑错误 | compaction 应保证分离；不可行时应显式失败/放松，而非静默违反下界 |
| 状态 | **开放**（边界退化） |

### 4.2 路由：端点 / 标签 / 几何契约

#### C6 — 平行边端点平移后离开节点边界（P1）

| 项 | 内容 |
|----|------|
| 位置 | `edge/common/routing_skeleton.rs` → `resolve_endpoints`（约 90–98） |
| 症状 | `edge_point` 得边界点后，对起终点施加同一法向 `(ox,oy)`；点一般**不再在边界上**，`select_port` 也可能选错侧 |
| 为何是逻辑错误 | 破坏「路径端点 = 节点边界端口」契约；箭头从框内/框外画出 |
| 影响 | 走该骨架的 straight / bezier / spline / organic |
| 复现 | 同对节点多条边，`edge_routing: bezier`；放大端点 |
| 状态 | **开放** |
| 修复方向 | 沿边界切线分配 slot，或只偏移路径中段、端点重投 `edge_point` |

#### C7 — 穿障改折线后标签仍按旧 Bezier 采样（P1）

| 项 | 内容 |
|----|------|
| 位置 | `edge_routing_bezier.rs`（约 173–201）、`edge_routing_circular.rs`、`edge_routing_organic.rs` |
| 症状 | 先 `build_edge_labels(..., cubic_bezier_point)`，再 `geometry = Polyline{detour}`，**不重建 labels** |
| 为何是逻辑错误 | 可见路径已是绕行折线，标签/引线仍挂在旧曲线参数 t 上 |
| 对照 | `edge_routing_spline.rs` 与正交 `sanitize` 会重建标签 |
| 状态 | **开放** |
| 修复方向 | 替换几何后用新 `path_points`/`sampled_path` 统一重建 labels |

#### C8 — Curved 自环端点在节点内部（P1）

| 项 | 内容 |
|----|------|
| 位置 | `edge/common/self_loop.rs` → `curved_loop_endpoints`（约 209–228） |
| 症状 | `sx/sy/ex/ey = center ± scale*0.35` 等**内点**公式，未 `edge_point`；箭头从框内穿出 |
| 为何是逻辑错误 | 与正交自环（用边界坐标）契约不一致 |
| 复现 | 任意 `a -> a` + circular / curved self-loop |
| 状态 | **开放** |
| 修复方向 | 改用 `edge_point` 或与正交自环同源边界公式 |

#### C9 — refine spline 兜底无质量门控（P1）

| 项 | 内容 |
|----|------|
| 位置 | `layout/refine/mod.rs`（约 149–157）、`refine/spline_fallback.rs` |
| 症状 | 仍穿障则**无条件**替换；空 detour 时退 Bezier **不**再验穿障；不比较替换前后 `edge_node_crossings` |
| 为何是逻辑错误 | refine 本意改善几何；无回归检查可变差或「兜底」后仍穿障 |
| 状态 | **开放** |
| 修复方向 | 替换前比较 crossing/长度；不改善则保留原路径 |

#### C10 — lane 用 `dy≈0` 判水平，斜段会沿错误轴平移（P2）

| 项 | 内容 |
|----|------|
| 位置 | `edge_routing_orthogonal/lane_assignment.rs` → `assign_lanes` |
| 症状 | 残留斜段被当竖段，对 x 做 offset → 非正交甚至自交 |
| 为何是逻辑错误 | 契约是「仅 H/V 段分离」；斜段应先 `force_orthogonal` 或跳过 |
| 状态 | **开放**（依赖上游消毒；消毒失败时爆发） |

#### C11 — refine 穿障检测缩小节点 → 贴边穿过漏检（P2）

| 项 | 内容 |
|----|------|
| 位置 | `refine/crossing.rs` → `analyze_edge_node_crossings`（`node_shrink` 默认 2） |
| 症状 | 边穿过节点外缘壳层不算穿障 → refine 早退 |
| 为何是逻辑错误 | 假阴性使视觉穿模得不到修复 |
| 状态 | **开放** |

#### C12 — bezier/circular 穿障采样固定 16 点，窄障碍可漏检（P2）

| 项 | 内容 |
|----|------|
| 位置 | `edge_routing_bezier.rs` / `circular` → `OBSTACLE_CHECK_SAMPLES = 16` |
| 症状 | 薄障碍落在采样间隙 → 不触发 detour，曲线实穿节点 |
| 状态 | **开放** |

#### C13 — Sequence 产边后跳过路由；若开启 node align，边不随节点更新（P2）

| 项 | 内容 |
|----|------|
| 位置 | `pipeline.rs`（`produces_edges` 跳过路由）+ `apply_node_frame` align |
| 症状 | 默认 sequence align 关闭；若 diagram override 开启，参与者移动后面消息端点仍指向旧 x |
| 为何是逻辑错误 | `translate_all` 只修整体平移，不修相对位移 |
| 状态 | **开放**（条件触发） |
