## 0. 一句话结论

本轮暴露两类系统问题；其中 **P1 条目会直接损害绘图正确性**，**P2 条目主要体现为边界退化、确定性风险或契约风险**：

1. **语义错位（假邻居母题）**：后处理 / 对齐 / 侧通道用的邻居或边集合，宽于或方向异于 FAS effective DAG + 邻层约束。  
2. **契约破坏（本节扩写）**：索引在变异容器上失效、放置宽度与游标宽度不一致、几何已换路径但标签仍按旧曲线采样、端点离开节点边界、检测成功却不修复等。

下列条目区分 **真逻辑错误**、**部分修复残余**、**有意启发式**；禁止用图名特判「修观感」。

## 1. 母题：已知已修案例（定标尺）

这些是「什么叫逻辑错误」的标尺，后续发现都按同一标准归类。

| ID | 表象 | 真正根因 | 修复要点 | 状态 |
|----|------|----------|----------|------|
| K1 | TCP：`SYN_RCVD→…→LAST_ACK` 阶梯右偏 | `align_singleton_layers_to_predecessors` 用**全部** DAG 前驱 median；FAS 反转长回边变成假前驱 | 主路径只认**邻层**前驱/后继 | **已修（主路径）**；fallback 仍开放 → L1 |
| K2 | warning→healthy 穿节点列 | 仅 FAS 回环边拿侧通道；长前向边走 Bottom↔Top；`stub_fix` 又把侧端口翻成 Top | 长跨度边进侧通道；侧通道边禁止 stub 翻 LR↔TB | **已修** |
| K3 | 引线指到箭头 / 一律中点破坏架构图 | 最近点落终点；错误改为强制 t=0.5 | 在**端点保护区外的弧长窗口内**找最近点 | **已修（引线）**；标签候选仍开放 → R4 |
| K4 | 双向弧贴在一起 | circular 正反边都走短弧同侧 | `arc_side` ±1 弦两侧分离 | **已修（同圆）**；跨圆仍开放 → R8 |
| K5 | label 避让被丢 / overshoot 死锁 | 管线时序 + sanitize 启发死锁 | 末尾 sanitize + 再 resolve；共线分数选角 | **已修**（见踩坑复盘） |

**通用判定规则**（后续审计复用）：

1. **DAG 语义单一来源**：median / barycenter / alignment / spine / side-channel 必须在 FAS **effective** 邻接上操作。  
2. **邻域默认 rank±1**：长边只经 dummy 进入邻域，禁止远端 real 节点直接进 median。  
3. **后处理不得宽于主算法**：coordinate / stub_fix / straighten 不得使用比 order/BK 更宽的邻居或更自由的端口。  
4. **硬约束与软惩罚一致**：`path_is_clean` 拒绝的路径不应仅因短而从 dirty 通道胜出；检测为真必须有修复或显式 degraded。  
5. **确定性**：驱动布局的节点/边枚举显式排序（AGENTS.md §2）。  
6. **几何契约**：路径端点在节点边界；替换几何后标签/引线同步重建；容器变异后不得用陈旧下标；同一布局只用一套尺寸源。

## 2. 布局算法发现

### 2.1 P1 — 真逻辑错误 / 高风险

#### L1 — singleton 对齐 fallback 仍用全图邻居（K1 残余）

| 项 | 内容 |
|----|------|
| 位置 | `sugiyama_v2/coordinate.rs` → `align_singleton_layers_to_predecessors` |
| 症状 | 无邻层前驱/后继时回退 `all_pred_centers` / `all_succ_centers`，再次纳入 FAS 假邻居 |
| 为何是逻辑错误 | 主路径注释已写明「只认邻层」，fallback 复现同一 bug class |
| 状态 | **部分修复** |
| 修复方向 | fallback 也只允许 rank±1；再无则 **跳过**，不要用全图邻居 |

#### L2 — Architecture 无 group 路径 BK：缺 effective 边 + 长边无 dummy

| 项 | 内容 |
|----|------|
| 位置 | `sugiyama_v2/coordinate.rs` → `assign_layer_centers_for_string_graph`；调用方 `architecture_v2/layout/coordinate.rs` |
| 症状 | （1）rank/order 用 `is_effective_edge`，BK 建边却扫原始 `out_edges`；（2）只连 `to_layer == from_layer + 1`，**不插 dummy**，rank 差 ≥2 的边对 BK 完全不可见 |
| 为何是逻辑错误 | 与 `build_proper_layer_graph`（会插 dummy）行为不一致；长边端点无法竖直对齐，正交路由易多余折弯 |
| 状态 | **开放** |
| 修复方向 | BK 建边走 effective DAG；跨层边插 dummy 或复用 proper layer graph 入口 |

#### L3 — 无 top group 路径中，`align_nodes_to_neighbors` 后处理可覆盖 BK

| 项 | 内容 |
|----|------|
| 位置 | `architecture_v2/layout/coordinate.rs` → `align_nodes_to_neighbors`；`NeighborAlignmentPhase`（`architecture_v2` **无 top group** 的旧全局 Sugiyama 路径） |
| 症状 | 对全部 in/out 边取 median，无 `is_effective_edge`、无邻层过滤；单节点层直接平移 |
| 为何是逻辑错误 | 与 K1 同类，且在 BK **之后**运行，可撤销正确对齐 |
| 状态 | **开放** |
| 修复方向 | 仅 rank±1 + effective 边；或与 singleton 对齐共用一套邻居过滤 |

#### L4 — `pull_toward_neighbors` 缺 effective 边过滤

| 项 | 内容 |
|----|------|
| 位置 | `architecture_v2/layout/coordinate.rs` → `pull_toward_neighbors`（约 405–442） |
| 症状 | 有邻层 `neighbor_x` 过滤，但仍遍历原始 in/out；邻层上的反转边仍可拉动 |
| 为何是逻辑错误 | 「邻层」必要但不充分；方向必须是 effective DAG |
| 状态 | **部分**（核验后修订：见下方作用域说明） |
| 修复方向 | 增加 `reversed` / `is_effective_edge`，与 order 一致 |

> **核验后修订（L4 作用域）**：无分组的全局路径 `assign_coordinates`（`coordinate.rs` 约 15–90）**不调用** `pull_toward_neighbors`；实际调用点在 `architecture_v2/two_phase.rs` → `assign_coordinates_intra`（约 1109–1128），即**只影响组内 intra 坐标**。同文件 `compute_ideal_x_positions`（约 95–157）为死代码，修复时可一并删除（AGENTS.md §1 无兼容约束）。因此 L4 的实际影响面小于初稿暗示的「全局」，优先级应低于 L2/L3。

#### L5 — 状态图 semantic rank 硬覆盖可破坏 DAG 单调性

| 项 | 内容 |
|----|------|
| 位置 | `sugiyama_v2/engine.rs` → `apply_state_semantic_rank_constraints`（`initial→0`，`final→max`） |
| 症状 | 若 DAG 中存在指向 initial 的边或从 final 出发的边，硬改 rank 产生 `rank(u) ≥ rank(v)` 的回退边；`build_proper_layer_graph` 可能画非 proper 层间边 |
| 为何是逻辑错误 | 语义约束未与拓扑求交，结构性违反分层前提 |
| 状态 | **开放** |
| 修复方向 | 冲突时传播调整或降级为软约束；禁止单点硬覆盖破坏 `∀(u→v): rank(u)<rank(v)` |

### 2.2 P2 — 中低风险 / 设计边界

| ID | 位置 | 问题 | 状态 |
|----|------|------|------|
| L6 | `engine.rs` → `apply_group_rank_constraints` | group 窗口重排后 ungrouped 节点原 rank 不变，可能跨界倒挂 | 开放（设计取舍） |
| L7 | `architecture_v2/.../infrastructure_anchor_x` | 锚点用任意层已放置邻居，无 FAS/邻层过滤 | 开放 |
| L8 | `center_group_hub_nodes` / `align_client_nodes_to_hubs` | 有下层集合过滤，缺 `is_effective_edge` | 开放 |
| L9 | `compute_spine_nodes` | FAS-DAG 上按出度贪心；长前向捷径可能抢走 spine | 启发式（影响 BK tie-break / compaction 权重） |
| L10 | `sugiyama_v2/graph.rs` → `greedy_cycle_reversal`（约 80–101）；另 `architecture_v2/layout/acyclic.rs` → `find_edges_to_reverse` | `graph.node_indices().collect()`（petgraph 插入序）未按 id 排序；`state/mod.rs`（约 115–137）反例已 `nodes.sort()`。核验后补充：`find_edges_to_reverse` 用 `graph.node_ids`（**声明序**，非 id 排序）——声明序是确定性的，但若上游生成 `node_ids` 的顺序不稳定则同样受影响，一并核查 | 开放（确定性） |

### 2.3 布局侧已正确（对照基线）

- `sugiyama_v2/order.rs` 的 `weighted_median_stats`：经 `neighbor_pos` 隐式限邻层。  
- BK `vertical_alignment_blocks` / conflict 检测：显式邻层。  
- `architecture_v2` rank/order：普遍 `is_effective_edge`。  
- `common/acyclic.rs` → `greedy_fas`：sink/source 剥离前排序。  
- `compact_layer_centers`：在 layered_graph 上操作，real 邻居必邻层。

## 3. 路由算法发现

### 3.1 P1 — 真逻辑错误 / 高风险

#### R1 — `rank_span==1` 仍偏好正对端口，可穿中间列

| 项 | 内容 |
|----|------|
| 位置 | `feedback_side.rs` → `prefers_opposite_ports_over_side_channel` |
| 症状 | 相邻层且投影重叠时跳过侧通道；几何上中间仍可能有节点列 |
| 为何是逻辑错误 | 用图 rank 差代替「正对通道是否干净」；与 K2 同类边界漏网 |
| 状态 | **开放** |
| 修复方向 | `rank_span==1` 时对正对候选跑 `path_is_clean`；不干净则强制侧通道 |

#### R2 — 无 clean 候选时可选穿节点 dirty 路径

| 项 | 内容 |
|----|------|
| 位置 | `path.rs` → `select_best_path_with_scorer_stats` / `orthogonal_degraded_fallback` |
| 症状 | `best_strict` / `best_nodes_only` 皆空时走 `best_dirty`；兜底允许 `node_dirty` |
| 为何是逻辑错误 | 硬过滤与软惩罚不一致；干净通道未生成时短脏路径胜出 → lint `edge_through_node` |
| 状态 | **开放**（部分为故意降级，但与产品「不穿节点」冲突） |
| 修复方向 | dirty 前强制升档 channel/z-fold；非 degraded 标记禁止 node_dirty |

#### R3 — 非 corridor 边不强制 `path_avoids_group_interiors`

| 项 | 内容 |
|----|------|
| 位置 | `mod.rs` → `should_strict_group_transit`；`path.rs` 选择分支 |
| 症状 | 非 corridor 架构边可走 `best_nodes_only`（穿无关 group） |
| 为何是逻辑错误 | 分组硬约束与 `GROUP_TRANSIT_PENALTY` 软惩罚混用 |
| 状态 | **开放**（注释称防 k8s 回归） |
| 修复方向 | 长跨度/feedback 边强制避组内部；或 profile 级 strict 开关 |

#### R4 — 标签候选仍用无保护区最近点（K3 残余）

| 项 | 内容 |
|----|------|
| 位置 | `label_candidate.rs` → `preferred_t_for_label` / `path_t_for_center` / `score_candidate` |
| 症状 | 引线已用 `leader_anchor_on_path`；标签本体偏好 t 仍可被箭头端 stub 吸引 |
| 为何是逻辑错误 | 同类缺陷不同代码路径；引线修好后标签仍可贴箭头 |
| 状态 | **开放** |
| 修复方向 | 共享「弧长窗口内最近点」工具函数 |

#### R5 — circular 穿障检测成功但 detour 为空时保留穿障曲线

| 项 | 内容 |
|----|------|
| 位置 | `edge_routing_circular.rs` → `route_edges_circular` |
| 症状 | `curve_intersects_obstacles` 为真且 `shortest_path` 为空 → 仍输出穿障 Bezier |
| 为何是逻辑错误 | 检测与修复不对称 |
| 状态 | **开放** |
| 修复方向 | 空 detour 时 outer 折线 / spline 全路由 / 显式 degraded 标记 |

## 4. 其它正确性缺陷（不限假邻居类）

本节为第二轮扩写：凡**破坏几何契约 / 索引契约 / 检测-修复对称性**、导致漏画、穿模、重叠、端点离框、标签挂错路径的，均收录。已用源码核对。

### 4.1 布局：索引 / 尺寸 / 成员集合契约

#### C1 — `group_aware_reorder`：在已变异的 `result` 上用原始下标（P1）

| 项 | 内容 |
|----|------|
| 位置 | `architecture_v2/layout/order.rs` → `group_aware_reorder`（约 177–224） |
| 症状 | 同层多个「多成员 group」时，先处理的组会 `remove`/`insert` 改写 `result`；后续组仍用**第一次** `ordered` 的下标去索引**当前** `result`，取错/删错节点 |
| 为何是逻辑错误 | 「从后往前」只保证**单组内** remove 安全；跨组后下标契约已失效，排序结果确定性错误 |
| 复现 | Architecture 全局 Sugiyama：同 rank 两个 top group 各 ≥2 节点 |
| 状态 | **开放** |
| 修复方向 | 每轮按**当前** `result` 重算组成员位置；或一次性用稳定置换生成新序，禁止边变异边索引 |

#### C2 — 无 group 节点被当成同一组 `""` 吸附（P1）

| 项 | 内容 |
|----|------|
| 位置 | 同上，`unwrap_or_default()` → gid `""` |
| 症状 | 层内 ≥2 个基础设施/无组节点被当成「同一多成员组」强行聚块 |
| 为何是逻辑错误 | 注释意图是「同 top group 相邻」，实现把互不隶属节点并组 |
| 复现 | 基础设施行或多 ungrouped 同层 |
| 状态 | **开放** |
| 修复方向 | 无 group 时**不**进入 multi_groups；仅对真实 gid 吸附 |

#### C3 — Sequence 放置用 `w`、游标步进用 `DEFAULT_NODE_WIDTH`（P1）

| 项 | 内容 |
|----|------|
| 位置 | `layout/node/sequence.rs` → `compute`（约 118–130） |
| 症状 | `NodeLayout.width = styled_node_size(...).w`，但 `current_x += DEFAULT_NODE_WIDTH + spacing`；长标签参与者与右侧重叠，`total_width` 偏小 |
| 为何是逻辑错误 | 同一布局用两套宽度，违反矩形不重叠不变量 |
| 复现 | Sequence：多个长 label / 加宽样式参与者 |
| 状态 | **开放** |
| 修复方向 | 游标与 `total_width` 一律用实际 `w` |

#### C4 — 组内同 rank Y 对齐漏 `group_id` 成员（P2）

| 项 | 内容 |
|----|------|
| 位置 | `architecture_v2/two_phase.rs` → `align_intra_group_same_rank_y`（核验后修订：成员构造约在 1913–1923） |
| 症状 | 只扫 `g.entity_ids`；仅挂在 `entity.group_id` 上的成员不参与 Y 微对齐；与 `effective_entity_ids` 成员集不一致 |
| 为何是逻辑错误 | 同组节点集合定义不唯一 → 视觉不齐 |
| 状态 | **开放** |
| 修复方向 | 与 `group_bounds::effective_entity_ids` 共用成员解析 |

#### C5 — BK `horizontal_compaction` 在 `lower>upper` 时仍写入违反下界的坐标（P2）

| 项 | 内容 |
|----|------|
| 位置 | `sugiyama_v2/coordinate.rs` → `horizontal_compaction`（约 693–712） |
| 症状 | 约束冲突时 `candidate.min(upper)` 可得到 `< lower_bound`，层内间距约束被打破 → 同层重叠风险 |

## 11. 精确落点与实现细节（核验后补充）

> 本节为「便于后续 agent 正确实现」的实现级说明。每条给出：**核验状态**、**精确落点（函数 + 核验时行号）**、**根因锚点（关键代码语义）**、**具体改法（步骤级）**、**不变量 / 回归 gate**、**易踩的坑**。  
> 行号会漂移，实现前**先用函数名定位**再核对；所有落点均已在 2026-07-13 二次核验中确认存在。

### 11.0 通用工具与共享概念（先读，避免重复造轮子）

- **effective DAG / 反转边判定**：`is_effective_edge(from, to, reversed)`。凡涉及 median/barycenter/alignment/pull/anchor/spine 的邻居枚举，必须过滤反转边并保持 DAG 方向。architecture rank/order 已是范式（见 `rank.rs`/`order.rs`）。
- **邻层判定**：real 节点邻居须满足 `rank(neighbor) == rank(self) ± 1`；长边只能经 dummy 进入邻域，禁止远端 real 节点直接进 median。
- **端点边界契约**：路径两端必须落在 `edge_point(node, toward.x, toward.y)` 给出的**节点边界**上；任何后续法向/lane 偏移都必须把端点**重投**回边界，或只偏移中段。
- **几何-标签同步**：任何「先建 labels，后换 geometry」的写法都错。正确顺序是**先确定最终采样路径（`sampled_path`/`path_points`），再 `build_edge_labels(..., 采样闭包)`**。spline 路由器（`edge_routing_spline.rs` 约 135–157）与 `refine/spline_fallback.rs` 约 118–121 是范式。
- **确定性容器**：驱动几何的枚举一律 `Vec` + 显式 `sort()`（按 id/rank/插入序），或 `IndexMap`/`BTreeMap`；禁止 `HashMap::values()/iter()` 直接驱动布局（AGENTS.md §2）。`label_common.rs` 的 `sorted_node_obstacles`、`sorted_group_shell_obstacles` 是范式。
- **检测≠修复对称性**：任何 `curve_intersects_obstacles`/`analyze_edge_node_crossings` 为真的分支，必须导向「真正改善的几何」或「显式 degraded 标记」，禁止「检测成功 → 保留原穿障几何」。
- **验真**：`cargo run -p plotgram-cli`（勿信 `./target/release/plotgram` 陈旧 binary）；改 Rust 后若涉 WASM 前端，按 AGENTS.md §6 重建并同步 pkg。

### 11.1 批次 A — 契约破坏（复现直接、边界清晰，优先做）

#### C3 — Sequence 尺寸双轨（`layout/node/sequence.rs` → `compute` 约 118–136）

- 根因：`NodeLayout.width = styled_node_size(entity, DEFAULT_NODE_WIDTH, DEFAULT_NODE_HEIGHT).w`，但 `current_x += DEFAULT_NODE_WIDTH + spacing`，`total_width` 也用累加后的 `current_x`。
- 改法：
  1. 在循环内先取 `let (w, h) = styled_node_size(...)`；写 `NodeLayout.width = w`。
  2. 游标步进改为 `current_x += w + config.node_spacing;`（用**同一个 `w`**）。
  3. `total_width` 保持 `current_x - config.node_spacing + PADDING`——此时已基于真实 `w`，无需再动。
  4. 若后续有「生命线 x = 参与者中心」的计算，确认其读取的是 `NodeLayout.x + width/2`，而非 `DEFAULT_NODE_WIDTH/2`。
- 不变量：任意两参与者矩形不重叠；`total_width ≥ Σ w + (n-1)·spacing + 2·PADDING`。
- 回归：长 label 参与者 showcase，肉眼 + 重叠严重度不升。

#### C1 — `group_aware_reorder` 变异容器 + 陈旧下标（`architecture_v2/layout/order.rs` 约 177–227）

- 根因：`result = ordered.to_vec()`；对每个 multi-group 用 `positions`（**始终是 `ordered` 的原始下标**）在**已被前一组 remove/insert 改写的 `result`** 上 `remove(idx)` / `insert(...)`。同层 ≥2 个多成员组时读/删/插全部错位。`non_group_before_median` 命名也误导（统计的是同组内 median 前成员数）。
- 改法（二选一，推荐 2）：
  1. **每轮基于当前 `result` 重算成员位置**：处理某组前，用「node id → 当前 result 下标」重新解析该组 `positions`，再 remove/insert。
  2. **一次性稳定置换**（更稳）：不做增量 remove/insert；构造目标顺序——按「每个多成员组的原 median 位置」为锚，把该组成员聚为连续块，其余节点保持相对序，用一次稳定排序/重排生成新 `Vec`，禁止边遍历边变异。
- 不变量：输出是输入的置换（元素集合不变、无重复、无丢失）；单组时结果与旧逻辑一致（回归对照）。
- 坑：注意与 C2 联动——先修 C2（排除空 gid），再验 C1，否则空组会污染测试。

#### C2 — 空 gid 并组（同文件 约 185–192）

- 根因：`group_map.node_to_top_group.get(node).cloned().unwrap_or_default()` 让无组节点得到 `""`；`filter(|(_, positions)| positions.len() > 1)` 把同层多个无组节点当成一个多成员组。
- 改法：解析 gid 时用 `Option`，`None`（无 top group）**不进** `group_positions`；仅对 `Some(real_gid)` 聚组。即把 `unwrap_or_default()` 改为在 `if let Some(gid) = ...` 分支内 push。
- 不变量：ungrouped 节点相对序不被 group 吸附改变。

#### C6 — 平行边端点离开边界（`edge/common/routing_skeleton.rs` → `resolve_endpoints` 约 93–119）

- 根因：`(sx,sy)=edge_point(from_nl, c2)`、`(ex,ey)=edge_point(to_nl, c1)` 得到边界点后，直接 `(sx+ox, sy+oy)`；`(ox,oy)` 是**平行边法向偏移**（`perp*offset_scalar`），使端点脱离边界，`select_port` 也可能选错侧。
- 改法（推荐 A）：
  - **A（只偏移中段）**：端点保持 `edge_point` 结果不加 `(ox,oy)`；仅对路径**中间控制点/中段**施加法向偏移，实现平行分离而端点仍贴边。
  - **B（端点重投）**：先按 `(ox,oy)` 造出偏移目标方向，再对每个端点用 `edge_point(node, 目标点)` **重新求边界交点**（沿边界切线分配 slot），保证仍在边界。
- 不变量：`点在 node 边界矩形的边上`（可加 debug assert：端点到 node 边界距离 ≈ 0）；箭头不从框内/框外冒出。
- 影响面：straight / bezier / spline / organic 全部走该骨架，回归要覆盖多种 `edge_routing`。

#### C7 — 穿障改折线后标签仍按旧 Bezier（`edge_routing_bezier.rs` 约 149–177；`edge_routing_circular.rs` 约 118–124；`edge_routing_organic.rs` 约 338–383）

- 根因：先 `let labels = build_edge_labels(rel, t, off, |t| cubic_bezier_point(...))`，构造 `EdgeLayout { geometry, labels }` 后，若 `curve_intersects_obstacles` 命中就 `edge.geometry = Polyline{detour}`，**labels 未重建**，仍绑定旧 Bezier 的 t 映射。
- 改法（对齐 spline 范式）：
  1. **先决定最终几何**：算出 `detour`（空则维持原曲线），得到最终 `geometry` 与用于标签采样的 `sampled_for_label`（折线用 `point_at_path_t(&detour, t)`，曲线用 `cubic_bezier_point`）。
  2. **再** `build_edge_labels(rel, t, off, |t| sample(sampled_for_label 或曲线, t))`。
  3. 三个路由器都改（bezier / circular / organic），并抽一个共享闭包选择器减少重复。
- 不变量：labels/leader 的锚点落在**可见路径**上（换几何后标签不悬空）。
- 与 R4/R5/C9 联动：C7 是「几何换、标签没换」；R4 是「标签本体 t 无端点保护区」；两者独立但同一批验证。

#### C8 — Curved 自环端点在框内（`edge/common/self_loop.rs` → `curved_loop_endpoints` 约 209–228）

- 根因：`sx/sy/ex/ey` 用 `center ± scale*0.35 / *0.55` 内点公式，未过 `edge_point`，端点可能在节点内部。
- 改法：与**正交自环**同源——起终点用 `edge_point(node, 朝向 corner 方向的外部参考点)` 求边界坐标；`loop_r`/`corner` 仅用于控制外凸的控制点，不再决定端点本身。可直接复用正交自环里已有的边界端点函数（查 `self_loop.rs` 内正交分支）。
- 不变量：自环两端在边界；箭头贴边收口。回归：`a -> a` + `edge_routing: curved`/circular self-loop。

#### L1 — singleton 对齐 fallback 仍用全图邻居（`sugiyama_v2/coordinate.rs` → `align_singleton_layers_to_predecessors` 约 93–182）

- 根因：主路径优先 `adj_pred_centers`（`rank-1`）正确；无邻层前驱时**回退**依次用 `adj_succ` → `all_succ_centers` → `all_pred_centers`（后两者是全图邻居，重新纳入 FAS 假邻居）。
- 改法：删掉 `all_succ_centers` / `all_pred_centers` 两个 fallback 分支；顺序改为「`adj_pred` → `adj_succ`（仅 `rank+1`）→ 都无则 `continue`（跳过，不移动）」。
- 不变量：singleton 只被**邻层**真前驱/后继牵引；无邻层时保持原位（不引入假邻居偏移）。
- 坑：`all_*` 分支的向量收集若不再使用要一并删（AGENTS.md §1）。

#### R4 — 标签候选无端点保护区（`edge/common/label_candidate.rs` → `preferred_t_for_label`/`path_t_for_center`/`score_candidate` 约 192–234, 331, 360–363）

- 根因：`preferred_t_for_label` 用全局 `closest_point_on_path` 无端点保护区（`dist<80` 即 blend closest t），会把标签吸向箭头端 stub；`leader_anchor_on_path`（`edge_geometry.rs` 约 454–477）已有 `LEADER_END_GUARD_*` 弧长窗口，二者不一致。
- 改法：抽公共工具「弧长窗口内最近点」——把 `leader_anchor_on_path` 里的 `guard_t = (LEADER_END_GUARD_PX/total_len).clamp(min,max)` 逻辑提取为 `closest_point_in_arc_window(path, p, guard_px)`；`preferred_t_for_label` / `path_t_for_center` 改调用它，`t` 只在 `[guard_t, 1-guard_t]` 内取。`score_candidate` 对 `preferred_t` 的加权保持，但输入 t 已受保护。
- 不变量：标签本体与引线**共用**同一「端点保护区外最近点」语义；标签不贴箭头。

### 11.2 批次 B — Architecture DAG/BK 语义 + refine 回退

#### L2 — 无 group 路径 BK 缺 effective 边 + 长边无 dummy（`sugiyama_v2/coordinate.rs` → `assign_layer_centers_for_string_graph` 约 805–881；调用方 `architecture_v2/layout/coordinate.rs` 约 42–48）

- 根因：rank/order 用 `is_effective_edge`，但 BK 建边直接扫 `graph.out_edges`，无 `reversed`/effective 过滤；且只连 `to_layer == from_layer + 1`，rank 差 ≥2 的长边被静默丢弃、端点无法竖直对齐。
- 改法：
  1. BK 建边改走 **effective DAG**：枚举边时带 `reversed`，用 `is_effective_edge` 过滤，方向与 rank/order 一致。
  2. **长边插 dummy**：跨层边（`to_layer > from_layer + 1`）拆成逐层 dummy 链参与 BK，或直接复用 `build_proper_layer_graph` 的 proper layer 入口（更稳，避免两套长边逻辑）。
- 不变量：长边端点在 BK 中可见并能竖直对齐；与 `build_proper_layer_graph` 行为一致。
- 坑：AGENTS.md §5——先追管线时序确认「最终坐标是谁写的」；改 BK 后要确认没有下游后处理再次覆盖。

#### L3 — `align_nodes_to_neighbors` 后处理覆盖 BK（`architecture_v2/layout/coordinate.rs` → `align_nodes_to_neighbors` 约 666–762；`NeighborAlignmentPhase` 见 `architecture_v2/pipeline.rs` 约 104–116，管线序 `layout/mod.rs` 约 118–130）

- 根因：对全部 in/out 邻居取 median，无 effective/邻层过滤；且在 BK **之后** run_pipeline 执行，可撤销正确对齐。
- 改法：给邻居枚举加「`is_effective_edge` + `rank±1`」双过滤（与 L1/L4 共用一套过滤 helper）；或评估该 Phase 是否仍必要，若 BK 修好（L2）后冗余则删。
- 不变量：后处理不得宽于主算法（通用规则 §1.3）。

#### L4 — `pull_toward_neighbors` 缺 effective 过滤（`architecture_v2/layout/coordinate.rs` 约 405–442，**仅 `two_phase.rs::assign_coordinates_intra` 约 1109–1128 调用**）

- 根因：邻层过滤靠 `neighbor_x`（只含邻层中心）间接实现，但仍遍历原始 in/out，反转边可拉动。
- 改法：邻居枚举加 `is_effective_edge`（带 `reversed`）；`compute_ideal_x_positions`（约 95–157）是死代码，可删。
- 优先级：影响面仅组内 intra，低于 L2/L3。

#### C9 — refine spline 兜底无质量门控（`layout/refine/mod.rs` 约 149–157；`refine/spline_fallback.rs` 约 91–116）

- 根因：`edge_node_crossings > 0` 即无条件对 problem 边跑 spline fallback；`detour_path.is_empty()` 退 Bezier **不再** `curve_intersects_obstacles` 复检；不比较替换前后 crossing/长度。
- 改法：
  1. 对每条候选替换：算 `before = analyze_edge_node_crossings(原边)`、`after = analyze(...新几何)`；仅当 `after < before`（或 crossing 相等但长度/弯折更优）才替换，否则**保留原路径**。
  2. `detour_path.is_empty()` 退 Bezier 后**重跑** `curve_intersects_obstacles`；仍穿障则保留原边并打 degraded 标记（不要静默输出穿障）。
- 不变量：refine 单调不退化（替换后 crossing 不增）。与踩坑复盘「无退化要可量化」一致。

### 11.3 批次 C — 路由穿节点 / 穿障

#### R1 — `rank_span==1` 偏好正对端口穿中列（`feedback_side.rs` 约 87–94, 251–292）

- 根因：`rank_span==1` 且投影 overlap>0 或 gap<`OPPOSITE_PORT_GAP_THRESHOLD` 即 `continue` 跳过侧通道，未验证「正对通道几何是否干净」。
- 改法：`prefers_opposite_ports_over_side_channel` 命中后，再对正对候选跑一次 `path_is_clean`（或轻量通道占用检查）；不干净则**不 continue**，让该边进侧通道桶。
- 坑：别只按 rank 差判断（AGENTS.md §5「端口去冲突从通用规则出发」）。

#### R2 — 无 clean 候选时选 dirty 穿节点（`path.rs` 约 309–314, 449–476, 555–587）

- 根因：`best_strict.or(best_nodes_only).or(best_dirty)`；`orthogonal_degraded_fallback` 排序键 `(group_hits, node_dirty, len)` 允许 `node_dirty=1`。
- 改法：dirty 前**强制升档**——先尝试提高 channel/z-fold 预算重路由生成 clean 候选；确实无 clean 时，仅在**显式 degraded** 语境允许 `node_dirty`，非 degraded 路径禁止 `node_dirty=1`（对 fallback 排序键加硬门：`node_dirty` 命中直接判非法，除非 degraded 标志置位）。
- 不变量：硬过滤与软惩罚一致（§1.4）；产品「不穿节点」优先。

#### R5 — circular 检测穿障但空 detour 保留穿障曲线（`edge_routing_circular.rs` 约 113–127）

- 根因：`curve_intersects_obstacles` 真 + `shortest_path` 空 → 不替换，保留原 Bezier。
- 改法：空 detour 时走兜底——outer 折线 / spline 全路由重算；仍失败则打 degraded 标记，不静默输出穿障。可与 C9 的 degraded 机制共用标记。

### 11.4 批次 D — 结构与确定性清理

- **L5**（`engine.rs` → `apply_state_semantic_rank_constraints` 约 308–336）：`initial→0`/`final→max` 硬覆盖破坏 `∀(u→v):rank(u)<rank(v)`。改：覆盖后做一次拓扑合法性检查，冲突时**传播调整**（把违反的下游整体后移）或降级为软约束（加权拉向 0/max 而非硬钉），禁止单点硬覆盖产生回退边。
- **L6**（`apply_group_rank_constraints` 约 245–305）：group 窗口重排后 ungrouped 节点 rank 不变。改：重排后对 ungrouped 节点按其邻居 rank 重新夹取到合法区间，避免跨界倒挂。（设计取舍，非必修。）
- **L7 / L8**（`infrastructure_anchor_x` 约 548–578；`center_group_hub_nodes`/`align_client_nodes_to_hubs` 约 209–381）：邻居枚举加 `is_effective_edge`（L8 已有 `lower_set`，仅补方向过滤；L7 补 FAS/邻层）。与 L1/L3/L4 共用过滤 helper。
- **L9**（`compute_spine_nodes` 约 501–527）：已按 `(Reverse(out), id)` 稳定排序，属启发式；仅当长前向捷径抢 spine 影响 tie-break 时再调，非必修。
- **L10 / R7 / R13 / R6**（确定性）：统一「枚举前 `sort()`」。`graph.rs::greedy_cycle_reversal` 约 80–101 的 `node_indices().collect()` 加 `sort_by_key(id)`；`routing_skeleton.rs::build_obstacle_context` 约 50–66 改用 `sorted_node_ids`（对齐 `spline_fallback` 范式）；`label_avoidance.rs` Phase-2 约 91–102 改用 `sorted_node_obstacles`；`compute_lane_offsets` 约 237–266 对 `from_groups` 外层按 key 排序迭代。
- **R8**（`route_inter_circle_edge` 约 339–369）：跨圆双向边引入 `arc_side`（±1 弦两侧分离），与同圆 `route_intra_circle_edge` 一致。
- **R9**（`mod.rs` `coordinate_port_sides` vs `apply_feedback_side_overrides` 约 557–564, 1427–1441, 1626–1651）：协调按 pair 整组改端口，覆盖只按 hint 边恢复 → 被改却无 hint 的边不还原。改：覆盖阶段对整个 pair 恢复，或记录协调前快照按 pair 回滚。
- **R10 / R11 / C10 / C11 / C12**：R10（`rank_span_for_edge` 约 179–197 无 ranks 时 `dist/48`）优先透传真实 ranks；R11（`scoring.rs::path_is_clean` 约 200–212）评估是否需对源/宿节点做「仅端口附近豁免、其余段仍检测」而非全程豁免；C10（`lane_assignment.rs::assign_lanes` 约 260–271, 368–374）斜段先 `force_orthogonal` 或跳过，勿按 `dy≈0` 二分当竖段；C11（`crossing.rs` 约 40–45 `node_shrink=2`）贴边检测评估调小 shrink 或加壳层判定；C12（`obstacle_check.rs` 约 11–27 `OBSTACLE_CHECK_SAMPLES=16`）改为按弧长自适应采样数或抬高常量。
- **C4**（`two_phase.rs::align_intra_group_same_rank_y` 约 1913–1923）：成员解析复用 `group_bounds.rs::effective_entity_ids`（约 115–128），勿只扫 `g.entity_ids`。
- **C5**（`sugiyama_v2/coordinate.rs::horizontal_compaction` 约 698–701）：`lower_bound > upper_bound` 时不要 `candidate.min(upper)` 静默违反下界；应 clamp 到 `[lower, upper]` 的可行情形，或对冲突显式放松/记录（保证层内分离不变量）。
- **C13**（`pipeline.rs` 约 40–56 + `canvas_finalize.rs::translate_all` 约 127–143）：仅在 diagram 显式开 align 时暴露；若要修，align 后需对边端点做相对重定位（而非仅 `translate_all` 整体平移），或在 sequence 开 align 时不跳过路由。

## 12. 面向 agent 的执行计划

> 目标：把上述缺陷按「复现清晰度 × 影响面 × 相互依赖」排成可独立提交的小批次。**每批一个 PR/一次提交**，逐批验真，禁止一次性大改。全程遵守 AGENTS.md §1（无兼容包袱，直接删旧码）、§2（确定性）、§4（lint 参考非硬性）、§5（先追时序再改启发）、§6（WASM 计时/pkg 同步）。

### 12.0 每批统一工作流（Definition of Done）

1. **前置阅读**：本文件对应条目 + §11 落点 + [布局与路由改造踩坑复盘-2026-07.md](./布局与路由改造踩坑复盘-2026-07.md)。
2. **定位**：用**函数名**（非行号）在源码二次定位，核对 §11 描述与当前代码一致。
3. **改动**：只动本批条目；直接删死代码（如 `compute_ideal_x_positions`），不留兼容层。
4. **确定性自查**：本批若碰到枚举，确认无 `HashMap::iter()/values()` 直接驱动几何。
5. **验真**：`cargo build -p plotgram-core` + `cargo run -p plotgram-cli` 渲染对应 showcase（勿信旧 binary）。
6. **回归 gate**：对比改动前后**节点坐标**（无关图应不变）+ 全量 showcase **重叠严重度**（非单图观感/计数）不升；仓库既有测试若先前失败，先钉基线再对比。
7. **WASM**（若改动在 render/lint/parse 路径）：`wasm-pack build crates/plotgram-wasm --target web --release` 并同步 pkg 到 `playground/`、`agent-demo/`。
8. **提交**：一批一提交，信息写清「修哪个不变量」，不写图名特判。

### 12.2 依赖与并行建议

- **可并行**（互不触碰同一文件核心逻辑）：A1 / A5 / D1 彼此独立；A3 与 A4 分属 `self_loop.rs`+`routing_skeleton.rs` 与 labels 采样，可并行但都动 `edge/common`，合并时留意。

### 12.3 风险与红线

- ❌ 图名特判（`if diagram_id == "tcp"`）——一律从通用规则出发（AGENTS.md §5）。
- ❌ 为消 lint warning 引入穿模或显著复杂化（AGENTS.md §4）。
- ❌ 一律 leader 挂中点（已证过宽回滚）。
- ❌ 信任陈旧 `target/release` binary 或未同步的 WASM pkg。
- ⚠️ 改 BK/rank/后处理时，先用「最终坐标是谁写的」时序追踪，避免改了上游被下游覆盖（踩坑复盘核心教训）。
