## 0. 一句话目标

把「auth/db 应对齐」从**个案拉扯**提升为可证明的布局契约：  
**在不动（或可证明地极少动）其它节点的前提下，让满足谓词的邻层悬挂关系在主轴上对齐**——

| 情形 | 对齐语义 |
|------|----------|
| **单 pendant** | `movable` 与 `anchor` **节点中心重合**（主轴差 ≤ ε） |
| **同锚同层多 pendant** | **组质心**相对 `anchor` 中心 ≤ ε；组内按 `node_gap` 对称排开（**不可能**每个叶子都与锚点同心，否则重叠） |

实现落在 Sugiyama 坐标阶段，路由只消费结果。

## 1. 问题数值化（已知事实）

### 1.1 代表图结构

```text
client → gateway → auth ⇄ db
                 ↘ cache ⇄ auth
                 ↔ gateway（响应）
```

| 节点 | 角色 | 与对齐相关的邻居 |
|------|------|------------------|
| **auth** | 扇出枢纽 | 上：gateway；下：db、cache；回：gateway |
| **db** | 叶子 | **仅** auth（正反向各一条边；无向邻居节点 = {auth}） |
| **cache** | 叶子 | 仅 auth（正反向） |

观感与数量级（**非正式实测，待 V3b-0 dump 钉死**）：auth/db 中心差可达数十 px；平行边 gap 已由 V3a 单独保证，**与中心差正交**。

### 1.2 为何现有机制盖不住（结构论证；数值待 dump）

| 机制 | 为何不够 |
|------|----------|
| **L2**（`assign_layer_centers_for_string_graph`：effective + dummy） | **仅 architecture 无 group 路径**；`n.user-auth` 是 flowchart → 走 `sugiyama_v2`，L2 **根本不跑**。是否「数值上也不够」由 V3b-0 用中心差表钉死，**不得在 dump 前写「已测」** |
| **`align_singleton_layers_to_predecessors`** | 仅当**整层恰好 1 个 Real**（`coordinate.rs`：`real_ids.len() != 1` 则 skip）；db 与 cache **同层**时整层不是 singleton → db 不进该函数 |
| **BK median / 块对齐** | auth 被 gateway+db+cache 多方拉扯；db 的 median 邻可能经 FAS/块冲突落在偏离 auth 中心的位置 |
| **「唯一邻层邻居」盲目拉齐**（已试回滚） | 谓词过宽或级联拉动，曾出现全局坐标漂移；说明**必须有锚点所有权 + 冲突检测**，不能「凡唯一就拉」 |

**与 P1 收口计划 §5.3 的关系**：该处写「L2 已落地 → 下一步是**测**，不是再实现一遍」。本方案 §8 / V3b-0 承接该「测」；在 dump 产出中心差表之前，**不**断言「L2 已测不够用」。

### 1.3 用户硬约束（本方案必须遵守）

1. **优先只动 db（被对齐者）**，auth（锚点）尽量不动。  
2. **禁止**为对齐挪 gateway / client；同层其它非 pendant Real 默认不动（见 R2 / §5.2）。  
3. **时机**：仅布局、路由之前；路由后禁止挪节点（会反馈 space-budget / 假回归）。  
4. **禁止** `if diagram_id == "user-auth"`。

### 1.4 代码现状对账（审查已核验）

| 主张 | 代码 | 结论 |
|------|------|------|
| singleton align 仅整层 1 Real | `coordinate.rs`：`real_ids.len() != 1` → continue | ✅ db+cache 同层跳过 |
| 管线：BK+compaction → resolve_overlaps → align_singleton → normalize_padding | `coordinate.rs` 调用序 | ✅ 新步插在 align_singleton **之后**可行 |

| L1 fallback 禁止全图 `all_pred` | 邻层 only + continue | ✅ 比部分审计文档更新 |

## 2. 高维视角：问题属于哪一类契约

V3b 不是「再写一个 align_xxx」，而是补一张缺失的契约表行：

```text
布局契约（节点级）
  C-LayerSeparation     同层最小间距、无重叠
  C-BKCompact           BK 四趟 + 紧凑化语义
  C-NeighborCenter  ★   满足谓词的邻层关系：单节点同心 / 多节点组质心对齐
  C-AnchorOwnership ★   每一组对齐有唯一锚点；只允许移动非锚点
```

与边级契约（C-ParallelGap / C-PortExclusive）的关系：

| 契约 | 阶段 | 解决什么 |
|------|------|----------|
| C-NeighborCenter | **布局** | 节点该不该对齐（中心或组质心） |
| C-ParallelGap | **路由后处理** | 对齐之后正反向边仍要分开（V3a 已做） |

**顺序**：先中心/质心对齐，再路由，再 gap——否则对齐会毁掉已分离的边，或边偏移掩盖节点未对齐。

## 3. 核心抽象：对齐谓词与锚点所有权

### 3.1 对齐对（Alignment Pair）

二元组 `(movable, anchor)`，主轴为 TB 的 x（或 LR 的 y）。

**本切片采用的谓词：仅 P-Pendant**（P-Mutual / P-HubSpoke 作概念对照，**不进 V3b-1/2 实现**）。

| ID | 名称 | 谓词（同时满足） | 意图 |
|----|------|------------------|------|
| **P-Pendant** | 悬挂叶子 | ① `rank` 相邻；② **无向邻层邻居集合**（忽略 FAS 方向、只计 Real）= `{anchor}`；③ 该集合大小为 1（与 ② 同一语义，**不是**边条数） | db→auth、cache→auth 类 |
| P-Mutual | 双向邻层对 | 邻层 + 正反向边都存在 + 两端邻层邻居集大小均为 1 | 纯 2-节点往返；**本轮不做** |
| P-HubSpoke | 扇出辐条 | hub 扇出到同层多个叶子；叶子满足 P-Pendant | 由 S-Pack 覆盖多叶子；谓词仍是逐叶子 P-Pendant |

**术语澄清（硬伤）**：db 对 auth 常有 **两条有向边**（auth→db、db→auth）。若「度数」指边数则为 2，若指邻居节点数则为 1。P-Pendant **一律按无向邻层邻居集合大小**理解，禁止用边条数。

**n.user-auth 判定**：

- `(db, auth)`：**命中 P-Pendant**（db 的无向邻层邻居集 = {auth}）。  
- `(cache, auth)`：同样命中；同层共锚时走 **S-PackUnderAnchor**（组质心对齐，非双同心）。  
- `(auth, gateway)`：auth 邻层邻居集大小 > 1 → **auth 不作 movable**。

### 3.2 锚点所有权（关键，防布局崩）

| 规则 | 含义 |
|------|------|
| **R1 锚点不动** | 默认只改 `movable`（或 pendant 组）的中心 → 对齐到 `anchor`；**永不**为对齐移动 anchor |
| **R2 同层打包优先** | 若移动导致与同层其它 Real **重叠或间距 < `preset.node_gap`**（**注意：不是 `layer_gap`**；`layer_gap` 是层间垂直间距，同层水平/主轴间距用 `node_gap`，见 `coordinate.rs` overlap/compaction），则：先尝试在同层内对「同锚 P-Pendant 组」做 S-Pack；若仍与**非 pendant**冲突 → **整组放弃**（保 C-LayerSeparation），或按 §5.2 启用条件直接降级 |
| **R3 禁止级联 + 单次赋值** | 一轮扫描内每个节点至多被写入坐标 **一次**。**S-PackUnderAnchor 视为对组内每个节点的一次原子赋值**；pack 完成后**禁止**再对同节点做二次微调或二次单点对齐。禁止 A←B←C 链式传递 |
| **R4 锚点冲突** | 若两对抢同一 movable，取「锚点邻层邻居集更大」或「上层优先」的一对，另一对跳过 |

上次失败的根因：缺少 R1–R3，把「唯一邻居」当成无条件平移，可能拉动本应作锚点的枢纽或引发同层雪崩。

## 4. 三条高维实现路线（比较）

### 路线 A — 后 BK 局部修复（推荐作为第一刀）

```text
BK + compaction + overlap resolve
  → align_singleton_layers（已有）
  → normalize padding
  → ★ align_pendants_under_anchors（新；须在 normalize 之后）
  → route …
  → finalize_canvas_bounds（bbox 左扩时可能整体平移）
```

| 优点 | 缺点 |
|------|------|
| 边界清晰；易测；不动 BK 核心 | 与 BK 块「理想位置」可能略不一致（可接受） |
| 天然满足「只动叶子」 | 同层冲突时可能 **放弃对齐**（需 R2 / 启用条件） |

**落地落点**：`sugiyama_v2/coordinate.rs`，在 `normalize_layout_to_padding` **之后**。  
**不**自动作用于 `architecture_v2`（见 §9.3）。

### 路线 B — 把 P-Pendant 写进 BK / 紧凑化目标

在 `vertical_alignment_blocks` / `horizontal_compaction` 中：对 P-Pendant 边加重「对齐权重」，或强制 movable 与 anchor 进同一 alignment block（在无冲突时）。

| 优点 | 缺点 |
|------|------|
| 对齐进入主算法，少后处理 | 改 BK 风险大；与 conflict 检测、spine 交互复杂 |
| | 难保证「绝对不动 auth」 |

**建议**：作中期选项；仅当路线 A 在全量 showcase 上频繁因 R2 放弃而对齐率不够时再开。

### 路线 C — 二次坐标优化（QP / 迭代）

布局后再做带约束的迭代：  
`min Σ (cx_i - cx_j)²` for pendant pairs，s.t. 同层分离、组框约束。

| 优点 | 缺点 |
|------|------|
| 表达力强，可一次处理多对 | 实现与调参重；WASM/性能需预算；易过度工程 |

**建议**：暂不作为 V3b 第一版。

## 5. 推荐方案（路线 A 细化）

### 5.1 算法草图（纯 P-Pendant；不含 P-Mutual）

```text
输入：dag, layered_graph, layers, nodes, horizontal
ε = 1.0（内部阈值）；门禁用 2.0

1. 建 real_layer: id → rank
2. 收集候选：对每个 Real id（按 id 字典序稳定遍历）：
     nbrs = 无向邻接 ∩ Real ∩ 邻层
     if |nbrs| != 1: continue
     movable = id
     anchor = nbrs 中唯一元素
     // R1：仅当 movable 是悬挂叶、anchor 邻层邻居集大小 > 1（枢纽）
     //     或 anchor 虽也是叶但我们仍以「邻层邻居唯一」的 movable 为准、
     //     且要求 undirected_adj_layer_nbrs(movable) = {anchor}
     if |undirected_adj_layer_nbrs(movable)| != 1: continue
     if |undirected_adj_layer_nbrs(anchor)| <= 1:
          // 两端都像叶：本切片 skip（留给未来 P-Mutual）；不交换、不对齐
          continue
     // 至此：movable 挂到枢纽 anchor → 纳入候选
3. 按 (rank(movable), id) 分组：同一 (layer, anchor) 的 pendants 成一组
4. 对每组：
     if |group| == 1:
         trial = axis_center(anchor)
         若与同层非组员间距 < node_gap → skip（S-SkipIfConflict）
         否则 set_axis_center(movable, trial) 一次写入
     else:
         若启用条件满足（§5.2）→ S-PackUnderAnchor 一次原子写入整组
         否则 → S-SkipIfConflict（或整组跳过）
5. R3：本轮已写入的节点不再作为后续组的可动成员
```

**刻意删除**：旧稿中 `both degree == 1` 互为叶子分支（那是 P-Mutual，超出 V3b-1 DoD）。若未来要做，另开切片并改 DoD。

### 5.2 同层 db + cache：S-PackUnderAnchor

auth 下同层常有 **db 与 cache**。两者都是 P-Pendant→auth。

| 策略 | 行为 | 观感 |
|------|------|------|
| **S-SkipIfConflict** | 单点对齐；冲突则跳过 | 可能只有一个同心；V3b-1 默认 |
| **S-PackUnderAnchor**（V3b-2） | 收集挂到同一 anchor、同层的全部 pendant，在 **anchor 中心两侧** 按 `node_gap` 对称放置，使「组质心 = anchor 中心」 | 视觉对准 auth；左右分开 |
| **S-Priority** | 按边类型/实体类型优先 | **禁止**（易滑向图名特判） |

**启用条件（硬伤 5，实现契约）**：

```text
S-PackUnderAnchor 仅当同时满足：
  (E1) 组内全部是同锚 P-Pendant；
  (E2) 该层「会被 pack 写入的节点」之外，不存在会与试探包围盒在 node_gap 内冲突的其它 Real
      —— 推荐实现：pack 仅在「整层 Real 全部是该组 pendants」时启用；
         否则整组降级为 S-SkipIfConflict（逐个尝试，冲突则 skip）。
```

pack 后仍须做 **scoped 校验**：对受影响层，检查组内两两间距 ≥ `node_gap`，且组相对同层非组成员间距 ≥ `node_gap`；任一失败 → **回滚该组全部写入**（R3 下回滚不算「第二次移动」，视为该组本次未移动）。

伪代码：

```text
pendants = { n in same_layer | P-Pendant(n, anchor) }
sorted by (current_axis_center, id)   // 同 center 时按 id 字典序（AGENTS.md §2）
place around anchor.center with gap ≥ preset.node_gap
质心对齐 anchor.center（整体平移）
scoped overlap check vs 同层非组成员 → fail 则 rollback
```

**与 R3**：pack = 组内每人至多一次原子赋值；成功后禁止二次微调。

### 5.3 与 FAS / 假邻居

- 邻居枚举用 **无向 + 邻层 Real**，不要用「仅 effective 入边」——否则反转后 db 可能看不到 auth 为前驱。  
- **禁止**再引入全图 `all_pred`（L1 红线）。  
- Dummy 不参与 P-Pendant 的「唯一邻居」计数。

### 5.4 明确不做什么

- 不在 `straighten` / stub_fix 里挪节点来「对齐」。  
- 不用增大 parallel offset 假装节点对齐。  
- 不对 auth 做「向 db/cache 的 median 再拉一次」（那会动枢纽，违反用户约束）。  
- 不在 V3b-1/2 实现 P-Mutual 交换锚点逻辑。

## 8. 决策记录（方案层）

| 问题 | 结论 |
|------|------|
| L2 能否替代 V3b？ | **否**。D1：`n.user-auth` 走 `sugiyama_v2`/flowchart，L2=N/A。D2：实现前 `|auth-db|≈13.6`、组质心差≈91.6，远超 2px 门禁 |
| 第一刀选哪条路线？ | **路线 A**（后 BK 局部修复）— **已落地** |
| 单 vs 多 pendant？ | 单 → 节点同心；多 → **组质心** + pack（§0） |
| 同层多 pendant？ | V3b-1 Skip；V3b-2 **S-PackUnderAnchor**（E1/E2），只动叶子 — **已落地** |
| R3 × pack？ | pack = 组内每人一次原子赋值；之后禁止二次微调；失败整组回滚 |
| 同层间距配置项？ | **`preset.node_gap`**，不是 `layer_gap` |

## 11. 总结

V3b 的高维解法是：**定义 P-Pendant（邻居集合语义）+ 锚点所有权，在 BK 之后只移动悬挂叶子（必要时同层 pack 且整组校验），枢纽 auth 冻结**。  
单叶子求同心，多叶子求组质心——这比「再调一次 median」或「唯一邻居无条件平移」更安全，也比改 BK/上 QP 更可控。
