## 0. 一句话目标

把「auth/db 应对齐」从**个案拉扯**提升为可证明的布局契约：  
**在不动（或可证明地极少动）其它节点的前提下，让满足谓词的邻层节点对主轴中心重合**；实现落在 Sugiyama 坐标阶段，路由只消费结果。

## 1. 问题数值化（已知事实）

### 1.1 代表图结构

```text
client → gateway → auth ⇄ db
                 ↘ cache ⇄ auth
                 ↔ gateway（响应）
```

| 节点 | 角色 | 与对齐相关的邻居 |
|------|------|------------------|
| **auth** | 扇出枢纽 | 上：gateway；下：db、cache；回：gateway |
| **db** | 叶子 | **仅** auth（正反向各一条） |
| **cache** | 叶子 | 仅 auth（正反向） |

实测（V3a 收口后，数量级）：auth/db **中心差可达数十 px**；平行边 gap 已由 V3a 单独保证，**与中心差正交**。

### 1.2 为何现有机制盖不住

| 机制 | 为何不够 |
|------|----------|
| **L2**（architecture BK + dummy） | 只作用于 architecture 无 group 路径；flowchart 走完整 sugiyama，L2 **不自动**消 n.user-auth |
| **`align_singleton_layers_to_predecessors`** | 仅当**整层恰好 1 个 Real**；db 与 cache **同层**时整层不是 singleton → db 不进该函数 |
| **BK median / 块对齐** | auth 被 gateway+db+cache 多方拉扯；db 的 median 邻可能经 FAS/块冲突落在偏离 auth 中心的位置 |
| **「唯一邻层邻居」盲目拉齐**（已试回滚） | 谓词过宽或级联拉动，曾出现全局坐标漂移；说明**必须有锚点所有权 + 冲突检测**，不能「凡唯一就拉」 |

### 1.3 用户硬约束（本方案必须遵守）

1. **优先只动 db（被对齐者）**，auth（锚点）尽量不动。  
2. **禁止**为对齐挪 gateway / cache / client（除非可证明无冲突且有显式二级策略）。  
3. **时机**：仅布局、路由之前；路由后禁止挪节点（会反馈 space-budget / 假回归）。  
4. **禁止** `if diagram_id == "user-auth"`。

## 2. 高维视角：问题属于哪一类契约

V3b 不是「再写一个 align_xxx」，而是补一张缺失的契约表行：

```text
布局契约（节点级）
  C-LayerSeparation     同层最小间距、无重叠
  C-BKCompact           BK 四趟 + 紧凑化语义
  C-NeighborCenter  ★   满足谓词的邻层对：主轴中心差 ≤ ε
  C-AnchorOwnership ★   每一对对齐有唯一锚点；只允许移动非锚点（或对称共享预算）
```

与边级契约（C-ParallelGap / C-PortExclusive）的关系：

| 契约 | 阶段 | 解决什么 |
|------|------|----------|
| C-NeighborCenter | **布局** | 节点该不该同心 |
| C-ParallelGap | **路由后处理** | 同心之后正反向边仍要分开（V3a 已做） |

**顺序**：先中心对齐，再路由，再 gap——否则对齐会毁掉已分离的边，或边偏移掩盖节点未对齐。

## 3. 核心抽象：对齐谓词与锚点所有权

### 3.1 对齐对（Alignment Pair）

二元组 `(movable, anchor)`，主轴为 TB 的 x（或 LR 的 y）。

**候选谓词（建议采用 P-Pendant，见下）**：

| ID | 名称 | 谓词（同时满足） | 意图 |
|----|------|------------------|------|
| **P-Pendant** | 悬挂叶子 | ① `rank` 相邻；② 无向邻居集合（忽略 FAS 方向）∩ 邻层 Real = `{anchor}`；③ `movable` 在邻层的无向度数 = 1 | db→auth、cache→auth 类 |
| P-Mutual | 双向邻层对 | 邻层 + 正反向边都存在 + 两端在对方邻层度数均为 1 | 纯 2-节点往返 |
| P-HubSpoke | 扇出辐条 | hub 扇出到同层多个叶子；叶子满足 P-Pendant | 允许多个 movable 共锚同一 auth |

**n.user-auth 判定**：

- `(db, auth)`：**命中 P-Pendant**（db 邻层唯一邻居 = auth）。  
- `(cache, auth)`：同样命中；是否一起拉齐由策略决定（见 §5）。  
- `(auth, gateway)`：auth 邻层度数 > 1 → **auth 不作 movable**。

### 3.2 锚点所有权（关键，防布局崩）

| 规则 | 含义 |
|------|------|
| **R1 锚点不动** | 默认只改 `movable` 的中心 → `anchor` 中心 |
| **R2 同层打包优先** | 若移动 `movable` 导致与同层其它 Real **重叠或间距 < layer_gap**，则：先尝试在同层内「挤开邻居」**仅当邻居也是 P-Pendant 且共锚**；否则 **放弃该对**（保 C-LayerSeparation） |
| **R3 禁止级联** | 一轮扫描内每个节点至多被移动一次；禁止 A←B←C 链式传递 |
| **R4 锚点冲突** | 若两对抢同一 movable，取「锚点度数更高」或「上层优先」的一对，另一对跳过 |

上次失败的根因：缺少 R1–R3，把「唯一邻居」当成无条件平移，可能拉动本应作锚点的枢纽或引发同层雪崩。

## 4. 三条高维实现路线（比较）

### 路线 A — 后 BK 局部修复（推荐作为第一刀）

```text
BK + compaction + overlap resolve
  → align_singleton_layers（已有）
  → ★ align_pendant_to_anchor（新，仅 P-Pendant + R1–R4）
  → normalize padding
  → route …
```

| 优点 | 缺点 |
|------|------|
| 边界清晰；易测；不动 BK 核心 | 与 BK 块「理想位置」可能略不一致（可接受） |
| 天然满足「只动叶子」 | 同层 db/cache 挤在一起时可能 **放弃对齐**（需 R2 策略） |

**落地落点**：`sugiyama_v2/coordinate.rs`，紧接 `align_singleton_layers_to_predecessors`。

### 路线 B — 把 P-Pendant 写进 BK / 紧凑化目标

在 `vertical_alignment` / `horizontal_compaction` 中：对 P-Pendant 边加重「对齐权重」，或强制 movable 与 anchor 进同一 alignment block（在无冲突时）。

| 优点 | 缺点 |
|------|------|
| 对齐进入主算法，少后处理 | 改 BK 风险大；与 conflict 检测、spine 交互复杂 |
| | 难保证「绝对不动 auth」 |

**建议**：作中期选项；仅当路线 A 在全量 showcase 上频繁因 R2 放弃而对齐率不够时再开。

### 路线 C — 二次坐标优化（QP / 迭代）

布局后再做带约束的迭代：  
`min Σ (cx_i - cx_j)²` for pendant pairs，s.t. 同层分离、组框约束。

| 优点 | 缺点 |
|------|------|
| 表达力强，可一次处理多对 | 实现与调参重；WASM/性能需预算；易过度工程 |

**建议**：暂不作为 V3b 第一版。

## 5. 推荐方案（路线 A 细化）

### 5.1 算法草图

```text
输入：dag, layered_graph, layers, nodes, horizontal
ε = 1.0（中心差阈值）

1. 建 real_layer: id → rank
2. 对每个 Real id（稳定排序）：
     nbrs = 无向邻接 ∩ Real ∩ 邻层
     if |nbrs| != 1: continue
     anchor = nbrs[0]
     movable = id
     // R1：枢纽不作 movable
     if undirected_adj_layer_degree(anchor) > 1
        AND undirected_adj_layer_degree(movable) == 1:
          // movable 是叶子，anchor 是枢纽 → OK
     else if both degree == 1:
          // 互为叶子：上层或 id 序小者为 anchor
          按 rank(anchor) < rank(movable) 决定方向；否则交换
     else:
          continue  // 两边都是枢纽，不对齐

3. target = axis_center(anchor)
4. 若 |axis_center(movable) - target| ≤ ε: continue
5. 试探位置 trial = target
6. R2：检查同层其它 Real 与 trial 的间距
     - 若冲突且冲突者同为「挂到同一 anchor 的 P-Pendant」：
         可选策略 S-Pack：在同层按 anchor 中心对称重排这些 pendant（只动 pendant 组）
     - 若冲突且涉及非 pendant：skip（记录 skipped_conflict）
7. 应用 set_axis_center(movable, trial)；标记 moved
8. R3：已 moved 的节点本轮不再作 anchor 的依赖源（或整轮只一遍）
```

### 5.2 同层 db + cache 策略（必须先定）

auth 下同层常有 **db 与 cache**。两者都是 P-Pendant→auth。

| 策略 | 行为 | 观感 |
|------|------|------|
| **S-SkipIfConflict** | 谁先排谁对齐；冲突则后者跳过 | 可能只有一个同心 |
| **S-PackUnderAnchor**（推荐） | 收集挂到同一 anchor、同层的全部 pendant，在 **anchor 中心两侧** 按最小间距对称放置，使「组质心 = anchor 中心」 | 主轴视觉对齐到 auth；左右分开 db/cache |
| **S-Priority** | 按边类型/实体类型优先（易滑向图名特判） | **禁止** |

**推荐 S-PackUnderAnchor**：满足「视觉上对准 auth」，同时不清空同层分离；**仍不移动 auth**。

伪代码：

```text
pendants = { n in same_layer | P-Pendant(n, auth) }
sorted by current center
place around auth.cx with gap ≥ layer_min_sep
质心对齐 auth.cx（整体平移 pendants，再微调间距）
```

### 5.3 与 FAS / 假邻居

- 邻居枚举用 **无向 + 邻层 Real**，不要用「仅 effective 入边」——否则反转后 db 可能看不到 auth 为前驱（曾用 succ±1 补丁的原因）。  
- **禁止**再引入全图 `all_pred`（L1 红线）。  
- Dummy 不参与 P-Pendant 的「唯一邻居」计数。

### 5.4 明确不做什么

- 不在 `straighten` / stub_fix 里挪节点来「对齐」。  
- 不用增大 parallel offset 假装节点对齐。  
- 不对 auth 做「向 db/cache 的 median 再拉一次」（那会动枢纽，违反用户约束）。

## 10. 总结

V3b 的高维解法是：**定义 P-Pendant + 锚点所有权，在 BK 之后只移动悬挂叶子（必要时同层 pack），枢纽 auth 冻结**。  
这比「再调一次 median」或「唯一邻居无条件平移」更安全，也比改 BK/上 QP 更可控。
