# P0-1：正交路由统一障碍模型（消除穿节点 / 穿组）

> 指标：`edge_node_crossings`（边穿过无关节点）、`edge_through_groups`（边穿过分组内部）。  
> 目标：把「分组框 + 所有非端点节点」纳入统一障碍集，供事后阶段真正**消除**已存在的穿越，而非仅在候选打分时软惩罚。

---

## 1. 现状数据流

正交路由管线（对照手册 §3.1）：

```text
route_edges → replan_slots → straighten → reroute(4d)
 → stub_fix → lane_assignment → semantic_trunk_merge
 → sanitize → snap_and_repulse → label_resolve
```

## 2. 根因

**候选生成阶段全穿越时进 degraded fallback（`best_dirty`）输出脏路径；此后没有任何一个阶段以「消穿越」为目标**：

- `conflict_reroute` 只看**边-边间距**，脏路径只要不与其它边挤压就不会被触碰。
- `sanitize` 只修几何不变量（反向 stub、斜段、微折），甚至可能因 `merge_overshoot` 把避障台阶拉直而**新增**穿越。
- `lane_assignment` 只在偏移时 `validate_shift` 校验不新增穿节点，但对**已存在**的穿越无能为力。
- `corridor_route` 退化时只绕组不绕节点。

数据结构层面缺口：`PreparedObstacles` 没有「给定 polyline → 返回其穿过的 node/group 集合」的统一查询，导致事后阶段即使想修也没有统一入口；scoring 里的硬过滤逻辑分散、只服务候选筛选，无法被 reroute/sanitize 复用。

## 3. 修复方案

### 3.1 升级 `PreparedObstacles` 为可查询障碍集合

在 [`context.rs`](../../crates/plotgram-core/src/layout/edge/edge_routing_orthogonal/context.rs) 为 `PreparedObstacles` 增加统一查询方法（详见 [README §2](./README.md)），复用 `common/geom_obstacle.rs` 的 primitive 保证与 lint 判定一致：

```text
fn path_violations(&self, path, exempt_src, exempt_dst, nodes, group_ctx)
    -> ObstacleViolations { node_hits, group_hits }
```

- 豁免规则与 `path_is_clean` / `path_avoids_group_interiors` 完全一致（源首段、宿末段 stub 豁免），把两处硬过滤逻辑收敛到此单一实现，scoring 改为调用它，避免判定双轨（手册 §2.2 契约单尺寸源）。

### 3.2 conflict_reroute 增加「穿障违规」触发条件

在 [`reroute_conflicting_edges`](../../crates/plotgram-core/src/layout/edge/edge_routing_orthogonal/conflict_reroute.rs#L26-L176) 现有 `collect_spacing_conflicts` 之外，增加 `collect_obstacle_violations`：对每条已路由边调用 3.1 的 `path_violations`，若 `node_hits`/`group_hits` 非空，将该边纳入重路由集合。

- 重路由时优先取 `best_strict`；取不到再 `best_nodes_only`；仍不行才保留原 `best_dirty` 并**显式标记 degraded**（手册 §3.5 P1 优先级：不穿组 ≫ 不穿节点 ≫ 短/共线）。
- 遵守手册 §1.2「合流重造整条路径」教训：重路由保留源 stub / 绕障前缀，只改必要 suffix。

### 3.3 走廊行驶纳入节点障碍

[`corridor_travel_skirting_foreign`](../../crates/plotgram-core/src/layout/edge/edge_routing_orthogonal/corridor_route.rs#L376) 的外绕判定，从「只绕 foreign group」扩展为「绕 group ∪ 途经非端点节点」，用 3.1 的统一查询驱动外绕方向选择，避免走廊退化时穿节点。

### 3.4 sanitize 侧只加防御不加激进修复

保持 `sanitize` 保守（手册 §1.1 法则 2）。仅把 `validate_route_edit` 的「编辑前干净→编辑后穿」增量回退从 `merge_overshoot` 专用**扩展到 `sanitize_polyline_ext_guarded` 的所有几何编辑**，防止 sanitize 自身新增穿越。真正的消穿越由 3.2 的 reroute 承担。

## 5. 验证

1. `cargo run -p plotgram-cli` 渲染既有穿节点/穿组样例（architecture / flowchart 中 through 较多者），确认穿越消除或转为**显式 degraded**（非静默斜线）。
2. 全量 showcase 重跑，`edge_node_crossings` + `edge_through_groups` 总量**下降或持平**，重叠严重度不上升。
3. 手册 §3.5 P3 红线：refine/reroute **不得**为消 through 毁掉已避组几何——只对当前仍穿越的边重路由，已避组仅 through 的边默认不动。
4. 节点坐标不变（本方案只改边路由，不动节点）；如坐标变动即为回归，须排查。
