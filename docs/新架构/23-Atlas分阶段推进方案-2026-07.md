## 0. 推进原则

### 0.1 三条铁律

1. **每个 Stage 结束时，主干必须能出图。** 允许观感退化，不允许「中间态跑不通」。
2. **每个 Stage 必须关掉它替换掉的旧路径。** 不允许「新旧长期并存」——双轨期限定在单个 Stage 内。
3. **对拍替代阻断。** 门禁关了（§10），但每个 Stage 有明确的**对拍口径**：新旧管线同图集跑，产出差异报告；退化要能说清是哪一类。

### 0.2 门禁关闭期的替代品

| 原门禁 | 本期替代 |
|--------|----------|
| `check-*.sh` 棘轮硬 FAIL | Stage 0 的**影子对拍报告**：新旧节点坐标 diff、lint diff、SVG 并排 |
| `compare.sh` product 硬 FAIL | 同一脚本 report-only 模式，人工判读 + 每 Stage 记「已知退化清单」 |
| CI `cargo test` 阻断 | `continue-on-error`；Stage 7 按新架构不变量重建 |

**仍然硬的**（§10 未豁免）：确定性、WASM 禁 `std::time`、禁图名特判、用 `cargo run -p plotgram-cli` 验真。

### 0.3 影子执行（Shadow）机制

贯穿 Stage 1–6 的核心工具：

```text
同一个 .pgm
   ├── LegacyPipeline  → LayoutResult_legacy
   └── AtlasPipeline   → LayoutResult_atlas
                ↓
        ShadowReport（差异报告）
          · 节点坐标 diff（逐节点 dx/dy，统计 p50/p95/max）
          · 组框 diff
          · lint 计数 diff（穿组 / 穿节点 / 交叉 / 折点）
          · 相 I 可行性（Plan 是否成功）与相 II 松弛级别
          · SVG 并排 HTML
```

切换开关：`PLOTGRAM_PIPELINE=atlas|legacy|shadow`（默认随 Stage 推进而变）。

## 1. Stage 总览

| Stage | 名称 | 核心交付 | 主干默认管线 | 预期退化窗口 |
|-------|------|----------|--------------|--------------|
| **S0** | 地基与对拍 | Provenance、Occupant/Demand 类型、Shadow 框架 | legacy | 无（纯新增） |
| **S1** | Plan IR 与表达力验证 | `Plan` 结构 + Legacy Adapter | legacy | 无（旁路） |
| **S2** | 度量相统一（节点 + 组框） | 组框进 LP，删后验包围盒 | atlas（无组图） | 组框几何变化 |
| **S3** | 通道进度量相 | Channel 成为 Occupant，删 SpaceBudget 回环 | atlas（含组图） | 边缝与间距明显变化 |
| **S4** | 组合相真实现 | 抽象通道图选路，删 repair/sanitize/repulse | atlas（全 Hierarchical） | **最大**：边几何全面重算 |
| **S5** | Dialect 收敛 | Hierarchical 吞 two_phase + group_divide | atlas | architecture 观感风险最高 |
| **S6** | 四内核归位 + 增量 | Tree/Sequence/Circular Dialect；Plan diff 增量 | atlas（全五图种） | mindmap/sequence 局部 |
| **S7** | 新门禁与收口 | 不变量门禁重建，恢复棘轮 | atlas | 收敛，无新退化 |

**关键里程碑**：S4 结束 = 新管线成为 Hierarchical 系图种默认，**并作为评估门停下**（决策 D5，判据见 §11）；S6 结束 = 五图种全切；S7 结束 = §10 豁免退出。

### 交付物

| # | 交付 | 落点（建议） |

| 0.1 | `Provenance` 类型 + 几何量携带机制 | `layout/atlas/provenance.rs` |

pub enum OccupantKind { Node, GroupFrame, Channel, LabelBox }

## 3. Stage 1：Plan IR 与表达力验证

### 目标

**先证明 `Plan` 装得下所有图种的离散决策，再谈换求解器。** 手段：让**旧管线**去填充 `Plan`。

### 交付物

| # | 交付 |
|---|------|
| 1.1 | `Plan` 结构：rank / order / gate / port / channel / merge 拓扑 |
| 1.2 | `Plan` 序列化 + 稳定哈希 + `diff()` |
| 1.3 | **Legacy Adapter**：从旧管线中间产物（`LayeredDraft`、`endpoint_map`、`LaneAssignment`、`MergeInterval`）反向构造 `Plan` |
| 1.4 | **Ink 原型**：`(Plan, 旧坐标) → 边几何`，与旧几何对拍 |
| 1.5 | 表达力缺口清单 |

### `Plan` 建议骨架

```rust
pub struct Plan {
    pub substrate: Substrate,                    // rank 轴 × order 轴骨架
    pub node_slots: IndexMap<NodeId, Slot>,      // (rank, order)
    pub group_scopes: IndexMap<GroupId, Scope>,  // 收缩层次 + rank 区间
    pub ports:    IndexMap<EdgeId, (PortId, PortId)>,
    pub gates:    IndexMap<EdgeId, Vec<GateId>>, // 跨组闸口序列
    pub channels: IndexMap<EdgeId, Vec<TrackSlot>>, // track 序列 = 路径拓扑
    pub bundles:  Vec<BundleId>,                 // 共享 track 后缀 = 合流
    pub provenance: ProvenanceMap,
}
```

### 关键验证问题（Stage 1 必须回答）

1. architecture 的 macro rank / equal-track 能否表达为 `group_scopes` + Profile？
2. sequence 的「布局阶段产边」能否表达为 `channels` 的退化形式（每条消息一条固定 track）？
3. mindmap 的径向布局 `Substrate` 怎么定义（rank = 层级深度，order = 角度序）？
4. `semantic_trunk_merge` 的 `MergeInterval` 能否无损映射为 `bundles`？

### 验收

- 五图种 showcase 全部能构造出 `Plan`（Adapter 路径）
- **Ink 原型重放**：`Ink(Plan_from_legacy, 旧坐标)` 的边几何与旧几何差异 ≤ 容差（说明 `Plan` 无损）
- 缺口清单落文档；无法表达的项显式记债

### 回滚点

Adapter 与 Ink 原型均为旁路，主干管线不变。

> **这是整个方案风险最低、信息量最大的一步。** 如果 `Plan` 装不下某图种，在这里就暴露，代价是一个 Stage 而不是整个重构。

## 4. Stage 2：度量相统一（节点 + 组框）

### 目标

**杀死后验包围盒。** 组框四边成为相 II 的真变量。

### 交付物

| # | 交付 |
|---|------|
| 2.1 | 打开 `GroupContainment` 投影（现"首期不投影，仅审计"） |
| 2.2 | 打开 `GroupSiblingSeparation` 投影 |
| 2.3 | 逐轴交替求解框架 `solve_axis(X) / solve_axis(Y)` |
| 2.4 | 删除 `compute_group_bounds` 在主路径的调用 |
| 2.5 | `Contract` 成为**唯一**坐标入口：删 `engines/coordinate/builder` 与 architecture 自有装配 |
| 2.6 | `engines/` 目录清空（遗留 `coordinate` builder 迁入 kernel 或删除） |

### 算法要点

- 组框变量已存在（`GroupVariable.{left,right,top,bottom}`），需要的是**把约束接上投影**
- 组包含约束形式：`g.left ≤ min_{v∈g}(v.left) − pad_left`，是标准分离约束，PAVA 可直接处理
- 嵌套组：按 group 树深度**由内向外**加约束，Dykstra 处理约束簇交
- 裙边（`Skirt`）作为组框的 `Demand`，不再是 `GROUP_BORDER_SHELL_PAD` 常量硬编码

### 主干切换

`PLOTGRAM_PIPELINE` 默认切 `atlas`，但**仅对无 group 的图**；有 group 的图仍走 legacy（Stage 3–5 逐步接管）。

### 验收

- 无组图：节点坐标与 legacy 差异 p95 ≤ 2px（求解器同源，差异应很小）
- 有组图（shadow 模式）：组框由求解产出，与后验包围盒对比，**面积差与偏移记录成基线**
- `write_counter` 的 group 写点降为 0（不再有 materialize 写，组框是求解输出）

### 已知退化窗口

组框几何会变（求解 vs 后验包围）。**这是预期的**，需逐图记录。

### 回滚点

`PLOTGRAM_PIPELINE=legacy` 单开关回退。

## 5. Stage 3：通道进度量相

### 目标

**边缝与节点距同源。** `Channel` 成为 Occupant，`SpaceBudget` 回环消失。

### 交付物

| # | 交付 |
|---|------|
| 3.1 | `track` 坐标变量进 `CoordinateProblem` |
| 3.2 | 通道净空硬约束：`track.coord` 与两侧 Occupant 分离 |
| 3.3 | lane 导出规则：`lane.coord = track.coord + i × pitch`（非自由变量） |
| 3.4 | Channel `Demand` 由 Plan 的 lane 数决定（`min = n × pitch`） |
| 3.5 | 删 `demand/space_budget_guard`、删 `post_route/border_repulse` |
| 3.6 | `RelaxationLadder` L0–L4 实现 + Provenance 留痕 |

### 算法要点

- 此时 Plan 的 `channels` 仍由 Stage 1 的 **Legacy Adapter** 提供（相 I 还没换）——**这是刻意的**：先验证「通道进 LP」这一件事，不与「换选路算法」耦合
- track 变量数量级：O(层数 × 每层通道数)，远小于节点数
- 净空约束与节点分离约束同型，PAVA 无需改造

### 验收

- **核心指标**：`ortho.degraded_count` 应显著下降（挤不下的情况由 LP 撑开而非降级）
- `hugging_violations`（贴边）应趋零（净空是硬约束，不再需要 repulse）
- 画布尺寸会增大（缝是真需求了）——记录增幅

### 已知退化窗口

- 画布变大、间距变松：**这是正确性换来的**，Stage 4 的紧凑目标会收回来一部分
- 边几何仍由 legacy 路径决定，可能与新坐标不完全协调（Stage 4 解决）

## 6. Stage 4：组合相真实现

> **本方案的核心 Stage，也是退化窗口最大的一步。**

### 目标

用抽象通道图选路替换正交路由主链；删除全部补救阶段。

### 交付物

| # | 交付 |
|---|------|
| 4.1 | 抽象通道图构建：`PortSlot` / `TrackSlot` / `Gate` 顶点 + 转移边 |
| 4.2 | Gate 分配（最小费用流 / 带容量匹配） |
| 4.3 | 通道选路：`lex_astar` 在通道图上运行（复用 `kernel/route/search.rs`） |
| 4.4 | 全局协调：有界块坐标下降（Ordering / Gate / Channel 三块，≤3 轮） |
| 4.5 | 合流 = 共享 track 后缀（替换 `semantic_trunk_merge`） |
| 4.6 | **删除**：`path_solver` rip-up、`sanitize`、`canonicalize_orthogonal_edges`、Coordinator repair loop |
| 4.7 | Ink 相正式化（Stage 1 原型转正） |
| 4.8 | `edge_routing_orthogonal/` 目录大幅缩减（预计 −60% 以上） |

### 算法要点

- **规模优势**：OVG 顶点 O(V²)（代码里 `ovg_enabled` 限节点 ≤50）；通道图顶点 O(层数 × 通道数)。可对**全部边**做完整搜索，不再需要 `ovg_enabled` 这类规模开关
- **穿组不可表达**：没有 gate 就没有跨越 → `H2GroupInterior` 由构造保证，不再是检测项
- **正交性由构造保证**：track 是轴向的，折点是 track 切换点 → 不需要 sanitize
- 接受判据统一为 `LexCost` 词典序严格改善（手册「候选破约即回滚」自动满足）

### 验收

| 维度 | 口径 |
|------|------|
| 正确性 | 穿组 = 0（构造保证，可用 lint 反证）；`det = true` |
| 可行性 | 相 I 成功率 100%；相 II 松弛级别分布（L0 占比应 > 90%） |
| 美学 | crossings / bends 与 legacy 对拍；**允许有界退化**，逐图记录 |
| 性能 | product 集 median_ms 不劣于 legacy 的 1.3×（通道图更小，预期反而更快） |
| 代码量 | `routing/` 行数应下降（今天 ~30k / 82 文件） |

### 已知退化窗口

**这一步会让所有边几何重算。** 明确接受：

- 边走向与 legacy 明显不同（拓扑级选路 vs 像素级选路）
- 部分图的美学指标（bends / crossings）可能短期变差
- 退出判据：product 集**正确性零违规** + 美学退化项逐图有解释

### 回滚点

Stage 4 应拆成**至少 3 个可回滚子步**：
- 4a 通道图 + Gate（Plan 仍用 legacy channels 对拍）
- 4b 选路切换（保留 repair loop 兜底）
- 4c 删补救阶段（repair / sanitize / repulse）

| 拓扑合法性由构造保证 | 反证测试：随机图跑 Atlas，lint 穿组恒为 0 | repair loop |
