## 0. 推进原则

### 0.1 三条铁律

1. **每个 Stage 结束时，主干必须能出图。** 允许观感退化，不允许「中间态跑不通」。
2. **每个 Stage 必须关掉它替换掉的旧路径。** 不允许「新旧长期并存」——双轨期限定在单个 Stage 内。
3. **对拍替代阻断。** 门禁关了（§10），但每个 Stage 有明确的**对拍口径**：新旧管线同图集跑，产出差异报告；退化要能说清是哪一类。

### 0.2 门禁关闭期的替代品

| 原门禁 | 本期替代 |
|--------|----------|
| `check-*.sh` 棘轮硬 FAIL | Stage 0 的**影子对拍报告**：新旧节点坐标 diff、lint diff、SVG 并排 |
| `compare.sh` product 硬 FAIL | 同一脚本 report-only 模式，人工判读 + 每 Stage 记「已知退化清单」 |
| CI `cargo test` 阻断 | `continue-on-error`；Stage 7 按新架构不变量重建 |

**仍然硬的**（§10 未豁免）：确定性、WASM 禁 `std::time`、禁图名特判、用 `cargo run -p plotgram-cli` 验真。

### 0.3 影子执行（Shadow）机制

贯穿 Stage 1–6 的核心工具：

```text
同一个 .pgm
   ├── LegacyPipeline  → LayoutResult_legacy
   └── AtlasPipeline   → LayoutResult_atlas
                ↓
        ShadowReport（差异报告）
          · 节点坐标 diff（逐节点 dx/dy，统计 p50/p95/max）
          · 组框 diff
          · lint 计数 diff（穿组 / 穿节点 / 交叉 / 折点）
          · 相 I 可行性（Plan 是否成功）与相 II 松弛级别
          · SVG 并排 HTML
```

切换开关：`PLOTGRAM_PIPELINE=atlas|legacy|shadow`（默认随 Stage 推进而变）。

## 3. Stage 1：Plan IR 与表达力验证

### 目标

**先证明 `Plan` 装得下所有图种的离散决策，再谈换求解器。** 手段：让**旧管线**去填充 `Plan`。

### 交付物

| # | 交付 |
|---|------|
| **1.0** | **channel 合法化（前置，见下）**：27 号文 **L1–L4 + L8** —— 轨道分段、gate 绑定边界线（配对范围 `(o0,o1]`/`(r0,r1]`）、`span_weight` 真实化、gate 容量改输出、**搜索期作用域过滤**（编号 L*，勿与 24 号文 R1–R5 混淆） |
| **1.0b** | **合法性自反证检查器**（27 号文 **L6**）：`Substrate::verify_no_group_penetration()`，O(段数 × 组数) 静态检查 |
| 1.1 | `Plan` 结构：rank / order / gate / port / channel / merge 拓扑 |
| 1.2 | `Plan` 序列化 + 稳定哈希 + `diff()` |
| 1.3 | **Legacy Adapter**：从旧管线中间产物（`LayeredDraft`、`endpoint_map`、`LaneAssignment`、`MergeInterval`）反向构造 `Plan`。**注意**：Adapter 必须提供组矩形在 rank/order 网格上的覆盖区间（分段的输入），而不只是组树 |
| 1.4 | **Ink 原型**：`(Plan, 旧坐标) → 边几何`，与旧几何对拍 |
| 1.5 | 表达力缺口清单 |
| 1.6 | 探针三列口径改造（27 号文 **L5** / §5.1）+ 重采 25 号文全部数字 |

### 前置：channel 合法化（1.0 / 1.0b）

`layout/atlas/channel/` 原型已实现并出了[探针报告](25-Atlas-相I可行率探针报告-2026-07.md)。结论分两半：

- ✅ **粒度够、性能够**：三集 77 图 / 1152 边零「网格不可表达」；channel 本体 ≈35 ms。22 号文 §8 风险台账第一条结案。
- ❌ **合法性不成立**：H2「穿组不可表达」在 derive 产物上为假，实测 ≥2.3% 的边走穿组路径，且穿组是词典序**严格最优**（0 折点 vs 绕行 ≥2 折点）；gate 的 side 维度退化为装饰。

根因是省掉了**段（Segment）**维（22 号文 §3.1）。但**段维只解一半**：分段消灭「跨线跳跃」式借道，消灭不了「沿同一条线从左根段直穿到右根段」——后者 gate 同向 0 折点、几何最短，在 Q3/Q4 上双双最优，词典序必选（27 号文 §3.1）。因此必须同时上 **L8 搜索期作用域过滤**，否则 L1–L3 干完重跑探针 A2 会直接爆掉，且极易误判成「分段做错了」。

改造主要落在 `derive.rs` + `substrate.rs`；`search.rs` 只加一个作用域谓词（词典序 Dijkstra 本体、平局键、确定性不变）；`bundle.rs` / `Occupancy` **不动**。

**建议实施次序**：L1 分段 → L2 gate → **L8 过滤** → L6 检查器 → L3 span_weight → L4 容量 → L5 探针。L8/L6 插在 L3 之前，是因为 L3 会把边从最外框走廊赶回图内部（原型的穿组率之所以只有 2.3%，是代价退化把边都挤到了图外框），先立合法性约束再改代价，A2 的变化才归因得清。

**这不是新 Stage**，而是 Stage 1 的入场券：Legacy Adapter 若接到一个会穿组的基底上，后面所有对拍都在拿错误结果做基准。**1.0 / 1.0b 未过，不启动 1.3。**

### `Plan` 建议骨架

```rust
pub struct Plan {
    pub substrate: Substrate,                    // rank 轴 × order 轴骨架
    pub node_slots: IndexMap<NodeId, Slot>,      // (rank, order)
    pub group_scopes: IndexMap<GroupId, Scope>,  // 收缩层次 + rank 区间
    pub ports:    IndexMap<EdgeId, (PortId, PortId)>,
    pub gates:    IndexMap<EdgeId, Vec<GateId>>, // 跨组闸口序列
    pub channels: IndexMap<EdgeId, Vec<TrackSlot>>, // track 序列 = 路径拓扑
    pub bundles:  Vec<BundleId>,                 // 共享 track 后缀 = 合流
    pub provenance: ProvenanceMap,
}
```

### 关键验证问题（Stage 1 必须回答）

1. architecture 的 macro rank / equal-track 能否表达为 `group_scopes` + Profile？
2. sequence 的「布局阶段产边」能否表达为 `channels` 的退化形式（每条消息一条固定 track）？
3. mindmap 的径向布局 `Substrate` 怎么定义（rank = 层级深度，order = 角度序）？
4. `semantic_trunk_merge` 的 `MergeInterval` 能否无损映射为 `bundles`？
5. **分治网格 vs flat 网格**：25 号文的探针是统一 flat 口径，不镜像 `divide-conquer` / `two_phase` 的真实几何（三集中 27 张图受影响）。Adapter 接上真实 blueprint 后，这些图的合法可行率需**单独复测**——这是 flat 口径下唯一没被回答的问题。
6. **mindmap 深树**：stress-deep 在 flat 网格里峰值 lane 33（全部边压进少数几条缝）。27 号文 **L3** 修正 `span_weight` 后应大幅回落；若仍居高，说明径向图种确实需要另一套 `Substrate`（rank = 层级深度、order = 角度序），而不是通道图缺陷。

### 验收

**门 A（1.0 / 1.0b 合法化，硬）**——判据即 27 号文 §7：

| # | 判据 | 改造前 | 目标 | 由谁保证 |
|---|---|---|---|---|
| A1 | `verify_no_group_penetration()` 全集通过 | 无此检查 | 77 图全通过 | L1 / L6 |
| A2 | 借道穿「两端都不属于的组」的边数 | 27 / 1152 | **0** | **L8**（L1–L4 不足以达成） |
| A3 | 同一 gate 被同一条边穿越 ≥2 次 | 116 / 1152 | **0** | L2 |
| A4 | 合法单边可行率（三集） | 100%（含非法路径） | ≥ 99%，失败边逐条有解释 | 兜住 L8 的可行性副作用 |
| A5 | 峰值 lane demand（stress / product / demo） | 33 / 10 / 25 | 显著下降（27 号文 L3 效果度量，不设硬指标） | L3 |
| A6 | 端口争用成功率（27 号文 L5 生产口径） | 未测 | 出数并逐图分析；**不得**与 A4 合并成「争用也 100%」 | L5 |
| A7 | channel 本体耗时（三集合计） | ≈35 ms | ≤ 100 ms（段数上升的预算） | — |
| A9 | L1.1 切割边界用例单测 B1–B7 | 无 | 全部通过 | L1 |
| A10 | L8 副作用边界单测（组横跨全列时外框绕行仍可行） | 无 | 通过 | L8 |

A2 / A3 归零是**硬判据**——它们正是「由构造保证」这句话的定义。A3 不过查 L2；**A2 不过先查 L8 的作用域掩码，不要先怀疑 L1 分段**。

**门 B（Plan 表达力）**：

- 五图种 showcase 全部能构造出 `Plan`（Adapter 路径）
- **Ink 原型重放**：`Ink(Plan_from_legacy, 旧坐标)` 的边几何与旧几何差异 ≤ 容差（说明 `Plan` 无损）
- 缺口清单落文档；无法表达的项显式记债

### 回滚点

Adapter 与 Ink 原型均为旁路，主干管线不变。

> **这是整个方案风险最低、信息量最大的一步。** 如果 `Plan` 装不下某图种，在这里就暴露，代价是一个 Stage 而不是整个重构。

## 4. Stage 2：度量相统一（节点 + 组框）

### 目标

**杀死后验包围盒。** 组框四边成为相 II 的真变量。

### 交付物

| # | 交付 |
|---|------|
| 2.1 | 打开 `GroupContainment` 投影（现"首期不投影，仅审计"） |
| 2.2 | 打开 `GroupSiblingSeparation` 投影 |
| 2.3 | 逐轴交替求解框架 `solve_axis(X) / solve_axis(Y)` |
| 2.4 | 删除 `compute_group_bounds` 在主路径的调用 |
| 2.5 | `Contract` 成为**唯一**坐标入口：删 `engines/coordinate/builder` 与 architecture 自有装配 |
| 2.6 | `engines/` 目录清空（遗留 `coordinate` builder 迁入 kernel 或删除） |

### 算法要点

- 组框变量已存在（`GroupVariable.{left,right,top,bottom}`），需要的是**把约束接上投影**
- 组包含约束形式：`g.left ≤ min_{v∈g}(v.left) − pad_left`，是标准分离约束，PAVA 可直接处理
- 嵌套组：按 group 树深度**由内向外**加约束，Dykstra 处理约束簇交
- 裙边（`Skirt`）作为组框的 `Demand`，不再是 `GROUP_BORDER_SHELL_PAD` 常量硬编码

### 主干切换

`PLOTGRAM_PIPELINE` 默认切 `atlas`，但**仅对无 group 的图**；有 group 的图仍走 legacy（Stage 3–5 逐步接管）。

### 验收

- 无组图：节点坐标与 legacy 差异 p95 ≤ 2px（求解器同源，差异应很小）
- 有组图（shadow 模式）：组框由求解产出，与后验包围盒对比，**面积差与偏移记录成基线**
- `write_counter` 的 group 写点降为 0（不再有 materialize 写，组框是求解输出）

### 已知退化窗口

组框几何会变（求解 vs 后验包围）。**这是预期的**，需逐图记录。

### 回滚点

`PLOTGRAM_PIPELINE=legacy` 单开关回退。

## 5. Stage 3：通道进度量相

### 目标

**边缝与节点距同源。** `Channel` 成为 Occupant，`SpaceBudget` 回环消失。

### 交付物

| # | 交付 |
|---|------|
| 3.1 | `track` 坐标变量进 `CoordinateProblem` |
| 3.2 | 通道净空硬约束：`track.coord` 与两侧 Occupant 分离 |
| 3.3 | lane 导出规则：`lane.coord = track.coord + i × pitch`（非自由变量） |
| 3.4 | Channel `Demand` 由 Plan 的 lane 数决定（`min = n × pitch`） |
| 3.5 | 删 `demand/space_budget_guard`、删 `post_route/border_repulse` |
| 3.6 | `RelaxationLadder` L0–L4 实现 + Provenance 留痕 |

### 算法要点

- 此时 Plan 的 `channels` 仍由 Stage 1 的 **Legacy Adapter** 提供（相 I 还没换）——**这是刻意的**：先验证「通道进 LP」这一件事，不与「换选路算法」耦合
- track 变量数量级：O(层数 × 每层通道数)，远小于节点数
- 净空约束与节点分离约束同型，PAVA 无需改造

### 验收

- **核心指标**：`ortho.degraded_count` 应显著下降（挤不下的情况由 LP 撑开而非降级）
- `hugging_violations`（贴边）应趋零（净空是硬约束，不再需要 repulse）
- 画布尺寸会增大（缝是真需求了）——记录增幅

### 已知退化窗口

- 画布变大、间距变松：**这是正确性换来的**，Stage 4 的紧凑目标会收回来一部分
- 边几何仍由 legacy 路径决定，可能与新坐标不完全协调（Stage 4 解决）

## 6. Stage 4：组合相真实现

> **本方案的核心 Stage，也是退化窗口最大的一步。**

### 目标

用抽象通道图选路替换正交路由主链；删除全部补救阶段。

### 交付物

| # | 交付 |
|---|------|
| 4.1 | 抽象通道图构建：`PortSlot` / `Segment` / `Gate` 顶点 + 转移边（Stage 1 的 1.0 已完成合法化，此处接生产 blueprint） |
| 4.2 | Gate 分配（最小费用流 / 带容量匹配），容量走「Demand → 相 II 撑开」（22 号文 §5.1 I.4） |
| 4.3 | 通道选路：`lex_astar` 在通道图上运行（复用 `kernel/route/search.rs`） |
| 4.4 | 全局协调：有界块坐标下降（Ordering / Gate / Channel 三块，≤3 轮） |
| 4.5 | 合流 = 共享 track 后缀（替换 `semantic_trunk_merge`） |
| 4.6 | **删除**：`path_solver` rip-up、`sanitize`、`canonicalize_orthogonal_edges`、Coordinator repair loop |
| 4.7 | Ink 相正式化（Stage 1 原型转正） |
| 4.8 | `edge_routing_orthogonal/` 目录大幅缩减（预计 −60% 以上） |

### 算法要点

- **规模优势已实测**：OVG 顶点 O(V²)（代码里 `ovg_enabled` 限节点 ≤50）；通道图上三集 1152 边全部选路合计 ≈35 ms，最重单图 7.0 ms（25 号文 §7）。可对**全部边**做完整搜索，不再需要 `ovg_enabled` 这类规模开关，且给有界回溯留足预算
- **性能瓶颈在上游不在通道图**：端到端 94–98% 的时间在 `LayeredKernel::compute`（最重单图 162.7 ms）。Stage 4 若出现性能回归，先查分层求解，别怪通道图
- **穿组不可表达**：段被组边界打断 + 跨越只能经 gate → `H2GroupInterior` 由构造保证，不再是检测项
- **正交性由构造保证**：段是轴向的，折点是异向段切换点 → 不需要 sanitize
- 接受判据统一为 `LexCost` 词典序严格改善（手册「候选破约即回滚」自动满足）

### 验收

| 维度 | 口径 |
|------|------|
| 正确性 | 穿组 = 0，**三轨证明**：① `verify_no_group_penetration()` 静态通过（基底归属正确）② 搜索期作用域过滤在位、A2 = 0（路径不借道）③ 生产 lint 反证为 0（端到端）。任一不过即判失败——原型的教训是「声称由构造保证」而无检查器时违规会静默存在（27 号文 §2 F1），而只做静态那条时「同线直穿」的借道仍是最优解（27 号文 §3.1）；`det = true` |
| 可行性 | 相 I 成功率 100%（**合法路径口径**，非「图上有没有路」）；相 II 松弛级别分布（L0 占比应 > 90%） |
| 容量口径 | gate 与端口容量均按生产口径（22 号文 I.4 / 27 号文 L5），**不得**用「容量 = 需求」或「容量 = 不限」出数 |
| 美学 | crossings / bends 与 legacy 对拍；**允许有界退化**，逐图记录。峰值 lane demand 作为通道拥塞监控项 |
| 性能 | product 集 median_ms 不劣于 legacy 的 1.3×（通道图本体已实测 ≈ 数毫秒量级，预算充裕） |
| 代码量 | `routing/` 行数应下降（今天 ~30k / 82 文件） |

**优先回归样本**（25 号文 §4.3 高压图 + 27 号文违规 Top）：`demo.plotgram-core-mod-deps`（原型下 29 条成功边里 16 条穿组）、`demo.k8s-multi-namespace-overview`（gate 需求 18）、`demo.k8s-multi-cluster-federation`（峰值 lane 25）、`product.cloud-native`、`product.ecommerce-platform`、`stress.layout-stress-nested`。这些是通道压力最大、最先暴露问题的图。

### 已知退化窗口

**这一步会让所有边几何重算。** 明确接受：

- 边走向与 legacy 明显不同（拓扑级选路 vs 像素级选路）
- 部分图的美学指标（bends / crossings）可能短期变差
- 退出判据：product 集**正确性零违规** + 美学退化项逐图有解释

### 回滚点

Stage 4 应拆成**至少 3 个可回滚子步**：
- 4a 通道图 + Gate（Plan 仍用 legacy channels 对拍）
- 4b 选路切换（保留 repair loop 兜底）

| # | 决策 | 结论 | 状态 |
|---|------|------|------|
| **D1** | 代码组织 | **`layout/atlas/` 新子树 + `PLOTGRAM_PIPELINE` 开关**；新旧两条管线共存于同一进程，供影子对拍。每个 Stage 结束关掉对应旧路径，双轨不跨 Stage | ✅ 已定 |

| **D3** | Stage 4 退化容忍 | **正确性硬、美学软**：穿组 = 0 与 `det = true` 不可退；crossings / bends 允许有界退化，逐图记入 §10 已知退化清单 | ✅ 已定 |
| **D4** | group 嵌套深度 | Atlas 递归天然支持任意深度；DSL 当前限 2 层（`dsl/parser/stmt.rs:301`）。建议 Stage 5 顺带解开 | 待定 |
| **D5** | 节奏 | **先推到 Stage 4 停下评估**。彼时新管线已成型、旧补救阶段已删，是天然决策点；S5–S7 视评估结果再启动 | ✅ 已定 |
| **D6** | gate 容量的性质 | **容量是输出，不是输入**。相 I 只累计 `crossing_demand`，相 II 用「边界段长 ≥ demand × pitch」撑开，撑不开走 `RelaxationLadder`。固定容量仅作诊断扫描通道。理由：「容量 = 边长 / 最小间距」是相 I 拿不到的几何量；原型用「容量 = 该组跨界边数」绕过，等于把约束设成恒真（27 号文 F3） | ✅ 已定（22 号文 §5.1 I.4 已改） |
| **D7** | 通道图的维度取舍 | **段（Segment）维必需，lane 维可延后**。lane 分配本质是度量相的事，相 I 不必区分同段第几条车道；但段维是 H2、gate 语义、Q4 长度三者共同的前提，省掉即三者同时失效（27 号文 §3） | ✅ 已定（22 号文 §3.1 已改） |
| **D8** | 「由构造保证」的证明义务 | **凡在文档或代码里写「由构造保证」，必须配一个 O(n) 静态检查器**，并纳入对应 Stage 的验收门。原型的 H2 声称由构造保证却无检查器，违规静默存在了整轮探针 | ✅ 已定（Stage 1 交付 1.0b、Stage 4 验收三轨） |
| **D9** | 「穿组不可表达」由什么构成 | **静态 + 动态两条，缺一不可**：① 基底侧——段被组边界切开，无根段几何贯穿组体（L1，检查器 L6 证）；② 搜索侧——边只能使用与其两端作用域链相容的段（L8）。只做 ①，「沿同一条线直穿组体」仍是 0 折点 + 几何最短的双优路径，A2 无机制支撑。**取硬过滤而非软罚项**：软罚项等于把 A2 退回软指标，与「不可表达」的立意冲突。代价是少数边真正 `Infeasible`，由 A4「≥99% + 逐条解释」接住，**禁止兜底路径掩盖** | ✅ 已定（27 号文 §3.1 / L8） |
