## 0. 第一性原理：一个优秀 hierarchical 引擎的最小完备闭环

yFiles hierarchic layout 三十年沉淀下来的不变结构，剥到最里面就五件事：

```
① 拓扑决策    rank / order / 反转边          （组合相）
② 端口决策    每条边两端 (node, side, 位置)   （必须是显式一相！）
③ 度量决策    坐标、缝宽、track 位置          （度量相）
④ 落笔        决策 → 几何，零新决策           （Ink）
⑤ 标注        label 与几何联合求解或至少联合避让
```

核心纪律只有两条：

- **每个几何自由度有且只有一个写者**（single writer per degree of freedom）；
- **下游不得推翻上游，只得展开上游**——落笔相如果需要"发明"坐标，说明上游有决策没做完。

用这把尺子量 Atlas，上述落笔缺陷多属同一类病：**② 和 ④ 之间存在一段"没人认领的决策"**。端口的"侧"是 Plan 决策了，但端口在侧上的**位置**没人决策，Ink 只好硬编码侧中点 → 反向边重合；肘点插入、bundle 接合处的正交修补，本质都是 Ink 在补路径拓扑决策的洞。这不是几个孤立 bug，是一个结构性缺口的多次显影。

## 1. 缺失（按严重度排序）

### M1 ★★★ 端口分配不是一个"相"，而是一串巧合

现状链条：

- `derive_node_ports` 每个节点每侧只挂 **1 个 slot**（`slot_index=0, capacity=4`）——substrate 精心设计的 `(node, side, slot_index)` 语义身份和 P-inv-1~4 不变量，在生产路径上**只用到了退化情形**；
- `route_candidates` 逐边贪心选侧，端口"位置"概念不存在；
- `spread_port_points` 在 Ink 里按 (node, side) 分组事后散布——它能救急，但它是**落笔相在做端口决策**，违反"落笔零新决策"纪律。

yFiles 的对应物是独立的 port assignment / port distribution 阶段：先按对端方向给同侧端口排序（crossing-free ordering），再按 spacing 策略定位置，然后才路由。**位置是路由的输入，不是渲染的补丁。**

**应做**：把 `spread_port_points` 的逻辑上提为 Plan 的显式产物——`PortRef` 增加（或旁挂）`offset` 决策，由相 I 之后、度量相之前的一个端口求解 pass 写入。职责边界见 [`22` §5.1 I.5](22-Atlas下一代布局与路由架构-总纲-2026-07.md) 与 [`24`](24-Atlas-channel端口挂接与候选端点增强需求-2026-07.md)（channel 只挂接、**不**做完整侧/位置策略；完整 I.5 应落在 Plan 装配层）。slot_index 机制要么真用起来（每侧多 slot、边占独立 slot），要么承认 capacity 共享模型并让"侧内排序+定位"成为正式决策。

### M2 ★★★ 相 I 是顺序贪心，全局性只靠"倒着再跑一遍"兜底

`build_channel_metric_from_slots_with_opts` 的选路循环：按 EdgeId 顺序逐边 `route_candidates` → `commit`。先到先得，后来的边看到的是既成事实。L2 松弛的补救手段是 **PhaseIEdgeOrder::Reverse 整个重跑**——这等于承认"边序影响全局质量"，然后只提供两种边序。

yFiles 的 EdgeRouter 同样有顺序性，但它有 rip-up & reroute 迭代：路完一轮后把代价最高的边拔掉重路。Atlas 的 `Occupancy` 已经有 `release`（tests 里在用），**返工循环的全部零件都在，就是没有装配**。

**应做**：相 I 加一轮有界返工（如对 lane_demand 峰值 track 上的边，按代价降序 release→reroute，1–2 轮封顶）。这比引入 MCF 便宜一个数量级，且能消化大部分"边序敏感"病例。`gate_mcf.rs` 自述"诊断用，非 MCF"——它是占位符（见 R4）；**勿把 README 的「先 MCF」当成下一刀**。

### M3 ★★☆ lane 排序不做交叉最小化

`assign_lane_indices`：同一 track 上的边**按 EdgeId 升序**得 0,1,2…。这是确定性的，但和边的进出几何毫无关系——两条边在走廊里完全可能因为 lane 序与端点序相反而白白交叉一次。

yFiles 在 channel/lane 分配里做的是经典的 **lane ordering by endpoint positions**（本质是区间图着色 + 逆序对最小化），线性对数代价，收益是走廊内零无谓交叉。

**应做**：lane 序改为按「(入口坐标, 出口坐标) 的字典序」排布，EdgeId 只做平局裁决（确定性红线仍守住）。

### M4 ★★☆ Main 轴走廊坐标没有单一真源

`AtlasSolveOutput.track_coords` 经 `InkContext::apply_track_coords` **只覆盖 Cross** track；Main 走廊的 x 由 `from_plan_and_rects` 用节点 bbox + `margin=20.0` + `k*50.0` 兜底**现场重算**。度量相明明有 `main_gap_demands` 参与了缝宽求解，但求解出的 Main 走廊位置没有回传，Ink 再逆向猜一遍。

这是教科书式的"双写者"：同一自由度（Main 走廊 x）被度量相和落笔相各算一次，靠"通常猜得差不多"维持一致。图一密、缝一挤，两边就会分叉——而且分叉时没有任何审计能发现。

**应做**：Main track 坐标与 Cross 一样进 `track_coords`，`InkContext` 的间隙表只保留"track 缺失时"的降级路径，并打 `perf_log` 记账。

### M5 ★★☆ 规范空间 ↔ 画布空间没有正式边界

left-to-right 事故的深层原因：**布局内核在画布空间输出**（`kernel/layered/coordinate` 里 `horizontal` 时转置节点），而 Plan/Substrate 恒在抽象 (rank, order) 空间。修复方式是在 Ink 入口/出口各转置一次——能用，但现在整条管线是「内核转置 → Ink 反转置 → Ink 再转置」，三次坐标翻转分散在两个模块，靠注释维持。

更精确地说：

- flat 路径有 `LayeredDraft.horizontal`（Sugiyama **轴转置**）；
- weak 另有 `ArrangementMode::Horizontal`（**组堆叠方向**），与 DSL `direction: left-to-right` **不是同一概念**；
- Ink 入口用 `output.draft.as_ref().is_some_and(|d| d.horizontal)`——**weak/strong 无 draft → 恒 false**，有组图的 **LTR 轴转置在 Ink 侧常被静默忽略**（组排列可能仍水平，但边落笔坐标系不对齐）。

**应做**：内核输出规范空间，「规范 → 画布」的转置作为管线最后一步统一做一次（节点、边、label、组框一起）。这样 Ink 的转置代码可整体删除，weak/strong 自动获得真正的 LTR。这是 yFiles `LayoutOrientation` 的标准做法：算法永远只认 top-to-bottom，OrientationLayout 在外壳做一次性变换。

### M6 ★★☆ label 是事后贴的，不参与度量

Ink 的 `edge_from_points` 把 label 钉在折线中点，然后交给旧管线的 `LabelSolver` 事后避让。度量相的缝宽（`channel_band_width`）只算 lane，**不给 label 留地**——密集图 `label_node_overlap degraded` 的病根在这：等 label 求解时，几何已冻结，无处可躲。

yFiles 的答案是 integrated edge labeling：label 作为虚拟节点/虚拟占用参与 rank 与坐标求解。Atlas 不必一步到位，但至少：

**应做**：相 I 后统计每条 Cross 走廊上「带 label 的边数」，把 label 高度计入该走廊的 `Demand`（`space.rs` 的 Demand 模型现成）。这是把 ⑤ 拉进 ③ 的最小一步。

### M7 ★☆☆ 穿组防线的最后一环仍靠旧管线的"事后硬修"

管线里穿组有三道防线：substrate 构造性反证（L6）→ `verify_no_group_penetration` → **`repair_ink_group_pierces` 调旧管线的 `reroute_edges_for_repair`**。前两道是新架构的（静态、可证明），第三道是旧世界的 dogleg 硬修。

Post-S7 **有意**保留第三道，以换取 product 穿组 lint=0（D3）。代价是：

- 有组图路由耗时的主要来源之一；
- 修完的几何**不回写 Plan** → 增量指纹 / 对拍 / 自反证在这些边上失真。

**应做**：短期给 repair 打上「修了几条、Plan 已失真」的显式标记进 hints；中期让 gate 语义在 Ink 落笔时被真正遵守（边过组界必须走 gate 坐标），让第三道触发率趋零后删除。穿组门禁已硬，下一步是**降触发率**，不是再抬基线接受穿组。

### M8 ★☆☆ 增量入口是半成品（已有 skip，命中过严）

Post-S7 已实现：`can_skip_phase_i_search` 在 slots 一致且每条非自环边已有 channel 时**跳过相 I 选路**，度量/Ink/Label 仍重跑。CLI `PLOTGRAM_ATLAS_PLAN_CACHE` 已接线。

仍半成品的部分：

- `pipeline` 入口对 prev 的拓扑粗检**仍只打日志**（"attempt phase I skip"），真正行动在 metric 构建内；
- 命中要求 `node_slots` 完全相等——slots 从 draft/ranks 重算，多数「同拓扑微调」打不中；接近「一字不改重渲染」才稳；
- L2 反序重跑传 `prev=None`，松弛路径上增量直接失效。

**应做**：要么放宽到「rank/order 拓扑同构」并补 Plan 重定位；要么在文档/API 上明确标为**实验特性**（`PLOTGRAM_ATLAS_PLAN_CACHE`），避免每次改动都按生产增量路径回归。

## 2. 冗余（按删除收益排序）

### R1 ★★★ 旧正交路由器体量大，Hier 主路径只用少数零件——但不可整目录清空

`layout/routing/` 约 29.6k 行。Atlas **Hierarchical 生产路径**真正直接依赖的主要是：`LabelSolver`、`reroute_edges_for_repair` / 相关 repair 几何（M7）、`FrozenNodeProduct`。`cargo check` 告警大量集中在 `edge_routing_orthogonal`（scoring / visibility_graph / channel_load 等）——OVG 主搜索、语义干线、通道负载模型对 Hier Ink **多半是死重**。

**存活调用者（删前必须点名）**：

| 调用者 | 说明 |
|--------|------|
| `repair_ink_group_pierces` → refine | Hier 穿组硬修（M7），仍要几何零件 |
| `PipelineChoice::Shadow` → `LayoutPipeline` | 对 flowchart 等仍可跑 `OrthogonalRecipe` 全链 |
| Tree / Sequence / Circular | 委托 `LayoutPipeline`；默认多为 Curved/SelfLoop，**通常不进 OVG**，但不能假设「永远零调用」 |
| demand / coordinator / 大量单测 | `estimate_layer_band_demands` 等仍引用 |

**应做**（分层，勿一次「净删一万行」口号）：

1. 调用图 / `udeps` 确认**无引用子模块**，按子树删除（告警集中区优先）；
2. 先把 Hier 仍需的 repair / Label **抽成最小岛**，再砍 OVG 主体；
3. **R2 退役 Shadow（或 Shadow 不再对 Hier 跑旧正交）之后**，再评估整目录收缩。

留着死代码的真实成本是**每次全局搜索与重构评估都要读一遍**，但误删 repair 会直接打穿 D3。

### R2 ★★☆ 对拍三件套完成了历史使命

- `adapter.rs`：旧 EdgeLayout → Plan 的逆向适配器，硬编码 `slot_index: 0`，语义落后于生产路径；
- `shadow.rs`：新旧管线影子对拍——Stage 7 后旧 Hier 路径已不是生产参照系；Shadow 仍活着，却主要是在**维持 R1 的存活理由**；
- `compare_ink_vs_legacy` + `InkDiffReport`：同上。

门禁关闭期「用对拍替代阻断」的价值取决于参照系仍有效。现在旧路径修不修 bug 都没人当真理源，对拍结果难判读。

**应做**：归档删除 adapter/shadow/compare_ink_vs_legacy（或 Shadow 改为 Atlas-only 诊断）。把「对拍」升级为**自反证**：Ink 落笔后验证几何与 Plan 决策一致（边经声称的 track/gate、端口在声称的侧上）——三相下有意义的持续验证，并覆盖 M7 的 Plan 失真检测。

### R3 ★★☆ 三条求解路径 = 组合相没有真正统一

flat / weak(group_divide) / strong(architecture two_phase) 三条路径是旧管线的三个布局器换壳搬运：能力不齐（只有 flat 有 draft / Sugiyama 轴转置，见 M5）、`AtlasSolveOutput` 里一堆 `Option` 字段专门表达「这条路径没有那个东西」（`draft`、`main_problem`）。22 号文设想的「组合相」应当是**一个**产出 (rank, order, 收缩树) 的相，组只是收缩策略参数。

**应做**：大重构，不必急。方向钉死：weak/strong 收敛为「收缩→flat 求解→展开」；`AtlasSolveOutput` 的 Option 应逐个变必填。判断标准：**当三条路径的输出类型完全一致时，组合相才算存在**。

### R4 ★☆☆ 占位模块与兼容别名

- `gate_mcf.rs`：自述「诊断用，非 MCF」的平凡赋值 + 测试。挂着 MCF 名但无 MCF 实现，易误导（README 曾把它当下一出口）。改名 `gate_diag` 或并入 probe；
- `coord_descent.rs`：I.7 三块有界下降同样是**占位 + 创新模式登记**，与 `gate_mcf` 同级——实现空、勿当已交付；
- `solve.rs` 的 `is_atlas_flowchart` / `is_hierarchical`：注释「兼容旧名」。无兼容约束的仓库不需要旧名，删；
- `pipeline.rs::topology_plan`：给非 hierarchical 图种造 `rank=0, channels 全空` 的假 Plan 塞进 hints——下游若当真 Plan 用就是雷。要么 `TopologyOnly` 变体，要么非 Hier 不放 Plan。

### R5 ★☆☆ InkContext 的间隙推导与度量相重复

`from_plan_and_rects` 从节点 bbox 反推 rank/order 边界再取中点——与度量相层缝计算是同一件事的两次实现（M4 的另一面）。M4 落地后此处大半可删。

## 3. 修复优先级与依赖

> **覆盖** [`README`](README.md) Wave3 记债顺序与 23 号文「先 MCF / 先清空 ortho」叙事：以下梯队为准。

```
第一梯队（修正确性语义，小改动）
  M1 端口位置上提为 Plan 决策   ← spread_port_points 直接上移
  M3 lane 交叉最小化            ← 独立小改
  M4 Main track 坐标回传        ← 顺带完成 R5

第二梯队（还债 + 减重，删多于增）
  R2 删/退役对拍三件套 → 立自反证 verifier（覆盖 M7 失真检测）
  R4 占位/别名清理（含 gate_mcf / coord_descent 命名诚实化）
  R1 按子树删无引用 ortho 模块（repair 岛保留；Shadow 退役后可加深）

第三梯队（架构收敛，需要创新模式登记，AGENTS §7）
  M2 相 I 有界返工              ← 先于 MCF
  M5 规范空间统一（顺带 weak/strong 真 LTR）
  M6 label 进 Demand
  R3 三路径收敛为一个组合相
  M8 增量放宽或明确降级为实验特性
  （其后才考虑真 MCF / I.7 下降 / 非 Hier Ink 内化）
```

一条判断线索留给后续所有改动：**如果一个 bug 的修法是「在 Ink 里再补一个特判」，那它多半是上游某个决策缺位的显影**——先问「这个自由度的写者应该是谁」，再动手。肘点/接合/转置三个属于落笔职责（几何展开）；端口散布是借住在 Ink 的上游决策，应尽早搬家（M1）。
