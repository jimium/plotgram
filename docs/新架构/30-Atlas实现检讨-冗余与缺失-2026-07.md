## 0. 第一性原理：一个优秀 hierarchical 引擎的最小完备闭环

yFiles hierarchic layout 三十年沉淀下来的不变结构，剥到最里面就五件事：

```
① 拓扑决策    rank / order / 反转边          （组合相）
② 端口决策    每条边两端 (node, side, 位置)   （必须是显式一相！）
③ 度量决策    坐标、缝宽、track 位置          （度量相）
④ 落笔        决策 → 几何，零新决策           （Ink）
⑤ 标注        label 与几何联合求解或至少联合避让
```

核心纪律只有两条：

- **每个几何自由度有且只有一个写者**（single writer per degree of freedom）；
- **下游不得推翻上游，只得展开上游**——落笔相如果需要"发明"坐标，说明上游有决策没做完。

用这把尺子量 Atlas，上述落笔缺陷多属同一类病：**② 和 ④ 之间存在一段"没人认领的决策"**。端口的"侧"是 Plan 决策了，但端口在侧上的**位置**没人决策，Ink 只好硬编码侧中点 → 反向边重合；肘点插入、bundle 接合处的正交修补，本质都是 Ink 在补路径拓扑决策的洞。这不是几个孤立 bug，是一个结构性缺口的多次显影。

## 1. 缺失（按严重度排序）

### M1 ★★★ 端口分配不是一个"相"，而是一串巧合

> **进度（2026-07-28）**：**已落地（along + 真多 slot）**。`PortRef.along_offset` 为侧内切向像素决策；节点定稿后、Ink 前由 `Plan::assign_port_along_offsets` 写入；Ink 只读。`derive_node_ports` 每侧挂 `slot_index = 0..default_capacity`（默认 4，每槽 `capacity=1`）；`route_candidates` 在多槽候选上选路。`side_order` 仍由相 I 后写入。

（历史：每侧仅 `slot_index=0` + capacity 共享退化。）
### M2 ★★★ 相 I 是顺序贪心，全局性只靠"倒着再跑一遍"兜底

> **进度（2026-07-28）**：**已落地**。相 I 贪心选路后调用 `bounded_phase_i_ripup`（最多 2 轮 × 8 边）：峰值 `lane_demand` track 上的边按 `LexCost` 降序 `release` → `route_candidates_congested`（`LexCost.q5` 拥塞软偏好）→ 仅当全局 peak/sum 改善才接受。L2 `PhaseIEdgeOrder::Reverse` 仍保留作另一条边序兜底。单测：`phase_i_ripup_diverts_equal_cost_corridor` / `noop_when_peak_le_one` / `restores_when_no_alternate`。

（历史问题：仅 EdgeId 序贪心 + Reverse 整跑；`Occupancy.release` 有、返工未装配。）旧 `gate_mcf` 占位已删（R4）；**勿把「加深轮数 / 真 MCF」当成下一刀**——有界返工够用再议。

### M3 ★★☆ lane 排序不做交叉最小化

> **进度（2026-07-28）**：**已落地**。`Plan::assign_lane_indices` 按端点槽位字典序：Cross `(from.order, to.order, eid)`、Main `(from.rank, to.rank, eid)`；缺 ports/slots 回退 EdgeId。相 I 后由 `channel_metric` 调用；单测 `assign_lane_indices_follows_endpoint_slots_not_edge_id`。度量相前无像素坐标，槽位序即 Plan 世界的入口/出口代理。

（历史问题：曾按 EdgeId 升序得 lane，与进出几何无关，走廊内易无谓交叉。）

### R3 ★★☆ 三条求解路径 = 组合相没有真正统一

flat / weak(group_divide) / strong(architecture two_phase) 三条路径是旧管线的三个布局器换壳搬运：能力不齐（只有 flat 有 draft / Sugiyama 轴转置，见 M5）、`AtlasSolveOutput` 里一堆 `Option` 字段专门表达「这条路径没有那个东西」（`draft`、`main_problem`）。22 号文设想的「组合相」应当是**一个**产出 (rank, order, 收缩树) 的相，组只是收缩策略参数。
