## 0. 第一性原理：一个优秀 hierarchical 引擎的最小完备闭环

yFiles hierarchic layout 三十年沉淀下来的不变结构，剥到最里面就五件事：

```
① 拓扑决策    rank / order / 反转边          （组合相）
② 端口决策    每条边两端 (node, side, 位置)   （必须是显式一相！）
③ 度量决策    坐标、缝宽、track 位置          （度量相）
④ 落笔        决策 → 几何，零新决策           （Ink）
⑤ 标注        label 与几何联合求解或至少联合避让
```

核心纪律只有两条：

- **每个几何自由度有且只有一个写者**（single writer per degree of freedom）；
- **下游不得推翻上游，只得展开上游**——落笔相如果需要"发明"坐标，说明上游有决策没做完。

用这把尺子量 Atlas，上述落笔缺陷多属同一类病：**② 和 ④ 之间存在一段"没人认领的决策"**。端口的"侧"是 Plan 决策了，但端口在侧上的**位置**没人决策，Ink 只好硬编码侧中点 → 反向边重合；肘点插入、bundle 接合处的正交修补，本质都是 Ink 在补路径拓扑决策的洞。这不是几个孤立 bug，是一个结构性缺口的多次显影。

## 1. 缺失（按严重度排序）

### M1 ★★★ 端口分配不是一个"相"，而是一串巧合

> **进度（2026-07-28）**：**已落地（along 切片）**。`PortRef.along_offset` 为侧内切向像素决策；节点定稿后、Ink 前由 `Plan::assign_port_along_offsets` 写入（间距策略与历史 Ink 一致）；Ink `expand_port_points` **只读** offset + 侧中点。`side_order` 仍由相 I 后 `assign_port_side_orders` 写入。多 `slot_index` / 真多 slot 仍债。

现状链条（历史）：

- `derive_node_ports` 每个节点每侧只挂 **1 个 slot**（`slot_index=0, capacity=4`）——生产路径仍用退化情形；
- `route_candidates` 逐边贪心选侧；
- ~~`expand_port_points` 在 Ink 里算 pitch~~ → 已上提为 Plan `along_offset`。

**仍可做**：slot_index 真用起来（每侧多 slot），或正式承认 capacity 共享并完善 I.5 侧策略。

### M2 ★★★ 相 I 是顺序贪心，全局性只靠"倒着再跑一遍"兜底

> **进度（2026-07-28）**：**已落地**。相 I 贪心选路后调用 `bounded_phase_i_ripup`（最多 2 轮 × 8 边）：峰值 `lane_demand` track 上的边按 `LexCost` 降序 `release` → `route_candidates_congested`（`LexCost.q5` 拥塞软偏好）→ 仅当全局 peak/sum 改善才接受。L2 `PhaseIEdgeOrder::Reverse` 仍保留作另一条边序兜底。单测：`phase_i_ripup_diverts_equal_cost_corridor` / `noop_when_peak_le_one` / `restores_when_no_alternate`。

（历史问题：仅 EdgeId 序贪心 + Reverse 整跑；`Occupancy.release` 有、返工未装配。）旧 `gate_mcf` 占位已删（R4）；**勿把「加深轮数 / 真 MCF」当成下一刀**——有界返工够用再议。

### M3 ★★☆ lane 排序不做交叉最小化

> **进度（2026-07-28）**：**已落地**。`Plan::assign_lane_indices` 按端点槽位字典序：Cross `(from.order, to.order, eid)`、Main `(from.rank, to.rank, eid)`；缺 ports/slots 回退 EdgeId。相 I 后由 `channel_metric` 调用；单测 `assign_lane_indices_follows_endpoint_slots_not_edge_id`。度量相前无像素坐标，槽位序即 Plan 世界的入口/出口代理。

（历史问题：曾按 EdgeId 升序得 lane，与进出几何无关，走廊内易无谓交叉。）

### M4 ★★☆ Main 轴走廊坐标没有单一真源

> **进度（2026-07-28）**：**已落地**。度量相 `publish_main_track_coords`（flat 后置 + weak/strong `metric_from_slots_publish_tracks`）写入 `AtlasSolveOutput.track_coords`；Ink `apply_track_coords` 覆盖 Main→`order_gap_x`（与 Cross→`rank_gap_y` 对称）；缺键保留 seed 并 `perf_log` fallback。interior `order_gap`/`rank_gap` 不再 bbox 中点双写（占位 `k*50`，真值靠 publish）。单测：`apply_track_coords_main_and_cross_do_not_clobber`、`publish_main_track_coords_midpoint_between_order_columns`。

（历史问题：`apply_track_coords` 只覆盖 Cross，Main x 由 Ink `from_plan_and_rects` 现场猜。）边界 seed（±20）仍作缺键兜底；彻底砍掉属 R5 收尾，非本切片。

### M5 ★★☆ 规范空间 ↔ 画布空间没有正式边界

left-to-right 事故的深层原因：**布局内核在画布空间输出**（`kernel/layered/coordinate` 里 `horizontal` 时转置节点），而 Plan/Substrate 恒在抽象 (rank, order) 空间。修复方式是在 Ink 入口/出口各转置一次——能用，但现在整条管线是「内核转置 → Ink 反转置 → Ink 再转置」，三次坐标翻转分散在两个模块，靠注释维持。

更精确地说：

- flat 路径有 `LayeredDraft.horizontal`（Sugiyama **轴转置**）；
- weak 另有 `ArrangementMode::Horizontal`（**组堆叠方向**），与 DSL `direction: left-to-right` **不是同一概念**；
- Ink 入口用 `output.draft.as_ref().is_some_and(|d| d.horizontal)`——**weak/strong 无 draft → 恒 false**，有组图的 **LTR 轴转置在 Ink 侧常被静默忽略**（组排列可能仍水平，但边落笔坐标系不对齐）。

**应做**：内核输出规范空间，「规范 → 画布」的转置作为管线最后一步统一做一次（节点、边、label、组框一起）。这样 Ink 的转置代码可整体删除，weak/strong 自动获得真正的 LTR。这是 yFiles `LayoutOrientation` 的标准做法：算法永远只认 top-to-bottom，OrientationLayout 在外壳做一次性变换。

### M6 ★★☆ label 是事后贴的，不参与度量

Ink 的 `edge_from_points` 把 label 钉在折线中点，然后交给旧管线的 `LabelSolver` 事后避让。度量相的缝宽（`channel_band_width`）只算 lane，**不给 label 留地**——密集图 `label_node_overlap degraded` 的病根在这：等 label 求解时，几何已冻结，无处可躲。

yFiles 的答案是 integrated edge labeling：label 作为虚拟节点/虚拟占用参与 rank 与坐标求解。Atlas 不必一步到位，但至少：

**应做**：相 I 后统计每条 Cross 走廊上「带 label 的边数」，把 label 高度计入该走廊的 `Demand`（`space.rs` 的 Demand 模型现成）。这是把 ⑤ 拉进 ③ 的最小一步。

### M7 ★☆☆ 穿组防线的最后一环仍靠旧管线的"事后硬修"

管线里穿组曾有三道防线：substrate 构造性反证（L6）→ `verify_no_group_penetration` → **`repair_ink_group_pierces` dogleg**。前两道是新架构的；第三道是旧世界硬修（几何不回写 Plan → 自反证失真）。

> **进度（2026-07-27）**：短期标记 + 中期 Ink 守 gate + **M7-2 几何硬门禁** + **M7 后期已删** `repair_ink_group_pierces`（product∪stress Hier `distorted≡0` 后，见 [31](31-Atlas-M7-0-ink-repair基线-2026-07.md)）。现证明链：L6 → Ink gate/裙边 → M7-2 → lint 穿组。**`PortSideMismatch` 已升硬**；**M1 `along_offset` 已上提 Plan**。

### M8 ★☆☆ 增量入口（实验特性 + 拓扑放宽）

Post-S7 已实现：`can_skip_phase_i_search` 在槽位齐全且每条非自环边已有 channel 时**跳过相 I 选路**，度量/Ink/Label 仍重跑。CLI `PLOTGRAM_ATLAS_PLAN_CACHE` 已接线。

> **进度（2026-07-27）**：
> - **A**：标为**实验特性**（CLI 模块文档 / 日志 / `compute_layout_incremental` / plan README）；默认路径不依赖 cache，无 CI 门禁。
> - **B**：skip 条件从 slots 全等放宽为 rank/order **拓扑同构**（`canonicalize_slots`）；命中时绝对槽重定位写入 Plan；L2 Reverse 仍禁止 skip（可传入 prev，不改变 Reverse 语义）。

仍半成品 / 未做：

- `pipeline` 入口对 prev 的拓扑粗检**仍只打日志**（真 skip 在 metric 内）；
- Reverse 热启动未做；增量仍为 opt-in 实验 env。

**应做（已收口）**：文档标实验 + 拓扑同构放宽。后续若要生产化，另开切片（默认开启 / CI / Reverse 热启动）。

### R3 ★★☆ 三条求解路径 = 组合相没有真正统一

flat / weak(group_divide) / strong(architecture two_phase) 三条路径是旧管线的三个布局器换壳搬运：能力不齐（只有 flat 有 draft / Sugiyama 轴转置，见 M5）、`AtlasSolveOutput` 里一堆 `Option` 字段专门表达「这条路径没有那个东西」（`draft`、`main_problem`）。22 号文设想的「组合相」应当是**一个**产出 (rank, order, 收缩树) 的相，组只是收缩策略参数。

**应做**：大重构，不必急。方向钉死：weak/strong 收敛为「收缩→flat 求解→展开」；`AtlasSolveOutput` 的 Option 应逐个变必填。判断标准：**当三条路径的输出类型完全一致时，组合相才算存在**。

#### 现状决策树（入口 `solve_from_contract_with_prev`）

| 条件 | 路径 | 组合产物 | 度量尾段 |
|------|------|----------|----------|
| `!should_contract`（无 group） | **flat** | `LayeredDraft` | Cross/Main LP（L0–L3）+ track 发布 |
| 有 group × `GroupPolicy::Weak` | **weak** | `divide_flowchart_nodes` ranks/order | slots→channel；启发式 gap；**无** Main LP |
| 有 group × `GroupPolicy::StrongMacro` | **strong** | `contract_strong_macro` ranks | 同上（无 main gap expand） |

`should_contract` ≈ `!diagram.groups.is_empty()`。Scheme→Profile：flowchart/state → Weak；architecture → StrongMacro。

**能力差**：仅 flat 填 `draft` / `main_problem`；weak 的 `ArrangementMode::Horizontal` 是组堆叠方向，**≠** Sugiyama 轴转置（M5）。

#### 目标形态（对齐 22 §5.1）

组合相单一产出 `(slots 或等价 draft, contraction_meta)`；Weak/StrongMacro 只是**收缩策略参数**。全量收敛宜与 M5 同轨，须 **AGENTS §7 创新模式**登记。
