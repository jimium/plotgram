## 0. 一页结论

**channel 的骨架是对的，但 derive 出来的基底不满足它自己声称的核心不变量。**

| 判定 | 内容 |
|---|---|
| ✅ **抽象是对的** | 「track 序列代替像素路径」「lane 数是输出」「合流是后缀共享」「构建期拒绝代替事后检测」四个立意都站得住，性能实测也证明了通道图比 OVG 小两个数量级（channel 本体 1152 边共 ≈35 ms） |
| ✅ **粒度够细** | 22 号文 §8 风险台账第一条（通道图过粗）**可以结案**：三集 1152 边零「网格不可表达」 |
| ❌ **合法性不成立** | README 不变量 1「穿组不可表达（H2 由构造保证）」在 derive 产物上**为假**。借道穿越无关组的路径不但存在，而且在词典序下**严格最优**（0 折点 vs 绕行 ≥2 折点） |
| ❌ **gate 的 side 维度是装饰** | 四个 gate 退化成两个池，每池重复注册两次；且轴向搞反（顶/底边界挂了水平缝，左/右边界挂了垂直走廊） |
| ⚠️ **自适应争用 100% 被高估** | ① 图上多出了非法路径；② **自适应路径**上 gate 容量按构造 ≥ 需求、端口容量恒不限 → 争用 100% 接近同义反复。固定容量扫描（cap=1/2）仍有真实失败，gate 硬约束本身并未失效（见 §2 F3） |
| ⚠️ **Q4 长度失效** | `span_weight` 全表恒为 1.0，最短路退化成「最少轨道数」，绕远免费。这才是 stress-deep 峰值 lane 33 的根因，不是报告说的「flat 口径失真」 |

**结论**：channel **不能**按 25 号文 §6.1 的说法「进入默认路径推进 Stage 1+」。需要先做一轮**合法化改造**（本文 §4 的 **L1–L4 + L8**，主要落在 `derive.rs` + `substrate.rs`，`search.rs` 只加一个作用域谓词，`bundle.rs` 不动），改造后重跑探针，把 25 号文的数字按**新口径**重新采一遍（见 §4 L4 / §5）。改造属于 Stage 1 的前置，不是新 Stage。

> ⚠️ **L1–L4 不足以让「穿组 = 0」成立**。分段只消灭「跨线跳跃」这一种借道形态，**同线直穿**（左根段 → gate → 组内段 → gate → 右根段，全程 0 折点、几何最短）在 L1–L4 之后反而变成「诚实且双优」的路径。必须配 **L8 搜索期作用域过滤**，推演见 §3.1。

> **编号约定**：本文改造项用 **L1–L8**（Legalization），不与 [24 号文](24-Atlas-channel端口挂接与候选端点增强需求-2026-07.md) 已落地的 **R1–R5**（PortSlot / 候选端点）撞号。下文凡写「R1」而无「24 号文」前缀，均指 24 号文；本文需求一律写「L*」。L8 编号后置是因为它在 L1–L7 定稿后补入，优先级见 §8。

## 2. 缺陷台账

### F1（Blocker）穿组不但可表达，而且是词典序最优解

**声称**（`channel/README.md` 不变量 1、22 号文 §5.1 I.4 / Stage 4 验收「穿组 = 0 由构造保证」）：

> 跨 scope 的轨道 link 在构建期被拒绝；跨组转移只能经 Gate。于是「穿组」不再是路由后检测项——图上根本不存在那样的转移。

**实际**：构建期只拒绝了**跨 scope 的 link**，没有约束**一条轨道的几何延展是否压过组框**。derive 的 `build_region(root, ...)` 给根区域铺的 cross/main 轨道**横跨整图**，任何一条落在某个组的 rank/order 跨度内的根轨道，几何上都从组体正中穿过。它 scope 是 `None`，因此走它完全合法。

更糟的是，**借道进出组比绕行更便宜**。构造实测：

```text
节点 x(rank2, order0)、y(rank2, order3) —— 两端都在组外
组 G 占 rank 1..3、order 1..2
边 x → y 的最优路径：
    root main(gap0) --Gate(2)--> G 内 main(gap2) --Gate(2)--> root main(gap2)
    折点 = 0，长度 = 3
```

因为 gate 两侧同向（main↔main）不计折点（`search.rs::step_cost`），**穿过组体是 0 折点**；而从组的上方或下方绕过去，必须经两次 Main×Cross 转向，**至少 2 折点**。Q3 折点优先于 Q4 长度 → Dijkstra **必然**选择穿组。这不是平局的偶然，是代价函数的系统性偏好。

注意这条路径的 `gates = [GateId(2), GateId(2)]`：同一个 gate 被记了两次（进一次、出一次），而 `Occupancy::commit` 对 gate 按边去重，于是这条穿越了 G 边界**两次**的边只占 **1** 单位容量池。

**图集量化**（三集 1152 边，单边空占用）：

| 集 | 边 | 借道穿「两端都不属于的组」 | 同一 gate 被同一边穿 ≥2 次 |
|---|---|---|---|
| product | 265 | 2（0.8%） | 13（4.9%） |
| stress | 188 | 0 | 2（1.1%） |
| demo | 699 | 25（3.6%） | 101（14.4%） |
| **合计** | **1152** | **27（2.3%）** | **116（10.1%）** |

最严重：`demo.plotgram-core-mod-deps` 29 条成功边里 **16 条**（55%）借道穿了无关组。

> **这两个数字都是下界。** 检测只能识别「路径进入了组 scope 的轨道」；根轨道几何贯穿组框那一类（上一段说的情况）在当前模型里**没有任何可观测量**——组框的几何范围压根没进 Substrate。真实违规率只会更高。

**对 25 号文的影响**：§2 的「单边可行率 100%」测的是「图上有没有路」，而图上多出了不该有的路。它是**合法可行率的上界**，不能直接当作「表达能力已闭环」的证据。改造后必须重采。

### F2（Blocker）gate 的 side 维度是装饰：四个门退化为两个池、每池重复两次、且轴向倒置

derive 产物实测（组 G 占 rank2、order0..2 的单组图）：

```text
gate 0  side=MainLow   inner=[T10,T11](Cross,Cross)  outer=[T2,T3](Cross,Cross)
gate 1  side=MainHigh  inner=[T10,T11](Cross,Cross)  outer=[T2,T3](Cross,Cross)   ← 与 gate 0 逐字段相同
gate 2  side=CrossLow  inner=[T12..T15](Main×4)      outer=[T6..T9](Main×4)
gate 3  side=CrossHigh inner=[T12..T15](Main×4)      outer=[T6..T9](Main×4)       ← 与 gate 2 逐字段相同
```

问题分三层：

**(a) 重复注册。** `add_boundary_gates` 把同一组 `inner_cross` / `outer_cross` 同时喂给 MainLow 与 MainHigh（main 侧同理）。`ChannelGraph::from_substrate` 对每个 gate 做 inner × outer 全展开，于是同一对轨道之间有**两条并行 Gate 转移**：

```text
track T10 的 8 条转移中：
  -> T2 via Gate(0)      -> T2 via Gate(1)      ← 重复
  -> T3 via Gate(0)      -> T3 via Gate(1)      ← 重复
```

后果：
- **有效容量 = 标称 × 2**。25 号文 §3 的容量扫描表要按「每轴有效容量 = 2×cap」重读：product/stress 的「饱和点 cap=4」实为有效 8，demo 的 cap=8 实为有效 16。这张表目前不能直接用来定容量常数。
- **搜索开销翻倍**。性能报告 §7.2 提到 `plotgram-core-mod-deps` 有 12078 条转移，其中 gate 部分有一半是冗余边。

**(b) 轴向倒置。** `MainLow`（主轴低端 = 顶边界）挂的是 **Cross**（水平缝）轨道；`CrossLow`（左边界）挂的是 **Main**（垂直走廊）轨道。物理上正相反：穿越顶/底边界的是**垂直走廊**，穿越左/右边界的是**水平缝**。`PortSide::required_orient` 把这个关系写对了（`MainLow` 要 Cross 宿主轨道 —— 那是端口挂接，语义不同），但 gate 侧没有对应约束，于是写反了也没人拦。

**(c) 根因：gate 没有绑定到一条具体的边界线。** 现在的 `Gate { inner: Vec<TrackId>, outer: Vec<TrackId> }` 是**区域内全部同向轨道 × 祖先全部同向轨道**的笛卡尔积。一条组内 main 走廊与父区域的同 order-gap main 走廊之间的转移，物理上既可能发生在组的**顶**边界、也可能在**底**边界——模型无从区分，因为 track 是「整条线」而不是「被边界切开的段」。

后果链：
- 22 号文 §5.1 I.4「费用 = 该 gate 与边两端的方向一致性」**无法实现**——选哪个门与方向完全无关。
- 「进一次、出一次」落在同一个 gate 上，被 `commit` 去重（F1 末尾），容量会计低估 ≥10%。
- 顶边界与底边界共享一个容量池，左右同理。密集图上这会掩盖真实的边界拥塞。

### F3（重要）自适应争用 100% 接近同义反复；固定容量扫描仍有效但数字被 F2a 扭曲

25 号文 §2「多边全局争用三集也全部 100%」和 §3 观察 3「自适应容量是正确的生产答案」，这两条**在自适应路径上**不成立：

**gate 容量（自适应）**：公式是 `capacity = max(GroupSpec.gate_capacity, boundary_degree)`，而

```rust
// derive.rs：boundary_degree = 恰有一个端点在组子树内的边数
bp.edges.iter().filter(|(f, t)| inside(f) != inside(t)).count()
```

`boundary_degree` **就是**需要穿越该组边界的边总数。把容量设成需求，gate **按构造**永远不会成为瓶颈。这不是「找到了正确的容量」，是「取消了容量这道题」。

**端口侧容量**：探针 `attach_probe_port` 传 `capacity = 0`（不限），并且按 `(node, side)` 递增分配 `slot_index`，**每条边的每个端点独占一个槽**。于是 `PORT_SIDE_CAPACITY` 这条 22 号文 I.5 的硬约束在整个探针里一次都没生效过。

**口径分界（勿一刀切）**：

| 探针路径 | gate 硬约束是否生效 | 端口硬约束是否生效 | 「争用 100%」能否当独立证据 |
|---|---|---|---|
| **自适应**（生产路径） | 否（容量 = 需求） | 否（capacity=0） | **否**，接近同义反复 |
| **固定 cap 扫描**（§3 表） | **是**——cap=1 时 product 240/265、demo 584/699 有真实失败 | 否 | 部分成立：证明 gate 硬约束本身能挡边，但见下 |

固定容量扫描表**有真实信息量**，不能说「两条硬容量同时失效」——那只对自适应路径成立。真正的问题是：

1. 自适应路径上两条硬约束都关掉 → 「争用 100%」与单边可行率不是两份独立确认；
2. F2a 使固定扫描的**有效容量 = 标称 × 2**，表上「饱和点 cap=4」实为有效 8，**数字失真**，不能直接用来定生产常数。

**更根本的矛盾**：22 号文 §5.1 I.4 把 gate 容量定义为「边长 / 最小间距」——这是**几何量，相 I 时还不知道**。channel 用 `boundary_degree` 绕过了这个鸡生蛋问题，但绕的方式恰好抵消了约束本身。正确解法见 §4 的 L4：**gate 容量应当和 lane 数一样是输出，不是输入**（这与 B1 公理完全一致，22 号文自己没把这条推到 gate 上）。

### F4（重要）`span_weight` 恒为 1.0，Q4 退化为跳数，绕远免费

`build_region` 建每一条轨道时一律传 `1.0`；实测 derive 产物的 `distinct span_weight = [1.0]`。加上「同 scope 内 Cross × Main **全 link**」，任意两条异向轨道一跳可达，于是：

- Q4「长度」= 路径上的轨道条数，与真实几何长度完全脱钩；
- 绝大多数边的最优解都是 3 条轨道（起点缝 → 某条走廊 → 终点缝），**代价严格相等**；
- 选哪条走廊完全由平局打破决定，而 `search.rs::State::cmp` 的平局键是 `TrackId`，`alloc_track_id` 又是递增分配的 → **恒选 id 最小的那条**，即最靠图左上外框的走廊。

这就是 25 号文 §4.1「stress-deep 峰值 lane 33」的真正成因：不是 mindmap 径向图种在 flat 网格里的口径失真，而是**代价函数退化把所有边赶到了同一条走廊**。报告把它归因为「flat 口径的已知失真，不构成 channel 表达缺陷」——这个归因是错的，它是 channel 可修的模型缺陷。

同时它也解释了 F1 的违规率为什么还不算太高：最小 id 走廊通常在整张图的最外侧，恰好在所有组之外。**一旦 L3 把 span_weight 修对、边不再全挤外框，F1 的穿组违规会立刻暴涨。** 这两条必须一起改。

## 3. 根因归一：缺的是「段」维，不是「lane」维——但段维只解一半

`channel/README.md` 的「与 22 号文规格的分歧点」表里，诚实记录了一条刻意简化：

> 规格顶点 = PortSlot / **TrackSlot(track_id, lane_index)** / Gate；本 mod 做 track 级选路，lane 数事后导出。**刻意简化**：lane 分配本质是度量相的事。

这条简化**是对的**，lane 维确实可以延后。但真正致命的省略是**另一个维度，而且没有被记录**：

> **一条 track 不是一条线，是被组边界切成的若干段（Segment）。**

| 缺 Segment 导致 | 表现 |
|---|---|
| 根轨道未被组框打断 | 根 scope 路径几何贯穿组体，H2 不成立（F1 的**跨线跳跃**变体） |
| 组内轨道与父轨道是「同一条线的两段」，却建模成两个无位置的顶点 | 二者之间的转移无法确定跨的是哪条边界 → gate 无 side（F2c） |
| 没有段，就没有段长 | `span_weight` 无从计算，只能填 1.0（F4） |

补上段维（L1 / L2），F2 与 F4 **全解**，F1 解一半。改造集中在 `derive.rs` 的建图规则与 `substrate.rs` 的 `Gate` 结构，`bundle.rs` 与 `Occupancy` 账本语义不动。

### 3.1 段维解不掉的那一半：同线直穿

**分段只杀死「跨线跳跃」，杀不死「沿同一条线直穿」。** 这是本文最容易被漏掉的推论，单独钉住：

F1 §2 的实测例子（`root main(gap0) --Gate--> 组内 main(gap2)`）是**笛卡尔积伪影**——两条不同的线之间凭空跳。L2 的 G-inv-2（配对段必须在同一条线上）把它消灭了。但分段完成后，借道换了个形态卷土重来：

```text
Cross 缝 gap k（r0 < k ≤ r1，被 G 切开）：
    左root段 --CrossLow gate--> 组内段 --CrossHigh gate--> 右root段

两端都在组外的同 rank 边：
    直穿：gate 同向 ×2 → Q3 折点 = 0
    绕行：下到未被切开的边界缝再回来 → Q3 折点 ≥ 4
```

这条路径**几何上是诚实的**（它确实是一条直线），也确实穿过了 G 的框体。更糟的是 L3 之后 Q4 也偏好它——直线就是最短。**Q3 与 Q4 双双偏好借道**，词典序必选。L4 把 gate 改成 `Unbounded` 后，容量也不再拦。

因此：**L1–L4 全做完，A2（借道穿无关组 = 0）仍然没有任何机制支撑**，重跑探针会直接爆掉，且极易被误判成「L1 分段做错了」。A3（同 gate 双穿）能靠 L2 归零，A2 不能。

补救是 **L8**（§4）：搜索期作用域过滤。两条不变量的分工要说清——

| | 管什么 | 何时检查 |
|---|---|---|
| **L6** `verify_no_group_penetration` | **基底**里没有归属错误的段（静态结构正确） | 建完 Substrate，O(段数×组数) |
| **L8** 作用域过滤 | **搜索**不借道无关组（动态路径合法） | 每次转移松弛 |

A1 验 L6，A2 验 L8。缺任何一条，「H2 由构造保证」都只是半句话。

## 4. 改造需求

> 编号 **L1–L8**（Legalization），与 24 号文 **R1–R5** 并列时必须写清文档号。L8 排在 L7 之后只因补入时间晚，优先级见 §8。

### L1（Blocker）轨道分段：track = 被组边界打断的线段

**规则（主文）**：

- 一条 rank-gap `k` 的 Cross 线，被所有「rank 跨度覆盖 k」的组按 order 区间切开（覆盖谓词见下节边界用例）。
- 一条 order-gap `og` 的 Main 线同理，被「order 跨度覆盖 og」的组按 rank 区间切开。
- 每段是一个 `Track`，`scope` = 覆盖该段的**最深**组（无组则 `None`）。
- **同一条线上的相邻段之间不 link**——它们中间隔着组边界，转移必须经该边界的 gate。
- 异向段之间的 link 只在**几何真的相交**时建立（区间重叠；边界缝处的开闭规则见 B8），不再是区域内全 link。

#### L1.1 切割规则边界用例（实现前钉死，禁止各写各的）

组 G 的矩形记为 ranks `[r0, r1]`（闭区间，含端点节点所在层）、orders `[o0, o1]`。gap 索引与 derive 现状一致：Cross 缝在 gap `0..=rank_count`，Main 走廊在 gap `0..=order_count`。

| # | 场景 | 钉死规则 |
|---|---|---|
| **B1** | Cross 线 gap `k` 是否被 G 切开 | **半开覆盖**：`r0 < k ≤ r1` 时切开（与初稿「严格包含」同义，写成不等式以免歧义）。`k = r0`（组顶缝）**不**被 G 切开——该缝属于组**边界**，由 L2 的 `MainLow` gate 服务，不是组内段 |
| **B2** | Main 线 gap `og` 是否被 G 切开 | 对称：`o0 < og ≤ o1` 时切开；`og = o0`（组左缝）属边界，不进组内 |
| **B3** | 切点位置 | Cross 线被切开时，切点为 order-gap `o0` 与 `o1+1`（组左边界缝与组右外侧缝）；Main 线切点为 rank-gap `r0` 与 `r1+1` |
| **B4** | 嵌套组切割次序 | **自深向浅一次切完**：先收集全部覆盖该线的组的切点，对切点排序去重后切段，再给每段赋 `scope = 覆盖该段的最深组`。禁止「先浅后深再切」的两阶段（会产生中间态重复切点与零长段） |
| **B5** | 零长段 | 切点重合或相邻切点间距为 0 时 **丢弃零长段**，不注册 `Track`。相邻非零段之间仍不 link，转移只经 gate。**无例外**（B7 已改为不产生零长段） |
| **B6** | 同边界多组对齐 | 两兄弟组共享同一条边界缝（如 `G1.r1 + 1 = G2.r0`）时，该缝上的段 `scope = None`（或共同父组），两侧组内段分别经各自 gate 接到该缝——不合并两个 gate |
| **B7** | 退化跨度组（含单节点组） | `r0 = r1` 时该组在 Cross 轴**不产生任何组内段**（`o0 = o1` 时 Main 轴同理），单节点组两轴都不产生。**不得**为此往未被切开的线里插零长 stub 段——那会把一条完整的根段劈成两截，阻断无关边沿该缝直行，并与 B5 冲突。正确处理：成员节点该侧端口的宿主就是**未被切开的边界缝根段**（`resolve_host_track` 恒有解，因为线被完整划分为段，任一位置必落在某段上）。此时「穿越组框」与「离开端口」在几何上重合，由 `PORT_SIDE_CAPACITY` 承接，该轴不设 gate crossing |
| **B8** | 切点处边界缝归属 | 被切开的线在边界缝处一分为二后，**边界缝归外段**：外段延伸至组框边线、在该边界 gap 处与边界缝**正常 link**；内段止于组框边线、在其两端的边界 gap 处与边界缝**不 link**（相交判定对内段按开端点计）。两个答案都错的坑：若端点相接算相交，组内段可 1 折点 link 到边界缝、**完全绕过 gate**（`crossing_demand` 漏记、A3 失真）；若端点相接一律不算，组外段到边界缝的正常转移也被杀掉、图断连。推论一：组内段的异向 link 只可能落在组内部 gap 上，**跨越组边界的唯一通道是 gate**；推论二：这是 L8「段过滤 ↔ gate 过滤」两种表述等价的前提 |

> **B7 的语义交代**：退化组在该轴上没有「内部」可穿，所以也没有边界可跨——crossing 数恒 0 是正确答案，不是丢失了容量账。真正的挤压发生在端口侧，而端口容量本来就是 L4 之后相 I 唯一的硬约束（见 L4 附表）。

**收益**：
- 根轨道不再贯穿组体，F1 的**跨线跳跃**变体消失（同线直穿另需 L8，见 §3.1）。
- 「全 link」变成「相交才 link」→ 图更稀疏，转移数下降（抵消 F2 去重后的收益之外还有额外收益）。
- 段有了明确的槽位区间 → L3 的 `span_weight` 有了来源，L6 的静态检查有了判定对象。

**代价**：track 数上升（一条线切成 k 段就是 k 个顶点）。性能预算充裕：现有 substrate 推导最重单图 264 µs、graph 构建 380 µs，即使段数翻几倍仍是亚毫秒级。

### L2（Blocker）Gate 绑定到一条具体边界线，inner/outer 一一配对

`Gate` 结构改为携带被穿越的边界线标识，`inner`/`outer` 从笛卡尔积改为**配对列表**：

```rust
pub struct Gate {
    pub id: GateId,
    pub group: GroupId,
    pub side: GateSide,
    /// 跨该边界线的段对：(组内段, 组外段)，一一配对而非笛卡尔积。
    pub crossings: Vec<(TrackId, TrackId)>,
    pub capacity: GateCapacity,   // 见 L4
}
```

**配对规则**（范围与 L1.1 B1/B2 严格对齐——**只有被 G 切开的线才有组内段可配**）：

| gate | 边界线 | 遍历范围 | 配对内容 |
|---|---|---|---|
| `MainLow` | 顶边界，rank-gap `r0` | order-gap `og ∈ (o0, o1]` | 组内 Main 段（rank 跨 `[r0, r1+1]`）↔ 其上方相邻的组外 Main 段 |
| `MainHigh` | 底边界，rank-gap `r1+1` | order-gap `og ∈ (o0, o1]` | 组内 Main 段 ↔ 其下方相邻的组外 Main 段 |
| `CrossLow` | 左边界，order-gap `o0` | rank-gap `k ∈ (r0, r1]` | 组内 Cross 段（order 跨 `[o0, o1+1]`）↔ 其左侧相邻的组外 Cross 段 |
| `CrossHigh` | 右边界，order-gap `o1+1` | rank-gap `k ∈ (r0, r1]` | 组内 Cross 段 ↔ 其右侧相邻的组外 Cross 段 |

> ⚠️ **初稿的 `og ∈ [o0, o1+1]` / `k ∈ [r0, r1+1]` 是错的**：按 B2，`og = o0`（组左边界线）与 `og = o1+1`（右边界线）**不被 G 切开**，那两条线上没有组内 Main 段，遍历到它们只会配出空对或越界。范围必须是**恰好被切开的那些线**，即开区间下界。
>
> 推论：**退化跨度组的对应 gate 的 `crossings` 为空**（B7）。空 gate 不注册（沿用现 `add_gate_if_nonempty` 的语义），不是错误。

**同时补一条构建期不变量**（与 24 号文 P-inv-4 同级）：

| ID | 规则 |
|----|------|
| G-inv-1 | `MainLow` / `MainHigh` 的配对段必须是 **Main** 走向；`CrossLow` / `CrossHigh` 必须是 **Cross** 走向（修正 F2b 的轴向倒置） |
| G-inv-2 | 每对 `(inner, outer)` 在同一条线上且分别位于边界两侧（段区间相邻） |
| G-inv-3 | 同一 `(group, side)` 只允许一个 gate（禁止 F2a 的重复注册） |

**收益**：四个门语义独立、容量独立；「进一次出一次」自然落在两个不同 gate 上，`commit` 的按边去重不再误伤（F1 末尾、F2 全解）。

### L3（Blocker）`span_weight` 编码真实槽位跨度

相 I 无坐标，但**有槽位**。取：

- Cross 段：`span_weight` = 该段覆盖的 order-gap 数；
- Main 段：`span_weight` = 该段覆盖的 rank-gap 数。

按 L1.1 B5 零长段一律不注册，因此 `span_weight ≥ 1` 恒成立，不需要为零长情形设特例。

若日后需要更贴近几何，可由 Dialect/Profile 提供每槽的权重（宽列更重），但**绝不能保持恒 1**。

**收益**：Q4 恢复语义，绕远有代价，边不再全挤最外框。**这一条应当带来 peak lane demand 的显著下降**——25 号文 §4.1 的 10 / 33 / 25 是改造前基线，改造后重采即为效果度量。

> ⚠️ L3 必须与 L1/L2 同批交付。单独修 L3 会让边离开最外框走廊、从而**放大** F1 的穿组违规。

### L4（重要）gate 容量改为输出，与 lane 数对齐

当前把 gate 做成硬容量、又把容量设成需求（F3 自适应路径），是自相矛盾的中间态。正确做法与 B1 公理一致：

| 相 | gate 的处理 |
|---|---|
| **相 I** | 不设硬容量。每个 gate 累计 `crossing_demand`（穿越边数），与 track 的 `lane_demand` 完全同构 |
| **相 II** | 组框四边是变量；边界段实际容量 = 段长 / `min_gate_pitch`。约束形式：`边界段长 ≥ crossing_demand × min_gate_pitch`，与「track 两侧撑开」同型，PAVA 可直接处理 |
| **不可行时** | `RelaxationLadder`：级1 压 gate pitch → 级2 回相 I 改走别的边界 → 级3 放宽裙边 → 级4 显式 Degraded（沿用 22 号文阶梯编号，**勿**与本文 L1–L8 混淆） |

`GateCapacity` 保留一个 `Fixed(u32)` 变体，**仅供诊断扫描**（现 `gate_capacity_override` 的角色），生产路径恒为 `Unbounded`。

**收益**：删掉 `boundary_degree` 这个自证公式；gate 容量与 lane 数走同一条「需求 → 度量相撑开 → 撑不开才放松」的路，架构一致性回来了。

#### L4 之后的探针语义变化（必读）

L4 落地后，相 I 生产路径上**只剩端口侧容量一条硬约束**（lane / gate 均为输出 Demand）。因此：

| 旧探针列（25 号文） | L4 后含义 | 处置 |
|---|---|---|
| 「多边争用成功率」（自适应 gate） | 争用失败**只可能**来自端口满容；与「gate 争用」无关 | **删掉或改名**，勿再叫「全局协调争用」 |
| 「gate 容量扫描」cap=1/2/4/8 | 仍有诊断价值（`Fixed` 变体），但测的是「人为限容时的可行性曲线」，**不是生产路径** | 保留为附录「诊断扫描」，表头标明 `gate_capacity_override` |
| 「自适应争用 100%」 | 在「gate 无硬容 + 端口不限」下必然 ≈ 单边可行率 | **禁止**再与单边可行率并列成两份独立证据 |

25 号文重采时的**推荐表结构**见 §5.1。A6 保留端口生产口径是对的，但必须与「表达上界 / 诊断扫描」分列，否则又是一轮同义反复。

### L5（重要）探针恢复端口容量口径 + 重设计争用表

当前每条边端点独占一个 `PortSlot` 且 `capacity = 0`，等于把 I.5 的硬约束整个关掉。改为三列并行出数（不是两列）：

| 口径 | 端口挂法 | gate | 测什么 |
|---|---|---|---|
| **表达上界** | 每边独占槽，`capacity=0` | `Unbounded`（L4 生产） | 「图上有没有合法路」（合法化后的单边可行率） |
| **端口生产** | 同 `(node,side)` 共享槽，`capacity=PORT_SIDE_CAPACITY` | `Unbounded` | **唯一的相 I 硬争用**：端口侧压力 |
| **gate 诊断** | 表达上界挂法 | `Fixed(cap)` 扫描 | 人为限容曲线；不进生产结论 |

「多边争用」一词在 L4 后应特指**端口生产口径**下的共享占用贪心布边；gate 不再参与「争用失败」归因。

### L6（重要）合法性自反证检查器

分段（L1）之后，每个 `Track` 段都有明确的槽位区间。加一个 `Substrate::verify_no_group_penetration()`：

```text
对每个段 s、每个组 G（G ≠ s.scope 且 G 不是 s.scope 的祖先）：
    断言 s 的槽位区间与 G 的矩形内部不相交
```

「内部」与 L1.1 B1/B2 对齐：组边界缝本身不算内部。O(段数 × 组数) 的纯组合检查，无几何。

**L6 只证明基底结构正确，不证明路径合法**——一条合法归属的组内段仍可被无关边借道（§3.1）。路径侧由 L8 负责。二者缺一，「H2 由构造保证」都不成立。

### L8（Blocker）搜索期作用域过滤：借道也不可表达

> 编号后置只因它是 L1–L7 定稿后补入；优先级是 **P0**，与 L1/L2 同批（见 §8）。位置紧接 L6 是因为二者是同一条不变量的静态面与动态面。

**这是 A2 = 0 的唯一机制**，不是可选优化。没有它，L1–L4 做完后 A2 必然爆掉（§3.1 已推演），且现象极易被误判成「L1 分段做错了」。

**规则**：边 `e = (u, v)` 在搜索时的可用段集合限制为

```text
allowed_scopes(e) = {None} ∪ chain(scope_of(u)) ∪ chain(scope_of(v))
    其中 chain(g) = g 及其全部祖先组
```

等价表述（实现上更直观）：**组 G 的四个 gate 只对「至少一端在 G 子树内」的边开放**；对其余边，G 的 gate 转移从图上消失。两种表述等价——组内段的唯一入口就是 G 的 gate（该前提由 L1.1 B8 保证：内段与边界缝不 link，link 无法旁路 gate）。

**为什么必须是硬过滤而不是软罚项**：备选方案是「给无关组穿越计一个排在 Q3 之前的词典位」，允许无路可绕时借道。但那与 A2 = 0 的硬判据直接冲突，除非把 A2 软化成「无绕行余地时可豁免」。**二者只能取一**。本文选硬过滤，理由：

- 它是 H2「借道也不可表达」的**构造性**版本，与 B2 公理、23 号文 D8（凡称「由构造保证」必配检查器）一致；
- 与 L6 的口径天然同构（同一套 scope 归属判定，一个查基底、一个查路径）；
- 软罚项会让「穿组 = 0」重新变成需要事后统计的软指标，正是 Atlas 要消灭的东西。

**副作用：部分边会真正 `Infeasible`**，这是预期的，由 A4「≥99% + 失败边逐条解释」接住，不得用兜底路径掩盖。可行性风险实际很低，因为**最外框的四条缝按 B1/B2 永不被切开**：

```text
Cross gap 0        切开条件 r0 < 0        → 恒假
Cross gap rank_count   切开条件 rank_count ≤ r1  → 恒假（r1 ≤ rank_count-1）
Main  gap 0 / order_count  同理恒假
```

即根 scope 始终存在一圈贯通的外框走廊（四条线两两相交、互相 link），任意两个根 scope 位置总能经外框互达。即使某个组横跨全部列（此时被切开的 Cross 线整条归该组），无关边仍可走左右外框 Main 走廊绕过。绕行的代价是多几个折点，不是不可行。

**实现落点**：`route` / `route_candidates` 增一个作用域掩码参数，在转移松弛处跳过 `scope ∉ allowed` 的目标段。搜索算法本身（词典序 Dijkstra、平局键、确定性）**不变**——这是本文唯一需要碰 `search.rs` 的改动，且是一个谓词。

**验收**：A2 = 0（硬）。另需单测钉死副作用边界：组横跨全部列时，两端在组外、分居组上下的边**仍可行**（走外框），路径不含该组任何段。

### 5.1 L4/L5 落地后的重采表结构（避免第二轮同义反复）

L4 之后相 I 生产路径只剩**端口容量**一条硬约束，「多边争用」若仍与「单边可行率」并列表头，会再次变成同义反复。重采时建议固定为：

```text
## 总体（合法化后）
| 集 | 边 | 合法单边可行率 | 借道穿组 | 同gate双穿 |
|---|---|---|---|---|

## 端口争用（生产口径 = 相 I 唯一硬争用）
| 集 | 边 | 端口争用成功 | 端口争用失败 | 峰值侧负载 |
|---|---|---|---|---|

## gate 诊断扫描（Fixed cap，非生产；附录）
| cap | 声明序成功 | 逆序成功 | 顺序敏感缺口 |
|---|---|---|---|

## 需求画像（输出给相 II）
| 集 | 峰值 lane demand | 峰值 gate crossing_demand |
|---|---|---|
```

验收门 A6 只看「端口争用」表；A4 只看「合法单边可行率」；gate 扫描表**不进**「争用 100%」类结论句。

## 8. 优先级与工作量估计

| 优先级 | 项 | 影响面 | 估计 |
|---|---|---|---|
| P0 | L1 轨道分段 + L1.1 边界用例 | `derive.rs` 建图规则重写 | 主要工作量所在 |
| P0 | L2 Gate 绑定边界线 + G-inv-1/2/3（配对范围 `(o0, o1]` / `(r0, r1]`） | `substrate.rs::Gate` + `derive.rs::add_boundary_gates` + `graph.rs` 展开 | 中 |
| P0 | **L8 搜索期作用域过滤** | `search.rs` 加谓词 + 调用方传掩码 | 小（但缺了 A2 必爆） |
| P0 | L3 span_weight 真实化 | `derive.rs::build_region` | 小（依赖 L1 的段区间） |
| P1 | L4 gate 容量作输出 | `substrate.rs` + `graph.rs::Occupancy` + 删 `boundary_degree` | 中 |
| P1 | L6 自反证检查器 | 新增 `substrate.rs` 方法 | 小 |
| P1 | L5 探针三列口径 + 25 号文表结构重设计 | `atlas_probe.rs` | 小～中 |
| P2 | L7 债务 T1–T7 | 分散 | 小，可随手带 |

**建议实施次序**：L1 → L2 → **L8** → L6 → L3 → L4 → L5。把 L8 与 L6 插在 L3 之前，是因为 L3 会把边从最外框走廊赶回图内部（F4 末段已预警「F1 违规会立刻暴涨」）——先立起合法性约束再改代价函数，才能把 A2 的变化归因清楚。

`bundle.rs`（后缀 trie）与 `Occupancy` 的账本语义**无需改动**；`search.rs` 只加一个作用域谓词，词典序 Dijkstra 本体、平局键与确定性不变。这印证了 §0 的判断：抽象是对的，坏在 derive 出来的基底与「谁能走哪段」的缺失。
