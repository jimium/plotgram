# 问题整理

> 本文档记录用户在开发过程中发现的问题，由 AI 协助整理、分析与讨论。
> 文档最终将整体提交给 AI 做进一步分析与判断。

## 协作模式

1. **用户**：分多次提出问题（文字描述 + 可选截图）。
2. **AI**：整理并更新本文档；不照搬原话，会进行分析与讨论。
3. **截图流程**：
    - 用户将截图放入 `收件箱/` 文件夹并告知；AI 将其移动到 `归档图片/` 并重命名为 `ISS-XXX-描述.png`，与本文档中的条目对齐。
4. **后续**：整份文档提交给 AI 做整体分析。

## 文件夹结构

```
docs/问题整理/
├── 问题清单.md        # 本文档（主索引 + 各问题详情）
├── 收件箱/            # 用户投放截图的临时区（AI 不在此处长期保留文件）
└── 归档图片/          # AI 管理的截图归档区（按 ISS-XXX 命名）
```

## 问题条目格式

每个问题按以下结构记录：

```
### ISS-XXX  标题
- 状态：待讨论 / 分析中 / 已定位 / 已修复 / 暂缓
- 分类：布局 / 路由 / 渲染 / 交互 / DSL / 性能 / 其他
- 发现时间：YYYY-MM-DD
- 问题描述：（经整理的问题陈述）
- 截图：[ISS-XXX-xxx.png](./归档图片/ISS-XXX-xxx.png)
- 分析与讨论：（AI 的分析、推测、可能成因、可选方案）
- 关联代码：file:///... 链接（若可定位）
- 后续动作：下一步建议
```
