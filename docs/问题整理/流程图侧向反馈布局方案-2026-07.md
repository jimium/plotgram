## 1. 一句话

经典 Sugiyama **proper layering** 把回环汇合点沉到主链下方，与人类「驳回贴决策旁、终点贴最后一步旁」的构图冲突；order / 路由补丁够不着同层旁置。根本解法是在 **rank 层承认同层侧向边**，并区分真终点与 FAS 假 sink。

---

## 2. 问题与目标

### 2.1 现象（order-approval）

当前布局大致为：

```text
        提交订单
           │
        经理审核
           │
      金额是否超限
           │
        财务复核
           │
        审批通过 ──────────┐
           │               │
     驳回修改 ←──左廊───┘  完成
           │
           └──重新提交（左外廊绕回顶部）──→ 提交订单
```

人类期望：

```text
        提交订单
           │
        经理审核
           │
      金额是否超限
           │
 驳回修改 ─ 财务复核
     │         │
     │      审批通过 ─ 完成
     │
     └──重新提交（左侧短回环）──→ 提交订单
```

直观收益：回环总边长显著下降；左驳回 / 右前进符合流程图惯例；ISS-008 的「折点过多」也会因几何变短而自然缓解（路由仍可再优化，但不靠路由救构图）。

### 2.2 产品目标

| 目标 | 说明 |
|------|------|
| G1 | 反馈汇合点与其**主前驱**同层、主列左侧（TB）或上侧（LR） |
| G2 | 真 `end` 在合适时与唯一前驱同层邻接（ISS-007），而非一律沉底 |
| G3 | 无图名特判；规则由图角色（feedback hub / end）与拓扑导出 |
| G4 | 确定性；主链分层与少交叉能力不退化到不可接受 |
| G5 | 路由继续消费 feedback 语义画外环，但**节点 y/x 已在布局定好** |

### 2.3 非目标（本草案不做）

- 不接入 ELK / yFiles 作为主引擎（对照可另开）
- 不做完整 BPMN / SESE 结构化流分解（可作远期）
- 不靠边 label 文本（「驳回」「通过」）驱动布局（易碎、多语言）
- 不把「总边长最小化」做成全局优化主目标（只通过侧向反馈间接缩短）

## 3. 根因：为什么补丁无效

### 3.1 管线写权

```text
flowchart → sugiyama_v2
  FAS 破环 → rank (NS) → sink clamp → proper 层图
  → order（仅层内）→ coordinate（y = layer_offsets[rank]）
  → 路由（可标 feedback_side，不改节点层）
```

节点纵向位置在 **rank → coordinate** 已冻结；路由无法把 `驳回修改` 抬到 `财务复核` 旁。

### 3.2 结构禁区

对 `product.order-approval.pgm`：

1. FAS 反转 `rejected → submit` 后，`rejected` 在 DAG 中 **出度 = 0**（假 sink）。
2. 仍保留的 `finance → rejected` 要求 `rank(rejected) ≥ rank(finance)+1` —— **同层旁置在 proper layering 下非法**。
3. `apply_sink_rank_constraints` 把 `type=end` **或** `out_degree==0` 钳到 `max_rank`，与 `done` 同沉底层。
4. order 只做层内排序，不能跨层；median 倾向收拢主列。

因此：

| 手段 | 最多能做到 | 能否到 finance 同层左侧 |
|------|------------|-------------------------|
| 放宽 sink clamp | 升到 approved 层附近 | 否 |
| order 左偏置 / decl_order | 同层左右挪 | 否（人不在那一层） |
| 路由 feedback_side | 左边好看一点 | 否 |
| **同层侧向边 + hub 识别** | 合法同层旁置 | **是** |

**结论**：基底缺「侧向反馈」建模；松约束只能缓解，不能达标。

## 4. 同行借鉴（可抄什么、别指望什么）

| 体系 | 可借鉴 | 局限 |
|------|--------|------|
| **Graphviz dot** | `rank=same`、`minlen=0` 同层边；同层侧边是一等公民 | 常靠用户约束，非全自动「懂驳回」 |
| **ELK Layered** | `layerConstraint`、层内边、cycle 策略 | Mermaid+ELK 仍有回环构图问题；换引擎不自动达标 |
| **yFiles Hierarchical** | 边角色 + Layer/Sequence 约束工厂 | 闭源；学建模不抄实现 |
| **BPMN 布局** | 网关左右分支、重试块旁置 | 域绑定重；本阶段只借「左回 / 右进」惯例 |
| **Mermaid dagre/ELK** | — | **同类痛点**，不作答案库 |

工业共识：好看靠 **同层边 / 约束 API / 域规则** 至少一者，不是更强的 network-simplex。

## 5. 方案总览

### 5.1 主路线：侧向反馈模型（扩 sugiyama_v2 基底）

在 **rank 阶段**引入边角色与同层许可，使「反馈汇合点 ‖ 主前驱」成为合法解；order / coordinate / 路由消费该结果。

```text
边分类：Forward | Branch | Feedback
          ↓
识别 Feedback Hub（回环汇合点）
          ↓
Rank：hub 与主前驱同层；入边标 SameLayer（minlen=0）
      假 sink 不再被 sink clamp 沉底
          ↓
Order：hub 相对主前驱偏「回环侧」（TB→左；LR→上）
      end 相对唯一前驱偏「前进侧」（TB→右；LR→下）可选
          ↓
Coordinate：同层横排；主链仍按 layer_offsets
          ↓
Route：短回环走侧廊；ISS-008 在短几何上再抠折点
```

### 5.2 与 ISS-007 的关系

ISS-007（`done` 贴 `approved` 右侧同高）与 ISS-006 **同源**：都需要「允许同层邻接边 / 放松对部分节点的强制下层」。建议同一方案内分两档交付：

| 档 | 内容 | 问题 |
|----|------|------|
| P0 | Feedback hub 同层侧置 + 假 sink 免沉底 | ISS-006 |
| P1 | 单一前驱的 `end` 同层邻接（前进侧） | ISS-007 |
| P2 | DSL `rank=same` / `order left-of` 约束（兜底与作者控制） | 两者 |

ISS-008 以路由优化为主；本方案缩短几何后作为前置，不替代路由修复。

## 6. 算法设计

### 6.1 边角色（EdgeRole）

在 FAS 之后、rank 之前（或与 FAS 同步）标注：

| 角色 | 判定（草案） | 布局含义 |
|------|--------------|----------|
| **Feedback** | 被 FAS 反转的边；或原图中 `rank` 启发式上指向更早层的边 | 不参与「强制下一层」的前向跨度压力；回环走侧廊 |
| **Forward** | DAG 中保留的、沿主流向的边 | 默认 `minlen ≥ 1` |
| **Branch** | 同层候选的侧向边（见下） | `minlen = 0`，允许同层 |

实现注意：角色按 **拓扑 / FAS 结果** 导出，**不读 label 文案**。

### 6.2 Feedback Hub 识别

节点 `h` 称为 feedback hub，当同时满足：

1. 存在至少一条 **Feedback** 出边（破环前指向更早节点，如 `rejected → submit`）；
2. 存在至少一条 **非 Feedback** 入边来自「前向主链」节点（如 `finance → rejected`）；
3. （可选收紧）在 DAG 中因 FAS 导致出度为 0，或所有 DAG 出边都是反转边。

**主前驱 `p`**：在非 Feedback 入边中选一条——优先唯一入边；多条时取声明序最早或层内中位前驱（需固定确定性键）。

order-approval：`h = rejected`，`p = finance`。

### 6.3 Rank 规则变更

对 hub `h` 与主前驱 `p`：

1. 将 `p → h` 标为 **SameLayer**（`minlen = 0`），允许 `rank(h) = rank(p)`。
2. Network-simplex / longest-path 初值：把 `h` 的目标 rank 设为 `rank(p)`（或 NS 在 `minlen=0` 约束下自然压到同层）。
3. **禁止**因同层边破坏其它 Forward 边的 `minlen≥1`（标准 NS 约束兼容）。

Proper layering：

- SameLayer 边 **不**插入 dummy 链；
- 同层边在 order 阶段按层内左右邻接处理，在路由阶段按水平/短 L 处理。

### 6.4 Sink clamp 收紧

当前（`engine.rs::apply_sink_rank_constraints`）：

```text
type=end  OR  out_degree==0  →  max_rank
```

改为：

| 条件 | 行为 |
|------|------|
| `type=end` 且 **非** P1「可邻接 end」 | 仍可沉到 `max_rank`（或见 §6.5） |
| `out_degree==0` 且为 **Feedback Hub** | **不**因出度 0 沉底 |
| `out_degree==0` 且非 hub、非 end | 保持沉底（真叶子） |

flowchart 路径上 sink 会跑两次（group 前后）；两处语义必须一致。

### 6.5 End 同层邻接（P1 / ISS-007）

当 `e` 满足：

- `type=end`；
- 恰有一条非 Feedback 入边来自 `u`；
- `u` 不是 decision 的「多分支汇合复杂源」（草案：`u` 为 process/start 等单后继友好类型，或 `u` 出度在扣除指向 `e` 后为 0）。

则：

- `u → e` 标 SameLayer；
- `rank(e) = rank(u)`；
- order：`e` 在 `u` 的前进侧（TB 右侧）。

与「end 必须在最底」的旧审美冲突时，以 **邻接可读性** 为准；孤立 end（无前驱）仍沉底。

### 6.6 Order 偏置

在 `order_layers_weighted_median` 的比较键中增加软项（不覆盖交叉硬改善过多时的回退）：

| 节点关系 | TB | LR |
|----------|----|----|
| hub 相对主前驱 | x 更小（左） | y 更小（上） |
| 邻接 end 相对前驱 | x 更大（右） | y 更大（下） |

交叉数若因偏置显著变差：允许回退该层偏置（可测阈值），但 **rank 同层关系保持**（几何旁置优先于完美零交叉）。

### 6.7 与路由的接口

布局 hints 建议增加（名称可调）：

- `same_layer_edges: Vec<(from, to)>`
- `feedback_hubs: Vec<{ hub, primary_pred }>`
- 既有 `sugiyama_ranks`

路由侧：

- Feedback 边继续走 `feedback_side` 外廊逻辑；
- SameLayer 边优先短横/短 L，避免再绕底廊；
- ISS-008 在短几何上减少折点与端口误选。

## 7. 非法态变更（契约）

| 旧契约 | 新契约 |
|--------|--------|
| 所有 DAG 边 `rank(to) ≥ rank(from)+1` | Forward：是；SameLayer：允许相等 |
| `out_degree==0` ⇒ `max_rank` | Feedback hub 豁免 |
| `type=end` ⇒ 一律 `max_rank` | P1：可邻接 end 豁免 |
| order 只优化交叉 / median | 增加侧向语义软偏置 |

红线不变：确定性迭代、禁止图名特判、WASM 禁裸 `std::time`、穿组正确性。

## 8. 实施阶段

### P0 — Feedback hub 同层侧置（ISS-006）

1. 边角色 + hub / 主前驱识别（单测覆盖 order-approval 拓扑）。
2. SameLayer `minlen=0` 接入 rank / proper graph。
3. 收紧 sink clamp（hub 豁免）。
4. order 左侧偏置。
5. 回归渲染 `product.order-approval`：目视 + 坐标断言（hub 与 finance 同 rank，hub.x < finance.x）。

### P1 — End 邻接（ISS-007）

1. 可邻接 end 判定 + SameLayer。
2. order 右侧偏置。
3. 与 P0 同图验收：`done` 与 `approved` 同高邻接。

### P2 — DSL 约束兜底（可选）

学 Graphviz / yFiles：

- `constrain rank=same A B` 或等价语法；
- `order A left-of B`（层内）。

算法启发式不够稳时由作者钉死；**默认路径仍应自动做好 P0**。

### P3 — 远期（本草案不排期）

- SESE / 结构化重试块布局；
- 决策多出边的左右展开（仍不靠 label 文案，可靠声明序 / 稳定边序）；
- 可选 ELK 对照引擎。

## 9. 验收与回归

### 9.1 锚点图（硬）

`showcase/flowchart/product.order-approval.pgm`：

| 检查 | 通过标准 |
|------|----------|
| ISS-006 | `rank(rejected)==rank(finance)` 且 TB 下 `rejected.x < finance.x`（间隙 ≥ 节点间距下限） |
| ISS-006 | `重新提交` 路径不再从画布底绕到顶（可用路径 bbox 高度或折点数作软指标） |
| ISS-007（P1） | `rank(done)==rank(approved)` 且 `done.x > approved.x` |
| 正确性 | `det=true`；无穿组 |

### 9.2 防回归集

- 若干含回环的 flowchart product / smoke（从 `benchmarks/sets` 抽，**禁止**单图特判分支）。
- 无回环主链图：分层视觉不应无故变「扁」。
- 多 hub / 嵌套回环：至少 1～2 张手工样例，记录期望或「可接受退化」。

### 9.3 门禁说明

当前全局优化期质量轨豁免（`AGENTS.md` §8）仍适用；本方案验收以 **锚点图几何契约 + 正确性** 为主，不以 stress 数字卡死。阶段收敛后把锚点断言收进 product-gate 或专用 layout contract 测试。

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| Hub 误识别，把普通叶子当旁置 | 要求同时具备 Feedback 出边 + 前向入边；单测边界 |
| 同层边增多导致交叉上升 | order 偏置可回退；SameLayer 数量通常很少 |
| 与 group_divide / 泳道交互 | P0 先限无组 flowchart；有组时 hub 不跨 leaf 同层强拉 |
| NS 与 `minlen=0` 实现细节 | 对齐 Graphviz 语义；单测紧约束树 |
| 只改布局、路由仍绕远 | hints 打通 same_layer；ISS-008 跟进 |

## 11. 明确不采用的路线

1. **仅 order 左偏 / 声明序** —— 达不到同层。  
2. **仅放宽 sink** —— 最多升一层，仍低于 finance。  
3. **仅优化回环路由** —— 边短不了，构图仍错。  
4. **图名 / 节点 id 特判** —— 违反红线。  
5. **以换 ELK 替代本方案** —— 不解决「自动侧向反馈」建模缺口。

---

## 12. 开放问题（讨论时拍板）

1. Hub 多前驱时主前驱选择：唯一入边优先以外，用声明序还是最大「前向权重」？  
2. P1 的 end 邻接是否默认开启，或仅当 `end` 出度为 0 且前驱出度（扣除 end）为 0？  
3. SameLayer 边是否允许跨越 group 边界？草案：**P0 禁止**。  
4. DSL P2 是否与本算法同迭代，还是算法稳定后再加？  
5. 验收是否增加「回环路径曼哈顿长度 / 折点数」定量阈值，还是先目视 + rank/x 契约？
