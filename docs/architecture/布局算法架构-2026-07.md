## 1. 概述

Plotgram 布局系统采用 **Pipeline → Recipe → Engine → Kernel** 四层分工：

| 层 | 目录 | 职责 |
|----|------|------|
| **Pipeline** | `layout/pipeline/` | 入口调度、计划解析、布局+路由全生命周期编排 |
| **Recipe** | `layout/recipes/` | 图类型语义：compile → solve → product |
| **Engine** | `layout/engines/` | 共享算法：Sugiyama 分层、IR 构建、通用工具 |
| **Kernel** | `layout/kernel/` | 纯数学：PAVA + 投影梯度，无 `DiagramType` |

路由（`layout/routing/`）、空间需求（`layout/demand/`）、分组框（`layout/group/`）与布局并行存在，由 Pipeline 在节点冻结前后分别调度。

> **吃狗粮**：架构图不再用 Mermaid，而是用 Plotgram flowchart DSL 编写，经自家 WASM 布局引擎渲染为 SVG。源码见 [HTML 版](./布局算法架构-2026-07.html) 或下文各节。

```
layout/
├── pipeline/          # 管线编排（runner / registry / plan / entry）
├── recipes/           # 图类型配方（flowchart / architecture / state / er / …）

│   ├── layered/       # Sugiyama：rank / order / LayeredKernel
│   ├── coordinate/    # CoordinateProblem builder + objectives
│   └── common/        # 图工具、group_bounds、overlap 等
├── kernel/            # 坐标内核
│   ├── coordinate/    # model / projection / optimizer / auditor
│   ├── coordinator.rs # CoordinateKernel 统一入口
│   ├── recipe.rs      # LayoutRecipe trait
│   └── frozen.rs      # FrozenNodeLayout 快照
├── demand/            # SpaceBudget、SpacingDemandStore、RoutingContract
├── routing/           # 边路由（orthogonal / bezier / spline / …）
├── group/frame/       # GroupFramePass
├── route_feedback.rs  # 预路由 + 路由后 refine + feedback re-solve
├── refine/            # 交叉消解（skip_push=true）
├── post_route/        # snap、repulse、D 段修复
├── snap/              # grid snap、canvas finalize
└── quality/           # lint、metrics
```

> **注意**：旧路径 `layout/node/` 已删除；builder 位于 `engines/coordinate/`，配方位于 `recipes/`。

## 3. Pipeline 全生命周期

`LayoutPipeline::run` 是用户可见的完整管线：

```plotgram
diagram flowchart {
    title: "LayoutPipeline"
    edge_routing: orthogonal
    config { direction: top-to-bottom }
    entity[start] s1 "strategy.compute"
    entity[process] s2 "apply_node_frame"
    entity[process] s3 "apply_pre_route"
    entity[process] s4 "complete_routing"
    entity[process] s5 "post_route + budget"
    entity[process] s6 "NodeFreeze.capture"
    entity[process] s7 "snap + sanitize_ext"
    entity[process] s8 "label_resolve"
    entity[end] s9 "canvas_finalize"
    s1 -> s2
    s2 -> s3
    s3 -> s4
    s4 -> s5
    s5 -> s6
    s6 -> s7
    s7 -> s8
    s8 -> s9
}
```

**写权要点**（★ 为关键冻结点）：

- **布局 solve 后**：节点相对坐标主要由 CoordinateKernel 写入。
- **路由前**：仍可能 `enforce_vertical_rank_gaps` 推节点。
- **路由中**：`FrozenNodeLayout` + debug 守卫；refine 不 push 节点。
- **NodeFreeze 后**：仅允许改边几何、label、annotation；节点坐标不应再变。

## 4. Recipe 层

### 4.1 LayoutRecipe 生命周期

```plotgram
diagram flowchart {
    title: "LayoutRecipe 生命周期"
    edge_routing: orthogonal
    config { direction: left-to-right }
    entity[start] c "compile"

    c -> so
    so -> a
    a -> p
}
```

Trait 定义：`layout/kernel/recipe.rs`

```rust
pub trait LayoutRecipe {
    type Problem;
    type Solution;
    fn compile(&self, diagram: &Diagram) -> Self::Problem;
    fn solve(&self, problem: &Self::Problem) -> Self::Solution;
    fn audit(&self, _problem, _solution) {}  // 默认 no-op
    fn product(&self, solution, diagram) -> LayoutResult;
    fn execute(&self, diagram) -> LayoutResult { ... }
}
```

### 4.2 各图类型路径

| 图类型 | Recipe | 主路径 | 坐标求解 | 备注 |
|--------|--------|--------|----------|------|
| Flowchart | `recipes/flowchart` | LayeredKernel → BK → CoordinateKernel | ✅ | 有 group 时走 `group_divide` bypass |
| State | `recipes/state` | FAS 阈值选 Circular 或 Sugiyama | ✅ Sugiyama 路径 | |
| ER | `recipes/er` | LayeredKernel + CoordinateKernel | ✅ | |
| Architecture | `recipes/architecture` | flat: ArchProblem；有 group: two_phase | ✅ flat + intra | `arch_builder` 用 entity id |
| Sequence | `recipes/sequence` | 专用时间轴布局 | — | 自产边，跳过路由管线 |
| Circular | `recipes/circular` | 极坐标几何 | — | |
| Mindmap | `recipes/mindmap` | 树形辐射 | 部分用 optimizer | |

## 6. Kernel 层：CoordinateKernel

### 6.1 模块职责

| 模块 | 路径 | 职责 |
|------|------|------|
| `model.rs` | `kernel/coordinate/` | `CoordinateProblem`、`HardConstraint`、`ObjectiveTerm`、`SolveAxis` |
| `projection.rs` | 同上 | 层内 PAVA + Dykstra 交替投影（bounds / MinSeparation） |
| `optimizer.rs` | 同上 | P1→P2→P3 投影梯度 + BB 步长 + best snapshot |
| `auditor.rs` | 同上 | P0 审计 + `validate_problem` |
| `analysis.rs` | 同上 | 连通分量、problem signature |
| `coordinator.rs` | `kernel/` | `CoordinateKernel::solve` 统一入口 |

### 6.3 优先级语义

```plotgram
diagram flowchart {
    title: "P0–P3 优先级"
    edge_routing: orthogonal
    config { direction: top-to-bottom }
    entity[process] p0 "P0 硬约束"
    entity[process] p1 "P1 结构目标"
    entity[process] p2 "P2 边友好"
    entity[process] p3 "P3 审美 BK"
    p0 -> p1
    p1 -> p2
    p2 -> p3
}
```

| 层级 | 类型 | 示例 | 执行方式 |
|------|------|------|----------|
| **P0** | 硬约束 | 层内分离、跨层 MinSeparation、Fixed/Bound | PAVA + Dykstra 投影 |
| **P1** | 结构软目标 | end 跟随、pendant 对齐、fan 对称 | 投影梯度，完成后锁 budget |
| **P2** | 边友好 | 边拉直、dummy 共线、singleton | 梯度，不破坏 P1 |
| **P3** | 审美 | BK 位置保持 | 梯度，不破坏 P1/P2 |

## 8. 节点冻结与写权

```plotgram
diagram flowchart {
    title: "节点冻结时序"
    edge_routing: orthogonal
    config { direction: top-to-bottom }
    entity[process] r "Recipe.solve"
    entity[process] pr "pre_route"
    entity[process] rt "router"
    entity[process] fb "route_feedback"
    entity[process] fz "NodeFreeze.capture"
    entity[process] lb "label_resolve"
    entity[end] ok "assert 节点未变"
    r -> pr
    pr -> rt
    rt -> fb
    fb -> fz
    fz -> lb
    lb -> ok
}
```

| 阶段 | 可写节点？ | 机制 |
|------|-----------|------|
| Recipe solve 后 | ✅ 唯一主写者 | CoordinateKernel |
| pre-route 竖缝 | ⚠️ 仍直接推 | `enforce_vertical_rank_gaps` |
| 路由中 | ❌ 意图冻结 | `FrozenNodeLayout` + debug_assert |
| route feedback re-solve | ⚠️ 可回写 | `route_feedback_resolve` |
| budget guard | ⚠️ 竖缝 + 兜底 | `space_budget_guard` |
| NodeFreeze 后 | ❌ 硬守卫 | `NodeFreeze.assert_unchanged` |

## 10. 图类型与算法矩阵

| 图类型 | 布局 Recipe | 分层引擎 | CoordinateKernel | 边路由 | 成熟度 |
|--------|-------------|----------|------------------|--------|--------|
| Flowchart | ✅ | LayeredKernel | ✅ | orthogonal 默认 | 主路径成熟；group bypass |
| State | ✅ | LayeredKernel / Circular | ✅ / — | 随路径 | 成熟 |
| ER | ✅ | LayeredKernel | ✅ | orthogonal | 成熟 |
| Architecture | ✅ | 自有 rank/order + two_phase | ✅ flat/intra | orthogonal | 部分后处理仍推点 |
| Sequence | ✅ | 专用 | — | 自产 | 跳过路由管线 |
| Mindmap | ✅ | 树形 | 部分 | organic 等 | 独立 solver |
| Circular | ✅ | 极坐标 | — | circular | 独立 |

## 11. 设计决策

| # | 决策 | 理由 |
|---|------|------|
| 1 | PAVA + Dykstra 投影 P0 | 硬约束可执行、可审计 |
| 2 | BK 仅作 warm start + P3 目标 | 初值好、不替代结构语义 |
| 3 | P1→P2→P3 分层 + budget | 避免 magic weight |
| 4 | Kernel 无 DiagramType | Recipe/Engine 编译语义 |
| 5 | Recipe 是普通 Rust 编排 | 不过度抽象 |
| 6 | Pipeline 与 Recipe 分离 | 路由/post_route 不属于布局 Recipe |
