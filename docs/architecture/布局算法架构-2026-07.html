1. 概述

Plotgram 布局系统采用 Kernel/Recipe 分层架构，将核心坐标求解算法与图类型语义解耦：

  • Kernel 层：共享的坐标约束求解器，不接受 DiagramType，只消费 IR
  • Node 层适配器：将图类型语义编译为 IR（builder + objectives）
  • Recipe 层：显式编排布局生命周期（compile → solve → audit → product）

2. 架构分层

Recipe 层（图类型编排）
FlowchartRecipe / ArchitectureRecipe / StateRecipe
职责：编排布局生命周期，调用 builder → solver → auditor
Node 层适配器
builder.rs / objectives.rs / structure_objectives.rs
职责：AST + Sugiyama layers → CoordinateProblem IR
Kernel 层（共享内核）
model.rs / optimizer.rs / projection.rs / auditor.rs
职责：消费 IR，输出坐标，无图类型语义

2.1 Kernel 层

位置：crates/plotgram-core/src/layout/kernel/coordinate/

模块职责
model.rsIR 数据结构（CoordinateProblem、HardConstraint、Objective）
optimizer.rsProjected Gradient 求解器（P1→P2→P3 分层优化）
projection.rsPAVA 硬约束投影（层内最小分离）
auditor.rsP0 约束审计（solver 后验证）

设计原则：

  1. 不接受 DiagramType 参数
  2. 只消费 CoordinateProblem IR
  3. 确定性：相同输入产生相同输出

2.2 Node 层适配器

位置：crates/plotgram-core/src/layout/node/coordinate_solver/

模块职责
builder.rs从 Sugiyama layers/sizes 构建 CoordinateProblem
objectives.rs基础目标（BK 位置保持、边拉直、dummy 共线）
structure_objectives.rs结构目标（线性链、end 跟随、pendant 对齐）

2.3 Recipe 层

编排流程：

compile (AST → IR)
  → solve (IR → coordinates)
  → audit (验证 P0 约束)
  → product (coordinates → NodeLayout)

3. 坐标求解器

3.1 IR 数据结构

pub struct CoordinateProblem {
    pub vars: Vec<NodeVariable>,          // 坐标变量
    pub layers: Vec<LayerConstraintSet>,  // 层约束（含最小分离）
    pub hard: Vec<HardConstraint>,        // P0 硬约束
    pub objectives: Vec<Objective>,       // P1/P2/P3 软目标
    pub initial: InitialValues,           // BK 初值
    pub config: SolverConfig,             // 求解配置
}

3.2 优先级分层

优先级含义示例
P0硬约束（可行域）层内最小分离、节点不重叠
P1结构目标线性链共轴、end 跟随、pendant 对齐
P2边友好目标边拉直、dummy 共线、singleton 对齐
P3审美目标BK 位置保持

3.3 求解算法

  1. PAVA 投影：将坐标投影到硬约束可行域（O(n) 时间）
  2. Projected Gradient：在可行域内按 P1→P2→P3 分层优化
  3. Barzilai-Borwein 步长：自适应加速收敛
  4. Best Feasible Snapshot：未收敛时返回最佳可行解

4. Sugiyama 布局管线

┌─────────────────────────────────────────────────────────────┐ │ 1. 预处理 │ │ - 解析 AST → Diagram │ │ - 确定方向（TB/LR） │ ├─────────────────────────────────────────────────────────────┤ │ 2. 分层（Rank Assignment） │ │ - 拓扑排序 → 层分配 │ │ - 长边插入 dummy 节点 │ ├─────────────────────────────────────────────────────────────┤ │ 3. 层内排序（Ordering） │ │ - 重心法 / 中位数法减少交叉 │ ├─────────────────────────────────────────────────────────────┤ │ 4. 坐标分配（Coordinate Assignment） │ │ - BK 算法 → 初值 │ │ - Compact → 紧凑化 │ │ - CoordinateSolver → 统一求解 │ │ - 物化 → NodeLayout │ ├─────────────────────────────────────────────────────────────┤ │ 5. 后处理 │ │ - Normalize（刚性平移到 padding） │ │ - Group bounds 计算 │ ├─────────────────────────────────────────────────────────────┤ │ 6. 边路由（Edge Routing） │ │ - 正交路由 / 贝塞尔 / 样条 │ │ - Refine（推开穿障节点，solver 冻结图类型跳过） │ └─────────────────────────────────────────────────────────────┘

5. 节点冻结机制

Phase 7 引入：使用 coordinate solver 的图类型（Flowchart/State/ER），solver 完成后节点即冻结：

组件冻结行为
route_feedback.rs跳过 enforce_horizontal_gaps
refine/mod.rs跳过 push（不推开节点）
space_budget_guard.rs跳过水平缝消解
pipeline.rs跳过 align_nodes

保留：enforce_vertical_rank_gaps（层缝硬约束仍需守约）

8. 设计决策记录

#决策理由替代方案
1PAVA 替代前扫+后扫L2 最优投影，O(n)线性规划（过重）
2BK 作为初值良好起点，加速收敛随机初值（收敛慢）
3分层优先级硬约束不可违反加权求和（权重难调）
4后处理全部删除消除顺序耦合保留部分（复杂度高）
5Kernel 不接受 DiagramType语义解耦图类型分支（耦合）
6Recipe 是普通代码避免过度抽象动态插件（过重）
