## 0. 结论摘要（TL;DR）

布局/路由功能完整且经实战打磨，但有三类与手册失败模式同源的结构债：

1. **边几何多写者链**：router 内 ~10 段 + `pipeline.rs` 末尾 ~18 段，合计 **~25 个潜在写者位点**（多数边不会被每段改写）。缺少「字段最终写者」可验证声明，易出现「改了 X 结果没变 / 假修好」。
2. **障碍判定分裂（函数多份 + pad 语义不一）**：lint 已委托 `refine::segment_intersects_node`；真正问题是 router 热路径（`scoring` / `path_avoids_*` / `lane_assignment`）用 **`NODE_OBSTACLE_PAD=18`** 等另一套含入规则，导致「router 自认干净、lint 报穿模」。末尾 `repair_through_edges_post_route` 是此债的产物。
3. **常量与巨型文件物理债**：`EPS=0.1`、同值多名的 stub/pitch 常量散落；`two_phase.rs` / `run.rs` / `path.rs` 等承担过多职责。

**两条主线**：

- **主线 A（结构重构，不改观感）**：统一障碍 primitive（含 pad 契约）→ 收敛常量 → 轻量阶段写权表 → 收敛 gap/group_frame →（热点安静后）拆巨型文件。DoD：`node_fp` + collinear 不变。
- **主线 B（行为改动）**：穿障严重度（硬过滤保留 + 连续量排序）→ 通道占用度（先只读诊断，属候选架构）→ architecture pendant 前移评估。

**立刻开干**：`A2`（可并行）+ **`A1` 最小集**（scoring / path_avoids / lane → 与 lint 同语义）。**不要先拆 `run.rs`（A4）**。

> **2026-07-19 收口注**：上句为开干时优先级；本轮已按 §9/§10 执行完毕并结案。勿把「立刻开干」当成仍待启动的任务列表。

### 1.5 已沉淀的正确性经验（并入本文，不再另立执行计划）

跨组走廊（federation 等）多轮试修回滚后的共识：

1. 根因常是 **走廊占用与后序 free-route 耦合**，不是「未开 strict」。

## 2. 技术债清单

### TD-1 ★ 多写者链缺少可验证的最终写者

- **证据**：§1.2–1.3；gap enforce 双次、sanitize 双次、group_frame 三入口。
- **后果**：局部修复被下游覆盖；末尾 enforce / repair 成「不信任上游」的补刀。
- **根因**：隐式调用链，无「谁最后写 points/labels/nodes」的静态声明。

### TD-2 ★ 障碍判定分裂：实现多份 + pad 语义不一

- **调用点（须统一委托 + 显式 pad）**：

| 位点 | 现状 |
|------|------|
| `lint` → `refine::segment_intersects_node` | **门禁真值**（全尺寸节点，跳过端点 stub 段） |
| `refine/geometry.rs` | lint / semantic_trunk / 部分 refine 共用 |
| `scoring::segment_intersects_node` + `path_is_clean` / `path_avoids_group_interiors` | router 热路径；`NODE_OBSTACLE_PAD=18` |
| `lane_assignment::segment_hits_node` | 自建 AABB + pad |
| `route_annotation` / `visibility` / `border_shell` / `label_avoidance` | 各自实现或不同 pad |
| `obstacle_check` | 仅曲线路由；正交/lint 不走 |

- **后果**：router clean ≠ lint through；调一处阈值不同步。
- **根因**：无单一 primitive；**pad / skip_stub / 边界含入未参数化成契约**。只合并函数名、不统一 pad，TD-2 不消失。
- **补充（实证）**：分歧分两层——(1) **节点级** router wrapper 已等价（`scoring::segment_intersects_node` ≡ `lane_assignment::segment_hits_node` 内层 = `Rect::expanded(pad).segment_crosses_interior(a,b,EPS)`），差异只在 pad；(2) **分组级是真算法分歧**：lint 用**段中点落域**（`lint/mod.rs:502` `point_in_rect_interior(mid,…)`），router 用**线段穿内部**（`scoring.rs:301` `segment_crosses_interior`）——非 pad 可调和，须作行为改动（B1）处理。`route_annotation::segment_intersects_node`（`:231`）是**另一套手写 AABB**，语义待核。

### TD-3 ○ 常量重复与同值多名

- `EPS=0.1`（8+）；`16.0`（PORT_CLEARANCE / PORT_STUB_CLEARANCE / ORTHOGONAL_STUB / COMPACT_SLOT_PITCH）；`24.0`（双份 STUB_GUARD_LENGTH / DEFAULT_STUB_LEN / REVERSE_STUB_THRESHOLD）。
- 同值未必同语义——合并前确认，独立语义保留命名并交叉注释（手册：勿误合并）。

### TD-4 ○ 巨型多职责文件

- `two_phase.rs` / `run.rs` 混装编排与实现；定位与 review 成本高。

### TD-5 ○ gap / group_frame 写权分散

- C 预修 + D 审计；group_frame refresh / restore / recompute 时序敏感。

## 3. 主线 A：结构重构（不改观感）

> 每步单独提交。DoD = **`node_fingerprint` 不变 + `compare-collinear` PASS**。fp/严重度变化 ⇒ 拆出为行为改动并显式说明。

### A1 ★ 统一障碍 primitive + pad 契约 —— 解 TD-2（最高 ROI）

**API 方向**（新建 `edge/common/geom_obstacle.rs` 或扩充现有模块）：

```rust
pub fn segment_hits_rect(a: Point, b: Point, rect: Rect, pad: f64) -> bool;

/// lint 门禁语义：全尺寸节点、跳过端点 stub 段
pub fn polyline_pierces_node_lint(pts: &[Point], nl: &NodeLayout) -> bool;

/// router 避障语义：显式 pad（当前默认 18），不得偷偷改 lint 语义
pub fn polyline_pierces_node_routed(pts: &[Point], nl: &NodeLayout, pad: f64) -> bool;

pub fn polyline_crosses_group_interior(...) -> bool; // 与 lint 同函数、同含入规则
```

**替换顺序（最小集优先）**：

1. 抽取 primitive，**精确复刻当前 lint / refine 语义**（门禁真值）。
2. 委托：`scoring` / `path_is_clean` / `path_avoids_group_interiors` / `lane_assignment`（router 热路径）。
3. 再委托：`route_annotation`、`visibility`、`border_shell`、`label_avoidance`。
4. 每替换一处：`node_fp` + collinear。若 fp 变 ⇒ **不在 A1 修行为**，记入 B1。

**A1 DoD 增量**：抽样或全量对比——同一条边上 `path_avoids_*` / `path_is_clean` 与 lint `edge_through_node` / `edge_crosses_group_interior` 的一致率有记录（即使暂时仍因 pad 故意不同，也须在注释/契约里写明「为何不同、何时应对齐」）。

**一致率笔记须区分两类因（关键）**：

- (a) **同一几何下的判定差异**（pad / 含入规则 / 分组中点-vs-线段穿越）——A1 统一 primitive / B1 统一分组算法可解。
- (b) **几何被 router 校验后又被后续阶段改写**导致的差异（TD-1：snap/repulse/sanitize/enforce/dock/repair）——router 打分时的折线 ≠ lint 最终看到的折线，A1 **救不了**。

**A1 单独是必要非充分**：真正闭环需配合 **A3 折线冻结点**（step 16 后）用 lint primitive 做**唯一一次复校**，`repair_through_edges_post_route` 收敛为该复校的唯一响应写者。量一致率若不分 (a)/(b)，会把两种因混谈。

### A2 收敛几何常量 —— 解 TD-3（可与 A1 并行）

语义分层示例（非强制合并同值）：

```rust
pub mod geom_eps {
    pub const COLLINEAR: f64 = 0.1;
    pub const OVERLAP: f64 = 0.5;
    pub const BORDER: f64 = 2.0;
}
pub mod stub {
    pub const PORT_CLEARANCE: f64 = 16.0;
    pub const GUARD_LENGTH: f64 = 24.0;
    pub const REVERSE_THRESHOLD: f64 = 24.0; // 若语义独立：保留名 + 交叉注释
}
pub mod slot {
    pub const ORTHO_PITCH: f64 = 40.0;
    pub const COMPACT_PITCH: f64 = 16.0; // 与 PORT_CLEARANCE 同值≠同义
}
```

### A3 轻量阶段写权表 —— 解 TD-1（禁止空壳契约）

**做**：在 `run_routing_pipeline`（及 router 总控）旁增加**声明式阶段注释/表**（或极薄的 `EdgeStage { name, writes }` 调度，**顺序与效果不变**），使「谁写 points/labels/nodes/annotation」可被列出（可进 perf log / `--dump-edge-stages`）。

**不做**：新建庞大的 `EdgeGeometryContract` 类型体系、也不在重构阶段重排阶段。

**「几何冻结」含义（写清，避免假屏障）**：

| 屏障 | 位置 | 之后允许 |
|------|------|----------|
| **节点冻结** | step 10 之后（reroute 完成） | 禁止再为 pendant/对称挪节点（debug_assert） |
| **折线冻结** | step 16 `repair_through` **之后** | 只允许 label / annotation / **幂等校验**（发现仍需大改 ⇒ warning，视为上游 bug） |

snap 之后、repair 之前仍会改 points——这是现状，A3 **承认**它，不假装 snap 后已冻结折线。

### A4 拆巨型文件 —— 解 TD-4（**后置**）

- `run.rs` → 总控 + `phases/*`（原样搬迁）。
- `two_phase.rs` → 编排 + macro_block / intra / super_graph（子系统内拆分；**勿**与 sugiyama coordinate 字节合并）。
- **时机**：A1/A2 与穿模相关行为稳定后；避免与正确性热点抢同一文件。

### A5 收敛 gap / group_frame —— 解 TD-5（依赖 A3）

- D 审计目标：**幂等校验**；若仍需大改几何 ⇒ 记 warning（预修 bug），默认不再静默第二版大改（若现状 D 必须改几何，先量测再收紧）。
- `group_frame` 三入口收进单一状态机（refresh → restore/recompute），`track:equal` 分支内聚。

## 4. 主线 B：算法微调 + 指标

> 行为改动。DoD：手册 §1.3 + 契约 C4 两轨（正确性轨 FAIL 不得宣称完成）。禁图名特判。

### B1 ★ 穿障严重度（建立在 A1 之上）

```rust
pub struct PierceSeverity {
    pub node_pierce: f64,   // Σ 深度×长度
    pub group_pierce: f64,
}
pub fn edge_pierce_severity(...) -> PierceSeverity;
```

**硬边界（防假修好）**：

- `strict_group_transit` / 穿组：**保留布尔硬过滤**（P1：不穿组 ≫ 不穿节点）。
- `pierce_severity`：**只用于**（1）已过硬过滤的候选排序；（2）无法全 clean 时选最浅并 **显式 degraded**；（3）门禁用严重度谈退化，替代「只数 violation」。
- **禁止**用连续罚分整体替换穿组硬过滤。

### B2 ○ 通道占用度（候选架构，非唯一正解）

- **动机**：全局改主链几何易在 federation 连坐；缺通道容量/占用的显式模型。
- **设计**：路由前构建 channel/corridor 占用图（扩展 `edge_band_demand`）；建廊剪枝与 free-route **读同一张图**。
- **落地**：须 A1+B1 完成后；**先只读诊断**（预测失容量边 ↔ 实际回归对照）再接入决策。
- **同时保留更局部的切口**：例如只对**当前 lint 穿组边**在 refine 前试 clean 两跳——不必等完整占用图。

### B3 ○ Architecture pendant 前移（评估项）

- 现状：`align_cross_scope_pendant_chains` 在路由后 step 8；与手册「路由后勿挪节点补 pendant」有张力。
- L2 已用局部刚体重申收敛质心；**全量 route 前重放 align 曾 FAIL**。
- **建议**：评估「路由前对齐 + 路由后只检测/Skip」，单独验证 architecture 全量；依赖 A3 节点冻结断言。
