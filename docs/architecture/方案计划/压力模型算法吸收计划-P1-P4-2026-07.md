## 0. TL;DR

压力层已具备「特征 → score → dump / budget」骨架。下一步不是再拆模块，而是按优先级挂四类算法：

| 编号 | 名称 | 本质 | 主要消费面 |
|------|------|------|------------|
| **P1** | 障碍穿透 proxy | 预路由只读特征 | `EdgeFeatures` → score / 加缝·侧廊偏好 |
| **P2** | D5 廊级 soft 进打分 | 统一 load/capacity + **pitch 单源** | `channel_load` / orthogonal scoring |
| **P3** | 粗网格 congestion | 新 `GridDemand` | score / 扩后的 `enrich_from_pressure` |
| **P4** | DifficultyProfile 校准管线 | 观测→调权 + **量纲归一化** | α…ζ / profile 版本化 |

推荐执行序：**P1（观测）→ P4（校准基线）→ P2（路由消费）→ P3（网格）→ 再开行为开关**。  
P4 可与 P1 并行（先有 dump 字段即可校准）。

```text
layout/demand
  band / corridor / port / pierce(P1) / grid(P3)
           │
           ▼
     EdgeFeatures + score(DifficultyProfile←P4，须归一化)
           │
     ┌─────┼──────────────┐
     ▼     ▼              ▼
  SpaceBudget*  scoring(P2)   dump / congestion / eval
  * 行为步须扩签名吃边级特征（见 §2.4 / §4.4）
```

## 1. 非目标（四项共用）

- 不在布局热路径调用完整 orthogonal / visibility / A\*。  
- 不维护第二套与 `CorridorDemand` 冲突的 capacity 公式。  
- 不把边级 predicted / 高分边直接当硬门禁（廊级 soft、加缝 soft）。  
- 不把校准做成图名特判表。  
- 不借本计划重排 `pipeline` 写权或拆 `run.rs`。  
- **不做**「AABB×节点」与「线段×节点」混称为同一 primitive（见 §2.2 定死语义）。

## 2. P1 — 障碍穿透 proxy（预路由）

### 2.1 动机

真路由前估计绕行压力，补 `EdgeFeatures` 里偏弱的「几何阻挡」维（span / 廊 / band 对「中间挡了一排盒子」不敏感）。

### 2.2 算法定义（v1 · **已定死**）

> **审计修正**：原稿「AABB 重叠 + 委托 `segment_intersects_node`」自相矛盾——仓库只有**线段×节点/组** primitive，没有 AABB×节点可委托。  
> **v1 定死为：最短正交两段骨架（L）+ 线段 primitive**（天然过渡到 P3 栅格化）。

对每条边 `(from, to)`（无折线）：

1. 取两端中心（v1；日后可改为 stub 外一点）。  
2. 生成**两条候选 L 骨架**（先水平后竖直 / 先竖直后水平）；每条骨架 = 两段正交折线。  
3. 对每段调用既有线段障碍 API（**禁止**再实现一套 AABB 重叠当 pierce）：  
   - 节点：`refine::segment_intersects_node`（或与 lint 同语义的委托入口；pad 与门禁对齐须显式）  
   - 组（可选 v1.1）：`segment_pierces_group_interior` 同类  
4. 统计**非端点**命中：`obstacle_hits = max(两候选骨架各自 hits)` 或取更干净候选的 hits（实现时定一种并单测钉死）。  
5. 写入 `EdgeFeatures.obstacle_hits`（可选拆 `node_hits` / `group_hits`）。  
6. score：`ε · obstacle_hits`（默认 ε=1；进 `DifficultyProfile`；**计数维**，须经 §7 归一化后再与 px 维混加）。

**不做 v1**：整框 AABB×节点重叠统计（若将来要做，须单独立项为 `rect_overlap` 特征，**不得**伪装成委托线段 pierce）。

**复杂度**：O(E·N) 量级；可用 spatial grid。perf 日志须用 `layout::perf::Instant`。

### 2.3 落点

| 项 | 路径 |
|----|------|
| 实现 | `layout/demand/pierce.rs`（新建） |
| 特征 | `EdgeFeatures` 扩字段；`collect_edge_features` 填充 |
| 障碍语义 | **仅**委托线段×节点/组 primitive；禁止本地抄 AABB 重叠当 pierce |
| dump | 既有 `PLOTGRAM_DUMP_*` 打出 hits |

### 2.4 分阶段

| 步 | 内容 | 写权 |
|----|------|------|
| P1.0 | 只读特征 + dump + congestion 摘要；**不**调用 `enrich_from_pressure` | 无 |
| P1.1 | score 含 ε·hits（归一化后）；对照真路由 bends/degraded | 无 |
| P1.2 | 高 hits → 软加缝 / 侧廊偏好 | **须扩写权出口**（见下） |

**P1.2 写权（结构改动，非「直接复用」）**  
现状 [`SpaceBudget::enrich_from_pressure`](../../../crates/plotgram-core/src/layout/space_budget.rs) 签名仅：

```text
enrich_from_pressure(diagram, nodes, corridor: &CorridorModel, bands: &[BandDemand])
```

**吃不下**边级 `obstacle_hits`。P1.2 必须二选一并写进 commit：

1. **扩签名**（推荐）：增加 `edge_features: &[EdgeFeatures]`（或瘦身后的边级压力切片），按高 hits 边抬相关 pair / 竖缝；或  
2. **新出口**：如 `enrich_from_edge_pressure(&mut self, …)`，由 `apply_pre_route` 显式调用。  

禁止在方案措辞上假装「现有 enrich 已能消费边级特征」。

### 2.5 DoD

- 固定小图：L 骨架穿过 1 个中间节点时 `obstacle_hits≥1`，无挡时为 0。  
- P1.0/P1.1：`node_fp` 不变——**显式约束：未接 enrich / 未改节点坐标**。  
- P1.2：全量严重度可解释；可用与 `PLOTGRAM_PRESSURE_BUDGET` 同类开关关闭。

### 2.6 风险

- 两候选 L 取 max 可能偏高估 → 单测 + P4 校准 ε。  
- pad 与 lint 不一致 → 只委托统一入口，禁止 scoring 私有 pad 副本渗入 demand。

## 3. P2 — D5：廊级 soft 进打分

### 3.1 动机

母方案后置 **D5**：已有 `CorridorDemand{load,capacity,gap}`，路由侧仍用 [`channel_load.rs`](../../../crates/plotgram-core/src/layout/edge/edge_routing_orthogonal/channel_load.rs) 自建 `ChannelLoadMap`。两套「通道挤不挤」并存，易漂移。

目标：**打分读同一廊级 load/capacity（或由其投影）**，软惩罚，不做全局建廊剪枝连坐。

### 3.2 对齐策略（已拍板）

1. **权威容量**：B2 / `demand::corridor` 的 v1（`floor(gap / CORRIDOR_LANE_PITCH)`，DEGEN 规则不变）。  
2. **ChannelLoadMap**：  
   - 短期：保留段级 map 作细粒度，penalty 增加「路径所经廊若 OVER 则额外罚」；数据来自注入的 `&[CorridorDemand]` / `CorridorModel`。  
   - 中期：廊级 capacity 不再在别处发明；段级 map 只表示瞬时几何拥挤。  
3. **lane pitch 单源（现状未达成 → P2.0 前置）**  
   仓库已有至少三份 `18.0`，**不是**「防止第三份」而是「先收敛」：  
   - `demand/corridor.rs`：`CORRIDOR_LANE_PITCH`（名义源，`demand` 再导出）  
   - `orthogonal/corridor_route.rs`：本地 `const CORRIDOR_LANE_PITCH = 18.0`  
   - `node/common/edge_gutter.rs`：本地 `LANE_PITCH = 18.0`  
   **P2.0 显式前置步骤**：上述两处改为 `use crate::layout::demand::CORRIDOR_LANE_PITCH`（或 `pub use` 再导出），删本地字面量；再谈「禁止新增第四份」。

### 3.3 落点

| 项 | 路径 |
|----|------|
| 模型 | 已有 `demand/corridor.rs` |
| 注入 | `OrthoRoutingContext` 增加 `corridor_demands: Option<&[CorridorDemand]>` |
| **注入方式** | **仿 `with_corridor_boost`：加 `with_corridor_demands(...)` builder**；**禁止**改 `OrthoRoutingContext::new` 签名连坐 trunk/refine/build/stub_fix 等调用点 |
| 打分 | `scoring` / `channel_load_penalty` 增加廊 OVER soft 项 |
| 构建时机 | pre-route 或 router 入口算一次 `CorridorModel`，禁每候选全量重建 |

### 3.4 分阶段

| 步 | 内容 | 行为 |
|----|------|------|
| P2.0a | **收敛三份 18 → `demand::CORRIDOR_LANE_PITCH`** | 观感目标：不变 |
| P2.0b | `with_corridor_demands` + dump 对照「段负载 vs 廊 OVER」 | 无观感变化 |
| P2.1 | OVER 廊路径 soft penalty；权重进 profile | 软；可关 |
| P2.2 | （可选）建廊/选侧偏好读 overflow；仍禁全局剪枝连坐 | 局部 |

### 3.5 DoD

- P2.0a：`rg '18\.0'` 在廊/gutter 相关路径无第三套本地 pitch（允许注释引用）。  
- P2.0b：tenant / multi-ns 廊 OVER 与 B2 dump 一致；**未接 enrich** → `node_fp` 不变。  
- P2.1：穿组/through 不升或可解释；仅打分不改节点时 `node_fp` 不变。  
- 无边级 predicted 硬失败。

### 3.6 风险

- 双重惩罚（段 map + 廊 OVER）过猛 → 分项可关；先 P2.0 对表再开 P2.1。  
- 每候选重建廊模型 → 必须缓存于 context。

## 4. P3 — 粗网格 congestion（GridDemand）

### 4.1 动机

Band/廊是「拓扑通道」视角；粗网格是「画布流量」视角。把每条边投到最短正交骨架上累加 cell 流量，得热点区。

### 4.2 算法定义（v1）

1. 画布按固定 **grid pitch** 划格。  
   - **默认独立常量**（建议 `GRID_DEMAND_PITCH = 40.0`），**不与** slot pitch 强耦合。  
   - 代码中槽位常量名为 [`ORTHO_SLOT_PITCH`](../../../crates/plotgram-core/src/layout/constants.rs)（=40），**不存在** `ORTHO_PITCH`；若刻意对齐，写清「数值对齐 `ORTHO_SLOT_PITCH`，语义仍是 grid pitch」。  
2. 每边生成 1～2 条候选正交骨架（与 P1 L 骨架可共享构造；无障碍绕行）。  
3. 沿骨架栅格化，`cell.load += 1`（确定性边序）。  
4. 输出 `GridDemand` + 边级 `grid_overflow` → `EdgeFeatures`。  
5. score：`ζ · grid_overflow`（计数维，须归一化）；行为步见 §4.4。

perf / 栅格化计时：仅用 `layout::perf::Instant`。

### 4.3 落点

| 项 | 路径 |
|----|------|
| 实现 | `layout/demand/grid.rs` |
| 类型 | `GridDemand` / `GridCellKey` |
| 消费 | `score`；行为步扩 `enrich_*`（同 P1.2） |
| dump | `PLOTGRAM_DUMP_GRID_DEMAND=1` |

### 4.4 分阶段

| 步 | 内容 |
|----|------|
| P3.0 | 只读 GridDemand + dump；**不**接 enrich；与真路由拥堵区对照 |
| P3.1 | 进 score（ζ，归一化后）；进 congestion metrics |
| P3.2 | 热点加缝：与 P1.2 **同一写权扩签名策略**（`enrich_from_pressure` 增 `edge_features` / 或 `enrich_from_edge_pressure`） |

### 4.5 DoD

- 确定性：同输入 grid load 指纹稳定。  
- P3.0/P3.1：`node_fp` 不变（**未接 enrich**）。  
- 不与廊 capacity 抢权威：网格是互补信号。

### 4.6 风险

- pitch 过细/过粗 → 先固定 40 + showcase 扫。  
- 骨架无绕障 → 与 P1 互补，勿单独预测外廊。

## 5. P4 — DifficultyProfile 校准管线

### 5.1 动机

α…ζ 结构可扩，缺的是用真路由质量反标定。  
**一等公民（审计）**：校准前必须处理 **score 量纲统一**——现状 `score_edge` 对 `band_deficit`（像素）与 `corridor_overflow`（边计数）做裸 `max`，母方案要求 overflow **归一化**后进 γ；P1/P3 再叠加计数维会加重错配。P4 校的是权重，不能在错配量纲上拟合。

### 5.2 管线定义

```text
showcase 集
  → compute_layout（默认 PRESSURE_BUDGET=0 以便纯观测）
  → 特征归一化（§7）→ PressureSnapshot（score）
  → 真路由后指标：bends / degraded / through / group_interior / lint severity
  → 对齐表：高分位边 vs 高代价边（Spearman / top-k hit rate）
  → 建议权重（人工确认后改 DifficultyProfile 默认值）
```

### 5.3 落点

| 项 | 决定 |
|----|------|
| CLI / bin | **默认扩**现有 `congestion-baseline` + `benchmark-data/congestion-set.txt`；**备选**再建 `demand-calibrate`（仅当扩现有 diff 过大） |
| 输出 | JSON：每图 top-k、相关、分位、量纲说明；可选建议 `(α…ζ)` |
| 配置 | `DifficultyProfile` 版本注释；**不**自动写回无审参数 |
| 单测 | 扩 ε/ζ 后须改 `score_weights_default`（现硬编码期望 18.0） |

### 5.4 分阶段

| 步 | 内容 |
|----|------|
| P4.0a | **归一化落地**：`corridor_overflow_norm` 等（见 §7）；dump 同时打原始量与归一化量 |
| P4.0b | 导出「score 分位 × 路由代价」表；无调参 |
| P4.1 | 报告建议权重；文档记一次人工采纳 |
| P4.2 | CI 可选：相关低于阈值 warning（默认不 fail 全量） |

### 5.5 DoD

- 一键对固定 set 出 JSON，可复现。  
- 调参须附前后相关 + 量纲说明；禁止「只改观感」。  
- 标定模式注明 `PRESSURE_BUDGET=0`（或等价）。

### 5.6 风险

- 小样本过拟合 → 固定 set + 留一验证图。  
- 未归一化就调 α…ζ → **禁止**；P4.0a 为硬前置。

## 7. DifficultyProfile 与量纲（规划）

### 7.1 公式

```text
score =
  α·span_ranks
+ β·corridor_risk.as_weight()
+ γ·max(band_deficit_norm, corridor_overflow_norm)
+ δ·port_pressure_norm
+ ε·obstacle_hits_norm          // P1
+ ζ·grid_overflow_norm          // P3
```

**归一化（P4.0a 定稿一种并单测）**建议起步：

| 原始量 | 量纲 | 建议 norm |
|--------|------|-----------|
| `band_deficit` | px | `min(1, deficit / ref_px)`，`ref_px` 取 profile.max_extra 或 48 |
| `corridor_overflow` | 边数 | `min(1, overflow / ref_edges)`，`ref_edges` 如 4 |
| `port_pressure` | 计数 | `min(1, count / ref_port)`，如 4 |
| `obstacle_hits` | 计数 | `min(1, hits / ref_hits)`，如 3 |
| `grid_overflow` | 计数 | `min(1, ov / ref_grid)`，如 3 |
| `span_ranks` | 层数 | 可保持原值或 `/ ref_span` |

现状代码 `band_deficit.max(corridor_overflow)` **裸混 px 与计数**——P4.0a 必须改掉，再谈调权。

### 7.2 默认权重与测试

- 字段：现仅 α/β/γ/δ；P1/P3 增加 `epsilon` / `zeta`，更新 `Default` 与 **`score_weights_default` 单测**（勿再硬编码仅四维时期望值 18.0 而不改断言）。  
- 默认：α=1, β=2, γ=1, δ=1, ε=1, ζ=1；以 P4.1 校准后替换并记纪要。

## 11. 成功标准（本计划）

- 四类算法均挂在 `layout/demand`（或 scoring 只读注入），无平行公式岛。
