## 0. TL;DR

行业惯用「先节点布局、后边路由」。布局阶段需要的不是提前跑真路由，而是 **O(E log E)～O(E·k) 的压力 / 难度代理（proxy）**，用来指导加缝、排序加权、端口偏好。

仓库里相关能力**已经存在但分散**：`edge_band_demand`、`SpaceBudget`、`estimate_layer_band_demands`、`crossings`、`channel_occupancy`（B2）、`channel_load`、stub occupancy / congestion metrics。问题不是缺算法，而是 **同一类「几何压力」没有单一语义源**，易继续打补丁。

本方案目标：**收缩与复用**——统一只读压力模型，把建议中的 `EdgeDifficulty` 做成该模型上的加权读出；布局 / 路由打分 / 诊断 / eval **共用同一套数字**。不新建第二套管线。

## 1. 问题与动机

### 1.1 现状碎片

| 能力 | 落点（当前） | 角色 | 写权 |
|------|--------------|------|------|
| 邻层边带 demand | `edge_band_demand.rs` | 布局阶段算 demand → 加缝 | 布局写 gap |
| 空间契约 | `space_budget.rs` + `route_feedback` | pair_gaps / port_clearance / pre-route | 布局 + guard |
| 层带 deficit 诊断 | `stub_occupancy::estimate_layer_band_demands` | demand vs face_gap | **只读**（公式与上者双轨） |
| 层内交叉 | `node/common/crossings.rs` | Sugiyama / arch 排序 | 不写几何 |
| 走廊 load/capacity | `channel_occupancy.rs`（B2） | 跨 leaf 廊级占用；路由后对照 lint | **只读**；尚未反哺布局 |
| 通道负载惩罚 | `orthogonal/channel_load.rs` | 路由候选打分 | 路由软约束 |
| 端口 stub 压力 | stub occupancy + `metrics/congestion` | 冲突诊断 / 门禁样本 | 路由后为主 |

### 1.2 双轨与补丁风险

1. **demand 公式双轨**：布局走完整 `EdgeBandDemandProfile`；诊断 `estimate_layer_band_demands` 内联粗公式（`parallel_scale=0.5` 等），数字不可直接对照。  
2. **B2 与加缝脱节**：廊级 `load/capacity/gap` 已可决策，却只在折线冻结后 dump；布局加缝仍主要看邻层 band / label pair。  
3. **边级难度无统一读出**：长跨度、跨组、超容、端口拥挤散落在各启发里，无法在排序 / 候选评估中廉价复用。

### 1.3 非目标（明确不做）

- 不在布局热路径调用完整 orthogonal / visibility 路由。  
- 不新建「智能布局总调度」或空壳几何契约类型体系。  
- 不借本方案重排 `pipeline` 写权链 / 拆 `run.rs`（属重构方案后置 A4）。  
- 不把 crossings 并进 `SpaceBudget`（维度不同：序 vs 缝）。  
- 不把 B2 边级 `predicted` 扇出直接当硬门禁（见 B2 笔记：廊级 OVER ≠ 必穿组）。

## 2. 目标架构

### 2.1 一句话

**一个只读压力层，多种消费面；`EdgeDifficulty` 是加权视图，不是第五套算法。**

```text
┌──────────────────────────────────────────────────────────┐
│  layout/demand（建议模块名；也可扩现有 edge_band_demand）   │
│                                                          │
│  BandDemand      load / gap|capacity / deficit           │
│  CorridorDemand  load / capacity / gap / span（≈ B2）    │
│  PortPressure    (node, side) → count                    │
│  EdgeFeatures    span_ranks, cross_group, …              │
│  score(edge)     α·span + β·cross + γ·deficit + δ·port   │
└───────────────────────────┬──────────────────────────────┘
                            │ 同一套数字
          ┌─────────────────┼─────────────────┐
          ▼                 ▼                 ▼
     布局启发            路由打分           诊断 / eval
  SpaceBudget 加缝    channel_load 软惩罚   congestion dump
  排序加权 / 端口偏好   （已有钩子）         B2 报告 / 门禁
          │
          ▼
   pipeline 写权链（唯一改节点/折线处）
```

### 2.2 设计原则

| # | 原则 |
|---|------|
| 1 | **公式单源**：邻层 demand 只由 `edge_band_demand`（或迁入后的 `demand`）计算；诊断只算 gap → deficit。 |
| 2 | **类型同构**：`CorridorDemand` 与 B2 `CorridorOccupancy` 字段对齐，避免「诊断一套、决策一套」。 |
| 3 | **只读模型不改几何**：压力层纯函数；改缝 / 挪点仍走 `SpaceBudget` / guard / 既有 router。 |
| 4 | **先观测、后决策**：`score` 与廊级超容先挂 dump / metrics，校准后再接入布局加权。 |
| 5 | **确定性**：聚合与边枚举显式排序（`AGENTS.md` §2）。 |
| 6 | **小步收缩**：优先委托与类型对齐，后移文件；热点安静前不拆 `run.rs`。 |

### 2.3 `EdgeDifficulty` 定义

边级特征（布局坐标已有、折线可无）：

```text
EdgeFeatures {
  span_ranks:        |rank(u) - rank(v)|          // 唯一需统一导出的小字段
  crosses_groups:    0|1 或廊链风险档              // 复用 B2 leaf / 链判断
  band_deficit:      边所跨邻层缝的 deficit        // 来自 BandDemand
  corridor_overflow: max(0, load - capacity) 沿链  // 来自 CorridorDemand
  port_pressure:     max(from_side_count, to_side_count)  // stub / 度数代理
}

score = α·span_ranks
      + β·crosses_groups（或廊风险）
      + γ·max(band_deficit, corridor_overflow 归一化)
      + δ·port_pressure
```

说明：

- **γ 项直接复用已有 deficit / load−capacity**，禁止再写第三套「通道不够」公式。  
- **β 优先用廊级信号**（有链但 OVER / 无链），与 B2 笔记一致；勿把边级 predicted 当硬门。  
- **α…δ 先常量、可 profile 化**；用 showcase 上 `score` 分位 vs 实际 bends / degraded / 穿组做校准，不凭观感调参。  
- crossings 可作为可选 **ε·layer_crossings_near_edge**，默认不进 v1，以免与排序目标纠缠。

## 3. 与现有模块的映射（收缩清单）

| 现有 | 收缩动作 |
|------|----------|
| `edge_band_demand` | **保留为 demand 公式权威**（或整文件迁入 `layout/demand/band.rs`，对外 API 稳定或再导出）。 |
| `SpaceBudget` / `enrich_adjacent_rank_demand` | **继续作为布局写权出口**；内部只消费 `BandDemand`，不内联第二套 demand。 |
| `estimate_layer_band_demands` | **改为委托** `edge_band_demand` 算 demand，本函数只聚类层 + face_gap + deficit；删除内联粗 profile。 |
| `channel_occupancy` | **拆「模型」与「报告」**：廊 load/capacity 计算可在节点已定位、折线未出时调用；报告仍路由后对照 lint。 |
| `channel_load` | 路由侧消费；能读同一 `CorridorDemand` / 粗网格时再对齐，**不强制首刀合并实现**。 |
| `crossings` | **保持独立**；排序继续用；不进 SpaceBudget。 |
| `metrics/congestion` | 增加 `score` 分位 / 高分边计数等样本字段，便于校准与回归。 |
| stub occupancy | 提供 `PortPressure` 聚合 API（按 node+side 计数）；去冲突逻辑仍留在 orthogonal。 |

## 4. 分阶段落地

### D0 — 文档与口径冻结（本文）

- 冻结：demand 单源、B2 廊级可前移、Difficulty = 加权视图、非目标列表。  
- DoD：本文合入；手册 / 重构方案后置项可链到本文（执行时再改交叉引用）。

### D1 — 消 demand 双轨（结构，观感目标：不变）

**做**：

1. `estimate_layer_band_demands` 对每一邻层调用 `edge_band_demand`（传入该层 upper/lower id 与完整或诊断用 profile）。  
2. 统一 `LayerBandDemand` 与 `EdgeBandDemandBreakdown` 可对照字段（`crossing_edges` / `demand` / `deficit`）。  
3. 单测：固定小图上 demand 与布局侧一致（允许诊断 profile 显式参数化，但禁止再内联魔法系数）。

**不做**：改 `SpaceBudget` 加缝量；不改 router。

**DoD**：`node_fp` 不变；congestion 样本中 `max_layer_deficit` 若变动须说明是「诊断对齐」并更新基线注释。

### D2 — 压力类型与边特征（只读）

**做**：

1. 引入（或扩模块）共享类型：`BandDemand`、`CorridorDemand`、`PortPressure`、`EdgeFeatures`。  
2. 从现有 rank / leaf-group / B2 廊图复用逻辑，实现 `collect_edge_features(diagram, nodes, ranks, …)`（**无折线**）。  
3. 实现 `score(features, weights) -> f64`；`PLOTGRAM_DUMP_EDGE_DIFFICULTY=1` 或并入既有 dump 开关。  
4. `compute_congestion_sample_metrics` 增加只读摘要（如 top-k score、超容廊数）。

**不做**：用 score 改 gap / 改序 / 改端口。

**DoD**：architecture / flowchart 若干 showcase 可 dump；与 B2 廊级 OVER 同向相关（人工抽检即可）。

### D3 — B2 模型前移（pre-route 只读评分）

**做**：

1. 将「廊邻接 + load/capacity」提取为可在 **节点布局完成、路由前** 调用的函数（输入：nodes + groups + relations；不依赖最终 polyline）。  
2. 路由后 `compute_channel_occupancy_report` 改为薄包装：同一模型 + lint 对照。  
3. pre-route dump：廊级 `load/capacity/gap` 与边 `score`。

**不做**：全局建廊剪枝连坐；边级 predicted 硬失败。

**DoD**：与现 B2 在「折线无关」字段上一致或可解释；手册写权不变。

### D4 — 布局消费（行为，小步）

仅在 D2/D3 校准后开启，按优先级择一接入（可并行但须分 commit）：

| 优先级 | 消费 | 写权出口 |
|--------|------|----------|
| P0 | 高 `band_deficit` / 廊 OVER → 加缝或抬 `pair_gaps` / 组间距 | 仅 `SpaceBudget` / 既有 band enrich |
| P1 | 高 `span_ranks` → 排序 / barycenter 已有长边加权的统一系数源 | sugiyama / arch order，禁图名 |
| P2 | 高 `port_pressure` → 出边侧偏好或同侧错开启发 | 端口/slot 阶段，不新开挪点环 |

**硬约束**：

- 候选若新制造节点碰撞 / 层缝破坏 → 回滚（手册 refine 法则）。  
- 全量严重度门禁：持平、可解释上升、或显式抬基线 + 残余样例。  
- 禁止「score 高就调用 router 试路由」。

**DoD**：目标图可解释改善；`node_fp` 仅预期节点动；契约正确性轨不回归。

### D5 — 路由侧对齐（可选后置）

- `channel_load_penalty` 与 `CorridorDemand` 口径对齐或共享 lane pitch（18）。  
- B2「决策软约束」：廊级 `load > capacity` 进打分 / 建廊候选（重构方案后置），**本方案 D4 加缝优先于剪枝**。

## 10. 开放决策（执行前可拍板）

1. **模块名**：新建 `layout/demand/` vs 扩 `edge_band_demand` + 再导出——偏好前者利于走廊/端口并列，后者 diff 更小。  
2. **rank 来源**：architecture 两阶段 vs sugiyama_v2 的 rank 表如何统一注入 `EdgeFeatures`（需一层薄 adapter，禁止两套 span 定义）。  
3. **α…δ 默认值**：首版可用整数权重（如 1, 2, 1, 1）仅排序相对大小；校准后再写入 `EdgeBandDemandProfile` 旁的 `DifficultyProfile`。  
4. **D4 第一刀**：建议只做 **P0 加缝**（与现 SpaceBudget 同构），端口与排序加权放后续。

## 11. 成功标准（方案级）

- 布局、诊断、B2 廊级、边难度评分对「通道够不够」说的是**同一套 load/demand/capacity**。  
- 新增启发优先**消费**压力层，而不是在 orthogonal / two_phase 里再抄公式。  
- `EdgeDifficulty` 可在路由前毫秒级计算，并经 dump 与真路由质量可对照。  
- 无第二套管线、无空壳契约、无图名特判。
