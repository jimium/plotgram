2本项目期望方案（规范性）

★ 产品规定（权威节）

本节定义 Plotgram 对共线 / 重叠 / 合流 / 箭头汇聚的期望边界。 后续算法、lint、基线、profile 均以本节为验收语言。实现细节可演进，不得违背允许/禁止边界。

2.1 产品定位声明

一句话：Plotgram 的「共线」是受控产品能力（端口汇聚 + 有界 trunk 共享），不是 bug，也不是默认墨水压缩。
维度本项目选择
产品身份可追溯边的正交图（Agent/架构/流程），不是「省墨海报」
合流哲学语义授权合流；禁止几何巧合冒充合流
端口哲学分级汇流 Single / Compact / Concentrate；合锚点不合边身份
分离哲学无授权 exact/tight → 必须可解释地分离或 Degraded
明确不做整边 concentrate；后置全文 bundling；图名特判；渲染反推语义

2.2 术语与分层

必须先分类再谈对错。是否允许重合 ← 语义；是否允许改折点 ← 改后是否守约束。

名称期望处置
表示冗余删除中点（等价变换）
微台阶 / overshoot有上下文才改；否则可暂留；禁无验证穿障
非语义重合NeedsSeparation；否则 Degraded(reason)
有意合流Allowed；须有区间端点与 fork/join 边界
端口汇聚按 DockingStrategy Allowed
T/L 接头通常 Allowed
正反向对始终 Forbid 共干；维持最小 gap
Allowed

有语义许可且在声明区间内。看起来「故意合在一起」。

NeedsSeparation

无许可或越界共干。最终应被推开；仍在则算缺陷或未收敛。

Degraded

空间不够无法干净分离。允许残余但必须带原因；禁止穿模换零重叠。

2.5 Trunk 共享授权（白名单）

同时满足才可 Allowed 共干：

  1. Profile 允许该种合流
  2. 共享有效组键：✅ FanOut / FanIn / ParallelPair；❌ SuperEdgePair 不授 trunk
  3. 重叠落在已声明共享区间内；越界立刻 Forbid
  4. 不是正反向对

2.8 非目标与反模式

禁止

整边 concentrate；后置 bundling；图名特判；渲染用点数猜 FanIn；无验证「为更直」穿障；共线计数归零当成功。

允许

有界语义合流；端口汇聚；合法单调台阶暂留；空间不够时显式 Degraded。

2.9 产品完成定义

  1. 任一 exact/tight trunk 可归为 Allowed / NeedsSeparation / Degraded，且依据可引用规则矩阵与白名单。
  2. 有意合流必有组键 + 共享区间；不存在「只有坐标相同」的 Allowed。
  3. 端口 4+ 呈 Concentrate（或显式关闭），边仍可区分。
  4. Flowchart 同源 fan-out 呈 trunk+fork；fork 后不再共干。
  5. Architecture 无关共干被分离或显式 Degraded。
  6. 正反向对始终分道（或 Degraded 有因）。
  7. 表示冗余已清理；改形状失败可回退；确定、无图名分支。
