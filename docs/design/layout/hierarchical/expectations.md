## 1. 主流程与层次

| 视觉期待 | 用户看见什么 | 主要写者 | 易冲突 |
|----------|--------------|----------|--------|
| **主轴顺流** | 多数箭头同一主方向，读图像顺着走 | Compose 层号 / 边反向 | 过多回边削弱顺流感 |
| **一层一排** | 同层大致成带，层次可读 | Compose 定序 + Metric 主轴 | 与「绝对等距」拉扯 |
| **主链中心共线** | 主链几何中心同一次轴线；扇出处不无故阶梯折 | Metric 次轴（§6.1） | 与扇出对称是**同一目标** |
| **主路径少折** | 关键路径少拐弯（尤其 critical） | Compose / Channel + Metric | 与「回边侧廊」抢走廊 |
| **声明靠前偏上游** | 先写的重要节点更靠起点一侧 | Compose 去环 / 定层 | — |

| 视觉期待 | 用户看见什么 | 主要写者 | 易冲突 |

| **组内成块** | 同组抱团，不与外组插队 | Compose + Metric 组框 | 与全局减交叉、全局对称 |

## 6. 已知视觉冲突（必须先裁定）

| 冲突 | 看起来像 | 当前裁定 |
|------|----------|----------|
| **平行折返** vs **回边侧绕** | 三层架构要平行；审批驳回要侧绕 | **有对向边的短折返 → 平行**；**跨列 / 短闭环（span=2）/ 跨组无对向 → 侧绕**；**同组共列长回边（span≥3 near-column）→ 主脊（用已有 dummy 列）** |
| **少交叉** vs **平行 / 对称** | 全侧绕交叉少但不好看 | 交叉不是唯一分数；代表图守平行与对称 |
| **平行绝对列** vs **同脸端口序** | twin 钉双极打乱同脸序 → 交叉 | 对齐**不得**打乱 Compose 相对序；触及脸由 PortLane **同一写者写完** |
| **图尽量窄** vs **分道 / 侧廊** | 多分道更清晰但更宽 | 清晰优先于极限压窄 |
| **作者钉侧** vs **全局更美** | 钉死局部别扭 | **作者胜** |

### 6.1 主链共线 ∩ 扇出对称

**裁定**：二者同一目标，不是二选一。Metric 用目标函数求次轴中心（默认 `λ_sym = 1.0`；多父折中）。算法与参数见 [symmetry-axis.md](phases/symmetry-axis.md)。

**用户应能指着说**

- 穿过扇结的主链与扇心在**同一条次轴线**；  
- 奇/偶扇都匀称；**上定心、下展叶**（禁止下游叶中点反拉上游汇入）；  
- **主臂 / 双胞胎占脊**，其余叶侧置（可单侧）；跨层直达支不抢主臂外廊；  
- 长边跨层仍算扇；**驳回回边不算另一把扇**；  
- 同脸扇出按远真实端层内序，不被 dummy order 打交叉。

**门禁（产品可读）**：主链共线（`flat-rest-api` / `constrain-flat-chain` / `order-approval`）；扇共轴（`smoke.multi-rank-backedge`）；twin 占脊（`mech.constrain-sink`）。

**废弃终态**：脊/扇产品二选一；对称寄生 BK 焊点；`deg≥2` 散落松开；约束循环 ad-hoc continue；恢复 `SymmetryPlan` 三张声明表。

### 6.2 平行走廊 vs 框内比例端口

**裁定**：请求–响应两端端口落在**同一世界坐标列**，**不依赖**全局 grid。共列 ≠ 强制 `axis ± pitch` 双极。PortLane 改写某脸时，该脸全部 along 由同一写者写完。细节见 [port-lanes.md](phases/port-lanes.md)。

**用户应能指着说**：一去一回平行、横平竖直；twin 与扇叶共脸时走廊成块、扇叶在序外侧；不开 grid 也成立。

**废弃**：Ink 抹 Δx；仅靠 Ordered 比例作平行终态；绑死「必须开 grid」；强制中轴双极打乱同脸序。

## 7. Weak vs Strong：组策略选型（`group_policy`）

组（group）在两条路径下语义不同，作者按图的诉求显式声明 `layout: hierarchical { group_policy: ... }`（缺省 = `weak`）：

| 诉求 | 选型 | 理由 |
|------|------|------|
| 密边、弯多、扇出扇入重的流程图 | `weak`（默认） | 软聚类 + D₁ 走廊；框由 Metric Fit 写真源（D₂ 已落地），不与 Strong 舞台争语义 |
| Weak 下组框合法性可证（不穿组、兄弟分隔） | `weak`（**D₂ 已关闭**） | 框进 Metric + sibling 硬分隔 + 穿组硬门禁；存量穿组见 C 类 `d2-exempt`（[group-frame-d2](phases/group-frame-d2.md)）。**不是**再做 StrongMacro |
| 架构图舞台感：子系统严格分区、上下叠放同轴 | `strong-macro`（已落地） | 宏收缩：框由 MacroBlockWriter 一次写定；跨组边走行缝 demand + 行对齐（[strong-macro.md](phases/strong-macro.md)）。泳道/矩阵另属 PartitionGrid（[partition-grid](phases/partition-grid.md)），勿用 group 冒充 |
| 泳道 / 矩阵（全局列行、跨列 rank 对齐） | PartitionGrid（引擎消费进行中） | DSL `partition` + `cell_*`；方案 PG-0–PG-4；**禁止** group Horizontal 冒充 |

**用户应能指着说**：strong 图里每个子系统是一块独立舞台；weak 图里组跟着节点，但框包得住、兄弟不叠，穿组在回归里被硬拦（豁免须显式标注）。

**声明方式**：`group_policy` 由作者在 `layout:` 选项里显式给出（解析层 → params，禁引擎图种分支，ADR-001）。architecture profile 默认本轮**不**自动切 strong-macro：strong 语料尚小（6 张基准图），默认切换会把未充分验证的宏收缩行为推给全部 architecture 图；待语料与门禁覆盖更大后再评估（strong-macro.md §6 SM-4）。
