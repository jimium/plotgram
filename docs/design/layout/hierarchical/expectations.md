本文只列 **Hier 图在用户眼里应像什么**。  
每条期待附带：谁负责把自由度写对、和哪条视觉期待容易打架。  
**不**在此展开算法细节；细节见 `phases/`。

**用法**：改布局前先问「破坏了哪条视觉期待」；两条期待抢同一观感且未声明谁让步 → 先在本文写清，再动代码。

## 1. 主流程与层次

| 视觉期待 | 用户看见什么 | 主要写者 | 易冲突 |
|----------|--------------|----------|--------|
| **主轴顺流** | 大多数箭头沿同一主方向（上→下或左→右），读图像「顺着走」 | Compose 层号 / 边反向 | 过多回边会削弱顺流感 |
| **一层一排** | 同层节点大致对齐成带；层次一眼可读 | Compose 定序 + Metric 主轴 | 与「绝对等距美观」可能拉扯 |
| **主轴节点中心共线** | 主链上一串节点的**几何中心**落在同一条次轴线；扇出处也不打无故阶梯折 | Metric 次轴 · **对称轴**（见 §6.1） | 与扇出对称是**同一目标**，不是互斥 |
| **主路径少折** | 关键路径上的边少拐弯、少绕行（尤其 critical） | Compose 定序 / Channel + Metric | 与「回边躲开主路径」抢走廊 |
| **声明靠前偏上游** | 先写的重要节点更靠主方向起点一侧 | Compose 去环 / 定层 | — |

## 2. 对称与对齐

| 视觉期待 | 用户看见什么 | 主要写者 | 易冲突 |
|----------|--------------|----------|--------|
| **整体对称（含扇出）** | 扇出/汇入左右匀称；扇的「心」与穿过该结的主轴是**同一条次轴线** | Metric · SymmetryAxisWriter（轴 + 刚体列 + FanPack） | 减交叉、组块连续可能局部让步；对称可能略增图宽 |
| **扇出对称** | 一源多汇时孩子次轴匀称、镜像感 | Compose 定序 + Metric FanPack | 从属于整体对称 |
| **汇入对称** | 多源一汇时汇合前对称收束 | 同上 | 同上 |
| **对位整齐** | 有对应关系的节点在次轴上能对上 | Metric 对齐 / 端口沿边序 | 过强对位会挤歪其它枝 |
| **组内成块** | 同组成员视觉上抱团，不与外组交错插队 | Compose 组约束 + Metric 组框 | 与全局减交叉、全局对称 |

## 3. 边：平行、回绕、正交

| 视觉期待 | 用户看见什么 | 主要写者 | 易冲突 |
|----------|--------------|----------|--------|
| **请求–响应平行** | 同列一去一回走主轴两侧错开的平行线，而不是一侧大弯绕行；**不等宽节点上也不因端口比例展开打出层间小折** | Compose 端口侧（双胞胎短回边走脊）+ **Metric PortLane（绝对列）** | **与「回边走侧廊」直接冲突** → 见 §6；与「框内比例端口」冲突 → 见 §6.2 |
| **闭环走侧廊** | 驳回重提、跨多层跳回等从两侧绕，不压在主轴顶头互穿 | Compose 端口侧（长回边 / 无对边短回边） | 与平行期待分域 |
| **正交干净** | 边横平竖直，折点少、不无故蛇形 | Channel 拓扑 + Ink 展开 | 过窄缝逼出多余折 |
| **不穿节点** | 边不从节点框中间穿过 | Channel / Ink 出桩与避障 | 缝太窄时与「图不要太宽」冲突 |
| **多边不错叠** | 同走廊多条边能分清 | TrackOrder + Metric 轨坐标 | 分道会增加图宽 |
| **扇出可合流** | 打开自动合流时，同侧多线先合干再分叉 | Compose bundle / 端口合流 | 与「每条边独立平行」观感不同（由开关选择） |

## 4. 间距与体量

| 视觉期待 | 用户看见什么 | 主要写者 | 易冲突 |
|----------|--------------|----------|--------|
| **不挤不散** | 节点有呼吸感，但整图不无故拉得很扁或很宽 | Metric 缝宽 + Demand 下界 | 侧廊回边、多分道 → 变宽 |

## 6. 已知视觉冲突（必须先裁定）

| 冲突 | 看起来像 | 当前裁定 |
|------|----------|----------|
| **平行折返** vs **回边侧绕** | 三层架构要平行；审批驳回要侧绕 | **有对向边的短折返 → 平行**；**跨层 / 无对向的回路 → 侧绕** |
| **尽量少交叉** vs **平行 / 对称** | 全侧绕交叉少，但不好看 | 交叉不是唯一分数；代表图要守平行与对称 |
| **图尽量窄** vs **分道 / 侧廊** | 多分道更清晰但更宽 | 清晰优先于极限压窄；Demand 只抬必要层缝 |
| **作者钉侧** vs **全局更美** | 钉死会局部别扭 | **作者胜** |

### 6.1 主轴共线 ∩ 扇出对称 → 同一条对称轴

**裁定（终态）**：主轴共线与扇出居中**不是**二选一，也不是「只恢复奇偶 if」。  
采用 Metric 显式子步骤 **SymmetryAxisWriter**：一次产出 **对称轴**、必须跟轴共线的 **刚体列成员**、扇叶相对轴的 **FanPack 槽位**；VPSC 约束与 desired **只消费这三张表**。算法契约见 [symmetry-axis.md](phases/symmetry-axis.md)。

用户可见结果：

- 穿过扇出结的主链中心，与扇的几何中心，落在**同一条次轴线**；  
- 奇扇 / 偶扇都满足「整体对称」，差别只在轴怎么从孩子算出（中位 vs 两中位中点），不在「硬锁奇、软放偶」的散落特判；  
- `Gateway→API→Worker(扇)` 整段跟轴，不再出现「上两节共线、扇结独自偏心」的阶梯折；  
- 扇叶相对轴镜像铺开（FanPack 覆盖 BK ideal，终态扇心与脊共轴）；  
- **跨层分支也算扇**（决策菱形一臂跨多层仍要跟轴）；**驳回类回边不算另一把扇**（环头不因回路被扯歪）。

**已兑现（对产品读者）**

| | 用户能指着说 | 状态 |
|--|--------------|------|
| 主链无阶梯折 | 代表图主链中心共线 | **已门禁**（`flat-rest-api` / `constrain-flat-chain` / `order-approval`） |
| 扇心与主链共轴 | 扇的「心」与脊同一条次轴线 | **已门禁**（FanPack 闭包；`smoke.multi-rank-backedge`） |
| 扇叶匀称铺开 | 孩子们相对轴镜像铺开 | **已门禁**（同上） |

**明确废弃作为终态的做法**

| 废弃 | 原因 |
|------|------|
| 「脊优先 / 扇优先」产品二选一 | 假冲突；目标是共轴 |
| 把对称轴寄生在 BK median 焊点 | BK 左偏置会毁掉「奇硬 = 居中」 |
| 凡 `deg≥2` 松开 + 只拉度数=1 邻居 | 实现漂移；制造阶梯折 |
| 在约束循环里叠第三个 ad-hoc continue | 违反熔断纪律；应上提成员表 |

**回归备忘（短）**：早期奇偶分治方向对，后改为凡 fan 松开，再加只拉度数=1 的 follower → 三图阶梯折。细节与分阶段落地只在 `symmetry-axis.md`，本文不跟实现日记。

裁定变更时只改本节，并同步改 `symmetry-axis.md` / 实现；禁止只改常数不改裁定。

### 6.2 平行走廊直 vs 节点框比例端口

**裁定**：请求–响应（双胞胎短折返）走廊两端端口必须落在**同一条世界坐标列**上，**不依赖**全局 grid 开关。  
节点中心共线不够；若端口仍按各节点 `Ordered×width` 比例展开，不等宽时必然打出层间小折。

采用 Metric **PortLaneWriter**（对照 yFiles PortAlignmentIds）：为走廊写绝对 cross 列，再展开为 `LocalOffset`。算法契约见 [port-lanes.md](phases/port-lanes.md)。

用户可见结果：

- 三层架构一类图：一去一回左右平行、横平竖直，不因中间节点更宽而「拧一下」；  
- **不开 grid** 也成立；全局贴网是另一产品选项，单开。

**明确废弃**

| 废弃 | 原因 |
|------|------|
| 在 Ink 里特判抹掉端口 Δx | 落笔零新决策；列位写者应在 Metric |
| 仅靠 Ordered 比例展开作为平行终态 | 随节点宽度漂移 |
| 把本需求绑死在「必须开 grid」 | 与 yFiles 对齐能力（alignment）混淆 |
