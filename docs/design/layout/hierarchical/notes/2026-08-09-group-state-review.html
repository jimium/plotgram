1 DSL：group 怎么设计

规范真源：docs/specs/dsl-spec.md §6；组间边 §5.7 / §7.6；ADR-004。

1.1 规范形态

group frontend {
    label: "Frontend"
    variant: primary          // 主题颜料；group 无 shape / archetype
    // layout: ...            // 规划中，引擎尚未读

    node a { label: "Web" }
    node b { label: "App" }
    a -> b                    // 组内边：两端须为本组后代

    group nested { ... }      // 嵌套深度不限制
}

// 跨组边：写在共同祖先或顶层，连的是 node，不是 group
a -> db

1.4 group_anchor 与 @group 糖

@frontend -> @backend { from_side: east, to_side: west }
// parse 展开为两个隐形 group_anchor node + 一条普通边
图 1.1 · @group 糖展开为两个隐形 group_anchor node + 一条普通边。边永远只连 node，不引入 Endpoint::Group。
字段含义
role: group_anchor结构角色（封闭集：entity / group_anchor）
host_group所属 group id（必填）
sidenorth / south / east / west（必填）
slot可选；同侧多锚点序
设计意图（ADR-004）：
  • 边永远只连 node；不引入 Endpoint::Group
  • render 不绘制锚点形体
  • 几何：组框定稿后，由 host_group + side + slot 唯一派生
  • 布局：锚点不应单独占 Sugiyama 叶层/序（收缩进 host）
现行缺口：group_anchor 经 all_node_ids() 仍与普通 node 同等进入 rank/order/metric——ADR-004 的「不参与叶分层」未闭合。

1.5 与 PartitionGrid 的关系

泳道 / 矩阵是 PartitionGrid（ADR-008：partition / cell_col / cell_row），与 group 正交。机制上可与「层内连续块」同构，但 Hier 尚未消费 partition；不要用 group「演」泳道。

3 概念词典（含图解）

3.A · group_path（每个 node 的 root→leaf 组链）

Compose 阶段的 graph_index 为每个 node 计算它从根组到所属叶组的 id 链。这是后续 ScopeMask / Gate 判定的基础。

图 3.A · 每个节点都有一条从 root 到所属叶组的 group_path。它定义了「这个节点属于哪些 scope」，是 ScopeMask 与 Gate 判定的输入。

3.B · 边界 dummy（GroupBoundary）

每层每个 group 插入 Left / Right 零宽夹点（dummy），把同组成员夹在中间；跨 rank 用高权段把同组的 L/R 边界对齐到同一 order 区间。这样不改交叉最小化内核，又能让同组在相邻层「连续块」对齐。

图 3.B · 橙色为边界 dummy（L/R）。跨 rank 的粗橙线是高权对齐段，把同组左右边界钉在同一 order 区间，从而形成「连续块」。

3.C · Substrate / Segment / Gate（核心机制）

Substrate 是 rank × order 离散走廊骨架；track（两 rank 之间的纵向走廊）被组边界 cut_line 切成多段 Segment；组边界上的「合法穿行口」即 Gate，把外侧 segment 与内侧 segment 配对。

图 3.C · Substrate（rank×order 走廊）被组边界 cut_line 切成 Segment；Gate 是 cut_line 上的合法穿行口（绿点），边穿组必须经 Gate。

3.D · Gate 是什么（重点）

Gate 不是 UI 控件，而是组边界上的合法穿行口。边要从组外进组内（或反过来），在离散 Substrate 上必须经 Gate。
图 3.D · Gate 是外侧↔内侧 segment 的配对口；穿组有三道防线，第三道（穿透 verifier）尚未落地。
容量：GateCapacity::Fixed 已删除；当前 Gate 无容量上限。容量作为 Metric 缝宽预算（相 I 累计 demand → 相 II 撑开段长）尚未落地。
fallback 后 Gate 消失 ≈「布局当这图没有组」——边可任意穿组，交叉容易爆炸。

3.E · ScopeMask（边的合法 scope 集合）

每条边允许走的 scope = 两端祖先链 ∪ 公共祖先。Channel 搜索时硬过滤掉非法 scope 的 segment。

图 3.E · 边 A→B 的 ScopeMask = ancestors(A) ∪ ancestors(B) ∪ common_ancestor(root)。其它组（如 Z）的 segment 被硬过滤，边不可穿。

3.F · channel-group-fallback

组矩形不纯（EmptyGroup / OverlappingGroups / ForeignNodeInGroupRect）或路由不可行时，退回 root Substrate，Gate 全部消失，ScopeMask::unrestricted()。

左：组矩形不纯
右：fallback 后退回 root
场景行为可观测性
组矩形不纯（EmptyGroup / OverlappingGroups / ForeignNodeInGroupRect）退回 derive_root_substrate；used_gates=falsediagnostics.relaxations
group-gate 路由不可行同上二次 fallbackroute_all
Ink 穿真实节点 + 曾用 gateCHANNEL_FORCE_ROOT 重跑mod.rs
启用率（2026-08-09 对照表）：组 fixture 约 32/40 启用 gate；约 8/40 仍 fallback（典型：多 namespace 跨层区间交叉换位）。

3.G · 三条不变量

真源：atlas-reference/group-invariants.md。

图 3.G · 三条不变量现状：Containment 弱保证、Sibling separation 未做、No penetration 部分实现。

4.2 现行策略 = Weak

  • 全图一套 Sugiyama
  • 组靠「层内被边界夹住 + 跨层软拉齐」保持连续块
  • 跨组路由靠 Gate

group_policy: strong-macro（组内分层 → macro → 回填）绑定即 Unsupported。现行方案见 phases/strong-macro.md。

4.3 边界 dummy 的用意

architecture.md §8.3：

  • 不改交叉最小化内核
  • 用夹点 + 高权跨层段，让同组在相邻层的 order 区间对齐
  • 对齐失败 → (rank, order) 包围盒互咬 → ForeignNodeInGroupRect → fallback
这正是 2026-08-08-hier-review.md §2.6 因果链的核心：层内连续不够，必须跨层区间对齐，组通道才能启用。

8「基本可用」vs「当优化目标」（决策备忘）

集中做 group 时，建议拆开两档，避免和全局走廊优化缠在一起：

基本可用（建议先做）当优化目标（可后置）
要什么组通道能开、少静默 fallback；包围盒/Scope 基本纯；穿透可证组框进 VPSC、递归子布局、组内美学 J
验收fallback 率、channel_used_gates、穿组 verifier框对齐、组内紧致、视觉打磨
和全局路由关系前置基板与 Channel 全局分配器正交、可后做

建议顺序（备忘，非契约）

图 8.1 · 建议实施顺序：结构 → 可证 → 写权 → anchor，之后才开全局走廊分配。
全局走廊分配器可以等「基本可用」至少到第 1（最好到第 2）之后；否则密集组图上的 crossings 仍会被 fallback 淹没，路由层收益验不出来。

9. 与边路由缺口的关系（上下文）

2026-08-08-hier-review.md §3 边路由行：加权 J + Occupancy 交叉项 + bounded rip-up 已闭合；仍缺 yFiles 级全局走廊分配器与边交叉后处理。

  • 若 group 尚未作为优化目标，路由主线是「准全局分配 + 廊内 CM + VPSC nudge」，组通道失效图上的高交叉记为 residual。
  • 若 先集中把 group 基本可用做好，则上述 residual 会明显缩小，再做全局路由更有验收意义。

本文只做回顾，不裁定二选一；顺序见 §8。
