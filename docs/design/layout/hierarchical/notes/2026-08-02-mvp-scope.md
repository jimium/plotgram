> 目的：记录本轮 `crates/plotgram-layout/src/layout/hierarchical/`（记录当时位于
> `plotgram-engine`，后随拆分迁移）实现相对

## 0. 触发校准的关键事实（实现前勘察）

1. `plotgram-engine-api::LayoutOutput` 目前只有 `{ nodes, edges }`。没有
   `groups` / `route_scene` / `diagnostics` 字段——`GroupPlacement` 由
   `plotgram-engine/src/finalize.rs` 在 `LayoutAlgorithm` 之外、**从最终
   node frame 反推**（子节点 bbox ∪ padding，`GROUP_PAD = 16.0`）。
   → architecture.md §3.2 要求"组框由 Metric 写、finalize 不重算"这条在当前
   trait 边界下不成立：`LayoutAlgorithm::layout` 根本没有输出组框的通道。
   **决定**：本轮不修改 `plotgram-engine-api`（风险/收益不对称，且没有第二个
   算法需要这个扩展）；组的处理目标改为"排出的 node 顺序/位置让 finalize 的
   bbox-并集看起来合理"，而不是把组框当 VPSC 变量求解。这是本轮最大的一处
   目标架构偏离，记在这里而不是代码注释里。
2. `plotgram-model::port` 只有 `PortConstraint{side, slot: Option<u32>}` /
   `PortRef{side, slot: u32}`——five-tier port（FIXED_RATIO / FIXED_POS /
   Candidates）**没有 model 层字段可落**。继续按现有二档模型实现；
   `FIXED_RATIO`/`FIXED_POS` 不做（没有字段，做了也没处放）。
3. `Graph.partition: Option<PartitionGrid>` 存在，但 DSL parser 对
   `partition { }` 语法标记 **planned**（未接入）——即当前不可能有真实
   graph 带 partition 数据。本轮**不消费** PartitionGrid，属于"暂不适用"而
   非"跳过硬需求"。
4. 69 个 showcase 文件 grep 结果：0 处用到 `port` 约束 DSL、0 处
   `partition`、0 处 `edge_group`/bundle、0 处真自环（`self-loop-retry` 实为
   2 节点环）、0 处 `group_policy: strong-macro`。所有 `group` 用例都是
   ≤3 层嵌套、组内数节点的小规模分组。
   → **StrongMacro 本轮不实现**，`group_policy: strong-macro` 直接
   `LayoutError`（对应 architecture.md 的 `Unsupported` 硬失败语义，不做
   静默退化）。**后续实现方案**见 [`phases/strong-macro.md`](../phases/strong-macro.md)，
   不再以本文为「不做」的现行指针。Channel/Gate/Substrate/track 拥塞重布的完整机制（rip-up、
   history cost）超出现有验收面，先实现"通过 dummy 链路径 + 正交清理"的
   直接展开，不做拥塞重布。along-yfiles-reference 的 ROI 列表本身也把
   rip-up 排在最后一优先级。
5. `plotgram-algo` 已提供可直接复用的核心部件：`fas::greedy_fas`（Greedy-FAS
   环去除）、`crossing::count_bipartite_crossings`（交叉计数 oracle）、
   `vpsc::solve`（1-D 变量放置+分隔约束 QP，用于次轴坐标求解/防重叠）、
   `interval_color::color_intervals`（区间着色，可用于同走廊 track 分配）、
   `path_ortho::normalize_orthogonal`（正交路径清理）、
   `orientation::Orientation`（TB 唯一核心 + 四方向变换）。
   Network Simplex 分层与 median 定序**不在** plotgram-algo（文档里也说明是
   故意的，因为和 proper hierarchy / dummy 强耦合），需要在 hierarchical
   模块内部实现。

## 1. 本轮范围（对照 architecture.md §12 里程碑）

做到大致 M1 + M2 的子集 + M3 的简化版：

| 相 | 做 | 不做 / 简化 |
|---|---|---|
| P1 去环 | `plotgram_algo::fas::greedy_fas`，working/original 双向字段 | — |
| P2 分层 | 简化版 Network Simplex（可行紧树 + cut-value pivot），有限迭代 | 每 partition 独立分层（本来就不做，无 partition 输入）|
| P3 定序 | median + transpose + best-snapshot（用 crossing oracle 选最优快照）；分组用**递归块定序**保持组内连续 | 真正的"边界 dummy"节点机制——用递归块排序达到同等的组连续性效果，未插入显式边界 dummy 节点；见 §3 |
| 端口 | FREE：按对侧 `(layer, order, EdgeId)` 排序；FIXED side/slot 遵作者约束 | FIXED_RATIO/FIXED_POS（model 无字段） |
| P4 坐标 | 主轴=层栈；次轴=（几轮阻尼重心松弛 [均值+0.5 阻尼] 得 ideal）+ VPSC（次序分隔约束 + 拉向 ideal 的加权最小二乘） | 完整 Brandes–Köpf 四遍法；组框不进 VPSC（见 §0.1）|
| P5 落笔 | dummy 链路径点 + 端口锚点 → `path_ortho::normalize_orthogonal` 清理 | Channel/Gate 走廊搜索、track 拥塞重布、bundle 干线合并（`edge_group` 目前透传但不做共享几何）|
| 组 | Weak：仅保证同层内组成员在 order 上连续（递归块排序）；不做 rank 连续区间约束、不做组框 VPSC 变量 | StrongMacro：`Unsupported` 硬失败（方案见 [phases/strong-macro.md](../phases/strong-macro.md)） |
| 自环 | 检测 `source == target`，走独立小回路桩几何，不进 rank/order | 多自环共节点防碰撞（仅一个自环时正确，多个简单偏移）|
| Orientation | 核心只实现 TB（canonical `(main, cross)`），四方向通过 `plotgram_algo::orientation` 在输入前/输出后转换 | — |
| Diagnostics | MVP 无（`LayoutOutput` 无字段可写），bind 阶段仍保留 warning 收集但不透出。**阶段 C 已补齐**：`LayoutDiagnostics`（warnings / relaxations / params_hash）随 `LayoutOutput` / `LayoutResult` 透出（roadmap §4） | 完整 relaxation 生产方（D 阶段 rip-up 等首批消费）|

## 2. 具体算法选择记录

### 2.1 分层（P2）

简化版 Network Simplex：
1. 初始可行秩 = longest-path（沿 working DAG，反向边已由 FAS 处理）。
2. 由初始秩构造紧生成树（tight tree）：BFS/并查集扩展，每次找 slack 最小的
   跨树边收紧。
3. 迭代：对树边计算 cut value（一次线性扫描，非逐边重算）；找 cut value < 0
   的树边，取其中 slack 最小的非树替换边入树（tie-break：
   `(slack, -|子树大小差|, EdgeKey)`），平移子树秩。
4. 有限迭代上限（如 `256`），连续 N 轮无改进提前停止——与 v1 一致的防御性
   写法（`docs/design/...` 强调禁止无界循环）。

### 2.2 定序（P3）与组连续性

**没有实现独立的"边界 dummy 节点"机制**——改用等价的递归块排序：

- 每层节点先按 group 嵌套关系分桶成"块"（block = 顶层组 in this layer 的
  成员集合 / 单个无组节点）；块内保持子块结构递归。
- median 计算在**块级**做：块的 median = 块内所有节点在相邻层的中位邻接
  位置；块间排序只交换块，不打散块内顺序。
- 块内部再对其孩子（子组或裸节点）递归同一算法。
- transpose 步骤同理，只允许交换"同一父块下的相邻兄弟单元"，不允许打散
  块边界。

效果等价于 architecture.md §8.3 描述的"边界 dummy 夹住同组节点"（都是不改交叉
最小化核心、只在块粒度约束顺序），实现更直接，但**不产生**可寻址的
`GroupBoundary` NodeKey——如果后续要接组框 VPSC 变量或跨组 gate，需要重新
评估是否要真正插入边界 dummy。记在这里以防后人以为块排序=完整 group 契约。

### 2.3 次轴坐标（P4）

不做四遍 Brandes–Köpf。改为两步：

1. **Ideal 位置**：对每个节点（含 dummy），初始 = 该节点在 order 内的
   packed 位置；做 6 轮**阻尼重心松弛**：每个节点被拉向其相邻层所有邻居
   次轴坐标的**均值**，步长阻尼 `RELAX_DAMPING = 0.5`（注意：**不是**
   中位数——早期注释误写 median，已于 2026-08-03 修正措辞）。dummy 链
   节点因为只有 1 个上/下邻居，天然会被拉直。
2. **VPSC 求解**：每层内按 order 生成相邻节点分隔约束
   `right >= left + (半宽 + 半宽 + node_gap)`；`Variable{desired: ideal, weight}`
   ——dummy 节点给更高 weight（更贴近 ideal，即优先保直）；跨层不加约束
   （层与层次轴独立求解，因为分隔只在同层内有意义；ideal 松弛已经承担了
   跨层对齐的作用）。

这不是 architecture.md 设想的"BK 给 ideal → VPSC 统一解组框/节点/cross-axis
band"的完整版本（没有组框变量、没有 partition band），但复用了同一颗
VPSC 求解器，且满足"次序即真源、像素是求解结果"的原则。也意味着设计
目标里的"端口对齐（P4）"在本轮尚未成立——重心松弛只保证 dummy 链拉直，
不保证真端口列对齐。

### 2.4 落笔（P5）

- 有 dummy 链的边：路径点 = 起点端口锚点 → 各 dummy 点（层间必然只需
  1 折）→ 终点端口锚点。
- 无 dummy（同层/相邻层直连）：退化为直接正交肘形（复用
  `route/core::orthogonal_elbow`）。
- 统一过 `plotgram_algo::path_ortho::normalize_orthogonal` 去重/去共线/吸收
  短段，保证端点像素级不变。
- **不做**：Channel 走廊搜索（跨组穿越判定简化为"允许"，不做 gate 合法性
  校验——因为没有组框/gate IR，见 §0.1）；这意味着跨组边可能会视觉上贴近或
  穿过无关组框。已知限制，留给下一轮如果要接组框 VPSC。

### 2.5 自环

`source == target` 的边在 compose 早期被抽出，不参与 rank/order/坐标；
落笔阶段在节点右侧画一个固定尺�寸的小矩形回路（幅度按 `node_gap` 缩放），
多个自环简单地在偏移量上错开，无严格防碰撞证明。

## 2.6 `layout: architecture` 注册表别名（发现于验收阶段）

`showcase/hierarchical` 中 11 个文件直接写 `layout: architecture`（而非
`layout: hierarchical`），旧 stub 时代就从未注册过这个名字（`Registry::standard`
一直只注册 `"hierarchical"`）——这是先于本轮重建就存在的 fixture/parser 缺口，
不是本轮引入的回归。

正确修法应在 DSL/profile 展开层把 `profile: architecture` 展开成
`layout: hierarchical` + StrongMacro 类 profile 参数（架构文档明确禁止
`ArchitectureLayout` 巨石）；但那属于 `plotgram-parse`，不在本轮 `plotgram-engine`
任务范围内，而且即便展开正确，落到的仍是本轮标为 `Unsupported` 的
`group_policy: strong-macro`，同样跑不通。

**决定**：在 `crates/plotgram-engine/src/registry.rs` 把 `"architecture"` 注册为
`HierarchicalLayout` 的第二个名字（同一个 `Arc`，Weak 策略），而不是新建
`ArchitectureLayout` 或在算法内部按名字分支——两个注册表 key 指向同一份实现，
算法本身仍不读取任何 diagram/profile 名，不违反 ADR-001。这是一个**已记录的
临时兼容别名**，等 `plotgram-parse` 的 profile 展开补上、且 StrongMacro 落地后，
应当移除这个别名，改由展开层正确产出 `layout: hierarchical` + 参数。

### 2.7 `edge_gap` / `group_sizing` / `group_align`：bind 期 Unsupported（2026-08-03 补记）

这三个选项原可在 `params.rs` bind 成功且带 preset 值，但全引擎**零消费者**
——architecture.md §1.1「能绑定参数但参数未被消费，视为未支持」、§13 反模式 13。
为不静默接受，`HierarchicalParams::bind` 现在对这 4 个键（`edge_gap` /
`edge_distance` / `group_sizing` / `group_align`）硬失败（与
`group_policy: strong-macro` 同一语义；阶段 C 落地 diagnostics 通道后
Unsupported 仍是硬失败——warning 只留给非致命观察，见 roadmap §4）。
字段保留在参数结构体中作为未来需求通道占位（track 间距 / 组框写权），
preset 仍会写 `edge_gap`，但当前无可观测效果。等 Channel/track 或组框
写者落地时，恢复 bind 与消费。另注：自环回路幅度目前用的是 `node_gap`，
不是 `edge_gap`。

## 3. 已知与目标架构的差距清单（供下一轮）

1. 组框不是 VPSC 变量，是 finalize 后验 bbox——跨组边可能贴框/穿框。
2. 没有 Gate/Scope 三道防线；`verify_no_group_penetration` 类检查未实现。
3. StrongMacro 完全未实现（`Unsupported`）。
4. PartitionGrid 完全不消费（当前无输入面）。
5. Channel track 拥塞重布 / rip-up / bundle 干线合并未实现；`edge_group`
   目前只透传、不产生共享几何。
6. ~~无 `LayoutDiagnostics` 输出通道~~ —— 阶段 C 已落地（roadmap §4）：
   warnings / params_hash 透出，relaxations 通道已立、暂无生产方。
7. `hub_client_align` 已按 architecture.md §9.2 的建议**删除**（无
   alignment_sets 替代，因为 model 层也没有该 IR；如需要以后再加）。

## 4. 评审/打分工具

`crates/plotgram-compile/tests/hier_eval.rs`（`cargo test -p plotgram-compile
--test hier_eval -- --nocapture`）遍历全部 69 个 `showcase/hierarchical/*.pgm`，
跑完整 pipeline（parse → measure → `hierarchical` layout），对每个文件的最终
像素几何做独立验证（不复用布局内部状态）：

- 硬失败（断言）：任意两节点 frame 重叠；边路径出现非正交线段；边路径首/尾点
  未落在其 source/target 节点 frame 边界上（端口锚点必须精确落界，不是"差不多"）。
- 仅打印、不失败：用自实现的正交线段相交计数器统计每图交叉数、最大折点数
  ——作为回归信号（图密会有交叉，非 bug），不是正确性证明。

视觉核验走 `resvg`（`cargo install resvg`，纯 Rust，无需系统 cairo/rsvg）把
CLI 输出的 SVG 转 PNG，再直接读图核验（本轮由多模态模型完成，未写脚本）。

## 5. 验收结果（2026-08-02）

- `cargo test --workspace`：全绿。
- `hier_eval` 测试：69/69 fixture 通过硬不变量（零重叠、全正交、端口锚点精确
  落界）；交叉数在 0～22 区间，随图复杂度自然增长，未见异常离群值。
- 全部 69 个 `showcase/hierarchical/*.pgm`（含 11 个 `layout: architecture` 别名
  文件，见 §2.6）经 CLI 渲染为 SVG 均成功，抽样 15+ 个跨简单/中等/复杂/嵌套组/
  含环/LR 方向的文件转 PNG 人工读图核验：节点不重叠、边正交、箭头方向与语义
  一致（含 FAS 反转边）、组内成员在同层保持连续、组标签不再压边框/压箭头。
  已知视觉局限：跨组边可能贴近或轻微穿过无关组框（§3 第1条，无 Gate 机制）；
  边标签与穿越边偶有位置临近（Integrated labeling 未做，架构文档本身承认的
  缺口）。
- 过程中发现并修的两个真实 bug（非目标架构偏离，是本轮实现的错误）：
  1. Ink 折线用单次折角会导致其中一端以水平方向进入 North/South 端口
     （箭头看起来"斜着扎进"节点），改为端点各自保持竖直的中点双折角。
  2. `finalize.rs` 的 `GROUP_PAD`(16px) 小于 group 标题带高度(18px)，标签必然
     压住组内第一个成员/其入边——与本轮 hierarchical 实现无关的共享代码 bug，
     顺手修成"有标题时顶部单独加宽到 24px"。
  3. （2026-08-03 评审发现）作者固定端口的 side 在非 TB 方向未经 Orientation
     变换：`assign_ports` 把物理 side 恒等映射直接当作 canonical side 用，
     而出口处又做了一次 `from_tb_side`，导致 LR/BT/RL 方向下锚点落到错误的
     物理边。修法：compose 入口对 fixed constraint 统一走 `to_tb_side`；
     补了覆盖四方向的回归测试。fixture 端口约束数为零，故此 bug 此前未暴露。
