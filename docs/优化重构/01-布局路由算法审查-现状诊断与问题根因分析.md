# 布局与路由算法审查：现状诊断与问题根因分析

> 日期：2026-07-20
> 范围：flowchart / architecture 的 Sugiyama 布局 + 正交边路由
> 目的：定位影响生产可用性的核心缺陷，为后续优化方案提供依据

---

## 1. 管线全景（当前）

```
节点布局 (Sugiyama V2 / Architecture V2)
  → group_frame (组框计算与对齐)

      ├── Phase 1: 端口选择 + Slot 分配
      ├── Phase 2: 边难度评分 + 分层排序
      ├── Phase 3: 逐边路径构建 (候选枚举 + 打分)
      ├── Phase 4b: replan_slots (全局 Slot 重规划)
      ├── Phase 4c: straighten_align (直连偏好)
      ├── Phase 4d: reroute (多轮冲突消解)
      ├── Phase 4e: stub_fix (反向 stub 端口翻转)
      ├── Phase 4f: lane_assignment (车道分离)
      ├── S3: semantic_trunk_merge (语义合流)

  → refine (穿障检测 + 节点推开)

```

## 2. 核心问题诊断

### 2.1 自循环边（Self-Loop）渲染效果差

**现象**：
- 自环形状固定为右上角矩形折线，尺寸公式化（`loop_r = min(w,h)*0.28`），不考虑周围空间
- 多自环仅做角落轮转（右上→左上→右下→左下），不感知相邻节点/边的占位
- 与主路由管线完全割裂——不经过 scoring、不避障、不参与 lane assignment
- 标签位置硬编码偏移，可能与相邻边/节点重叠

**根因**：
- `self_loop.rs` 是独立模块，在 `phase_route_edges` 中直接调用 `route_self_loop` 后 return
- 没有将自环纳入 `SegmentGrid`，后续边不感知自环的存在
- 没有障碍物感知——自环可能伸入相邻节点或组边框内

**行业对比**：
| 产品 | 自环处理 |
|------|---------|
| yFiles | 统一路由框架内处理，自动选择最优角落，考虑邻居占位 |
| ELK | 分层布局中自环有专用阶段，支持多方向、自适应尺寸 |
| Graphviz | 在 spline 路由中统一处理，自环走 visibility graph |
| draw.io | 用户可拖拽调整，自动模式走简单矩形环 |

### 2.2 边贴组边框走行（Group Border Hugging）

**现象**：
- 边路径紧贴 group 边框线走，视觉上像"描边"，不美观
- 尤其是跨组边在走廊中走行时，与组边框几乎重合
- `border_repulse` 后处理推开效果有限，因为路径已在走廊坐标上

**根因**：
1. **走廊坐标 = 组间隙中点**：`build_corridors_from_groups` 计算相邻组间隙中点作为走廊坐标。当间隙较窄时（如 40px），中点距两边框仅 20px，减去 `GROUP_BORDER_SHELL_PAD`(12px) 后视觉留白极小
2. **Scoring 中组近距惩罚偏弱**：`GROUP_NEAR_MISS_PENALTY`(2000) 远低于 `NODE_CROSSING_PENALTY`(10000)，scorer 对"贴组走"的厌恶不够强
3. **corridor_misalignment_penalty 反向锁定**：一旦路径被走廊规划锁定到走廊坐标，scorer 反而惩罚偏离走廊的行为——即使走廊坐标本身就贴边
4. **排斥是后处理而非路由约束**：`repulse_edges_from_group_borders` 在路由完成后才执行，此时路径拓扑已固定，排斥只能做微调

**行业对比**：
- ELK：组间距（`spacing.nodeNodeBetweenLayers`）默认较大（100px+），走廊天然宽敞
- yFiles：`OrthogonalEdgeRouter` 将组边框视为硬障碍，路径搜索时直接避开
- 当前实现：走廊是"软偏好"而非"硬约束"，但一旦锁定又变成"硬锁定"

### 2.3 不必要的弯折（Unnecessary Bends）

**现象**：
- 本可直连的边出现 Z 字弯或阶梯弯
- 端口选择正确但 slot 锚点不对齐，导致出发后立即折弯
- 后处理阶段（replan_slots、stub_fix）引入新弯折

**根因**：
1. **候选枚举的路径空间有限**：`select_best_path_with_scorer_stats` 枚举的候选路径形态有限（直连、单折、双折、走廊），复杂场景下最优路径不在候选集中
2. **BEND_PENALTY(16.0) 相对偏低**：路径长度权重为 1.0/px，一个弯折仅等价于 16px 路径长度。当绕行距离 < 16px 时，scorer 偏好绕行而非直连
3. **Slot 锚点不对齐**：同侧多边 slot 按 `(rank+1)/(count+1)` 均匀分布，但对端节点中心可能不在任何 slot 的正对面，导致出发后必须折弯对准
4. **straighten 只修正正对端口**：`is_opposite_port_pair` 限定 Bottom-Top / Left-Right，对 Bottom-Left 等非正对组合不做对齐
5. **sanitize 的 collapse_micro_jogs 阈值(24px)**：小于 24px 的微折被折叠，但 24-40px 的"中折"保留，视觉仍显冗余

### 2.4 布局对称性不足

**现象**：
- Fan-out 分支节点不对称（如 3 个分支，中间分支偏移）
- 同层节点间距不均匀
- 决策节点的 Yes/No 分支视觉权重不平衡

**根因**：
1. **Brandes-Köpf 四趟坐标分配**：取四趟中位数，但中位数对奇数分支不保证对称
2. **spine 加权 compaction**：`spine_weight=1.5` 将节点拉向主干，但副作用是分支被压缩
3. **缺少显式对称约束**：没有"同源 fan-out 子节点关于父节点中心对称"的硬约束
4. **层内排序（order.rs）的 median 启发**：weighted median 优化交叉数，但不优化对称性
5. **组框对齐（group_frame）可能打破对称**：组框 padding 和 sibling 对齐可能移动节点

### 2.5 回环/反馈边路由质量

**现象**：
- 回环边（如 `auth -> request "失败"`）绕行路径过长
- 多条回环边挤在同一侧通道
- 回环边与正向边交叉

**根因**：
1. **feedback_side 分配是静态的**：按 FAS 反转 + 左右均衡，不考虑实际通道拥堵
2. **回环边延后路由但通道已被占据**：`feedback_edge_set` 延后到所有正向边之后，此时最优通道已被占
3. **侧通道宽度固定**：`MAX_SAME_SIDE_FEEDBACK=3`，超过 3 条溢出到另一侧，但不考虑实际空间

## 3. 算法架构层面的结构性问题

### 3.1 候选枚举 vs 搜索式路由

当前路径搜索是**有限候选枚举 + 加权打分**：
- 生成 N 条候选路径（直连、单折、双折、走廊、外环等）
- 用 `DefaultScorer` 打分（长度 + 弯折 + 障碍 + 重叠 + 通道负载 + 走廊对齐）
- 选最低分路径

**根本局限**：
- 候选集是人工设计的有限模板，无法覆盖所有障碍配置下的最优路径
- 打分函数是多项式加权，各惩罚项之间存在博弈（如避障增加长度和弯折）
- 无法保证找到全局最优——只能保证在候选集中最优

**对比 A* / Visibility Graph**：
- A* on grid：在膨胀障碍物后的网格上搜索，保证找到最短无碰撞路径
- Visibility Graph：构建障碍物顶点的可见性图，在图上搜索最短路径
- 两者都能在任意障碍配置中找到最优路径，不依赖候选模板

### 3.2 逐边贪心 vs 全局优化

当前按 `edge_order`（rank + 连接度 + 难度分）逐边路由：
- 先路由的边占据通道，后路由的边避让
- 没有全局通道分配（ELK 有 channel assignment 阶段）
- 没有边交叉最小化（yFiles 有 crossing minimization）
- `reroute_conflicting_edges` 是事后修复，非全局优化

### 3.3 后处理层过厚

5+ 层串行后处理（replan → straighten → reroute → stub_fix → lane → sanitize）：
- 每层都可能触发重路由，引入新的弯折
- 层间存在写权竞争（手册 §1 已记录）
- 修复一层可能破坏另一层的成果
- 增加了调试难度和不确定性

## 4. Benchmarks 检验能力评估

### 4.1 当前门禁覆盖

| 维度 | 覆盖情况 | 不足 |
|------|---------|------|
| 正确性（穿组/确定性） | 硬门禁，全角色 | 充分 |
| 严重度（exact_sev/tight_sev） | product 硬 | 指标较粗，不区分弯折数/贴边/对称 |
| 共线/合流 | 有产品验收语言 | 充分 |
| 性能 | 10% budget | 充分 |
| 视觉美学 | **无量化** | 完全依赖人工审查 |

### 4.2 缺失的美学指标

当前 benchmarks 无法量化以下维度：
1. **弯折数（bend count）**：每条边的平均弯折数、最大弯折数
2. **贴边距离（border proximity）**：边与最近组边框的最小距离分布
3. **对称性（symmetry score）**：fan-out/fan-in 的对称偏差
4. **自环质量**：自环与邻居的最小间距
5. **边长均匀性**：同层边长的方差
6. **通道利用率**：走廊宽度 vs 实际边数

## 6. 结论

当前实现的核心矛盾是：**用工程化后处理弥补算法内核（候选枚举）的不足**。

- 后处理层已经非常厚（5+ 阶段），继续叠加的边际收益递减
- 候选枚举的路径质量上限受限于模板设计
- 美学问题（弯折、贴边、对称）需要在**路径生成阶段**而非后处理阶段解决

下一步优化应聚焦：
1. **短期**：扩展候选路径空间 + 调整 scoring 权重 + 走廊宽度保障
2. **中期**：引入 obstacle-aware 的路径搜索（A* 或 visibility graph）
3. **长期**：全局通道分配 + 边交叉最小化
