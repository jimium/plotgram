1. 一句话总览

路由 = 在节点位置已确定的前提下，为每条边计算：从哪条边连出 → 路径折点/曲线 → 标签放哪。

当前实现是双层结构：

  • 外层 pipeline/runner.rs：管全局时序（冻结节点、后处理、正交 D 段）
  • 内层 RecipeRouter：管六大家族各自的 compile → solve →（物化/标签）
布局层 路由层（Recipe） 后处理

3. 六大家族配方（RoutingRecipe）

注册于 pipeline/registry.rs，均由 RecipeRouter 包装驱动。

配方名 几何类型 适用图 成熟度 核心能力
straight 直线 / 短折线 ER 完整 Recipe 平行边偏移、端点解析
bezier 三次贝塞尔 Flowchart, Architecture, State, ER, Mindmap 完整 Recipe 穿障退化折线、自环、tension 配置
spline 样条 / 贝塞尔 Flowchart, Architecture, State, ER 完整 Recipe 可见性图绕障 + Catmull-Rom 拟合
circular 圆弧贝塞尔 State, ER 完整 Recipe 同圆/跨圆弧、RadialPlacer 标签
organic 有机贝塞尔 + Mindmap 完整 Recipe 深度衰减、端口均匀分布、mindmap 拉弓
orthogonal 正交折线 Flowchart, Architecture, State, ER 薄包装 端口求解、PathSolver、Lane、Bundle、D段

4. RecipeRouter 内部：两条路径

solve 产出 RouteSolution（family-neutral 路径 IR）+ EdgeLabelPlan。GeometryMaterializer 是几何的唯一正式写者。

正交目前用 overrides 绕过标准物化管线——这是架构成熟度最低、后续 R12c 要收口的点。

7. 专业术语表

点击卡片可快速浏览；按架构层次分组。

架构层

Recipe Routing Recipe
一种边路由「配方」。把图语义编译成求解问题，再产出路径解。如 BezierRecipe、OrthogonalRecipe。
RecipeRouter
泛型适配器，把具体 Recipe 包装成 pipeline 可调用的 RoutingRecipeDyn，统一驱动 materialize / audit / label。
RoutingCoordinator
路由协调器。当前负责串起 route → refine → budget reroute，是 runner 调用的唯一路由编排入口。
Kernel
共享算法能力模块（如避障、最短路、曲线拟合）。设计目标：不读 DiagramType，只消费窄 IR。
Solver
专用求解器，解某一子问题：端口分配、路径分配、车道、合流、标签等。如 PortAssignmentSolver、PathAssignmentSolver。

数据模型

Draft
compile() 产出的家族专属已编译事实（端点、障碍、边计划等），供 solve() 消费。
RouteSolution
family-neutral 路由解 IR：路径骨架、端口、车道、降级原因等，不含最终 SVG 折点写法。
RoutePath
路径内部表示：Straight / Cubic / Spline / Orthogonal / Radial 等枚举。
GeometryMaterializer
几何物化器。把 RouteSolution 写成最终 PathGeometry（points/controls）。设计上的唯一几何写者。
FrozenNodeProduct
只读节点/分组快照。路由不应修改其中的坐标；debug 下用 fingerprint 断言。
PreparedRoutingInput
已编译的只读路由输入：稳定边、契约、画布尺寸 + 确定性 problem_signature。
RoutingContract
路由语义契约：边角色、合流意图、走廊资源等——表达「为什么这样走」，区别于数值配置。
overrides
Recipe 求解时跳过 materialize 的「预制完整 EdgeLayout」（典型：自环、当前正交整包输出）。

正交专属

C 段 / D 段
C 段：正交 router 内部主流程（建路→PathSolver→Lane→Bundle）。D 段：snap 后 OrthogonalFinalizer 的收尾修复。
Port / Side / Slot
Port：连接边（Top/Bottom/Left/Right）。Side：选哪条边。Slot：该边上的具体锚点位置。
Stub
从节点边界伸出的短正交段（approach），路径进入通道前的「引脚」。
ResourceGraph
统一资源图：障碍、OVG 可见弧、通道、走廊等合并为一张图，供 PathSolver 最短路/重路由。
rip-up / reroute
Rip-up：临时拆掉某条边的路径占用。Reroute：在更新后的资源负载下重新求最短路。有界多轮。
Lane Assignment
车道分配：同一通道上多条边平行展开，避免重叠。
Bundle / Semantic Trunk Merge
语义合流：多条边共享一段垂直/水平「干线」suffix，常见于架构图 FanIn。
OVG
Orthogonal Visibility Graph，正交可见性图。在障碍角点间建水平/垂直可见弧，用于绕障最短路。
SegmentGrid
边占用网格：记录哪些网格格被哪条边的哪段路径占用，用于冲突检测与拥堵统计。
sanitize
几何消毒：删重复点、合并共线、修正反向 stub 等。分「保拓扑」与「改拓扑」两类。

标签与质量

LabelSolver
统一标签求解：place（按计划放初位）+ solve（冲突推开、merge dedupe）。
EdgeLabelPlan
单条边的标签计划：middle_t（路径参数位置）、偏移、可选采样折线。
route_annotations
路由注解：merge 区间、protected run、降级标记等，与几何同源维护。
DegradedReason
降级原因：如请求 Bezier 但穿障后实际走折线，必须显式记录，不可静默改 family。
RouteRepairIntent
修复意图：审计发现违规后产出的结构化修复请求（影响边、约束 ID），设计目标是由 solver 重解而非原地改点。
