## B1. 正交 Visibility Graph (OVG)

### 实现文件

`crates/plotgram-core/src/layout/edge/edge_routing_orthogonal/visibility_graph.rs`

### 核心算法

1. **构建阶段**：
   - 收集障碍物膨胀后的 bbox 四角作为候选顶点
   - 对每对顶点，检查水平/垂直可见性（线段不穿任何障碍物）
   - 可见则添加边，权重 = 线段长度

2. **路径搜索**：
   - Dijkstra 最短路径
   - 边权 = 线段长度 + bend_penalty × 转弯次数
   - 端点通过投影连接到图

### 集成点

`path.rs` 的 `select_best_path_with_scorer_stats`：
- 在 Level 3（阶梯候选）之后添加 Level 4: OVG 路径
- 仅当无 strict 候选且 OVG 可用时启用

### 环境变量

- `PLOTGRAM_OVG_ENABLED`：**默认开启**，设置 `=0` 或 `=false` 关闭

### 测试

- `test_ovg_empty_obstacles`：空障碍物
- `test_ovg_single_obstacle`：单障碍物构建
- `test_ovg_simple_path`：简单路径搜索
- `test_ovg_path_around_obstacle`：绕行路径
- `test_simplify_orthogonal_path`：路径简化

## B2. 端口约束求解器

### 实现文件

`crates/plotgram-core/src/layout/edge/edge_routing_orthogonal/port_solver.rs`

### 核心算法

1. **初始化**：使用几何规则（`choose_pair_sides_with_group`）
2. **局部搜索优化**（小规模 < 50 边）：
   - 尝试所有端口组合
   - 目标函数：弯折预估 + 端口冲突惩罚
   - 迭代直到无改善

### 约束

- 同节点同侧边数 ≤ 容量（PORT_CAPACITY_PER_SIDE = 4）
- 正对端口优先（减少弯折）
- 回环边使用 feedback 分配

### 环境变量

- `PLOTGRAM_PORT_SOLVER=1`：启用端口求解器（默认关闭，opt-in）

### 测试

- `test_estimate_bends_opposite`：正对端口弯折预估
- `test_estimate_bends_l_shaped`：L 形端口对
- `test_estimate_bends_same_direction`：同向端口
- `test_port_solver_disabled_by_default`：默认关闭

## B3. 全局通道规划器

### 实现文件

`crates/plotgram-core/src/layout/edge/edge_routing_orthogonal/channel_planner.rs`

### 核心算法

1. **收集通道候选**：
   - 组间隙中点
   - 节点间隙中点

2. **贪心分配**：
   - 按边序遍历
   - 为每条边分配负载最低的通道

### 数据结构

```rust
pub struct ChannelPlan {
    pub vertical_channels: BTreeMap<i64, Vec<usize>>,   // x 坐标 → 边列表
    pub horizontal_channels: BTreeMap<i64, Vec<usize>>, // y 坐标 → 边列表
}
```

- `test_channel_planner_disabled_by_default`：默认关闭

## 调优结果（2026-07-21）

### 四项关键技术改进

| 任务 | 内容 | 效果 |
|------|------|------|
| OVG 性能优化 | 零克隆搜索 + 空间过滤(bbox+80px) + 轻量级投影 | ecommerce 39ms→34ms（-13%），对比无 OVG 基线仅 +4% |
| OVG 边重叠感知 | Dijkstra 权重加入已路由边共线重叠惩罚 | 减少与已路由边的视觉重叠 |
| Channel Planner 接入 | 规划通道坐标注入 build_channel_detours 候选 | 为边提供全局最优通道候选 |
| Port Solver 增强 | 二次拥堵惩罚 + 角度对齐 + 高度节点局部搜索 | 修复 OVG 引入的 exact_sev 退化 |

### Benchmark 对比（product-regression-set，三特性全开 vs 无 OVG 基线）

| 指标 | 基线 | 当前 | 变化 |
|------|------|------|------|
| degraded_count 总计 | 90 | 30 | **-67%** |
| exact_sev | 0 | 0 | 无退化 |
| ecommerce-platform 性能 | 33ms | 34ms | +4% |
| 正确性轨（穿组/确定性） | PASS | PASS | ✓ |

| 图 | 基线 | 当前 |

| microservices | 3 | 0 |

### 三个模块的实际效果

1. **OVG（正交可见性图）**：
   - 核心收益：将 degraded 边从 90 降至 ~30，消除 67% 的退化边
   - 工作原理：当候选枚举无法找到 strict 路径时，OVG 通过 Dijkstra 在障碍物空间中搜索全局最优正交路径
   - 性能开销：+4%（空间过滤 + 零克隆优化后）
   - 已知 trade-off：空间过滤导致少数图 degraded 略升（可接受）

2. **Channel Planner（全局通道规划器）**：
   - 核心收益：为 build_channel_detours 提供全局规划的通道坐标，避免局部贪心导致的通道拥堵
   - 工作原理：预计算组间隙/节点间隙中点作为通道候选，按边难度降序贪心分配
   - 性能开销：可忽略（仅预计算一次）
   - 当前状态：提供候选坐标，不强制路由结果

3. **Port Solver（端口约束求解器）**：
   - 核心收益：修复 OVG 引入的 exact_sev 退化（边精确重叠），改善多边共享节点的端口分布
   - 工作原理：二次拥堵惩罚 + 角度对齐成本，局部搜索优化端口分配
   - 性能开销：小规模图 <1ms，中等规模仅优化高度节点
   - 已知 trade-off：password-reset degraded 1→4（端口分配变更导致），保持 opt-in
