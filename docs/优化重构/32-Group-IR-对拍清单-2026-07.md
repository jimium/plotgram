## 1. 对拍口径

| 项 | 说明 |
|---|---|
| **生产框** | `compute_group_bounds(diagram, nodes, padding)`（成员包围 + padding；容器组含后代） |
| **Shadow 框** | `attach_group_ir` → `project_hard_constraints` → `materialize_group_{cross,main}_bounds`（或 `refine_group_frames`） |
| **轴** | Cross：`x/width`（left/right）；Main：`y/height`（top/bottom） |
| **对齐阈值** | 叶子组位置/尺寸 `|Δ| ≤ 1.5`（与 `shadow_audit_group_bounds` EPS 一致） |
| **不要求对齐** | 父容器在 H-G2/H-G3 下可能比朴素包围略扩；sibling gap 强制缝；**禁止**对拍旧 Equal 条带 |

硬约束对照：

| ID | Shadow 编码 |
|---|---|
| H-G1 | `GroupContainment` + `MinSeparation`（成员 ↔ 组边界） |
| H-G2 | 子组边界 ⊆ 父组边界（`MinSeparation`） |
| H-G3 | `GroupSiblingSeparation` + `MinSeparation`（默认同级 gap；可 `draft_boost_h_g3_from_pair_gaps`） |
| H-G6 | 组框 lo 侧 `LowerBound(0)`（画布上界留给后续） |

## 3. 已知差异（预期，非回归）

1. **Shadow 未物化进生产**  
   architecture builder 仍调用 `attach_group_ir` 进 Cross 问题，但最终框仍由 `compute_group_bounds` / Frame 链写出；渲染字节相对 G-pre 应不变。

2. **父容器可能更松**  
   H-G2 要求子框 ⊆ 父框（含 padding），朴素 `compute_group_bounds` 按成员节点并集；当 sibling 被 H-G3 拉开后，父框 shadow 会更大。

3. **H-G3 默认 gap vs 走廊**  
   默认 sibling gap（arch 40）与真实 RouteDemand/走廊负载未闭环；`draft_boost_h_g3_from_pair_gaps` 仅草稿，G4 再接 `CorridorDemand`。

4. **双轴未联合**  
   Cross / Main 各解一次；同一次会话内交替留给 G3。

5. **H-G6 不完整**  
   仅 lo≥0；无 canvas 上界 `UpperBound`。

6. **不做** Equality / Equal track / SharedLines 翻译（方案 §0 / G2）。
