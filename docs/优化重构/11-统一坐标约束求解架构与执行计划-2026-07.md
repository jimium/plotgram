## 0. 一句话方案

将当前“BK 生成坐标后，多个 pass 依次改写坐标”的管线，重构为：

```text
rank / order 冻结离散拓扑
  → StructureModel 识别视觉结构
  → CoordinateIntent 收集全部目标与约束
  → BK 只生成初值
  → CoordinateSolver 统一求解相对坐标
  → ConstraintAuditor 只读审计
  → 全图 normalize / grid finalize
  → 冻结节点几何后进入路由
```

核心规则：

> **所有阶段只声明坐标意图；`CoordinateSolver` 是节点相对坐标的唯一写者。**

`space_budget`、route feedback、pendant、fan symmetry、spine、singleton、end 等逻辑都不能在求解器之后直接推节点。需要额外空间时，必须生成新的 `CoordinateIntent`，在有限轮次内重新求解。

## 1. 问题定义

### 1.1 当前管线的结构性缺陷

当前 `sugiyama_v2/coordinate.rs` 的横向坐标大致经历：

```text
compute_spine_nodes
  → Brandes-Köpf 四趟坐标
  → compact_layer_centers
  → enforce_fan_symmetry
  → resolve_real_node_overlaps
  → align_singleton_layers_to_predecessors
  → align_spine_chain
  → align_local_end_nodes
  → normalize_layout_to_padding
  → align_pendants_under_anchors
```

之后，`refine/space_budget` 和 route feedback 仍可能再次移动节点。

这里的问题不是某个 pass 必然写错，而是：

1. 多个阶段拥有同一字段的写权。
2. 每个阶段只知道自己的局部目标。
3. 各阶段的操作不满足交换律。
4. 后阶段缺少前阶段的结构语义。
5. 约束失败通常表现为“跳过”或“再补一次”，而不是可解释的冲突。
6. 当前 `spine` 是一条按出度和 id 贪心选择的路径，不能表达 split–join 的视觉主轴。
7. fan-in 回中不是一等目标，通常由 singleton median 间接产生。
8. 局部 padding 修复会移动单层，破坏跨层对齐；画布 padding 本应由最终全图平移完成。

典型破坏链：

```text
BK / compact 选择单侧 spine
  → fan symmetry 尝试把子节点组拉回父轴
  → overlap 或 padding 按层平移
  → singleton 按已经偏移的直接前驱 median 回中
  → local end 跟随已偏移的 singleton
  → space budget 再次推开节点
```

结果是每个局部函数都可能“按自己的规则正确”，最终图却不符合人类对整个结构的理解。

### 1.2 为什么人类认为这些目标并不冲突

以下结构在人类视角中同时满足“主干拉直”和“fan-out 对称”：

```text
                    ┌─ IT 开通账号 ─┐
签订合同 ── split ──┤               ├─ join ── 入职培训 ── 完成入职
                    └─ 行政分配工位 ┘
```

人类识别出的主轴是：

```text
签订合同 ── region axis ── 入职培训 ── 完成入职
```

两条分支是主轴两侧的成员，不要求主轴从其中一条分支穿过。

当前算法缺少 `split–join region` 和 `region axis`，只能从孩子中选择一条作为 spine。问题首先发生在结构语义层，随后才表现为坐标算法冲突。

### 1.3 重构目标

本方案要实现：

1. 节点相对坐标只有一个最终写者。
2. rank、order、结构语义、几何约束和审美目标职责清晰。
3. 主干、fan-out、fan-in、pendant、end、反馈结构都通过统一 IR 表达。
4. 防重叠和最小间距始终是硬约束。
5. 高置信 split–join 能形成稳定视觉主轴。
6. 普通非结构化图仍能使用 BK 得到稳定初值和合理降级。
7. 求解过程确定性、WASM 可用、无随机数、无 wall-clock timeout。
8. 冲突和降级可以按来源诊断，而不是静默失效。
9. 路由压力只能在坐标冻结前反馈，且反馈轮次有界。
10. 逐步迁移，不要求一次重写 rank、order 和路由。

### 1.4 非目标

首期不做：

1. 不重写 Sugiyama rank。
2. 不重写 crossing minimization / order。
3. 不把 `flowchart` 和 `architecture` 的结构分析逻辑强行合并。
4. 不引入依赖 BLAS、native backend 或系统线程的重型通用 QP 求解器。
5. 不追求一次解决所有路由后美学问题。
6. 不允许按图名或具体节点 id 特判。
7. 不用求解器掩盖错误的 effective DAG、rank 或 order。

## 2. 总体架构

### 2.1 阶段职责

```text
Diagram
  │
  ├─ Graph Semantics
  │    ├─ effective DAG
  │    ├─ feedback edge annotations
  │    ├─ ranks
  │    └─ fixed layer order
  │
  ├─ StructureAnalyzer
  │    └─ StructureModel
  │         ├─ linear chains
  │         ├─ split–join regions
  │         ├─ symmetry groups
  │         ├─ axis groups
  │         ├─ pendant groups
  │         └─ feedback regions
  │
  ├─ CoordinateIntentBuilder
  │    └─ CoordinateProblem
  │         ├─ variables
  │         ├─ hard constraints
  │         ├─ structural objectives
  │         ├─ aesthetic objectives
  │         └─ provenance
  │
  ├─ BK Initializer
  │    └─ initial_x
  │
  ├─ CoordinateSolver
  │    └─ best feasible relative coordinates
  │
  ├─ ConstraintAuditor
  │    └─ diagnostics only
  │
  ├─ Global Coordinate Finalize
  │    ├─ normalize whole graph to canvas padding
  │    └─ deterministic grid quantization + hard repair
  │
  ├─ bounded spacing feedback
  │    └─ optional re-solve, at most 1–2 rounds
  │
  └─ freeze node geometry
       └─ route edges
```

### 2.2 写权契约

实施完成后必须满足：

1. `StructureAnalyzer` 不写坐标。
2. `CoordinateIntentBuilder` 不写坐标。
3. BK 只写 `initial_x`，不写最终 `NodeLayout`。
4. `CoordinateSolver` 是相对主轴坐标的唯一写者。
5. normalize 只做全图刚性平移，不改变相对坐标。
6. grid finalize 如需修复间距，只能调用统一硬约束投影器。
7. `ConstraintAuditor` 永远只读。
8. route/refine 阶段禁止直接移动冻结后的节点。
9. route feedback 只能产生 spacing intent，并在重新路由前触发有界 re-solve。

### 2.3 相对坐标与绝对画布坐标分离

求解器解决的是相对坐标，不应把画布原点当成每层的局部约束。

```text
relative solve:
  允许整个图位于任意 x 原点

global finalize:
  shift = canvas_padding - graph_min_x
  所有节点和相关几何整体平移 shift
```

因此：

- 画布 `padding` 不进入层内 overlap 求解。
- 容器内部 padding、固定组边界、用户 pin 属于真正几何约束，可以进入求解器。
- 不允许为了画布左边距只平移某一层。

## 3. 结构语义层：StructureModel

### 3.1 为什么求解器不能替代结构识别

统一 QP 或凸优化只能回答：

> 在已经给定目标和约束时，哪个坐标解最好？

它不能自行回答：

- 哪个 join 对应哪个 split？
- spine 应穿过哪个节点，还是穿过两支之间的虚拟轴？
- 哪些边是反馈旁路，不应参与主轴？
- 哪组后继才是同一个 fan？
- 不等宽节点应按中心、轮廓还是端口对称？

如果结构语义错了，求解器只会更精确地优化错误目标。

### 3.2 输入语义

`StructureAnalyzer` 必须只使用稳定、通用的语义输入：

1. effective DAG，而不是原图全部有向边。
2. FAS 反馈边标记。
3. rank。
4. 固定层内顺序。
5. proper layered graph 与 dummy 链。
6. entity 类型和显式用户约束。
7. group/scope 信息。

禁止：

- 图名分支。
- 依赖 `HashMap` 迭代顺序。
- 用最终几何反猜 split–join。
- 把 FAS 反转后的假前驱当普通主轴邻居。

### 3.3 结构类型

建议首期定义：

```rust
pub struct StructureModel {
    pub regions: Vec<StructureRegion>,
    pub node_membership: Vec<Vec<RegionId>>,
    pub feedback_edges: Vec<EdgeId>,
}

pub enum StructureRegion {
    LinearChain(LinearChainRegion),
    SplitJoin(SplitJoinRegion),
    Symmetry(SymmetryRegion),
    Pendant(PendantRegion),
    Feedback(FeedbackRegion),
    Unstructured(UnstructuredRegion),
}
```

#### LinearChainRegion

表达相邻层的稳定单入单出链。

```rust
pub struct LinearChainRegion {
    pub id: RegionId,
    pub nodes: Vec<NodeIndex>,
    pub confidence: Confidence,
}
```

它生成“偏好共轴”，不默认生成不可违反的固定坐标。

#### SplitJoinRegion

表达一个分叉节点、若干分支和对应汇合节点。

```rust
pub struct SplitJoinRegion {
    pub id: RegionId,
    pub split: NodeIndex,
    pub join: Option<NodeIndex>,
    pub branches: Vec<BranchRegion>,
    pub axis: AxisId,
    pub parent: Option<RegionId>,
    pub confidence: Confidence,
}

pub struct BranchRegion {
    pub entry: NodeIndex,
    pub nodes: Vec<NodeIndex>,
    pub exit: Option<NodeIndex>,
    pub order: usize,
}
```

视觉规则：

1. split 与 join 偏好落在同一个 region axis。
2. join 后的线性 continuation 可加入同一 axis group。
3. 偶数分支时，axis 可以位于中间两支之间。
4. 奇数分支时，中间分支可以落在 axis 上。
5. 主轴不需要从某个任意选中的孩子穿过。

#### SymmetryRegion

表达关于某一 axis 的节点组。

```rust
pub struct SymmetryRegion {
    pub id: RegionId,
    pub axis: AxisId,
    pub members: Vec<NodeIndex>,
    pub mode: SymmetryMode,
    pub confidence: Confidence,
}

pub enum SymmetryMode {
    CenterCentroid,
    MirrorPairs,
    EqualGap,
    VisualEnvelope,
}
```

首期默认使用 `CenterCentroid`；高置信双分支可以使用 `MirrorPairs`。不等宽节点是否采用外轮廓对称，应由 profile 明确，不应混入通用规则。

#### PendantRegion

表达单锚点悬挂节点或同锚 pack：

```rust
pub struct PendantRegion {
    pub id: RegionId,
    pub anchor: NodeIndex,
    pub members: Vec<NodeIndex>,
    pub rank: usize,
    pub confidence: Confidence,
}
```

它替代后置 `align_pendants_under_anchors` 的直接写坐标行为。

#### FeedbackRegion

表达同层反馈 hub、返回边侧支和视觉主链。

反馈边不参与普通 split–join 的前驱 median；反馈结构可生成独立的 axis 或 side-placement intent。

### 3.4 Split–join 识别

推荐基于 effective DAG 的 dominator / post-dominator：

1. 为多出度节点寻找候选 split。
2. 计算 split 后继的最近共同 post-dominator。
3. 最近共同 post-dominator 作为候选 join。
4. 检查 split→join 区域是否满足单入口、单出口或可安全降级的近似 SESE。
5. 收集每个直接后继到 join 的分支节点。
6. 按 rank、层内 order、声明序、id 生成稳定分支顺序。
7. 嵌套 region 必须形成 laminar 层次。
8. 发生交叠但非包含的 region 不强行建立硬结构，降级为低置信 soft intent。

小图可使用确定性 bitset 实现 dominator/post-dominator；首期不需要引入复杂外部库。

### 3.5 置信度与降级

```rust
pub enum Confidence {
    Exact,
    High,
    Medium,
    Low,
}
```

建议映射：

- `Exact`：用户明确约束、严格 SESE。
- `High`：唯一最近共同 post-dominator，分支边界清晰。
- `Medium`：共享 join 明确，但存在跨分支边。
- `Low`：仅根据局部度数推测。

只有 `Exact/High` 可以产生 P1 结构目标。`Medium/Low` 只能产生较低优先级偏好，无法识别时回退 BK。

## 4. 目标与约束拆分

### 4.1 P0：不可违反的硬约束

硬约束定义可行域，任何美学目标都不能破坏它。

#### 固定 rank 和 layer order

坐标阶段不改变 rank，不交换层内顺序。

#### 层内最小分离

固定层序后，相邻节点满足：

```text
x[i+1] - x[i]
  >= width[i] / 2
   + node_gap[i]
   + width[i+1] / 2
```

非相邻节点无需枚举，两两相邻约束的传递性足以保证整层不重叠。

#### 容器与 scope 约束

若 group frame 在节点布局前已固定，节点必须位于合法内部区间。若 group frame 是节点布局后的派生结果，则不应反向约束节点。

必须明确 flowchart group 和 architecture macro-group 的不同语义。

#### 用户 pin / fixed side

显式用户位置、侧序和不可移动锚点属于硬约束。

#### 确定性

确定性不是数值目标，而是实现契约：

- 所有变量编号稳定。
- 所有 region 和 constraint 显式排序。
- 固定迭代顺序和上限。
- 禁止随机数。
- 禁止时间预算作为停机条件。

### 4.2 P1：高置信结构目标

P1 表达人类看到的结构关系：

- split 与 join 共 region axis。
- 高置信 linear chain 共轴。
- 双分支 mirror symmetry。
- fan-out centroid 对齐 parent/region axis。
- fan-in join 回到对应 split axis。
- 单前驱 end 跟随所属 chain/axis。
- pendant pack 的质心对齐 anchor。
- feedback 主链对齐，侧支保持侧向。

这些目标必须优先于普通紧凑和 BK 稳定性，但不允许破坏 P0。

### 4.3 P2：边与路由友好目标

- 相邻层边偏好较小水平跨度。
- dummy chain 偏好直线。
- 端口方向偏好。
- 已知 route demand 需要更宽间距时，生成 spacing intent。
- 主路径边偏好共轴。

P2 不能直接调用路由器反复推点。route demand 必须在坐标冻结前形成有界反馈。

### 4.4 P3：普通审美目标

- 靠近 BK 初值。
- 总宽度更小。
- 节点移动量更小。
- 邻居重心更接近。
- 布局相对上一次结果更稳定。

P3 用于多个合法结构解之间的选择，不能覆盖 P1。

### 4.5 画布 padding 的分类

必须区分：

1. **画布外边距**：求解后全图刚性平移，不属于相对坐标冲突。
2. **组内部 padding**：如果组边界固定，则属于 P0。
3. **节点/边障碍 clearance**：属于 spacing intent 或路由约束，不等同画布 padding。

## 5. Coordinate Intent IR

### 5.1 设计目标

IR 必须做到：

1. 结构识别与求解器解耦。
2. 每个意图带来源和优先级。
3. 可以审计“谁要求了什么”。
4. flowchart 与 architecture 可共享求解内核，但使用不同 builder/profile。
5. 求解器不读取 AST 节点类型做临时特判。

### 5.2 核心问题对象

```rust
pub struct CoordinateProblem {
    pub nodes: Vec<NodeVariable>,
    pub axes: Vec<AxisVariable>,
    pub layers: Vec<LayerConstraintSet>,
    pub hard: Vec<HardConstraint>,
    pub objectives: Vec<ObjectiveTerm>,
    pub initial: InitialCoordinates,
    pub config: CoordinateSolverConfig,
}

pub struct NodeVariable {
    pub node: NodeIndex,
    pub stable_id: String,
    pub rank: usize,
    pub order: usize,
    pub axis_size: f64,
    pub movable: bool,
    pub scope: ScopeId,
}

pub struct AxisVariable {
    pub id: AxisId,
    pub region: RegionId,
    pub initial: f64,
}

pub struct InitialCoordinates {
    pub node_x: Vec<f64>,
    pub axis_x: Vec<f64>,
}
```

运行期热路径使用连续 `Vec`，避免频繁通过 `HashMap<String, _>` 索引。

### 5.3 硬约束

```rust
pub enum HardConstraint {
    MinSeparation {
        left: VarId,
        right: VarId,
        distance: f64,
        source: ConstraintSource,
    },
    LowerBound {
        var: VarId,
        value: f64,
        source: ConstraintSource,
    },
    UpperBound {
        var: VarId,
        value: f64,
        source: ConstraintSource,
    },
    Fixed {
        var: VarId,
        value: f64,
        source: ConstraintSource,
    },
}
```

层内 order 不需要单独允许交换；变量顺序在 `LayerConstraintSet` 中冻结，`MinSeparation` 直接编码该顺序。

### 5.4 统一二次目标

将审美与结构目标统一表达为稀疏线性残差的平方：

```rust
pub struct ObjectiveTerm {
    pub priority: ObjectivePriority,
    pub coefficients: Vec<(VarId, f64)>,
    pub constant: f64,
    pub weight: f64,
    pub source: ConstraintSource,
}

// loss = weight * (constant + Σ coefficient[i] * variable[i])²
```

这样可以表达：

#### 两节点共轴

```text
(x[u] - x[v])²
```

系数：

```text
+1 * x[u]
-1 * x[v]
```

#### 节点对齐虚拟 axis

```text
(x[node] - axis[region])²
```

#### fan-out 质心对齐

```text
(Σ x[child] / child_count - axis)²
```

#### 双分支镜像

```text
(x[left] + x[right] - 2 * axis)²
```

#### 等间距

```text
((x[i+1] - x[i]) - (x[i] - x[i-1]))²
```

#### 靠近 BK 初值

```text
(x[node] - initial_x[node])²
```

#### 边水平长度偏好

```text
(x[from] - x[to])²
```

### 5.5 来源与诊断

```rust
pub struct ConstraintSource {
    pub kind: ConstraintSourceKind,
    pub region: Option<RegionId>,
    pub nodes: Vec<NodeIndex>,
    pub note: &'static str,
}

pub enum ConstraintSourceKind {
    LayerOrder,
    NodeSeparation,
    SplitJoinAxis,
    FanSymmetry,
    LinearChain,
    PendantAnchor,
    LocalEnd,
    FeedbackSpine,
    SpaceBudget,
    RouteDemand,
    BkStability,
    Compactness,
    UserConstraint,
}
```

诊断输出至少包含：

- 硬约束最大 violation。
- 每个 priority 的 loss。
- 每个 region 的 axis deviation。
- 被 active separation 卡住的节点对。
- 未收敛或降级的 objective source。
- re-solve 触发原因和轮次。

## 6. 求解器设计

### 6.1 为什么采用专用一维凸求解器

本问题在 rank/order 冻结后有明显结构：

1. 只求主轴的一维坐标。
2. 每层硬分离约束是一条有序差分链。
3. 大多数目标是稀疏线性残差平方。
4. 问题是凸的。
5. 常见图只有几十到几百个变量。

因此可以实现轻量、确定性、WASM 友好的专用求解器，无需首期引入通用 native QP。

### 6.2 数学模型

变量：

```text
z = [所有 node x, 所有 virtual axis x]
```

目标：

```text
minimize
  L_P1(z)
  then L_P2(z)
  then L_P3(z)
```

每层硬约束：

```text
x[i+1] - x[i] >= d[i]
```

可选边界：

```text
lower[i] <= x[i] <= upper[i]
```

所有 `L_Pk` 都是凸二次函数：

```text
L(z) = Σ weight[t] * residual[t](z)²
```

### 6.3 BK 的新职责

Brandes-Köpf 保留，但职责收缩为：

1. 提供确定性的 warm start。
2. 提供 P3 `PreferBKPosition`。
3. 为无法识别的普通区域提供合理默认美学。

BK 不再在之后单独追加 fan、singleton、spine、end、pendant 修改。

### 6.4 层内硬约束的精确投影

对于一层节点：

```text
x[i+1] - x[i] >= d[i]
```

定义累计最小距离：

```text
s[0] = 0
s[i] = Σ(k=0..i-1) d[k]
y[i] = x[i] - s[i]
```

约束变为：

```text
y[i+1] >= y[i]
```

这就是加权 isotonic regression。可以使用 PAVA（Pool Adjacent Violators Algorithm）在线性时间内把候选坐标精确投影到该层可行域。

收益：

1. 防重叠永远成立。
2. 不需要前扫、后扫、再回中多个 pass。
3. active block 可以解释哪些节点因为最小间距被绑定。
4. 固定输入顺序下结果确定。

### 6.5 分层优先级而不是巨型权重

不建议使用：

```text
P1 weight = 1e12
P2 weight = 1e6
P3 weight = 1
```

巨型权重会产生数值问题，也难解释。

首版采用分层优化：

1. 在 P0 可行域内优化 P1。
2. 保存 P1 最优 loss 和允许容差。
3. 优化 P2 时，候选若让 P1 超过 `best_p1 + tolerance_p1`，则缩小步长或拒绝。
4. 优化 P3 时，同时守住 P1/P2 的 loss budget。
5. 所有 tolerance 按 `node_gap` 和变量数量归一化，不依赖画布绝对坐标。

高置信、理论上必须精确的结构目标，应优先通过 region 变量设计让其自然可满足，而不是无限增大权重。

### 6.6 确定性 projected optimizer

建议实现固定顺序的 projected gradient / coordinate relaxation：

```text
input:
  initial z from BK

project z into P0 feasible set
best = z

for priority in [P1, P2, P3]:
  repeat up to fixed MAX_ITER[priority]:
    1. 按稳定 term 顺序计算 gradient
    2. 使用确定性的初始 step
    3. 生成 candidate
    4. 更新无硬约束的 virtual axis
    5. 对每层按 rank 顺序运行 PAVA hard projection
    6. 应用 fixed/lower/upper projection
    7. 如多类硬约束相交，运行固定轮次 Dykstra projection
    8. 检查更高 priority 的 loss budget
    9. 不满足则固定次数二分 step
   10. 接受更优可行 candidate
   11. 坐标变化和 loss 改善都小于 epsilon 时停止

return best feasible solution
```

停机条件必须是：

- 固定最大迭代次数。
- 固定 epsilon。
- 固定 step backoff 次数。

禁止：

- 运行多少毫秒后停止。
- 随机初值。
- 依赖 HashMap 遍历顺序。

### 6.7 active-set 快路径

后续可以增加 active-set 快路径：

1. PAVA 得到当前绑定的 separation blocks。
2. 每个 block 在当前迭代内视作一个平移变量。
3. 对 block 和 axis 构建更小的稀疏二次问题。
4. 解出 block 位移。
5. 若某个未绑定 separation 即将违反，则加入 active set。
6. 若某个 active constraint 的拉格朗日乘子应释放，则拆 block。

首版可以只做 projected optimizer；IR 不变，后续替换求解后端。

### 6.8 分量和 region 分解

为降低开销：

1. 根据 objective term 与 hard constraint 构建变量关联图。
2. 对互不相连的 component 独立求解。
3. component 内按稳定最小 node id 排序。
4. component 求解后再做全图紧凑排列。

不能为了局部并行破坏确定性；首期串行即可。

### 6.9 不可行与未收敛降级

#### 硬约束不可行

常见原因：

- 相互矛盾的 fixed position。
- 固定容器过窄。
- 用户 pin 与最小间距冲突。

处理：

1. 返回明确的 `InfeasibleHardConstraints`。
2. 输出最小可定位的冲突来源。
3. 不得静默违反节点分离。
4. 若冲突来自派生 group bound，应回到 bound 生成阶段修正。

#### 软目标未收敛

处理：

1. 返回迭代中记录的最佳 P0 可行解。
2. 标记 `degraded` 和未收敛 priority。
3. 不回退到会重叠的初值。
4. 不在求解器后加一个“补对称” pass。

### 6.10 grid snap

grid snap 可能重新破坏最小间距，因此必须属于 coordinate finalize：

```text
solver relative coordinates
  → deterministic quantization
  → hard separation projection in grid units
  → whole-graph normalize
```

如果整数网格投影导致 P1 偏差，只允许在网格可行域内重新优化，不能由后处理直接移动单个节点。

## 7. SpaceBudget 与路由反馈

### 7.1 当前问题

当前 `space_budget::enforce_horizontal_gaps` 会在坐标阶段之后直接移动节点。即使 Sugiyama 内部统一写权，只要它继续存在，最终仍然是多写者。

### 7.2 新契约

`SpaceBudget` 只生成：

```rust
pub struct SpacingIntent {
    pub left: NodeIndex,
    pub right: NodeIndex,
    pub min_gap: f64,
    pub scope: ScopeId,
    pub source: SpacingSource,
}
```

builder 将它转为 P0 `MinSeparation`。

### 7.3 有界 layout–route feedback

部分间距需求只有预路由后才知道。允许：

```text
solve nodes
  → route probe / demand analysis
  → produce additional spacing intents
  → re-solve affected components
  → final route
```

约束：

1. 最多 1–2 轮。
2. 每轮只增加或明确替换 spacing intent。
3. 不允许 route 后直接推节点。
4. 新 spacing intent 必须带 edge/source provenance。
5. re-solve 后相关边必须全部重路由。
6. 若第二轮仍有压力，保留最佳正确结果并标记 degraded，禁止无限振荡。

## 10. 面向 AI Agent 的执行计划

本节是执行规范。每个阶段应独立完成、独立验证，不要跨阶段顺手重构。

### 10.1 全程规则

AI agent 开始任何阶段前必须：

1. 阅读仓库 `AGENTS.md`。
2. 阅读布局与路由核心手册。
3. 检查当前 git status，不覆盖用户已有改动。
4. 确认当前最终坐标写者和阶段时序。
5. 使用稳定排序，不依赖 HashMap key 顺序。
6. 不增加图名特判。
7. `plotgram-core` 禁止裸用 `std::time::{Instant, SystemTime}`。
8. 日常验证不默认使用 `--release`。
9. 渲染验真使用 `cargo run -p plotgram-cli -- render ...`。
10. 每阶段结束记录：新增写者、删除写者、仍存写者。

每次实现前，agent 必须回答：

```text
本阶段修改哪个语义层？
谁是修改字段的最终写者？
新增的是 hard constraint、structural objective 还是 aesthetic objective？
失败时如何降级？
是否影响 rank/order？
是否影响 architecture？
如何保证确定性？
```

### 10.2 M0：建立坐标写权地图和只读诊断

目标：不改变布局行为，先让所有覆盖关系可观察。

任务：

1. 枚举 Sugiyama 后所有可能移动节点的函数。
2. 覆盖 `coordinate.rs`、`space_budget`、`route_feedback`、`refine`、grid snap。
3. 定义只读 diagnostic snapshot：
   - 每层节点中心。
   - 最小间距 violation。
   - fan centroid deviation。
   - split/join axis deviation。
   - 发生节点移动的阶段和节点 id。
4. 诊断默认关闭或只进入已有 debug/perf 机制。
5. 不改变任何坐标。

产物：

- 写权清单。
- 诊断结构。
- 目标样例的阶段前后坐标证据。

退出判据：

- 能明确回答 onboarding 图在哪一步开始偏离父轴。
- 能列出 solver 上线后必须删除或改造的全部直接写者。

停止条件：

- 如果发现还有未纳入计划的路由后节点移动，先更新本文写权边界，不继续实现 solver。

### 10.3 M1：引入 IR 骨架，行为保持不变

目标：建立数据边界，不启用新求解结果。

任务：

1. 新建 `coordinate_solver/model.rs`。
2. 定义 variable、hard constraint、objective term、source。
3. 从现有 layers/sizes 构建 `CoordinateProblem`。
4. BK 坐标填入 `InitialCoordinates`。
5. 将现有层内 node gap 编译为 `MinSeparation`。
6. 加入 auditor，但最终仍返回旧坐标。
7. IR 枚举全部显式排序。

产物：

- 可打印/审计的 `CoordinateProblem`。
- 旧坐标在 IR hard constraint 下的 violation 报告。

退出判据：

- 同输入多次生成完全相同的变量和 constraint 顺序。
- 不改变任何 SVG 节点坐标。

### 10.4 M2：实现 PAVA 硬约束投影器

目标：用单一算法替代分散的层内 overlap 推开。

任务：

1. 实现累计距离变换。
2. 实现 weighted PAVA。
3. 支持固定层序、变宽节点和 per-layer gap。
4. 支持 lower/upper/fixed 的明确冲突报告。
5. 实现 hard constraint auditor。
6. 双跑旧 `resolve_real_node_overlaps` 和新 projection，先只比较。
7. 新结果稳定后由 projection 接管 overlap。

重要限制：

- 这一阶段不迁移 fan/spine/pendant。
- 不修改 rank/order。
- 不引入 route feedback。

退出判据：

- 所有层满足 min separation。
- 相同初值下投影结果确定。
- 可以删除 `resolve_real_node_overlaps` 的坐标写入职责。

### 10.5 M3：实现基础 objective 和 projected optimizer

目标：让 BK 初值、边拉直和紧凑度进入统一求解。

任务：

1. 实现稀疏 residual loss 与 gradient。
2. 实现固定步长、固定 backoff 的 projected optimizer。
3. 实现 P1/P2/P3 分层 loss budget。
4. 实现 best feasible snapshot。
5. 实现未收敛 degraded 诊断。
6. 加入：
   - `PreferBKPosition`
   - `PreferShortHorizontalEdge`
   - dummy chain alignment
7. 输出相对坐标，再由全图 normalize 平移。

退出判据：

- P0 始终满足。
- 关闭新增 objective 时，结果等价于 BK 初值的硬投影。
- 无 wall-clock timeout。
- WASM 编译路径不引入不兼容依赖。

### 10.6 M4：迁移简单后处理为 intent

目标：先迁移语义明确、结构局部的写者。

迁移顺序：

1. singleton 邻层对齐。
2. single-predecessor local end。
3. pendant anchor / pack。

每迁移一个功能：

1. 旧函数先改为生成 objective。
2. 双跑并输出 deviation。
3. 验证 hard separation。
4. 删除旧直接坐标写入。
5. 更新写权清单。

退出判据：

- `align_singleton_layers_to_predecessors` 不再直接写布局。
- `align_local_end_nodes` 不再直接写布局。
- `align_pendants_under_anchors` 不再直接写布局。
- solver 之后不存在对应补救 pass。

### 10.7 M5：引入 StructureModel 与 split–join

目标：从“选择一条 spine”升级为“识别 region axis”。

任务：

1. 构建 effective DAG 结构输入。
2. 标记 feedback edges。
3. 实现 deterministic dominator/post-dominator。
4. 识别严格 split–join。
5. 构建嵌套 region 层次。
6. 识别 split、join、branches、continuation。
7. 为 region 创建 virtual axis。
8. 生成：
   - split→axis
   - join→axis
   - continuation→axis
   - child centroid→axis
   - 双分支 mirror pair
9. 无法识别时降级 BK，不猜测 join。

首批目标样例：

- `product.employee-onboarding.pgm`
- 普通菱形决策图
- 嵌套 fan-out/fan-in
- 有 feedback edge 的审批图

退出判据：

- onboarding 中 split、join、end continuation 共轴。
- IT/行政关于该 axis 对称。
- 不再由 id tie-break 选择行政或 IT 作为 region 主干。
- 反馈边不进入普通 fan-in median。

### 10.8 M6：迁移 feedback spine 并删除旧坐标修补

目标：统一剩余 Sugiyama 横向写权。

任务：

1. 将 feedback hub / side branch 建模为 region intent。
2. 将 `align_spine_chain` 改为 intent builder。
3. 将 `compact_layer_centers` 中 spine 特殊权重迁移为 objective。
4. 将 `enforce_fan_symmetry` 迁移为 symmetry objective。
5. 删除所有 solver 后相对坐标写入。
6. `coordinate.rs` 仅保留编排、物化和 finalize。

退出判据：

- coordinate solver 是 Sugiyama 相对主轴坐标唯一写者。
- 旧 fan/spine direct mutation 已删除。
- same-layer feedback 图和普通 fan 图不再通过全局开关共享错误 spine 规则。

### 10.9 M7：吸收 SpaceBudget 与 route feedback

目标：将坐标管线外部写者收口。

任务：

1. `SpaceBudget` 改为生成 `SpacingIntent`。
2. `enforce_horizontal_gaps` 不再直接用于冻结后的 flowchart 节点。
3. route pressure 转成带 provenance 的 spacing intent。
4. 实现最多 1–2 轮 re-solve。
5. re-solve 后重建 group frame、相关 hints 和路由输入。
6. 节点冻结后 refine 只能改边，不得改节点。

退出判据：

- route/refine 后节点坐标不再变化。
- 所有节点移动都能追溯到一次 solver run。
- 不出现 layout–route 无限反馈。

### 10.10 M8：finalize、审计和旧代码删除

目标：完成新架构收口。

任务：

1. 全图 normalize 只做刚性平移。
2. grid snap 并入 finalize。
3. snap 后统一运行 hard projection。
4. auditor 在冻结点复核全部 P0。
5. 删除旧 overlap/fan/singleton/spine/end/pendant 修补函数。
6. 删除只为旧 pass 存在的状态和开关。
7. 更新核心手册的坐标写权地图。

退出判据：

- solver 后只有 finalize 的整体平移/合法量化。
- 不存在“检测成功但由后阶段覆盖”的坐标目标。
- 诊断可以说明每个降级结构。

### 10.11 M9：Architecture 可选复用

仅在 flowchart 稳定后执行。

任务：

1. 保留 architecture macro/intra 两阶段语义。
2. 只复用 solver/model/projection/audit。
3. 新建 architecture-specific intent builder。
4. 不复用 flowchart entity/end/pendant 规则。
5. group bounds 和 infrastructure layer 规则显式进入 architecture profile。

退出判据：

- architecture 没有被 flowchart 的 split/end 语义污染。
- shared solver 没有 architecture 图名分支。

## 12. 风险与控制

### 12.1 结构误识别

风险：错误 split–join 比没有 split–join 更糟。

控制：

- 置信度分级。
- 严格 region 才进入 P1。
- 非 laminar overlap 降级。
- provenance 诊断。
- 无法确认时回退 BK。

### 12.2 权重调参替代架构

风险：把所有问题重新变成 magic weight。

控制：

- P0/P1/P2/P3 分层。
- term 按 node gap 归一化。
- 高置信结构使用 axis 模型，不只靠增大权重。
- 每个 weight 必须对应明确语义，不允许图名参数。

### 12.3 求解不收敛

控制：

- 凸目标。
- hard projection。
- 固定 step backoff。
- best feasible snapshot。
- 软目标 degraded，硬约束不降级。

### 12.4 旧写者残留

控制：

- M0 写权地图。
- freeze 后坐标 hash/快照。
- auditor 检测 route/refine 是否修改节点。
- 每迁移一个功能立即删除旧 direct mutation。

### 12.5 Flowchart 与 Architecture 污染

控制：

- 共享 solver，不共享结构 profile。
- architecture 最后迁移。
- 手册明确两类 coordinate 不是字节拷贝关系。

### 12.6 路由反馈振荡

控制：

- 反馈轮次上限。
- spacing intent 单调或显式替换。
- 每轮保存最佳正确结果。
- 最终 route 后不再推节点。
