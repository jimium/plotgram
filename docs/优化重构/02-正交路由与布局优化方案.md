### A1. 自环边路由重写

**目标**：自环边感知周围空间，选择最优方向和尺寸，避免与邻居重叠。

**当前问题**：
- `self_loop.rs` 固定右上角矩形环，尺寸 = `min(w,h)*0.28`
- 不感知相邻节点/边/组边框
- 不纳入 `SegmentGrid`

**方案**：

```rust
// 新设计：空间感知自环路由
pub fn route_self_loop_aware(
    rel: &Relation,
    node: &NodeLayout,
    loop_index: usize,
    ctx: &SelfLoopContext,  // 新增：包含邻居信息
) -> EdgeLayout
```

**SelfLoopContext 包含**：
- 相邻节点 bbox 列表（用于碰撞检测）
- 已路由边的 SegmentGrid（避免与已有边重叠）
- 组边框矩形（避免伸出组外）
- 可用空间四个方向的净空距离

**方向选择策略**：
1. 计算四个方向（上/下/左/右）的可用净空
2. 优先选择净空最大的方向（而非固定右上）
3. 多自环按净空排序分配方向，而非固定轮转
4. 净空不足时缩小环尺寸（下限 12px）

**几何改进**：
- 环尺寸自适应：`loop_r = clamp(available_clearance * 0.6, 14, min(w,h)*0.4)`
- 圆角可选：正交环的转角处支持 `rx/ry` 圆角（渲染层消费 annotation）
- 标签位置：放在环的外凸顶点外侧，而非固定偏移

**验证**：
- 单测：自环不穿邻居节点、不伸出组边框
- 视觉：`smoke.decision-loop.pgm` + 新增含多自环的 product 样例

**目标**：回环边有专用通道，不与正向边抢道。

### B1. 引入正交 Visibility Graph 路径搜索

**目标**：替代候选枚举，在障碍物空间中搜索全局最优正交路径。

**算法选择**：正交 Visibility Graph（OVG）而非 A* on grid

**理由**：
- A* on grid 需要栅格化，分辨率选择困难（太粗找不到路径，太细性能差）
- OVG 在障碍物顶点间构建可见性边，搜索空间小（O(n²) 顶点，n=障碍物数）
- OVG 天然产生正交路径（所有边都是水平/垂直的）
- Wybrow 2009 证明 OVG 在 connector routing 中效果优于 grid-based

**设计**：

```rust
// 新模块: layout/edge/edge_routing_orthogonal/visibility_route.rs

/// 正交可见性图：节点为障碍物顶点（膨胀后），边为水平/垂直可见线段
pub struct OrthogonalVisibilityGraph {
    vertices: Vec<Point>,
    // 邻接表：(vertex_index, vertex_index) → 线段长度
    edges: Vec<(usize, usize, f64)>,
}

impl OrthogonalVisibilityGraph {
    /// 从障碍物集合构建 OVG
    /// obstacles: 膨胀后的节点/组 bbox 列表
    /// margin: 额外留白（GROUP_OBSTACLE_PAD / NODE_OBSTACLE_PAD）
    pub fn build(obstacles: &[Rect], margin: f64) -> Self;

    /// 搜索从 start 到 end 的最短正交路径
    /// 使用 Dijkstra（边权 = 长度 + bend_penalty * 转弯次数）
    pub fn shortest_path(
        &self,
        start: Point,
        end: Point,
        from_port: Port,
        to_port: Port,
        bend_penalty: f64,
    ) -> Option<Vec<Point>>;
}
```

**集成策略（渐进式）**：
1. 先在 `select_best_path_with_scorer_stats` 中作为**额外候选**加入
2. OVG 路径与现有候选一起参与打分
3. 验证 OVG 路径在 product-gate 上的表现
4. 逐步提高 OVG 路径的权重，降低模板候选的依赖
5. 最终 OVG 成为主路径生成器，模板候选退化为 fallback

**性能考量**：
- OVG 构建：O(n² log n)，n = 障碍物顶点数（通常 < 200）
- 最短路径搜索：O(E log V)，E = 可见性边数
- 对大图（> 100 节点）：仅对"困难边"（候选枚举 degraded 的边）启用 OVG
- 缓存：同一路由批次内 OVG 只构建一次，多边共享

### B2. 端口选择优化：Port Constraint Solver

**目标**：端口选择从几何规则升级为约束求解，减少后处理修复。

**当前问题**：
- `choose_pair_sides_with_group` 是纯几何规则（`|dy| >= |dx| * threshold`）
- 不考虑同节点其他边的端口分配
- 导致 replan_slots / stub_fix 需要大量后处理

**方案**：
```rust
// 新模块: layout/edge/edge_routing_orthogonal/port_solver.rs

/// 端口约束求解器
/// 输入：所有边的端点对 + 节点几何 + 组关系
/// 输出：每条边的 (from_port, to_port) 分配
/// 约束：
///   - 同节点同侧边数 ≤ 容量（基于边长 / slot_pitch）
///   - 正对端口优先（减少弯折）
///   - 跨组边优先走组间隙方向的端口
///   - 回环边走外侧端口
/// 目标函数：最小化总弯折数 + 交叉数

pub fn solve_port_assignment(
    relations: &[Relation],
    nodes: &HashMap<String, NodeLayout>,
    group_ctx: &GroupRoutingContext,
    feedback: &FeedbackSideAssignment,
) -> Vec<(Port, Port)>
```

**求解方法**：
- 小规模（< 50 边）：穷举 + 剪枝
- 中规模（50-200 边）：贪心 + 局部搜索（swap 端口对，检查目标函数改善）
- 大规模（> 200 边）：保持当前几何规则 + 后处理

### B3. 全局通道分配（Channel Assignment）

**目标**：替代逐边贪心，全局规划通道使用。

**设计**：
```rust
// 新模块: layout/edge/edge_routing_orthogonal/channel_planner.rs

/// 全局通道规划器
/// 在逐边路由之前，为所有边预分配通道坐标
pub struct ChannelPlan {
    // 垂直通道 x 坐标 → 分配给哪些边的哪些段
    vertical_channels: BTreeMap<f64, Vec<(usize, SegmentRange)>>,
    // 水平通道 y 坐标 → 分配给哪些边的哪些段
    horizontal_channels: BTreeMap<f64, Vec<(usize, SegmentRange)>>,
}

/// 通道规划算法：
/// 1. 构建"通道需求图"：每条边需要哪些方向的通道
/// 2. 通道坐标候选：组间隙中点、节点间隙中点、图 bbox 外侧
/// 3. 贪心分配：按边难度降序，为每条边分配最不拥堵的通道
/// 4. 冲突消解：同通道多边按 lane 偏移
pub fn plan_channels(
    relations: &[Relation],
    nodes: &HashMap<String, NodeLayout>,
    group_ctx: &GroupRoutingContext,
    edge_order: &[usize],
) -> ChannelPlan
```

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| BEND_PENALTY 提高导致避障路径变长 | 监控 product-gate 路径长度指标 |
| OVG 性能在大图上不可接受 | 仅对 degraded 边启用；设置超时 fallback |
| 对称约束与交叉最小化冲突 | 对称约束优先级低于不制造碰撞 |
| 组间距扩大导致画布过大 | 设置最大推开距离（如 80px） |
| 后处理层与新路径搜索冲突 | Phase B 期间逐步裁剪后处理层 |
