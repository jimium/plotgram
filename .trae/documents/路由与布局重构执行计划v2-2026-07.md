#### 2.2 抽取 SpaceBudgetGuard(R-4 + R-14 + F-4 + C-2)

**新建文件**:`crates/plotgram-core/src/layout/space_budget_guard.rs`

**导出**:
```rust
use crate::ast::Diagram;
use crate::layout::{EdgeRoutingStrategy, EdgeSnapConfig, LayoutResult, GroupLayout, NodeLayout};
use crate::layout::edge_postprocess::repulse_edges_only;
use crate::layout::space_budget::{horizontal_gap_violations, resolve_residual_with_budget, SpaceBudget};
use crate::layout::post_route_hook::NODE_MOVE_REROUTE_EPS;
use std::collections::{HashMap, HashSet};

/// 对比节点位移,返回移动距离 >= NODE_MOVE_REROUTE_EPS 的节点 id 集合
pub fn diff_moved_nodes(
    pre: &HashMap<String, (f64, f64)>,
    current: &HashMap<String, NodeLayout>,
) -> HashSet<String> {
    current.iter()
        .filter_map(|(id, n)| {
            pre.get(id).and_then(|(px, py)| {
                let dx = n.x - px;
                let dy = n.y - py;
                if (dx * dx + dy * dy).sqrt() >= NODE_MOVE_REROUTE_EPS {
                    Some(id.clone())
                } else {
                    None
                }
            })
        })
        .collect()
}

/// space_budget 兜底:检测水平缝违反 → 推开 → 增量重路由 → repulse
/// 返回 (处理后的 result, 是否触发了 reroute)
pub fn enforce_and_reroute(
    diagram: &Diagram,
    mut result: LayoutResult,
    router: &dyn EdgeRoutingStrategy,
) -> (LayoutResult, bool) {
    let budget = result.hints.space_budget.clone()
        .unwrap_or_else(|| SpaceBudget::from_diagram(diagram));
    if !horizontal_gap_violations(&result.nodes, &budget).is_empty() {
        let pre: HashMap<String, (f64, f64)> = result.nodes.iter()
            .map(|(id, n)| (id.clone(), (n.x, n.y))).collect();
        resolve_residual_with_budget(&mut result.nodes, Some(&budget));
        result.hints.space_budget = Some(budget);
        let moved = diff_moved_nodes(&pre, &result.nodes);
        let triggered = !moved.is_empty();
        if triggered {
            result = router.route_after_node_moves(diagram, result, &moved);
            let snap_cfg = router.edge_snap_config();
            repulse_edges_only(&mut result.edges, &result.groups, &snap_cfg);
        }
        crate::perf_log!("[fallback] budget residual: {} moved nodes", moved.len());
        (result, true)
    } else {
        if result.hints.space_budget.is_none() {
            result.hints.space_budget = Some(budget);
        }
        (result, false)
    }
}
```

**改写**:
- `pipeline.rs:150-206` 的 S3 兜底块 → 调用 `enforce_and_reroute`(注意 pipeline 在 reroute 前还有 `recompute_group_bounds`,需保留这部分编排;只把"位移判定 + reroute + repulse"抽出)
- `route_feedback.rs:60-96` 的 S3 兜底块 → 调用 `enforce_and_reroute`(2.1 的修补自然融入)
- `post_route_hook.rs:60-85` 的 PRS 路径 → 用 `diff_moved_nodes` 共享位移判定(PRS 的 sibling 重叠消解逻辑独立,不强制用 enforce_and_reroute)

**关键约束**:
- pipeline.rs 在 reroute 前有 `recompute_group_bounds`(行 192-198),这部分**保留在 pipeline.rs**,不抽进 enforce_and_reroute(因为 route_feedback.rs 路径不需要)
- 抽取后 pipeline.rs 的 S3 块结构:`recompute_group_bounds` → `enforce_and_reroute`
- 抽取后 route_feedback.rs 的 S3 块结构:直接 `enforce_and_reroute`

## 三、Regression Prevention Strategy(防倒退策略)

### 3.1 每阶段必做验证矩阵

| 验证项 | 命令 | 通过标准 | 适用阶段 |
|---|---|---|---|
| 单元测试 | `cargo test -p plotgram-core --lib` | 新增失败=0(对比 15 既有失败) | 全部 |
| WASM 编译 | `cargo check -p plotgram-wasm --target wasm32-unknown-unknown` | 编译通过 | 涉及 render/parse 路径时 |
| Showcase 回归 | `./showcase/eval-showcase.sh check` | "✓ 未检测到指标回归" | 全部 |
| 全量渲染 | `./showcase/render-all.sh` | 83/83 成功 | 阶段 2/3/6 |
| 大图性能 | `cargo run --release -p plotgram-core --bin bench-phases -- showcase/architecture/c.k8s-platform-stack.pgm` | median_ms 退化 ≤10% | 阶段 2/3/6 |
| 节点坐标 diff | `diff <(jq '.layout.nodes' baseline) <(jq '.layout.nodes' after)` | 应为空(除非阶段明确允许节点移动) | 阶段 2 |

### 3.2 行为变更风险控制(阶段 2)

- **R-4 修复单独提交**:若 showcase 指标超容差,可独立回滚
- **R-4 修复后若指标变化**:只接受改进方向(label_overlaps 下降);若是退化则回滚
- **重新生成基线的条件**:R-4 修复后 label_overlaps 下降但 edge_crossings 上升超容差 → 目视确认是改进后重新生成 `eval-data/showcase-baseline.json`

### 3.3 纯重构风险控制(阶段 3/4/5)

- **不改阈值/常量/执行顺序**:阶段 3 拆分巨型函数时,所有数值常量(如 `STUB_GUARD_LENGTH=24.0`、`MAX_REROUTE_ROUNDS=3`、`channel_margin +10/+25/+40`)原样保留
- **每拆一个 phase 跑 eval-showcase**:不批量拆分后一次性验证
- **保持 `pub use` 重新导出**:阶段 4 文件拆分时,外部 API 无破坏

### 3.4 性能风险控制(阶段 6)

- **bench-phases 前后对比**:每步性能改动后跑 `bench-phases`,退化 >10% 回滚
- **P-1/P-2 改动后跑大图门禁样本**:`c.k8s-platform-stack.pgm`(3911 candidates)和 `c.k8s-tenant-isolation.pgm`(4572 candidates)

### 3.5 WASM 风险控制(AGENTS.md §6)

- 全程禁用 `std::time::{Instant, SystemTime}` / `std::thread` / `std::fs` / `std::net` / `std::process`
- 必须用 `crate::layout::perf::Instant`
- 阶段 6 E-1 修复 eval 的 `std::time` 用法时,加 `#[cfg(not(target_arch="wasm32"))]` 守卫
- 最终验收时 `wasm-pack build` + 同步 playground/agent-demo

4. **既有失败**:阶段 0 钉死的 15 个既有测试失败,全程忽略,只在最后对比"新增失败"。
5. **WASM 同步**:阶段 1-5 每阶段跑 `cargo check -p plotgram-wasm`;**仅阶段 6 结束后**跑一次完整 `wasm-pack build` + 同步。

4. 阶段 4 的文件拆分通过 `pub use` 保持外部 API 不破坏。
