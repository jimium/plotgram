### Step 1:R-5 收尾 —— `segments_violate_spacing` 改用 `classify_parallel_pair`

**文件**:`crates/tautcore-core/src/layout/edge/edge_routing_orthogonal/scoring.rs:401-452`

**当前状态**(已实读):`segments_violate_spacing` 内联 `a_horiz`/`b_horiz`/`a_vert`/`b_vert` 检测 + 水平-水平/垂直-垂直分支,与 `classify_parallel_pair` 逻辑重复。

**改动**:

```rust
pub fn segments_violate_spacing(
    a: &RoutedSegment,
    b: &RoutedSegment,
    min_gap: f64,
) -> Option<(SpacingViolationKind, f64)> {
    if a.edge_index == b.edge_index {
        return None;
    }

    let info = classify_parallel_pair(a, b)?;

    if !info.projection_overlaps {
        return None;
    }

    if info.gap < EPS {
        return Some((SpacingViolationKind::ExactOverlap, 0.0));
    }
    if info.gap < min_gap {
        return Some((SpacingViolationKind::TightSpacing, info.gap));
    }
    None
}
```

**关键约束**:
- 语义完全一致:原逻辑 `a_max <= b_min + EPS || b_max <= a_min + EPS` 等价于 `!projection_overlaps`(因为 `classify_parallel_pair` 用 `a_max > b_min + EPS && b_max > a_min + EPS` 定义 `projection_overlaps`)
- `gap < EPS` → ExactOverlap;`gap < min_gap` → TightSpacing;原样保留
- 非平行段(含正交交叉)返回 `None` —— `classify_parallel_pair` 返回 `None` 时 `?` 早退

pub fn fix_reverse_stub_ports(...) {
    // 1. 检测 from/to 是否有 reverse stub
    let from_fix = detect_endpoint_fix(/* is_from = */ true, ...);
    let to_fix = detect_endpoint_fix(/* is_from = */ false, ...);
    if from_fix.is_none() && to_fix.is_none() { return; }

    // 2. 生成候选
    let attempts = generate_attempts(from_fix, to_fix, ...);

    // 3. 逐个评估,选最优
    for attempt in &attempts {
        if let Some(result) = evaluate_attempt(edge_idx, attempt, ...) {
            apply_result(...);
            return;
        }
    }
}

## 五、Risk Control(风险控制)

### 5.1 纯重构风险(Step 1-7)

- **不改阈值/常量/执行顺序**:所有数值常量原样保留
- **每拆一个 phase/函数跑 eval-showcase**:不批量拆分后一次性验证
- **保持 `pub use` 重新导出**:Stage 4 文件拆分时外部 API 无破坏
- **F-1 同文件内抽取**:不建 `phases/` 目录,降低跨文件移动风险(对 v3 的安全修订)

### 5.2 性能风险(Step 8)

- **bench-phases 前后对比**:P-1/P-2 改动后跑大图门禁,退化 >10% 回滚
- **大图样本**:`c.k8s-platform-stack.taut`(3911 candidates)+ `c.k8s-tenant-isolation.taut`(4572 candidates)

### 5.3 WASM 风险(AGENTS.md §6)

- 全程禁用 `std::time::{Instant, SystemTime}` / `std::thread` / `std::fs` / `std::net` / `std::process`
- 必须用 `crate::layout::perf::Instant`
- Step 8 E-1 修复 eval 的 `std::time` 用法时,加 `#[cfg(not(target_arch="wasm32"))]` 守卫
- 仅 Step 9 最终验收时跑完整 `wasm-pack build` + 同步

### 5.4 行为变更风险(Step 8 E-2)

- E-2 是唯一的行为变更(eval 入口统一),需目视确认 eval 结果不退化
- 若 eval-showcase check 失败,回滚 E-2 单步,其余步骤不受影响

## 六、Assumptions & Decisions(假设与决策)

### 决策

1. **步骤顺序**:Step 0(验证)→ 1(R-5 收尾)→ 2(F-2)→ 3(F-3)→ 4(F-5)→ 5(F-1)→ 6(Stage 4)→ 7(Stage 5)→ 8(Stage 6)→ 9(最终验收)。由简到繁,降低风险。
2. **F-1 同文件抽取**:不建 `phases/` 目录(对 v3 的安全修订)。理由:775 行函数共享可变状态多,跨文件移动需引入 `OrthoRoutingContext` struct,抽象风险高;同文件私有函数 + `&mut` 参数更易验证行为一致性。
3. **F-1 拆分顺序**:由简到繁(labels→sanitize→lane→stub_fix→reroute→layer_order→initial_route→port_slot),每拆一个 phase 跑一次验证。
4. **提交粒度**:每个步骤(如 Step 1, Step 2, Step 5 内每个 phase)单独提交,便于回滚。
5. **既有失败**:阶段 0 钉死的 15 个既有测试失败,全程忽略,只在最后对比"新增失败"。
6. **WASM 同步**:Step 0-8 每步跑 `cargo check -p tautcore-wasm`;**仅 Step 9** 跑完整 `wasm-pack build` + 同步 playground/agent-demo。
7. **Step 8 E-2 行为变更**:eval 入口统一是必要修复(复盘文档指出 `tautcore-eval::engine` 绕过 `validate`),需目视确认后保留。

### 假设

1. `./showcase/eval-showcase.sh check` 的 12 项指标容差足以捕获渲染退化
2. `c.k8s-platform-stack.taut` + `c.k8s-tenant-isolation.taut` 的 bench-phases 耗时能代表大图性能
3. Step 1-7 的纯重构(不改阈值/常量/顺序)理论上零行为变化;eval-showcase check 应全绿
4. Step 6 文件拆分通过 `pub use` 保持外部 API 不破坏
5. Step 0 验证会通过(R-5 半完成的 `classify_parallel_pair` 抽取是字节级等价)

### 不做的事项(AGENTS.md + v3 计划否定结论)

- **不删** `architecture_v2/layout/acyclic.rs:34` 的 `inject_irreversible_edges`(在用)
- **不并** `layout/postprocess.rs` 的 bbox 逻辑进 R-3(职责不同)
- **不在**节点布局仍可变的阶段启用激进 `merge_overshoot`(踩坑复盘 §3)
- **不追求** 100% lint 干净牺牲算法简洁性(AGENTS.md §4)
- **不图名特判**(AGENTS.md §5)
- **不为 F-1 引入 `OrthoRoutingContext` struct**(同文件抽取更安全)
