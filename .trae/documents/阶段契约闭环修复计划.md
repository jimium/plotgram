#### P04 — `topological_sort_groups` 入度去重不对称

**文件**：`crates/plotgram-core/src/layout/node/flowchart/group_divide.rs`
**位置**：`topological_sort_groups` 函数，第 385–398 行

**问题**：第 390 行 `*in_degree.get_mut(to).unwrap() += 1` 按 edge 累加，第 397 行 `edges.dedup()` 只去重 `out_edges`，释放时（第 416–423 行）按去重后的 list 只减一次。多重 `A->B` 会让 `in_degree[B]` 永不到 0，落入循环恢复分支。

**修复**：从去重后的 `out_edges` 派生 `in_degree`，保证两者一致：
1. 删除第 390 行的 `*in_degree.get_mut(to).unwrap() += 1;`（保留 `out_edges.push`）
2. 在第 398 行 dedup 循环之后，新增一段从 `out_edges` 派生 `in_degree` 的循环：
   ```rust
   for edges in out_edges.values() {
       for to in edges {
           *in_degree.get_mut(to).unwrap() += 1;
       }
   }
   ```
   （HashMap 迭代安全：加法可交换，结果与顺序无关，符合 AGENTS.md 规则 2）

**测试**：在同文件 `#[cfg(test)] mod tests`（第 657 行起）新增 `topological_sort_duplicate_edges`，构造 2–3 条 `g1→g2` 跨组边（不同实体 id，同组），断言排序结果为 `["g1","g2","g3"]` 而非落入循环恢复。参考现有 `topological_sort_simple_chain`（第 658 行）的构造模式。

#### P06 — lane assignment fallback 绕过 validate_shift

**文件**：`crates/plotgram-core/src/layout/edge/edge_routing_orthogonal/lane_assignment.rs`
**位置**：`try_separate_edge_pair` 函数 fallback 分支，第 660–668 行

```rust
if force_shift_trunk_coord(&mut new_points, is_vertical, shared_coord, target)
    && validate_shift(&original, &new_points, si, nodes, sorted_node_ids)
{
    commit_shifted_path(edges, target_ei, &new_points, relations, from_side, to_side);
    return true;
}
```

**注意**：`force_shift_trunk_coord` 可能移动 `si-1`/`si+1` 之外的共线点，`validate_shift` 只检查 `si-1`/`si`/`si+1`。极端长共线 trunk 仍可能漏检。本次采用最小修复（严格优于现状），更彻底的全段校验留后续。

#### P15 — `normalize_layout_result_to_padding` 先移节点后算 group 平移

**文件**：`crates/plotgram-core/src/layout/node/sugiyama_v2/postprocess.rs`
**位置**：`normalize_layout_result_to_padding` 函数，第 45–71 行

**问题**：第 46 行先调 `normalize_layout_to_padding` 移动节点（基于原始 min 算 dx/dy 并应用），第 47–48 行再用移动后的 min 重算 dx/dy → 恒 ≤ 0 → 第 63 行 early return → groups 和 total_size 永不调整。

**修复（Option A，最小改动）**：重写函数体，从原始 min 一次性算 dx/dy，统一应用到 nodes + groups + total_size：
```rust
pub(super) fn normalize_layout_result_to_padding(result: &mut LayoutResult, padding: f64) {
    let min_x = result.nodes.values().map(|n| n.x).fold(f64::INFINITY, f64::min);
    let min_y = result.nodes.values().map(|n| n.y).fold(f64::INFINITY, f64::min);
    if !min_x.is_finite() || !min_y.is_finite() {
        return;
    }
    let dx = if min_x < padding { padding - min_x } else { 0.0 };
    let dy = if min_y < padding { padding - min_y } else { 0.0 };
    if dx == 0.0 && dy == 0.0 {
        return;
    }
    for node in result.nodes.values_mut() {
        node.x += dx;
        node.y += dy;
    }
    for group in result.groups.values_mut() {
        group.x += dx;
        group.y += dy;
    }
    result.total_width += dx;
    result.total_height += dy;
}
```
- 不再调用 `normalize_layout_to_padding`（该 helper 保留，`coordinate.rs:79` 仍在用）
- 删除第 47–64 行的死代码块

**测试**：在 `sugiyama_v2/mod.rs` 的 `#[cfg(test)]` 块新增测试：手构 `LayoutResult`（1 节点 `x=2,y=2`，1 group `x=2,y=2`，`padding=10`），调用后断言节点和 group 均 `x=10,y=10`，`total_width/height` 各 +8。再加一个负例（节点已 `x=20,y=20`）断言不动。

#### P03 — architecture_v2 约束注入在 FAS 之后

**文件**：
- `crates/plotgram-core/src/layout/node/architecture_v2/layout/mod.rs`（第 78–89 行）
- `crates/plotgram-core/src/layout/node/architecture_v2/layout/acyclic.rs`（`find_edges_to_reverse` 第 9–11 行）

**问题**：第 78 行 `GraphIndex::build` 只读 relations，第 81 行 FAS 在无约束图上跑，第 89 行才 `inject_irreversible_edges`。约束可能重新引入环，但 `reversed_edges` 已定型，下游 rank 用旧去环结果。

**关键发现**：
- `DirectedGraphIndex` 无 edge metadata（无 `reversible` 字段），不能像 sugiyama_v2 那样在图结构里标记
- `inject_irreversible_edges`（acyclic.rs:22-41）零环检测，盲插
- `find_edges_to_reverse` 调 `common::acyclic::greedy_fas`，传全量邻接，会反转约束边 → 违反"irreversible"契约
- 修复必须两步：(1) 注入提前到 FAS 之前；(2) FAS 排除约束边不反转

**修复**：

1. **`acyclic.rs` — 改 `find_edges_to_reverse` 签名**，新增 `non_reversible: &HashSet<(String, String)>` 参数，构建 FAS 邻接时过滤掉约束边（镜像 sugiyama_v2 的 `greedy_cycle_reversal` 做法）：
   ```rust
   pub(in super::super) fn find_edges_to_reverse(
       graph: &GraphIndex,
       non_reversible: &HashSet<(String, String)>,
   ) -> HashSet<(String, String)> {
       let mut out_neighbors: HashMap<String, Vec<String>> = HashMap::new();
       let mut in_neighbors: HashMap<String, Vec<String>> = HashMap::new();
       for node in &graph.node_ids {
           let outs = graph.out_edges.get(node).map(|v| {
               v.iter().filter(|t| !non_reversible.contains(&(node.clone(), (*t).clone())))
                   .cloned().collect::<Vec<_>>()
           }).unwrap_or_default();
           let ins = graph.in_edges.get(node).map(|v| {
               v.iter().filter(|f| !non_reversible.contains(&(f.clone(), node.clone())))
                   .cloned().collect::<Vec<_>>()
           }).unwrap_or_default();
           out_neighbors.insert(node.clone(), outs);
           in_neighbors.insert(node.clone(), ins);
       }
       acyclic::greedy_fas(&graph.node_ids, &out_neighbors, &in_neighbors)
   }
   ```

2. **`mod.rs` — 重排顺序**：注入提前到 FAS 之前，构造 `constraint_set` 传给 `find_edges_to_reverse`：
   ```rust
   let mut graph = types::GraphIndex::build(diagram);
   let group_map = types::build_group_map(diagram);

   // 先注入约束（与 sugiyama_v2::graph::build_graph 一致）
   let constraint_edges: Vec<(&str, &str)> = diagram.constraints.iter()
       .map(|c| (c.from.as_str(), c.to.as_str())).collect();
   acyclic::inject_irreversible_edges(&mut graph, &constraint_edges);

   // FAS：约束边参与拓扑但不被反转
   let constraint_set: HashSet<(String, String)> = constraint_edges.iter()
       .map(|(f, t)| (f.to_string(), t.to_string())).collect();
   let reversed_edges = acyclic::find_edges_to_reverse(&graph, &constraint_set);
   ```
   更新第 83 行注释为"先注入约束再 FAS（约束边永不被反转）"。

3. **影响面**：`find_edges_to_reverse` 仅 1 个调用方（本文件），签名变更安全。grouped（`two_phase`）和 non-grouped（`assign_ranks_group_aware`）两条路径都接收 `reversed_edges`，一次修复覆盖两者。

**测试**：在 `architecture_v2/layout/layout_tests.rs` 新增测试：relation `A→B` + constraint `B→A`（约束造环），调用 `ArchitectureV2Layout::default().compute(&d)`，断言 (a) `rank(A) < rank(B)`（约束方向被尊重），(b) 节点不全坍缩到同一 rank。参考 `super_graph_cycle_does_not_collapse_sink_to_rank_0`（第 667 行）的构造模式。

## Assumptions & Decisions

1. **P06 fallback 保留**：fallback 分支覆盖第一策略无法分离的场景，不能删除，只加校验门控。
