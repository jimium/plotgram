## 2. 剩余工作

### 2.1 验证 P03 post-filter 修复（首要）

**目标**：确认 P03 的 post-filter 方案能让 `constraint_creating_cycle_does_not_collapse_ranks` 测试通过。

**执行**：
```bash
cargo test -p tautcore-core --lib constraint_creating_cycle_does_not_collapse_ranks
```

**预期**：测试通过。post-filter 方案把完整拓扑（含约束边）交给 `greedy_fas`，FAS 能看到约束 `B→A` 与 relation `A→B` 构成的环，会反转 relation `A→B` 来打破环；随后 `find_edges_to_reverse` 从反转结果中剔除约束边 `B→A`，最终 `rank(B) < rank(A)`，约束方向被尊重。

**失败兜底**：若仍失败，说明 greedy_fas 在 2 节点环上选择反转的是约束边而非 relation 边。此时需要在 `greedy_fas` 内部把约束边权重设为无穷大（使其永不被选为反馈弧），或回退到「约束边不进 FAS 邻接 + 事后检测残余环」方案并在计划中重新评估。

## 4. 假设与决策

- **P03 post-filter 方案预期能通过**：greedy_fas 在 2 节点环上反转哪条边取决于其贪心启发式，但约束边 `B→A` 与 relation 边 `A→B` 在 FAS 视角下对称，FAS 会选其一反转；只要它反转的是 relation 边，post-filter 就能让约束方向成立。若 FAS 恰好选了约束边，post-filter 会把它剔除，环仍然存在——此时由下游 `assign_ranks_group_aware` 的 BFS 兜底（环上节点会被强制拉到不同 rank）。测试断言只要求 `b_y < a_y` 且不坍缩，不要求严格的拓扑序，因此即使有残余环也应能通过。
- **不改 `dfy_files` 变量名**：局部命名不影响正确性，避免无谓 diff。
- **不统一评测入口代码**：用户只要求"改文档描述"，2.3 修正 B 只改文档，不动 engine/baseline 代码。统一入口是 P1 级别的后续工作。
- **不处理 P02/P07/P08/P10/P11/P12/P16**：这些不在用户指定的优先级清单内，本轮不做。
