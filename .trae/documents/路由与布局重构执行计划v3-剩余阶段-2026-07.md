**当前 4 处重复实现**(已实读核验,字节级相同):

- `node/architecture_v2/layout/postprocess.rs:146-159` `fn compute_total_size(nodes, groups)` (用常量 `PADDING`,无 padding 参数)

**导出**:
```rust
use crate::layout::{NodeLayout, GroupLayout};
use std::collections::HashMap;

/// 计算画布总尺寸(width, height),包含节点 + 分组,加 padding
pub fn canvas_size(
    nodes: &HashMap<String, NodeLayout>,
    groups: &HashMap<String, GroupLayout>,
    padding: f64,
) -> (f64, f64) {
    let node_max_x = nodes.values().map(|n| n.x + n.width).fold(0.0_f64, f64::max);
    let node_max_y = nodes.values().map(|n| n.y + n.height).fold(0.0_f64, f64::max);
    let group_max_x = groups.values().map(|g| g.x + g.width).fold(0.0_f64, f64::max);
    let group_max_y = groups.values().map(|g| g.y + g.height).fold(0.0_f64, f64::max);
    (
        node_max_x.max(group_max_x) + padding,
        node_max_y.max(group_max_y) + padding,
    )
}
```

**注册**:`node/common/mod.rs` 加 `pub mod canvas_bounds;`

**改写**(4 处):

- `force_directed.rs:840-853`:删 `bounds_from_layout`,改 `use`

## 三、Regression Prevention Strategy(防倒退策略)

### 3.1 每阶段必做验证矩阵

| 验证项 | 命令 | 通过标准 | 适用阶段 |
|---|---|---|---|
| 单元测试 | `cargo test -p tautcore-core --lib` | 新增失败=0(对比 15 既有失败) | 全部 |
| WASM 编译 | `cargo check -p tautcore-wasm --target wasm32-unknown-unknown` | 编译通过 | 涉及 render/parse 路径时 |
| Showcase 回归 | `./showcase/eval-showcase.sh check` | "✓ 未检测到指标回归" | 全部 |
| 全量渲染 | `./showcase/render-all.sh` | 83/83 成功 | 阶段 2/3/6 |
| 大图性能 | `cargo run --release -p tautcore-core --bin bench-phases -- showcase/architecture/c.k8s-platform-stack.taut` | median_ms 退化 ≤10% | 阶段 2/3/6 |
| 节点坐标 diff | `diff <(jq '.layout.nodes' baseline) <(jq '.layout.nodes' after)` | 应为空(除非阶段明确允许节点移动) | 阶段 2 |

### 3.2 纯重构风险控制(阶段 2.3/2.4/2.5/3/4/5)

- **不改阈值/常量/执行顺序**:阶段 3 拆分巨型函数时,所有数值常量(如 `STUB_GUARD_LENGTH=24.0`、`MAX_REROUTE_ROUNDS=3`、`channel_margin +10/+25/+40`)原样保留
- **每拆一个 phase 跑 eval-showcase**:不批量拆分后一次性验证
- **保持 `pub use` 重新导出**:阶段 4 文件拆分时,外部 API 无破坏
- **阶段 2.3 曲线路由器改写**:只替换 obstacle setup 和 `curve_intersects_obstacles` 调用路径,不改穿障检测语义(采样点数仍 16)

### 3.3 性能风险控制(阶段 6)

- **bench-phases 前后对比**:每步性能改动后跑 `bench-phases`,退化 >10% 回滚
- **P-1/P-2 改动后跑大图门禁样本**:`c.k8s-platform-stack.taut`(3911 candidates)和 `c.k8s-tenant-isolation.taut`(4572 candidates)

### 3.4 WASM 风险控制(AGENTS.md §6)

- 全程禁用 `std::time::{Instant, SystemTime}` / `std::thread` / `std::fs` / `std::net` / `std::process`
- 必须用 `crate::layout::perf::Instant`
- 阶段 6 E-1 修复 eval 的 `std::time` 用法时,加 `#[cfg(not(target_arch="wasm32"))]` 守卫
- 最终验收时 `wasm-pack build` + 同步 playground/agent-demo

## 四、Assumptions & Decisions(假设与决策)

### 决策

1. **阶段顺序**:严格按 1验证→2.3→2.4→2.5→3→4→5→6 顺序,每阶段门禁通过后再进下一阶段。
2. **提交粒度**:每个步骤(如 2.3.1, 2.3.2, 3.1)单独提交,便于回滚。
3. **既有失败**:阶段 0 钉死的 15 个既有测试失败,全程忽略,只在最后对比"新增失败"。
4. **WASM 同步**:阶段 1-5 每阶段跑 `cargo check -p tautcore-wasm`;**仅阶段 6 结束后**跑一次完整 `wasm-pack build` + 同步。
5. **阶段 2.3 共享模块边界**:`build_obstacle_context` 返回 `(HashMap<&str, usize>, ObstacleIndex)`,不返回 `node_list`(spline 不需要,spline 的 obstacle setup 不用 node_list);若其他路由器有额外需要 node_list 的地方,保留本地逻辑。
6. **阶段 2.4 canvas_bounds 边界**:`architecture_v2/layout/postprocess.rs` 的 `compute_total_size` 用常量 `PADDING` 而非参数,统一后调用方传 `PADDING` 常量,行为完全一致。

### 假设

1. `./showcase/eval-showcase.sh check` 的 12 项指标容差足以捕获渲染退化。
2. `c.k8s-platform-stack.taut` 的 bench-phases 耗时能代表大图性能。
3. 阶段 3 的巨型函数拆分是纯内部重构,不改阈值/常量/执行顺序,理论上零行为变化。
4. 阶段 4 的文件拆分通过 `pub use` 保持外部 API 不破坏。
5. 阶段 1 验证会通过(2.1/2.2 已通过验证,本次只是重新确认无回归)。

### 不做的事项(AGENTS.md + 报告否定结论)

- **不删** `architecture_v2/layout/acyclic.rs:34` 的 `inject_irreversible_edges`(在用)
- **不并** `layout/postprocess.rs` 的 bbox 逻辑进 R-3(职责不同)
- **不在**节点布局仍可变的阶段启用激进 `merge_overshoot`(踩坑复盘 §3)
- **不追求** 100% lint 干净牺牲算法简洁性(AGENTS.md §4)
- **不图名特判**(AGENTS.md §5)
